# Redis 源码中有哪些巧妙的设计，举几个典型的例子？

## 回答重点

Redis 能做到单机 10 万级 QPS，离不开源码中大量精心设计的细节，典型设计包括 **SDS 字符串、压缩列表、渐进式 `rehash`、共享对象池，以及惰性删除与定期删除**。

### SDS 字符串

C 语言原生字符串获取长度需要 $O(N)$ 遍历，拼接时容易缓冲区溢出，也不能安全保存二进制数据。Redis 使用 SDS（Simple Dynamic String），在数据前保存已用长度和剩余空间：

```c
struct sdshdr {
    int len;      // 已用长度
    int free;     // 剩余空间
    char buf[];   // 实际数据
};
```

主要优点：

1. 获取长度为 $O(1)$，无需遍历。
2. 追加前检查剩余空间并自动扩容，避免溢出。
3. 不依赖 `\0` 判断结束，能够保存任意二进制数据。
4. 字符串缩短后保留部分空间，减少频繁内存分配。

### 压缩列表 ziplist

当 List 或 Hash 的元素较少且较短时，Redis 使用一整块连续内存保存数据。节点记录前一个节点的长度，因此可以前后遍历，同时省去链表指针带来的空间开销。

例如小 Hash 使用 ziplist 时，整体占用可能只有几十字节；当元素数量增多或单个元素超过阈值后，Redis 会自动转成更适合大数据量的结构。

> Redis 7.0 之后 ziplist 已被 listpack 替代。

### 渐进式 `rehash`

哈希表扩容如果一次性搬迁几百万个 `key`，会长时间阻塞主线程。Redis 准备 `ht[0]` 和 `ht[1]` 两张表，扩容时将新数据写入 `ht[1]`，并在每次增删改查时顺便迁移少量旧节点。等 `ht[0]` 清空后，再切换表指针。

这种方式把扩容成本分摊到日常操作中，避免长时间停顿。

### 共享对象池

Redis 默认预创建 0 到 9999 的整数对象并放入共享对象池。后续业务使用这些整数时直接复用对象，避免反复 `malloc/free`，计数器加减等操作也不需要频繁分配内存。

### 过期键处理

Redis 没有单独线程持续扫描所有过期键，而是组合使用两种策略：

1. **惰性删除**：访问 `key` 时检查是否过期，过期就立即删除。
2. **定期删除**：定期随机抽取设置了过期时间的 `key`，删除其中已过期的 `key`；如果过期比例较高，则继续抽样处理。

这种方式既能清理过期数据，又避免全量扫描阻塞响应。

## 扩展知识

### AOF 重写机制

AOF 记录写命令，长期运行后可能出现大量冗余。例如同一个 `key` 被 SET 多次，恢复时只需要最后一次结果。AOF 重写会 fork 子进程，根据当前内存状态生成精简命令集；主进程继续处理请求，并把新增写命令写入重写缓冲区。子进程完成后，主进程将增量命令追加到新文件，再原子替换旧文件。

### listpack 替代 ziplist

ziplist 的节点会记录前一个节点长度。当某个节点长度跨过编码阈值时，后续节点的 `prevlen` 可能都需要扩容，形成连锁更新，最坏情况下插入一个节点要修改整条链。

listpack 只记录当前节点自身长度，不记录前一个节点的信息，因此消除了连锁更新，内存布局也更简单。

### 内存编码的自动升级

Redis 会根据数据规模自动选择更节省内存或更适合查询的编码：

| 数据类型 | 小数据编码 | 大数据编码 | 典型切换阈值 |
| --- | --- | --- | --- |
| String | `int` / `embstr` | `raw` | 约 44 字节 |
| List | `quicklist` | `quicklist` | — |
| Hash | `listpack` | `hashtable` | 512 个 field |
| Set | `intset` / `listpack` | `hashtable` | 512 个元素 |
| ZSet | `listpack` | `skiplist` + `hashtable` | 128 个元素 |

相关阈值可以通过 `hash-max-listpack-entries`、`hash-max-listpack-value` 等配置调整。

## 面试官追问

### 提问：SDS 扩容时新容量如何计算？

如果扩容后长度小于 1 MB，通常按翻倍策略分配；超过 1 MB 后，每次额外增加约 1 MB。这样小字符串扩容速度快，大字符串也不会一次性浪费过多内存。

### 提问：渐进式 `rehash` 期间读操作如何处理？

先查 `ht[0]`，找不到再查 `ht[1]`；写操作只写入 `ht[1]`。因此 `rehash` 期间读写仍可正常进行，只是部分查询需要检查两张表。

### 提问：ziplist 的连锁更新如何发生？

ziplist 用 1～5 字节记录前一个节点长度。当节点长度从小于 254 字节变为更大值时，后续节点的 `prevlen` 可能从 1 字节扩为 5 字节；后续节点长度继续变化，就会产生连续扩容，形成连锁更新。

### 提问：共享对象池为什么只缓存 0 到 9999？

缓存整数越多，启动时占用的内存越大，而更大的整数命中率通常较低。0～9999 已覆盖大多数计数器、标志位和小 ID 场景，继续扩大范围的收益有限。
