# 数组和链表在 Java 中的区别是什么？

## 回答重点

数组和链表最根本的区别在于**内存布局**。数组是一整块连续的内存，链表是散落在各处、靠指针串起来的节点。

数组在内存里是挨着放的，通过「基地址 + 下标 × 元素大小」就能直接算出任意元素的地址，所以随机访问是 $O(1)$。但也正因为要保持连续，中间插入或删除元素就得把后面的全部搬家，最坏 $O(n)$。

链表每个节点除了存数据，还要存指向下一个节点的指针。节点可以散落在内存的任何角落，不需要连续空间。插入删除只需要改指针，$O(1)$ 就搞定，但要访问第 `n` 个元素就得从头一个个数过去，$O(n)$。

![](Z:/Public/images/Y6pxz3qt_Urke0uRg2B_mianshiya.webp)

| 对比维度 | 数组 | 链表 |
| --- | --- | --- |
| 内存分配 | 连续内存，声明时就定死大小 | 散装内存，按需分配 |
| 随机访问 | `O(1)`，直接算地址 | `O(n)`，从头遍历 |
| 插入删除 | `O(n)`，要搬运元素 | `O(1)`，改指针就行 |
| 内存开销 | 紧凑，只存数据 | 每个节点多存指针 |
| CPU 缓存 | 友好，预读有效 | 不友好，跳来跳去 |

## 扩展知识

### 数组为什么随机访问快

![20220219202821.png](Z:/Public/images/20220219202821_mianshiya.webp)

数组能做到 $O(1)$ 访问，靠的是两个前提：内存连续、元素大小固定。

比如一个 int 数组，基地址是 0x1000，每个元素占 4 字节。要访问第 5 个元素，直接算 0x1000 + 5 × 4 = 0x1014，一条指令就定位到了，不需要任何遍历。

这也解释了为什么 Java 的数组必须是同一类型。类型不同大小就不固定，地址就没法用公式算了。

### 链表为什么插入删除快

![20220219202832.png](Z:/Public/images/20220219202832_mianshiya.webp)

链表节点之间靠指针相连，插入一个新节点只需要改两个指针：让前驱节点指向新节点，新节点指向后继节点。删除同理，让前驱直接指向后继，被删节点就脱离链表了。

不过要注意一个陷阱：链表插入删除是 $O(1)$ 没错，但前提是你已经拿到了要操作的节点。如果你只知道「删除值为 100 的节点」，那还得先从头遍历找到它，加起来还是 $O(n)$。

### CPU 缓存和空间局部性

现代 CPU 读内存不是一个字节一个字节读的，而是一次读一个缓存行，通常是 64 字节。

数组内存连续，读一个元素的时候，相邻的元素大概率也被读进缓存了。下次访问相邻元素直接命中缓存，速度比访问内存快 100 倍。这就是空间局部性带来的好处。

链表节点散落各处，一次缓存加载只能命中当前节点，下一个节点在哪完全随机，大概率缓存不命中。所以即使两者理论复杂度一样，实际跑起来数组往往比链表快。

这也是为什么 `ArrayList` 在大多数场景下都比 `LinkedList` 快，虽然插入删除的理论复杂度 `ArrayList` 更高。

### Java 中的实际应用

数组最常见的封装是 `ArrayList`，它底层就是一个 Object[] 数组，增删时自动处理扩容和搬运。

链表对应的是 `LinkedList`，它是双向链表，每个节点存了前驱和后继两个指针，支持从头尾两端操作。

实际工作中，99% 的情况用 `ArrayList` 就够了。`LinkedList` 只在两个场景有优势：频繁在头部插入删除，或者用它当队列 / 双端队列用。

## 面试官追问

#### 提问：`ArrayList` 扩容是怎么实现的？

详细解答可以看：[Java `ArrayList` 的扩容机制是什么？](https://www.mianshiya.com/question/1839515038747066370)

回答：`ArrayList` 默认初始容量是 10。当元素装满了，就扩容到原来的 1.5 倍，也就是右移一位再加上原值。扩容本质是创建一个新数组，把老数组的内容 copy 过去，所以扩容是 $O(n)$ 的操作。如果能预估元素数量，建议用带初始容量的构造方法，避免反复扩容。

#### 提问：`LinkedList` 为什么实现了 Deque 接口？

回答：因为双向链表天生就支持两端操作，头部和尾部增删都是 $O(1)$。所以 `LinkedList` 既可以当 List 用，也可以当队列、栈、双端队列用。调用 addFirst / addLast 就是队列操作，调用 push / pop 就是栈操作。

#### 提问：什么场景下 `LinkedList` 比 `ArrayList` 快？

详细解答可以看：[Java 中 `ArrayList` 和 `LinkedList` 有什么区别？](https://www.mianshiya.com/question/1839516705798356994)

回答：几乎没有。理论上频繁在中间插入删除 `LinkedList` 应该快，但实际上 `ArrayList` 移动元素用的是底层的 `System`.arraycopy，这是 native 方法，CPU 层面有优化，比想象中快得多。再加上 `LinkedList` 查找位置本身就是 $O(n)$，综合下来 `ArrayList` 基本全面碾压。`LinkedList` 唯一的优势场景是当队列用，频繁操作头部，其他时候都选 `ArrayList`。
