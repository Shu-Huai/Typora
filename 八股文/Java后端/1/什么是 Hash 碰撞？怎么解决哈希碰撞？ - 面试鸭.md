# 什么是 Hash 碰撞？怎么解决哈希碰撞？ - 面试鸭 | 2026最新面试题+详细答案解析

## 回答重点

Hash 碰撞就是：**两个不同的 key，经过 hash 函数计算后，得到了同一个数组下标**。

![hashpeng.drawio.png](https://pic.code-nav.cn/mianshiya/question_picture/1783388929455529986/Gg9VjzoS_hashpeng.drawio_mianshiya.webp)

常见有以下几种方式解决哈希碰撞问题：

1）**拉链法**

将哈希表中每个槽的位置变成一个链表，当多个键的哈希值相同时，将它们存储在同一个链表中。Java 的 HashMap 就是这么干的。

2）**开放寻址法**

如果出现碰撞，寻找哈希表中的下一个可用位置。Java 的 ThreadLocalMap 用的就是这种方式。

3）**再哈希法**

在出现碰撞时，使用第二个哈希函数计算新的索引位置，如果还冲突则再用另一个哈希函数重新算一次位置，直到无冲突。

![haxipeng.drawio.png](https://pic.code-nav.cn/mianshiya/question_picture/1783388929455529986/Aq6VyuTl_haxipeng.drawio_mianshiya.webp)

## 扩展知识

### 一定会发生 Hash 碰撞吗

理论上是的，核心原因是**鸽巢原理**，也叫**抽屉原理**。

就像 10 只鸽子放进 9 个鸽笼，那么一定有一个鸽笼放进了至少两只鸽子。

![image.png](https://pic.code-nav.cn/mianshiya/question_picture/1783388929455529986/zlTSrjf0_image_mianshiya.webp)

同理，HashMap 初始桶数 16，key 的数量却是无限多，不论哈希函数多平均，要把无数的 key 放进有限的桶中，必然就会冲突。

所以碰撞无法避免，咱们能做的是"减少碰撞概率"或"优雅处理碰撞"。

### 拉链法

这是最常见、也是最容易理解的方法。Java 的 HashMap 就是采用这种方式，数组 + 链表/红黑树。

核心思想是**外挂存储**。哈希表的每一个槽位不再只存一个数据，而是作为一个"入口"。所有哈希值相同的 Key，都像挂葡萄一样，挂在这个入口下面的链表上。

![image.png](https://pic.code-nav.cn/mianshiya/question_picture/1783388929455529986/7zRnhjhO_image_mianshiya.webp)

工作流程：

1）计算 Hash(Key) 取余得到索引 i
2）查看数组下标 i 的位置
3）如果是空的，直接把数据放进去
4）如果已经有数据了，说明发生碰撞，就顺着链表往下找
5）如果链表中找到了相同的 Key，覆盖 Value
6）如果走到链表尾部还没找到，就把新数据追加到链表末尾

这种方式的优点：

1）内存利用率高，不需要预先分配大量连续空间，链表节点是动态申请的
2）处理冲突简单，无论冲突多少次，无非就是链表变长而已
3）对负载因子不敏感，即使哈希表里的元素数量超过了数组大小，它依然能工作，只是链表会很长、查询变慢

缺点也很明显：

1）额外的内存消耗，每个节点都需要额外的指针来指向下一个节点
2）缓存不友好，链表节点在内存中是分散的，CPU 缓存命中率不如连续数组高
3）查询退化，如果黑客故意构造大量 Hash 值相同的 Key 做 Hash 洪水攻击，链表会变得极长，查询时间从 O(1) 退化为 O(n)

>

💡所以：Java 8 引入了红黑树来解决这个问题，当链表长度超过 8 时转为红黑树，将 O(n) 优化为 O(log n)。详细可看[为什么 JDK 1.8 对 HashMap 进行了红黑树的改动？](https://www.mianshiya.com/bank/1788408712975282177/question/1780933294771171329)

### 开放寻址法

这种方法不使用额外的链表，所有的数据都必须存在主数组里。

核心思想是**占坑位**。如果你的位置被占了，你就去数组里找下一个空位。这就像在电影院找座位，票上的座位有人了，你就往后挨个找空座。

常见的探测方式：

1）线性探测：步长为 1。位置被占了，就看 index+1，再看 index+2... 直到找到空位
2）二次探测：步长为平方数。位置被占了，就看 index+1²，再看 index+2²... 避免数据聚集在一起

![image.png](https://pic.code-nav.cn/mianshiya/question_picture/1783388929455529986/qyMh9WMU_image_mianshiya.webp)

工作流程（以线性探测为例）：

1）计算 Hash(Key) 取余得到索引 i
2）如果 i 位置是空的，直接存入
3）如果 i 位置有人了且 Key 不同，就检查 (i+1) % size
4）重复步骤 3，直到找到空位或者遍历完整个数组

这种方式的优点：

1）节省内存，不需要指针，节省了指针占用的内存空间
2）缓存友好，数据都在连续的数组里，CPU 缓存命中率高

缺点：

1）删除困难，你不能直接把元素删掉，因为这会截断后续元素的查找路径。通常需要标记为"墓碑"或"已删除"，逻辑复杂
2）聚集现象，这是线性探测最大的问题。一旦某一块区域冲突多了，数据会连成一片，后续插入的数据为了找空位要走很久，导致性能急剧下降
3）容量限制，因为没有链表，数组存满了就必须扩容，负载因子通常不能太高，一般 0.7 左右性能就开始下降

![hashmapct.jpg](https://pic.code-nav.cn/mianshiya/question_picture/1783388929455529986/9cnp4j81_hashmapct_mianshiya.webp)

>

💡Java 的 ThreadLocalMap 使用的就是开放寻址法。

### 再哈希法

当一个哈希函数计算出的地址发生冲突时，它会使用另一个哈希函数来重新计算地址，直到找到一个空位为止。

核心思想是**多重哈希**。不进行探测，不去找相邻或跳跃的空位，而是直接换一个新哈希函数重新计算一个全新的地址，直到不冲突！

![image.png](https://pic.code-nav.cn/mianshiya/question_picture/1783388929455529986/1huhSpuj_image_mianshiya.webp)

工作流程：

1）计算 Hash(Key) 取余得到索引 i
2）如果 i 位置是空的，直接存入
3）如果 i 位置有人了且 Key 不同，使用备用的第二个哈希函数
4）计算新位置 Hash2(Key) 取余得到索引 j
5）如果 j 位置有人了且 Key 不同，继续用 Hash3(Key)...
6）直到找到空位

优点是不易产生聚集，因为不同的哈希函数计算出的分布通常是独立的，数据会散落得非常均匀，不会像线性探测那样连成一片。

缺点：

1）计算开销大，每次冲突都要做一次完整的、复杂的哈希运算，比简单的"加法探测"要消耗更多的 CPU 时间
2）函数设计难，需要准备好几个"足够好且相互独立"的哈希函数，这在实现上比较麻烦

### 三种方式对比

对比维度拉链法开放寻址法再哈希法代表实现HashMapThreadLocalMap布谷鸟哈希内存利用需要指针，开销大无指针，紧凑无指针，紧凑缓存友好度差，链表分散好，数组连续一般删除复杂度简单复杂，需墓碑标记复杂负载因子容忍度高，>1 也能跑低，0.7 开始下降中等最坏查询复杂度O(n)，转红黑树后 O(log n)O(n)O(n)

## 面试官追问

#### 提问：为什么 HashMap 选择拉链法而不是开放寻址法？

>

详细解答可以看：[说说 Java 中 HashMap 的原理？](https://www.mianshiya.com/question/1834107117591187457)

回答：主要是删除操作的考虑。HashMap 要支持频繁的增删改查，开放寻址法删除元素时不能直接删，得留个墓碑标记，否则会截断后续元素的探测路径。墓碑多了还得定期清理，逻辑复杂。拉链法删除就简单多了，链表里摘掉一个节点就行。另外 HashMap 设计上允许负载因子比较高，默认 0.75，开放寻址法在这个负载因子下性能已经开始下降了。

#### 提问：为什么 ThreadLocalMap 用开放寻址法而不是拉链法？

>

详细解答可以看：[Java 中的 ThreadLocal 是如何实现线程资源隔离的？](https://www.mianshiya.com/question/1780933295064772609)

回答：ThreadLocalMap 的使用场景比较特殊。一个线程里通常不会放太多 ThreadLocal 变量，一般也就几个到十几个，冲突概率本来就低。而且 ThreadLocal 很少删除，主要是 set 和 get，删除操作的劣势影响不大。用开放寻址法可以省掉链表节点的额外内存开销，数据都在数组里，缓存命中率也更高。

#### 提问：Hash 洪水攻击是怎么回事？怎么防范？

回答：攻击者构造大量 hashCode 相同的 key 塞进 HashMap，让所有数据都挂在同一个桶的链表上，查询复杂度从 O(1) 退化到 O(n)。如果服务端用用户输入作为 key 存进 HashMap，就容易被攻击。Java 8 引入红黑树就是为了缓解这个问题，链表超过 8 个节点就转红黑树，复杂度变成 O(log n)。另外可以在应用层做防护，比如限制单次请求的参数数量，或者对 key 做额外的扰动处理。

#### 提问：负载因子和碰撞概率有什么关系？

>

详细解答可以看：[为什么 Java 中 HashMap 的默认负载因子是 0.75？](https://www.mianshiya.com/question/1780933294758588418)

回答：负载因子 = 元素数量 / 数组长度。负载因子越高，数组越拥挤，碰撞概率就越大。HashMap 默认负载因子 0.75，意味着数组用了 75% 就扩容。如果把负载因子调到 0.5，碰撞会少一些但浪费空间；调到 1.0，空间利用率高了但碰撞明显增多，查询性能下降。0.75 是时间和空间的折中点。 ...
