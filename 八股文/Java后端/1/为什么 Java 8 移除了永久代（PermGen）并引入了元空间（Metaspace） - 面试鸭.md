# 为什么 Java 8 移除了永久代（PermGen）并引入了元空间（Metaspace）？ - 面试鸭 | 2026最新面试题+详细答案解析

## 回答重点

官方给出的直接原因是 **JRockit 和 HotSpot 要融合**，JRockit 压根没有永久代这个概念，为了统一就把 HotSpot 的永久代干掉了。

![](https://pic.code-nav.cn/mianshiya/question_picture/1772087337535152129/dEhYOWNf_35fca68e-d2c6-4c22-be0d-53a23c428b0b_mianshiya.webp)

但从技术上讲，永久代本身就有很多问题：

1）大小在启动时就定死了，很难调。设小了动态加载类多的应用动不动就 OOM，设大了又浪费内存

2）永久代归堆管，但里面存的都是类元数据这种几乎不会被回收的东西。永久代满了会触发 Full GC，但回收率极低，触发了也是白忙活

3）和堆放一起导致 GC 算法设计困难，不同的数据特性混在一起不好优化

元空间用本地内存存储类元数据，不再受堆大小限制。默认情况下只受机器物理内存约束，可以动态扩展，OOM 的风险大大降低。

## 扩展知识

### 永久代里到底存了什么

永久代主要存储这些内容：

1）类的元数据，包括类名、访问修饰符、字段描述、方法描述等

2）运行时常量池，编译期生成的各种字面量和符号引用

3）类的静态变量

**字符串常量池在 JDK 7 就已经从永久代移到堆里了**，不是 JDK 8 才挪的。因为字符串对象创建频繁，放在永久代回收效率太差，String.intern() 用多了很容易把永久代撑爆。

### 元空间的内存管理

元空间用的是本地内存，也就是操作系统的内存，不走 JVM 堆。默认情况下元空间可以无限扩展，直到耗尽物理内存。

可以通过这几个参数控制：

1）-XX:MetaspaceSize，初始阈值，达到这个值会触发 GC 并动态调整

2）-XX:MaxMetaspaceSize，最大限制，不设就是无限制

3）-XX:MinMetaspaceFreeRatio，GC 后元空间最小空闲比例

4）-XX:MaxMetaspaceFreeRatio，GC 后元空间最大空闲比例

元空间虽然不受堆大小限制，但也不是完全不用管。如果应用频繁加载卸载类，比如大量使用动态代理、CGLIB、Groovy 脚本引擎，还是可能出现元空间 OOM。生产环境建议设置 MaxMetaspaceSize 上限，避免元空间无限膨胀把系统内存吃光。

### 压缩类指针

64 位 JVM 默认开启压缩类指针，对象头里存的不是完整的 64 位类元数据地址，而是压缩后的 32 位偏移量。这个偏移量是相对于一块专门的内存区域计算的，这块区域叫 Compressed Class Space。

Compressed Class Space 是元空间的一部分，默认大小 1GB，可以通过 -XX:CompressedClassSpaceSize 调整。只有类的 Klass 结构存在这里，其他元数据还是放在普通元空间。

如果关闭压缩类指针或者堆超过 32GB，就用不了这个优化了。

### 元空间 OOM 的排查

遇到 java.lang.OutOfMemoryError: Metaspace 怎么办？

1）先看是不是类加载器泄漏。每个类加载器卸载时它加载的类才会被回收，如果类加载器被引用着就泄漏了。常见于热部署场景，Tomcat 重新加载应用但老的类加载器没释放

2）检查是否大量使用动态生成类的框架，比如反射、动态代理、CGLIB、ASM。每次 invoke 都可能生成新的类

3）用 jcmd pid VM.metaspace 查看元空间使用情况，或者用 jmap -clstats pid 看类加载器统计

4）加上 -XX:+TraceClassLoading -XX:+TraceClassUnloading 看类加载卸载日志

## 面试官追问

#### 提问：字符串常量池为什么在 JDK 7 就挪到堆里了？

>

扩展可以看：[什么是 Java 中的常量池？](https://www.mianshiya.com/question/1780933295182213122)

回答：主要是 String.intern() 用多了永久代容易爆。字符串对象创建很频繁，放在永久代回收效率太差。挪到堆里之后，字符串常量池里的对象可以被正常的 GC 回收，不用专门等 Full GC。另外永久代大小固定，堆的大小调整更灵活，字符串常量池可用空间更大了。

#### 提问：元空间会触发 GC 吗？什么时候触发？

>

详细解答可以看：[什么情况下会触发 Java 的 Full GC？](https://www.mianshiya.com/question/1780933295249321986)

回答：会的。当元空间使用量达到 MetaspaceSize 阈值时会触发 GC，尝试回收不再使用的类元数据。GC 后 JVM 会根据实际情况动态调整这个阈值。如果设置了 MaxMetaspaceSize，达到上限还是会 OOM。元空间的 GC 主要回收的是已经卸载的类加载器所加载的类，如果类加载器还活着，它加载的类就不会被回收。

#### 提问：为什么说永久代和堆放一起设计 GC 算法困难？

回答：堆里存的是普通对象，朝生夕死的居多，适合分代收集、复制算法。但永久代里存的是类元数据，生命周期和类加载器绑定，通常存活很久，很少被回收。两种完全不同生命周期特征的数据混在一起，收集器设计时要同时考虑两种场景，很难优化。分开之后堆可以专心用分代收集，元空间单独管理，各自用最适合自己特点的策略。 ...
