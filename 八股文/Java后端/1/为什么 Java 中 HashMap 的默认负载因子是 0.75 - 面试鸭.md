# 为什么 Java 中 HashMap 的默认负载因子是 0.75？ - 面试鸭 | 2026最新27 届校招 Java 热题+详细答案解析

## 回答重点

0.75 是时间和空间之间的一个**平衡点**。负载因子太低，扩容太频繁，内存浪费；太高，冲突太多，查找变慢。0.75 经过大量实践验证，在大多数场景下都能保持不错的性能。

负载因子决定了什么时候触发扩容。HashMap 的扩容阈值 = 容量 × 负载因子。比如默认容量 16，负载因子 0.75，那么存到第 13 （size > 16 * 0.75）个元素时就会触发扩容。如果负载因子是 0.5，存到第 9 个就扩容；如果是 1.0，存到 17 个才扩容。

![image.png](https://pic.code-nav.cn/mianshiya/question_picture/1783388929455529986/8iGS1dBs_image_mianshiya.webp)

负载因子越小，桶里元素越稀疏，查找快但空间浪费；负载因子越大，桶里元素越密集，省空间但冲突多。0.75 是个折中值，既不会让数组太空旷，也不会让链表太长。

```java
// 扩容触发条件
if (++size > threshold) {  // threshold = capacity * loadFactor
    resize();
}
```

## 扩展知识

### 0.75 背后的数学依据

![](https://pic.code-nav.cn/mianshiya/question_picture/1772087337535152129/IzQdlrA8_20b7c330-9493-4ce7-8a8a-2e6713e00ac1_mianshiya.webp)

HashMap 源码注释里提到了**泊松分布**。在理想的哈希分布下，负载因子为 0.75 时，一个桶里出现 8 个以上元素的概率只有千万分之六，基本可以忽略。这也是为什么 JDK 1.8 选择 8 作为链表转红黑树的阈值。

### 不同负载因子的取舍

1）**负载因子 0.5**：扩容频繁，内存利用率只有一半。适合那种读多写少、对查询延迟极度敏感的场景，比如缓存热点数据。不过一般不推荐，内存太浪费。

2）**负载因子 0.75**：默认值，绝大多数业务场景都够用。16 个槽位能装 12 个元素，利用率 75%，冲突概率也在可接受范围内。

3）**负载因子 1.0**：几乎不浪费空间，但冲突概率高。装满才扩容，桶里平均得有一个元素，链表长度上去查找就变成 O(n) 了。除非内存特别紧张，否则不建议。

### 扩容的代价

扩容不是白来的，代价很大。每次扩容要新建一个两倍大的数组，然后把所有元素重新算位置搬过去。负载因子太低扩容太频繁，这个开销就很可观了。

实际业务中，如果能预估数据量，最好在初始化时就指定容量：

```java
// 预估存 1000 个元素，考虑负载因子后需要 1000/0.75 ≈ 1334
// 向上取整到 2 的次方就是 2048
Map<String, Object> map = new HashMap<>(2048);
```

这样可以避免多次扩容带来的性能抖动。

### 为什么不动态调整负载因子

有人会问，能不能让 HashMap 根据实际情况自动调整负载因子？理论上可以，但实现起来复杂度太高。不同业务场景对时间和空间的偏好不一样，自动调整很难找到通用策略。而且负载因子一变，扩容阈值就变，可能触发意外的扩容，反而带来性能问题。所以 JDK 选择了一个经验值 0.75，让开发者自己根据场景去调。

## 面试官追问

#### 提问：实际项目中你会去改这个负载因子吗？什么情况下会改？

回答：基本不改。0.75 已经是个很好的平衡点，大多数业务场景都适用。只有两种极端情况会考虑调：一是内存特别紧张，比如嵌入式设备，可以调到 0.85 甚至 1.0；二是对查询延迟极度敏感，比如高频交易系统的热点缓存，可以调到 0.5 减少冲突。但一般来说，与其调负载因子，不如在初始化时合理预估容量。

#### 提问：ConcurrentHashMap 的负载因子也是 0.75 吗？能改吗？

回答：是的，默认也是 0.75。不能改，内部写死 0.75。官方认为 0.75 已经足够通用，不值得为了这个参数增加 API 复杂度。如果非要改，只能通过反射，但不推荐。构造方法里面有一个`ConcurrentHashMap(int initialCapacity, float loadFactor)`，该参数主要用于初始容量计算，扩容时内部还是使用固定比例。

#### 提问：你刚才说泊松分布，能简单解释下为什么用泊松分布来分析吗？

回答：泊松分布描述的是在固定时间或空间内，某个事件发生次数的概率分布。HashMap 里每个 key 落到哪个桶是随机独立的，可以近似看成泊松过程。当元素数量远大于桶数量时，每个桶的元素个数就服从泊松分布。负载因子 0.75 时，λ 大约是 0.5，算出来超过 8 个元素的概率极低，所以用 8 作为树化阈值是有数学依据的。
