# 几种线程创建方法

> 本文围绕 Java 中**线程的创建方式**、`start()` 与 `run()` 的本质区别、常用**线程控制方法**、**优先级与守护线程**、**线程池与最佳实践**以及**面试高频问题**做系统梳理。

## Java 线程的四种创建方式

Java 中“创建线程”本质上是：**提供一段要并发执行的代码，并交给 JVM / 操作系统调度执行**。常见方式可以归纳为四类。

### 继承 `Thread` 类

#### 基本步骤

```java
public class MyThread extends Thread {
    @Override
    public void run() {
        // 线程要执行的任务
        System.out.println(Thread.currentThread().getName() + " running...");
    }

    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.start();   // 一定要调用 start()，而不是直接 run()
    }
}
```

#### 特点

- `Thread` 本身封装了线程的基本属性：ID、名称、优先级、是否守护线程、线程组等。  
- 通过重写 `run()` 方法定义执行逻辑。
- 适合**比较简单**的场景或快速测试。

#### 局限

- Java **只有单继承**，一旦继承了 `Thread`，该类就无法再继承其他父类；
- 业务代码与线程控制耦合在一起，不利于复用与单元测试。

### 实现 `Runnable` 接口（最常用）

#### 实现步骤

```java
public class MyTask implements Runnable {
    @Override
    public void run() {
        // 任务代码
        System.out.println(Thread.currentThread().getName() + " running...");
    }

    public static void main(String[] args) {
        Runnable task = new MyTask();
        Thread t1 = new Thread(task, "worker-1");
        t1.start();
    }
}
```

#### 优势

1. **避免单继承限制**：业务类可以继承其他父类，同时实现 `Runnable`。
2. **更易复用和共享数据**  
   - 多个 `Thread` 可以共享同一个 `Runnable` 实例，将共享状态封装在该实例中。
3. **符合面向接口编程原则**：更利于解耦与测试。
4. 与线程池 (`ExecutorService`) 及各种并发工具类使用时更加自然。

> 面试时一般会说：**推荐优先使用 `Runnable`，把“要做什么”与“由谁来做（哪个线程执行）”解耦。**

### 实现 `Callable<V>` 接口（有返回值）

`Callable` 是对 `Runnable` 的增强版本：

```java
import java.util.concurrent.*;

public class SumTask implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        int sum = 0;
        for (int i = 1; i <= 100; i++) sum += i;
        return sum;
    }

    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newSingleThreadExecutor();
        Future<Integer> future = pool.submit(new SumTask());
        Integer result = future.get();  // 阻塞等待结果
        System.out.println(result);
        pool.shutdown();
    }
}
```

#### 相对 `Runnable` 的两大核心区别  

1. `Callable<V>#call()` **有返回值**，`Runnable#run()` 为 `void`；
2. `Callable` 的 `call()` 方法**允许抛出受检异常**，而 `Runnable` 只能在内部捕获处理，无法在方法签名中声明受检异常。

#### 使用方式

- 通常通过 `ExecutorService.submit(Callable)` 提交任务，返回 `Future<V>`/`FutureTask<V>`；
- 可以使用 `Future#get()` 阻塞等待结果，或配合超时时间、取消任务。

### 使用线程池（`ExecutorService` / `ThreadPoolExecutor`）

在生产环境中，**不推荐频繁 `new Thread()`**，而是将任务提交给**线程池**执行，这样可以复用线程、控制并发数量，避免资源耗尽。  

#### 常见线程池形式

- `Executors.newFixedThreadPool(n)`：固定大小线程池；
- `Executors.newCachedThreadPool()`：缓存线程池，适合大量**短生命周期任务**；
- `Executors.newSingleThreadExecutor()`：单线程串行执行任务；
- `Executors.newScheduledThreadPool(n)`：支持定时/周期任务。

> 实际开发中更推荐**显式使用 `ThreadPoolExecutor` 构造函数**，避免某些工厂方法的默认策略导致队列无限增长等问题。  

#### `ThreadPoolExecutor` 核心参数

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
        corePoolSize,      // 核心线程数
        maximumPoolSize,   // 最大线程数
        keepAliveTime,     // 非核心线程的空闲存活时间
        TimeUnit.SECONDS,
        workQueue,         // 任务队列（如 LinkedBlockingQueue）
        threadFactory,     // 创建线程的工厂
        handler            // 拒绝策略
);
```

简化理解其执行流程：  

1. **当前线程数 < corePoolSize**：直接创建新线程执行任务；
2. **线程数 ≥ corePoolSize 且队列未满**：任务进入队列排队；
3. **队列已满且线程数 < maximumPoolSize**：继续创建新线程，直到达到 `maximumPoolSize`；
4. **队列已满且线程数 = maximumPoolSize**：触发**拒绝策略**（`AbortPolicy`、`CallerRunsPolicy` 等）。

#### `execute()` vs `submit()`

- `execute(Runnable)`：  
  - 提交任务但**无返回值**；  
  - 如果任务抛出未捕获异常，异常会直接抛到线程的 `UncaughtExceptionHandler` 中。  
- `submit(Runnable / Callable)`：  
  - 始终返回一个 `Future<?>`；  
  - 异常会被封装在 `Future` 中，需要 `future.get()` 时才会以 `ExecutionException` 形式抛出。

## `start()` 与 `run()` 的本质区别

这是一道非常高频的面试题。

###  `start()` 方法

- 作用：**创建新线程并让其进入就绪状态**，等待 CPU 调度；  
- 内部会调用本地方法，在操作系统层面创建真正的线程，然后由该线程自动调用 `run()`。  
- 同一个线程对象**只能调用一次 `start()`**，否则会抛出 `IllegalThreadStateException`。  

### `run()` 方法

- 本质是一个**普通成员方法**，只是约定了线程要执行的代码。
- 直接调用 `run()` 时，代码在**当前线程**中同步执行，并不会创建新线程。

> 总结一句：  
>
> - **`start()` 负责“开一个新线程，然后由新线程调用 `run()`”；**  
> - **直接调用 `run()` 只是“普通方法调用，不会并发执行”。**

## 线程的控制方法

### `sleep(long millis)`

- 让当前线程**休眠指定时间**，释放 CPU，但**不释放已持有的锁**；
- 休眠结束后，线程从阻塞状态回到就绪状态，继续参与调度。  

### `yield()`

- 提示调度器：当前线程**愿意让出 CPU**，让同优先级的线程先运行；
- 只是“hint”，调度器可以**忽略**该请求，具有不确定性。

### `join()`

- 语义：**等待目标线程执行结束**。

```java
Thread t = new Thread(task);
t.start();
t.join();  // 当前线程（通常是 main）在此等待 t 结束
```

- 常用于主线程等待多个子线程都执行完毕再继续后续逻辑。

### 中断相关方法

- `interrupt()`：向线程发送“中断请求”；
- `isInterrupted()`：检查线程是否被中断；
- 一些阻塞方法（如 `sleep()`、`wait()`、`join()`）在被中断时会抛出 `InterruptedException`，需要在业务逻辑中**优雅地响应中断**。

> 注意：**中断不是强杀线程**，只是一个“协商机制”，需要在线程代码中主动检测并正确处理。

## 优先级与守护线程

### 优先级（Priority）

- 每个线程都有一个优先级，范围通常是 **1 ~ 10**，常量：`MIN_PRIORITY(1)`、`NORM_PRIORITY(5)`、`MAX_PRIORITY(10)`。  
- 调度器**倾向于**让优先级高的线程先执行，但不保证绝对顺序——因此**不要用优先级实现业务逻辑**。

```java
Thread t = new Thread(task);
t.setPriority(Thread.MAX_PRIORITY);
```

### 守护线程（Daemon）

- 守护线程一般用于**后台服务/辅助任务**（如 GC、监控线程等）。
- 当 JVM 中**只剩下守护线程**时，JVM 会直接退出。  

```java
Thread t = new Thread(task);
t.setDaemon(true);  // 必须在 start() 之前调用
t.start();
```

> 典型应用：日志刷盘、定时心跳、连接保活等 **“非关键”任务**。  
> 核心业务线程通常应为**非守护线程**，保证任务能正常执行完成。

## Lambda 表达式简化线程创建

在 Java 8 及之后，由于 `Runnable` / `Callable` 都是函数式接口，非常适合用 Lambda 表达式简化写法。

### Runnable + Lambda

```java
new Thread(() -> {
    System.out.println(Thread.currentThread().getName() + " running...");
}).start();
```

### CompletableFuture + Lambda（推荐写法）

```java
import java.util.concurrent.CompletableFuture;

public class Demo {
    public static void main(String[] args) {
        CompletableFuture
                .supplyAsync(() -> {
                    // 异步计算
                    return "result";
                })
                .thenAccept(result -> {
                    // 处理结果
                    System.out.println(result);
                });
    }
}
```

相对“手写线程 + 回调”，`CompletableFuture` 更适合做**复杂异步流程编排**（串行、并行、异常处理等），可读性和可维护性都更好。  

## 线程创建与使用的最佳实践

1. **优先使用线程池，而不是到处 new Thread()**
   - 统一管理线程数量，避免资源耗尽；
   - 能配合监控、日志等做可观测性。

2. 使用 `ThreadPoolExecutor` 时要**明确配置**：
   - `corePoolSize`：长期保持的工作线程数；
   - `maximumPoolSize`：在高峰期允许的最大线程数；
   - `workQueue`：队列类型影响任务排队策略（有界/无界）；
   - `RejectedExecutionHandler`：定义任务被拒绝时的行为。  

3. 对于需要返回值或抛出受检异常的任务，优先使用 `Callable + Future` / `CompletableFuture`。

4. 对共享状态进行访问时要**保证线程安全**：
   - `synchronized` / `ReentrantLock`；
   - 并发集合（`ConcurrentHashMap`、`CopyOnWriteArrayList` 等）；
   - 避免在多线程环境中直接操作非线程安全集合。

5. 在高并发场景中，注意：
   - 避免创建过多线程（线程上下文切换成本很高）；
   - 合理评估 CPU 核数、IO 特性来设定线程池大小；
   - 对异常及时记录日志，避免线程静默退出。

## 面试高频问答速记

1. **为什么通常推荐实现 `Runnable` 而不是继承 `Thread`？**
   - 避免单继承限制；
   - 业务逻辑与线程控制解耦；
   - 便于多线程共享同一任务实例；
   - 更符合面向接口编程。

2. **`start()` 和 `run()` 有什么区别？**
   - `start()`：创建新线程并由该线程调用 `run()`，实现真正的并发；
   - `run()`：普通方法，直接调用时在当前线程执行，不会并发；
   - 同一个线程对象只能 `start()` 一次，重复调用会抛异常。

3. **`Runnable` 与 `Callable` 的区别？**
   - `Runnable#run()` 无返回值，不能抛受检异常；
   - `Callable#call()` 有返回值，可抛受检异常；
   - 一般通过 `ExecutorService.submit()` 提交 `Callable`，获得 `Future`。

4. **为什么要使用线程池？**
   - 复用线程，降低创建销毁成本；
   - 统一控制并发度，避免 OOM；
   - 配合监控、限流、熔断等机制方便治理。
