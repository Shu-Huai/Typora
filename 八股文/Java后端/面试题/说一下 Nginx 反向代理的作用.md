# 说一下 Nginx 反向代理的作用

Nginx 反向代理已经从“一个 Web 服务器”演变成现代后端架构里几乎必备的**流量入口**。

它的核心作用可以概括为：

> **负载均衡 + 高可用 + 安全防护 + 缓存加速 + API 网关**

通过这些能力，Nginx 解决了传统单服务器架构的性能、可靠性与安全痛点。

## 正向代理 vs 反向代理

### 正向代理

- **服务对象：客户端**
- 典型场景：科学上网、公司内网访问外网  
- 特点：
  - 客户端把请求发给代理服务器，由代理去访问真实目标网站；
  - 目标网站只看到代理的 IP，看不到真实用户。

> 类比：你找“中介”帮你去某公司办事，公司只知道中介，不知道你是谁。

### 反向代理

<img src="http://public.file.lvshuhuai.cn/images\image-20251201195137964.png" alt="image-20251201195137964" style="zoom:50%;" />

- **服务对象：服务器集群**
- 典型场景：Nginx 放在所有后端服务前面，作为统一入口
- 特点：
  - 客户端只知道自己访问了 `nginx.mysite.com`；
  - 至于后面有几台服务器、分别是什么 IP、在哪个机房，客户端完全不知道。

> 类比：你去银行，只在大厅窗口排队，后台是几位柜员、如何分工你不需要知道，系统自动分配。

## 为什么需要反向代理：传统单机架构的困境

传统“1 台服务器 + 1 个 Web 服务”的架构有四个致命问题：

### 性能瓶颈  

- 一台机器 CPU、内存、网络带宽有限；
- 并发连接一多，响应时间急剧变慢。

### 单点故障  

- 这台机器宕机，服务整体瘫痪，完全无备份。

### 扩展困难  

- 想要扩容，只能加内存、加 CPU，纵向扩展有上限；
- 很难平滑地把流量分摊到多台服务器上。

### 安全暴露  

- 真实业务服务器直接暴露在公网，容易被扫描端口、穷举接口、直接攻击。

> 反向代理的本质，就是在客户端和后端服务器之间加一层“**智能中间人**”。

## 负载均衡：把压力均匀摊给多台机器

Nginx 最典型的作用之一，就是做 **负载均衡器**。

### 常见负载均衡策略（图片内容 + 拓展）

#### 轮询（Round Robin）  

默认策略，请求依次分发给后端服务器，简单易用。

#### 加权轮询（Weighted Round Robin）  

为性能更好的机器设置更高权重，让它承担更多请求。

例如：`16 核` 服务器权重 4，`8 核` 服务器权重 2。

#### IP 哈希（IP Hash）  

同一客户端 IP 的请求总是落到同一台后端上，适合做**会话粘滞**（如简单的 session 保持）。

#### 最少连接（Least Connections）  

把新请求分配给当前“连接数最少”的服务器，适合每个请求耗时较长的场景（如文件下载、大型报表）。

### 3.2 示例配置

```nginx
upstream app_backend {
    # 加权轮询
    server 10.0.0.1 weight=3;
    server 10.0.0.2 weight=1;
}

server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://app_backend;
    }
}
```

## 4. 高可用：健康检查 + 故障转移

Nginx 可以通过**健康检查与自动摘除**机制，保证服务在有机器故障时仍然可用。

### 健康检查机制

1. **主动或被动探测**后端服务器是否存活（如定期访问 `/health` 接口）；
2. 当发现某台服务器多次超时或返回错误，就将其标记为 **down**，停止转发请求给它；
3. 一旦恢复健康，再自动放回集群。

### 4.2 故障转移的价值

- 对客户端 **完全透明**，用户只是偶尔感觉“稍微慢一丢丢”，但不会出现整站 500；
- 结合多机房 / 多可用区部署，可以做到**机房级容灾**。

## 安全防护：给后端加一层“盾牌”

图片中列举了几类安全能力，我们可以扩展理解为：Nginx 是一层 **安全网关**。

### 5.1 IP 访问控制

支持配置 IP 白名单 / 黑名单：

- 白名单：只让特定 IP 访问管理后台；
- 黑名单：封锁恶意扫描、暴力破解来源。

```nginx
location /admin/ {
    allow 192.168.0.0/16;
    deny all;
    proxy_pass http://admin_backend;
}
```

### 5.2 请求过滤与 WAF

可集成 Web 应用防火墙模块（如 `ModSecurity`），过滤：

- SQL 注入
- XSS
- 常见扫描与脚本攻击

### SSL 终止与 HTTPS 卸载

Nginx 负责 TLS 握手和加解密，把解密后的 HTTP 请求转发给后端；

#### 优点

- 后端只需专注业务逻辑，无需关心证书；
- 减轻后端 CPU 压力，证书统一管理更安全。

### DDoS 缓解与限流

通过 **连接数限制、QPS 限制、突发流量限制** 等手段，缓解大流量攻击：

- 避免恶意脚本刷接口；
- 保证正常用户还有可用的资源。

## 缓存加速：让 Nginx 变成“超级 CDN 节点”

<img src="http://public.file.lvshuhuai.cn/images\image-20251201195452432.png" alt="image-20251201195452432" style="zoom:50%;" />

图片里提到三点，我们系统化整理一下。

### 缓存适用内容

不频繁变化的资源

- 静态文件：图片、CSS、JS、字体等；
- 一些读多写少的接口：如文章详情页、排行榜等。

### 缓存机制

- 缓存命中：Nginx 直接从本地磁盘或内存返回内容，**响应可从几百毫秒降到几十毫秒**；
- 缓存未命中：转发给后端，得到响应后，同时写入缓存。

### 6.3 简单示例

```nginx
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=STATIC:50m inactive=1d;

server {
    location /static/ {
        proxy_cache STATIC;
        proxy_pass http://static_backend;
        proxy_cache_valid 200 1h;  # 200 响应缓存 1 小时
    }
}
```

### 6.4 缓存带来的收益

- 前端加载速度显著提升，用户体验更好；
- 大量请求在 Nginx 层被“拦截”，后端 QPS 压力大幅下降；
- 结合多级缓存（浏览器缓存 + Nginx + 业务侧缓存），能支撑极高并发访问。

## API 网关：统一入口、统一治理

在微服务架构下，一个系统可能拆成几十个服务：用户、订单、支付、推荐……

如果让客户端直接调用这些服务：

- 需要记住一堆域名 / 端口；
- 每次新增服务都要更新客户端；
- 统一认证、限流、监控非常麻烦。

Nginx 作为 **API 网关** 可以统一解决这些问题。

### 统一路由与服务发现

- 根据**域名 / 路径 / 请求头**将请求路由到具体微服务：
    - `/api/user/*` → 用户服务
    - `/api/order/*` → 订单服务
    - `/api/payment/*` → 支付服务

### 通用功能下沉

- 身份认证（JWT 校验、Token 校验）
- 统一限流、熔断、降级
- 请求/响应日志、埋点
- 协议转换（如 HTTP ↔ gRPC）

这些通用能力集中在网关层实现，业务服务只关心“真正的业务逻辑”。

### 客户端视角的简化

- 客户端只要认识一个入口：`api.example.com`；
- 微服务如何拆分、内部地址如何变化，对客户端都是透明的。

## 其它常见能力（简要列举）

除了图片中提到的功能，Nginx 反向代理在实际项目中还有一些很常见的用途：

- **静态资源托管**：直接由 Nginx 返回前端页面、静态资源；
- **Gzip / Brotli 压缩**：减小传输体积；
- **跨域处理（CORS）**：在 Nginx 层统一加 CORS 头；
- **WebSocket / HTTP/2 支持**：反向代理长连接服务；
- **蓝绿发布 / 灰度发布**：通过路由规则把一部分流量导到新版本服务。
