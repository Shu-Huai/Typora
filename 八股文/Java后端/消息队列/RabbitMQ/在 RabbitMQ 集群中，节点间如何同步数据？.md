# 在 RabbitMQ 集群中，节点间如何同步数据？

## 回答重点

在 RabbitMQ 集群中，节点间的数据同步主要是通过镜像队列实现的。镜像队列（Mirrored Queue，也称为高可用队列）是 RabbitMQ 提供的一种机制，它可以将队列的数据同步到集群中的多个节点上。这样一来，即使某个节点发生故障，其他节点也会有这部分数据，保证数据的高可用性。

具体来说，一个镜像队列包括一个主节点和若干个从节点。主节点负责处理生产者和消费者的所有请求，而从节点则被动地复制主节点的数据。当主节点发生变化时，例如发布消息或消息被消费者确认，从节点会立即同步这些变化。

1. 配置镜像队列策略：通过策略配置，可以指定哪些队列需要镜像以及镜像到多少个节点。策略基于正则表达式匹配队列名称。

2. 同步方式：主节点的更新会以消息的形式传播到所有的从节点。这些更新消息包括新消息的发布、消息的确认、队列元数据的变化等。

3. 故障转移：当镜像队列的主节点故障时，从节点会自动选举出新的主节点，继续提供服务，而这对于生产者和消费者是透明的。

## 扩展知识

除了镜像队列，RabbitMQ 集群中的其他同步和高可用性方案也值得了解。

1. **Queue Master Locator**：RabbitMQ 提供了一种称为“队列主控定位器”的机制，用来决定哪个节点会成为队列的主控节点。一般有几种策略，例如 random、client-local 和 min-masters。

2. **Quorum Queue**：这是另一种高可用队列机制，基于 Raft 一致性算法，相比于镜像队列，Quorum Queue 对于消息的丢失和保证消息的顺序有更好的处理机制。不过，它可能效率稍低。

3. **消息持久化**：无论是镜像队列还是其他队列，都建议开启消息持久化，将消息存储到磁盘上，而非仅在内存中。这能够在节点重启或者集群不稳定时，保证数据不丢失。

4. **集群分区和网络分区处理**：在分布式系统中，网络分区是常见问题。RabbitMQ 提供多种策略来处理网络分区，比如自动停止某些节点、优先选择某些节点等，目的是为了尽量避免数据不一致的问题。
