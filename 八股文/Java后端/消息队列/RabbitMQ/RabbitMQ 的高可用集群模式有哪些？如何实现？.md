# RabbitMQ 的高可用集群模式有哪些？如何实现？

## 回答重点

RabbitMQ 的高可用集群模式主要有两种：普通模式和镜像队列模式。

1. 普通模式（普通集群模式）：所有节点共享元数据，但消息存储在单个节点上。如果存储该消息的节点挂掉，消息也会丢失。

2. 镜像队列模式：每个队列在多个节点上有副本（镜像）。消息在主节点和其副本之间同步，在任何一个节点上接收到消息后，会同步到其他节点中，从而实现消息的高可用性。如果主节点挂掉，备用节点会提升为新主节点继续服务。

## 扩展知识

RabbitMQ 高可用集群模式的重要性在于保障服务的稳定性和数据的可靠性。下面了解一下这两种模式的实现及其优缺点。

1. 普通模式：

- **实现方式**：将多个 RabbitMQ 节点组合成一个集群，同一个队列的消息只存储在一个指定节点上。配置相对简单，但需要对集群的管理进行较多的监控。
- **优点**：实现简单，性能较高，因为消息传递不需要网络同步。
- **缺点**：节点故障会导致消息丢失，因此这种模式更适合用于对消息丢失容忍度较高的应用场景。

2. 镜像队列模式：

- **实现方式**：配置 RabbitMQ 的策略，把队列设置为镜像队列，并指定在哪些节点上进行镜像。消息在任何一个节点接收时，都会被同步到副本节点上。
- **优点**：高可用性强，主节点出现故障时，副本节点会无缝接替主节点工作，确保消息不丢失。
- **缺点**：性能稍逊，因为需要在多节点之间进行同步操作。同时，镜像队列的写性能会受到影响。

### 实现步骤

以镜像队列模式为例，下面是实现步骤：

1. 启动多个 RabbitMQ 节点，并将它们加入同一个集群。

2. 在任意一个节点执行策略设置命令，例如：

```shell
rabbitmqctl set_policy ha-all "^" '{"ha-mode":"all"}'
```

这条命令的意思是，所有匹配正则 `^` 的队列（即所有队列）都设置为镜像队列，镜像到集群中所有节点上。

3. 在应用中，创建或绑定队列时，使用已经设置好的策略，确保队列自动成为镜像队列。消息发送和接收的代码几乎不用更改，仍然使用原有的 RabbitMQ 客户端库即可。
