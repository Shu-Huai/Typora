# 阻塞和非阻塞的区别？

## 回答重点

阻塞和非阻塞描述的是调用方等待结果时的状态：线程是停下来等待，还是立即返回去做其他事。

- **阻塞**：调用方发起请求后被挂起，必须等操作完成才能继续。例如 `read` 没有数据时，线程会进入等待状态。
- **非阻塞**：调用方发起请求后立即返回。数据未准备好时返回 `EAGAIN` 等错误码，调用方可以先处理其他任务，稍后再尝试。

## 扩展知识

### 阻塞的操作系统过程

线程执行阻塞调用时，操作系统会将其从运行态切换到等待态，并从 CPU 就绪队列移除。线程不再消耗 CPU 时间片，但仍占用内存资源。数据准备好后，内核将线程放回就绪队列等待调度。这个过程通常包含阻塞和唤醒两次上下文切换。

### 非阻塞的代价：轮询

非阻塞不会挂起线程，但调用方需要主动检查结果：

```java
while (true) {
    int result = read(fd, buffer);
    if (result > 0) {
        process(buffer);
        break;
    } else if (result == -1 && errno == EAGAIN) {
        Thread.sleep(10);
    }
}
```

轮询间隔太短会造成 CPU 空转，间隔太长又会增加响应延迟。因此实际开发通常将非阻塞 I/O 与 `select`、`poll`、`epoll` 等多路复用机制结合起来。

### 阻塞与非阻塞对比

| 维度 | 阻塞 | 非阻塞 |
| --- | --- | --- |
| 编程复杂度 | 低，调用后等待 | 高，需要处理返回状态 |
| CPU 利用率 | 等待时线程不工作 | 可以处理其他任务 |
| 线程利用率 | 常见一个连接一个线程 | 可配合多路复用管理大量连接 |
| 适用场景 | 连接少、逻辑简单 | 高并发、连接多 |

### Java 中的阻塞与非阻塞

传统 Java I/O 是阻塞式的，`InputStream.read()` 没有数据时会等待。Java NIO 可以将 Channel 设置为非阻塞：

```java
ServerSocketChannel serverChannel = ServerSocketChannel.open();
serverChannel.configureBlocking(false);

SocketChannel clientChannel = serverChannel.accept();
// 非阻塞模式下，没有连接时返回 null
if (clientChannel != null) {
    // 处理连接
}
```

NIO 配合 Selector 就是 I/O 多路复用，也是 Netty 的底层原理。

## 面试官追问

#### 提问：阻塞和挂起有什么区别？

回答：阻塞通常是线程主动发起阻塞系统调用后等待某个事件；挂起是操作系统强制暂停，例如内存不足时将进程页面换出到磁盘。阻塞线程位于等待队列中，挂起可能是整个进程被换出内存。

#### 提问：为什么高并发场景下阻塞 I/O 扛不住？

回答：阻塞 I/O 常见一个连接对应一个线程，10 万连接就需要大量线程，每个线程的栈和上下文切换都会消耗大量内存与 CPU。非阻塞 I/O 配合多路复用，可以用少量线程管理大量连接。

#### 提问：BIO、NIO、AIO 分别对应哪种 I/O 模型？

回答：BIO 是同步阻塞 I/O；NIO 是同步非阻塞 I/O，Linux 底层通常使用 epoll 多路复用；AIO 是异步 I/O，调用后立即返回，由操作系统完成 I/O 后回调通知。
