# 进程的调度算法你知道吗？

## 回答重点

进程调度的核心是决定 CPU 让哪个进程运行、运行多久，不同算法适合不同场景。

1. **先来先服务（FCFS）**：按到达顺序运行，简单但可能出现长作业阻塞大量短作业。
2. **短作业优先（SJF）**：优先执行预计时间短的任务，可降低平均等待时间，但需要预知执行时间；抢占式版本为 SRTF。
3. **优先级调度**：优先运行优先级高的进程，低优先级进程可能长期得不到调度而产生饥饿。
4. **时间片轮转（RR）**：每个进程运行固定时间片，时间到后切换到下一个，适合交互式系统。
5. **多级反馈队列（MLFQ）**：将多种策略结合，新进程从高优先级队列开始，长任务逐渐降级，短任务能快速完成。
6. **最高响应比优先（HRRN）**：通过响应比平衡长短任务，减少长任务饥饿，常用于批处理系统。

## 扩展知识

### 最高响应比优先（HRRN）

响应比公式为：

`响应比 = （等待时间 + 服务时间） / 服务时间`

短任务服务时间小，初始响应比高；长任务随着等待时间增加，响应比逐渐提升，最终也能得到调度。HRRN 比 FCFS 和 RR 实现复杂，但比 SJF 更公平，适合任务执行时间差距较大的批处理环境。

### 为什么需要多种调度算法

早期批处理系统任务少，FCFS 就够用；交互式系统要求快速响应，因此需要 RR；现代服务器同时运行数据库、Web 服务和后台任务，优先级和任务特征不同，MLFQ 等复合策略更合适。

### MLFQ 的工作细节

一个典型的三级反馈队列如下：

| 队列 | 优先级 | 时间片 | 典型任务 |
| --- | --- | --- | --- |
| Q0 | 最高 | 8ms | 交互式进程、刚创建的进程 |
| Q1 | 中等 | 16ms | 普通计算任务 |
| Q2 | 最低 | 32ms | CPU 密集型后台任务 |

调度规则：

1. 高优先级队列有任务时，优先运行高优先级队列。
2. 同一队列内使用 RR 轮转。
3. 新进程进入 Q0，用完时间片仍未结束就降到 Q1，再降到 Q2。
4. 定期将所有进程提升回 Q0，防止低优先级任务饥饿。

### Linux CFS 调度器

Linux 2.6.23 之后引入 CFS（Completely Fair Scheduler），不使用固定时间片，而是使用虚拟运行时间 `vruntime`。调度器每次选择 `vruntime` 最小的进程运行，运行越久，`vruntime` 增长越快，从而让进程获得相对公平的 CPU 时间。

CFS 使用红黑树组织可运行进程，最小 `vruntime` 位于最左侧，查找效率高。优先级通过 `nice` 值体现，范围是 -20 到 19；nice 越低，优先级越高，`vruntime` 增长越慢，获得的 CPU 时间越多。

### 实时调度

Linux 提供 `SCHED_FIFO` 和 `SCHED_RR` 两种实时调度策略，优先级高于普通 CFS 进程。只要实时队列有任务，就会优先运行实时任务。实时进程设置过多会使普通进程饥饿，因此生产环境需要谨慎使用。

## 面试官追问

#### 提问：时间片设多长比较合适，Linux 默认是多少？

回答：时间片太短会增加上下文切换，太长会降低响应性。CFS 不使用固定时间片，而采用调度周期和最小调度粒度的概念；较新内核中默认调度周期约 24ms，最小粒度约 3ms。交互式系统通常 10～20ms 比较合适，服务器可以适当调大。

#### 提问：进程优先级和 nice 值是什么关系？

回答：nice 是用户空间设置优先级的接口，范围 -20 到 19，默认 0。内核会将 nice 映射为调度权重，nice 越低权重越高，获得的 CPU 时间越多。通常只有 root 能设置负 nice 值，普通用户只能降低自己的优先级。

#### 提问：什么情况下会出现优先级反转，怎么解决？

回答：低优先级进程持有锁，高优先级进程等待该锁时会发生优先级反转；中优先级进程还可能持续抢占低优先级进程。解决方法是优先级继承，让持锁进程临时提升到等待锁的高优先级。

#### 提问：MLFQ 如何防止进程在时间片快用完时主动放弃 CPU 来维持高优先级？

回答：现代实现会记录进程在每个优先级队列累计使用的 CPU 时间，而不是只看单次时间片是否用完。累计时间超过阈值后就降级，无论进程是主动放弃还是被抢占。
