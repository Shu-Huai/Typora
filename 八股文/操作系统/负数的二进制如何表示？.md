# 负数的二进制如何表示？

## 回答重点

计算机用**补码**表示负数：先写出对应正数的二进制，按位取反，再加 1。

以 8 位表示 -5 为例：`5 = 00000101`，取反得到 `11111010`，加 1 得到 `11111011`。所以 -5 的补码是 `11111011`。正数的补码就是原码；最高位为 0 表示正数，为 1 表示负数。

## 扩展知识

### 为什么使用补码

原码存在正负零，并且加减法不能统一处理；反码仍有正负零和循环进位问题。补码让零只有一种表示，加减法都可以使用同一个加法器。

### 补码让减法变成加法

计算 `5 - 3` 时，硬件实际计算 `5 + (-3)`：

```text
  00000101  (5)
+ 11111101  (-3)
----------
 100000010
```

丢弃最高位溢出后为 `00000010`，结果是 2。其数学基础是模运算，8 位整数相当于模 256。

![补码运算](Z:/Public/images/GR6CiUgq_L6mK31P2Ds_mianshiya.webp)

### 补码表示范围

8 位有符号整数范围是 -128～127。正负零合并后，`10000000` 用来表示 -128，因此最小值绝对值比最大值大 1。

```java
byte b = -128;
System.out.println((byte) (-b)); // 仍然是 -128
```

32 位 `int` 范围是 -2147483648～2147483647，`Integer.MIN_VALUE` 取负仍是自身。

### 符号扩展

位数扩展时，正数高位补 0，负数高位补 1。例如 -5 的 8 位补码 `11111011` 扩展到 16 位为 `1111111111111011`。

```java
byte b = -1;       // 11111111
int i = b;         // 高位补 1，仍是 -1
int u = b & 0xFF;  // 按无符号数处理，得到 255
```

### 位移运算

Java 中 `>>` 是算术右移，高位补符号位；`>>>` 是逻辑右移，高位补 0。

```java
int x = -8;
int a = x >> 2;   // -2
int c = x >>> 2;  // 1073741822
```

## 面试官追问

#### 提问：为什么 Integer.MIN_VALUE 取负还是它自己？

回答：它的补码是 `10000000000000000000000000000000`，取反加 1 后仍溢出回该编码，因为 32 位有符号整数无法表示正数 2147483648。

#### 提问：浮点数的负数也用补码吗？

回答：不是。浮点数遵循 IEEE 754，负数只需将符号位设为 1，其他位保持对应绝对值的编码。

#### 提问：补码最小值为什么比最大值绝对值大 1？

回答：8 位共有 256 个编码，0 占一个编码，正数最多到 127，剩余的 `10000000` 没有对称正数可对应，因此用于表示 -128。
