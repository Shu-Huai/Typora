# 死锁是什么？如何预防和避免死锁？

## 回答重点

死锁是指两个或多个进程在执行过程中因争夺资源而互相等待，导致所有进程都无法继续执行，只能等待外部干预或主动放弃资源。

死锁通常同时满足四个必要条件：

1. **互斥**：资源同一时刻只能被一个进程占用。
2. **占有并等待**：进程已经持有部分资源，同时等待其他资源。
3. **不可剥夺**：资源只能由持有者主动释放，不能被系统强制夺走。
4. **循环等待**：存在进程等待链，形成首尾相接的循环。

预防和避免死锁的常见方法：

- 尽量一次性申请所有需要的资源，避免占有资源后继续等待。
- 缩短资源持有时间，减少“占有并等待”。
- 对可共享资源进行改造，尽量减少互斥使用。
- 必要时允许资源剥夺，暂停占用资源的进程，待资源释放后恢复。
- 对等待时间过长的进程进行抢占，强制释放其资源。
- 对资源申请进行安全性检查，只允许系统保持在安全状态。

## 扩展知识

### 死锁预防

死锁预防的思路是破坏四个必要条件中的至少一个：

- **破坏互斥**：能共享的资源尽量设计成可共享，例如只读数据；但打印机等资源无法完全共享。
- **破坏占有并等待**：进程开始执行前一次性申请全部资源，或申请新资源前先释放已有资源。
- **破坏不可剥夺**：资源申请失败时，要求进程释放已持有资源，之后重新申请。
- **破坏循环等待**：为资源统一编号，进程必须按编号递增顺序申请资源，释放顺序相反，避免环路。

### 死锁避免

死锁避免不是简单禁止某种行为，而是在每次资源分配前判断分配后是否仍处于安全状态。经典算法是**银行家算法**：系统预先知道各进程的最大资源需求，只有存在一条让所有进程都能完成的安全序列时才批准分配。

### 死锁检测与恢复

如果系统不主动预防，可以周期性检测资源分配图或等待图是否存在环。一旦发现死锁，可以：

- 终止一个或多个进程，释放其资源。
- 强制剥夺部分资源，回滚进程后重新执行。
- 根据进程优先级、已运行时间、已占用资源数量等选择牺牲进程。

### Java 中的死锁示例

```java
Object lockA = new Object();
Object lockB = new Object();

// 线程 1：先拿 A 再等 B
new Thread(() -> {
    synchronized (lockA) {
        synchronized (lockB) {
            // 业务逻辑
        }
    }
}).start();

// 线程 2：先拿 B 再等 A，形成循环等待
new Thread(() -> {
    synchronized (lockB) {
        synchronized (lockA) {
            // 业务逻辑
        }
    }
}).start();
```

实际开发中应统一锁的获取顺序、缩小锁范围，或使用 `tryLock(timeout)`，避免线程无限等待。

## 面试官追问

#### 提问：死锁和饥饿有什么区别？

回答：死锁是多个进程互相等待，所有相关进程都无法推进；饥饿是某个进程长期得不到资源或 CPU，但其他进程仍能继续执行。优先级反转和不公平调度都可能导致饥饿。

#### 提问：如何排查 Java 线程死锁？

回答：可以使用 `jstack <pid>` 查看线程栈，JVM 会尝试报告互相等待的锁；也可以使用 `jcmd <pid> Thread.print` 或 JConsole、VisualVM 查看锁竞争。定位后重点检查锁获取顺序和未释放的锁。

#### 提问：如何从根本上避免锁死锁？

回答：统一多个锁的获取顺序，尽量缩小临界区，避免在持锁期间执行耗时 I/O；必要时使用带超时的 `tryLock`，超时后释放已有锁并重试。
