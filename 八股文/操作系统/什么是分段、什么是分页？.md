# 什么是分段、什么是分页？

## 回答重点

分段和分页都是操作系统管理内存的方式，但划分依据不同：

- **分段**：按程序逻辑结构划分，例如代码段、数据段和栈段。段大小不固定，逻辑地址由段号和段内偏移组成，段表记录段基地址。
- **分页**：将虚拟地址空间和物理内存切成固定大小的页和页框，常见页大小为 4KB，页表记录虚拟页到物理页框的映射。

核心区别：分段粒度较粗，容易产生外部碎片；分页粒度固定且细，主要产生内部碎片。现代操作系统基本以分页为主，Linux 虽保留分段形式，但通常将段基地址设为 0，采用平坦模式。

## 扩展知识

### 分段的由来

早期 8086 处理器的寄存器为 16 位，而地址总线为 20 位，无法直接访问全部地址。于是使用“段基地址 + 段内偏移”，段基地址左移 4 位再加偏移，形成 20 位地址。

80286 引入保护模式和 GDT（全局描述符表），段寄存器保存选择子，通过段描述符完成地址范围和权限检查。80386 之后通用寄存器和地址总线扩展为 32 位，单靠段内偏移即可访问 4GB 空间，为向前兼容仍保留分段，但 Linux 把段基址都设置为 0，形成平坦模式。

### 为什么引入分页

分段粒度太粗，一个程序段可能很大，容易出现外部碎片。分页把内存按 4KB 等大小切分，只需要把实际用到的页加载进内存，内存利用率更高；换入换出时也只需处理若干页面，而不是整个段。

分页还构造了虚拟内存空间，让每个进程通过页表把虚拟地址映射到物理地址，物理内存不足时可把不常用页面换到 Swap。

### 段页式管理

在传统段页式系统中，逻辑地址先经过分段得到线性地址，再经过分页转换为物理地址。分段体现程序逻辑结构和权限，分页负责细粒度的物理内存管理。Linux 则通过平坦分段弱化了分段，主要依赖分页。

### 多级页表

32 位系统 4GB 地址空间按 4KB 分页时有 100 多万个页表项，单级页表约占 4MB。多级页表把页表本身也分页，只有实际使用到的地址范围才分配下级页表；32 位系统常用两级，64 位系统常用四级或五级。

### TLB 加速地址转换

CPU 使用 TLB 缓存最近使用的页表项，命中时无需多次访问内存查页表，命中率通常很高。TLB 未命中时才进行完整页表查询。进程切换时页表不同，TLB 可能需要刷新，这是进程切换开销较大的原因之一。

## 面试官追问

#### 提问：为什么页大小一般是 4KB？更大的页有什么优缺点？

回答：4KB 是内存容量和管理开销之间的折中。大页能减少页表项、让 TLB 覆盖更大内存并降低 TLB miss，但会增加内部碎片。Linux 支持 2MB 和 1GB 大页，数据库和虚拟机等大内存、规律访问场景会使用。

#### 提问：缺页中断和普通中断有什么区别？

回答：访问的虚拟页不在物理内存时触发缺页中断。内核会把页面从磁盘加载到内存、更新页表，然后重新执行触发异常的那条指令；普通中断处理完成后通常继续执行下一条指令。

#### 提问：页面置换算法有哪些，Linux 用哪种？

回答：经典算法有 FIFO、LRU 和 Clock。FIFO 简单但可能换出热点页，LRU 效果好但实现开销大。Linux 使用近似 LRU，通过 active 和 inactive 两个链表跟踪页面，优先换出 inactive 链表中长期未访问的页。

#### 提问：内核空间和用户空间的页表如何隔离？

回答：传统 32 位 Linux 将低 3GB 给用户空间、高 1GB 给内核空间，进程页表中包含内核映射，但用户态访问内核地址会触发保护异常。Meltdown 漏洞后，Linux 引入 KPTI，让用户态和内核态使用不同页表，切换会有一定性能损失。
