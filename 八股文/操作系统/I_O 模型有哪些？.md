# I/O 模型有哪些？

## 回答重点

I/O 模型主要有五种，核心区别在于“等待数据”和“将数据从内核拷贝到用户空间”两个阶段是否阻塞线程：

1. **阻塞 I/O**：调用 `read` 后线程一直等待数据准备和拷贝完成。
2. **非阻塞 I/O**：数据未准备好时立即返回 `EAGAIN` / `EWOULDBLOCK`，线程可先做其他事，但需要不断轮询。
3. **I/O 多路复用**：一个线程同时监控大量连接，常见实现有 `select`、`poll`、`epoll`。
4. **信号驱动 I/O**：注册信号处理函数，数据就绪后由内核发送 `SIGIO` 通知；TCP 事件复杂，实际较少使用。
5. **异步 I/O**：调用 `aio_read` 后立即返回，等待数据和拷贝全部由内核完成，完成后通过回调通知。

## 扩展知识

### 同步阻塞 I/O

线程调用 `read` 后，从网卡到内核缓冲区、再从内核到用户空间的整个过程都被阻塞。优点是简单，缺点是一个线程通常只能处理一个连接，线程会长时间等待。

![阻塞 I/O](Z:/Public/images/sLEt3F43_ecf434f3-36c8-4f3d-a5b8-a2c4b73f2f51_mianshiya.webp)

### 同步非阻塞 I/O

数据未准备好时 `read` 立即返回错误码，线程可以先做其他事情；但真正从内核拷贝到用户空间时仍会阻塞。若不断轮询，会产生大量系统调用和 CPU 空转。

![非阻塞 I/O](Z:/Public/images/gI4V8wdY_fbba018d-d0dd-4020-895f-ff5d120f3cf0_mianshiya.webp)

### I/O 多路复用

将多个连接注册给 `select`、`poll` 或 `epoll`，由一个线程等待事件，哪个连接就绪再调用 `read`。这样少量线程就能监控大量连接。

`select` 和 `poll` 每次都要拷贝并线性扫描全部 fd；`epoll` 在内核中维护 fd 集合，用回调把就绪 fd 放入链表，只返回就绪项，更适合高并发。

![I/O 多路复用](Z:/Public/images/CrpTkBSR_4d7795f6-04b1-47f8-b996-5771ba171d10_mianshiya.webp)

### 信号驱动 I/O

应用注册信号处理函数，数据准备好后内核发送 `SIGIO`，线程收到信号后再调用 `read`。TCP socket 可能因连接建立、断开、数据到达等多种事件触发同一个信号，难以区分，因此 TCP 场景很少使用，UDP 更适合。

### 异步 I/O

异步 I/O 将“等待数据”和“数据拷贝”都交给内核。`aio_read` 立即返回，内核后台完成操作后通过回调通知，数据已经位于用户空间，线程全程不阻塞。

![异步 I/O](Z:/Public/images/vB8pMtW8_639e926f-d60c-4e57-9627-98f44b0d6e9c_mianshiya.webp)

### select、`poll`、epoll 对比

| 特性 | select | `poll` | epoll |
| --- | --- | --- | --- |
| 最大连接数 | 通常 1024 | 无固定限制 | 无固定限制 |
| fd 拷贝 | 每次调用都拷贝 | 每次调用都拷贝 | 注册时拷贝 |
| 检测方式 | 线性扫描 | 线性扫描 | 回调 + 就绪链表 |
| 时间复杂度 | $O(n)$ | $O(n)$ | 近似 $O(1)$ |

### 同步与异步的判断

判断同步还是异步，关键看数据从内核拷贝到用户空间这一步由谁完成。前四种模型最终都需要用户线程执行 `read` 完成拷贝，因此属于同步 I/O；只有异步 I/O 由内核完成拷贝后再通知应用。

## 面试官追问

#### 提问：select 和 epoll 有什么区别？

回答：select 通常有 1024 个 fd 限制，每次调用都要把全部 fd 从用户态拷贝到内核并线性扫描；epoll 注册时拷贝一次，内核通过回调维护就绪列表，直接返回就绪 fd，因此连接数多时性能更好。

#### 提问：epoll 的水平触发和边缘触发有什么区别？

回答：水平触发只要 fd 缓冲区仍有数据，每次 `epoll_wait` 都会通知；边缘触发只在状态变化时通知一次。边缘触发效率高，但必须一次把数据读完，否则后续可能收不到通知。

#### 提问：为什么前四种 I/O 模型都是同步的？

回答：因为前四种最终都由用户线程自己执行 `read` 把数据从内核拷贝到用户空间，这一步会阻塞；异步 I/O 则由内核完成拷贝后再通知，线程全程不阻塞。

#### 提问：Java NIO 用的是哪种 I/O 模型？

回答：Java NIO 使用 I/O 多路复用，Linux 底层通常对应 epoll。Selector 对应 epoll 实例，Channel 对应 fd，SelectionKey 表示注册事件，Netty 就是在此基础上封装的。
