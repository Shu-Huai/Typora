# 同步和异步的区别？

## 回答重点

同步和异步的核心区别是：调用方是否需要等待结果返回后才能继续执行。

- **同步**：发起请求后调用方一直等待，操作完成并拿到结果后才能执行后续代码。
- **异步**：发起请求后立即返回，调用方可以继续做其他事，完成后通过回调、事件或 `Future` 通知结果。

## 扩展知识

### 代码直观对比

同步代码按顺序等待：

```java
// 同步方式
result = 搬一百块石头();
if (result) {
    石头搬完了发工资();
}
计算下一次搬石头的任务();
```

异步代码立即返回，通过回调处理结果：

```java
// 异步方式
搬一百块石头(() -> {
    // 石头搬完后执行
    石头搬完了发工资();
});
计算下一次搬石头的任务();
```

同步代码执行顺序与书写顺序一致，易读易调试；异步代码执行顺序可能与书写顺序不同，需要处理回调、事件和状态。

### 异步转同步

底层异步、上层同步是常见封装方式。Java 的 `Future` 提交任务时立即返回，但调用 `future.get()` 会阻塞等待，将异步调用转成同步。Dubbo 底层通过 Netty 异步发送请求，默认也会阻塞等待响应。

```java
Future<Result> future = channel.send(request); // 异步发送
return future.get(timeout);                     // 阻塞等待，变成同步
```

### 适用场景

同步适合：

1. 任务有严格先后依赖，上一步结果是下一步输入。
2. 任务执行很短，异步带来的复杂度不值得。
3. 业务简单，优先考虑代码可读性。

异步适合：

1. 网络请求、文件读写等 I/O 密集型操作。
2. 高并发场景，少量线程处理大量请求。
3. 不需要立即拿结果的任务，如发邮件、写日志和埋点上报。

### 同步与异步对比

| 维度 | 同步 | 异步 |
| --- | --- | --- |
| 代码复杂度 | 低，顺序直观 | 高，需要回调和状态管理 |
| 调试难度 | 简单，调用栈连续 | 较复杂，调用栈可能不连续 |
| 资源利用率 | 等待时线程闲置 | 等待时可以处理其他任务 |
| 吞吐量 | 通常受线程数限制 | 少量线程也能支撑高并发 |
| 适用场景 | 简单任务、强依赖 | I/O 密集、高并发 |

## 面试官追问

#### 提问：Java 中实现异步有哪些方式？

回答：可以使用新线程或线程池、`Future` / `CompletableFuture`、Spring 的 `@Async`，以及消息队列。`CompletableFuture` 支持链式回调和 `allOf`、`anyOf` 等组合操作，灵活性较高。

#### 提问：异步编程最容易踩什么坑？

回答：常见问题是回调地狱和异常处理遗漏。可以用 `CompletableFuture` 链式调用或协程减少嵌套，并通过 `exceptionally`、`handle` 等方法显式处理异步异常。

#### 提问：Node.js 为什么单线程异步也能处理高并发？

回答：Node.js 使用事件循环和 epoll，实际 I/O 由内核或线程池执行，主线程只负责调度和执行回调，不会被 I/O 长时间阻塞，因此单线程也能管理大量连接。
