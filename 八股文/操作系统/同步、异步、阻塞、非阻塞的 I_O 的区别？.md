# 同步、异步、阻塞、非阻塞的 I/O 的区别？

## 回答重点

这四个概念分成两组：

- **阻塞/非阻塞**描述发起 I/O 请求时用户线程的状态。
- **同步/异步**描述数据准备好后，内核拷贝数据时用户线程的行为。

具体来说：

- **阻塞 I/O**：请求后线程被挂起，等待数据准备和拷贝完成。
- **非阻塞 I/O**：请求后立即返回状态码，数据未准备好时由调用方轮询。
- **同步 I/O**：数据准备好后，用户线程等待内核将数据拷贝到用户空间。
- **异步 I/O**：内核自行完成数据拷贝，完成后通过回调或事件通知用户线程。

## 扩展知识

### 一次 I/O 的两个阶段

一次完整的 I/O 通常包含：

1. 等待数据准备好，例如网卡收到数据、磁盘读取完成。
2. 将数据从内核缓冲区拷贝到用户空间。

阻塞/非阻塞描述第一阶段的线程状态；同步/异步描述第二阶段由谁等待和完成。阻塞 I/O 数据没到时线程让出 CPU；非阻塞 I/O 立即返回 `EAGAIN` 或 `EWOULDBLOCK`。同步 I/O 要由用户线程等待拷贝；异步 I/O 由内核拷贝完成后再通知。

### 常见 I/O 模型

1. **同步阻塞 I/O**：传统 BIO，一个线程对应一个连接，简单但线程资源消耗大。
2. **同步非阻塞 I/O**：不断轮询数据是否准备好，准备好后仍要同步等待拷贝，CPU 空转严重。
3. **I/O 多路复用**：本质仍是同步 I/O，但一个线程通过 `select`、`poll`、`epoll` 监控多个文件描述符。Java NIO、Netty、Nginx、Redis 都采用这一思路。
4. **异步 I/O**：用户线程发起请求后立即返回，内核完成等待和拷贝，之后回调通知。Linux AIO、Windows IOCP 属于此类。

![I/O 模型组合](Z:/Public/images/cfbmA9QW_8EBHqZuExD_mianshiya.webp)

### 为什么 I/O 多路复用最常用

Linux 原生 AIO 早期对普通文件支持不够好，编程模型也较复杂；I/O 多路复用虽然数据拷贝阶段仍是同步的，但结合事件驱动，一个线程即可处理大量连接。Java NIO 使用 Selector 监控多个 Channel，Netty 进一步基于 Reactor 模型拆分 Boss 和 Worker 线程。

### 对比表

| 概念 | 关注阶段 | 用户线程行为 | 典型实现 |
| --- | --- | --- | --- |
| 阻塞 | 等待数据准备 | 挂起等待 | BIO |
| 非阻塞 | 等待数据准备 | 立即返回，需轮询或事件通知 | NIO Channel |
| 同步 | 数据拷贝 | 用户线程等待拷贝完成 | select/`poll`/epoll |
| 异步 | 数据拷贝 | 内核完成拷贝后通知 | AIO、IOCP |

## 面试官追问

#### 提问：非阻塞 I/O 和异步 I/O 都是立刻返回，有什么区别？

回答：区别在于数据拷贝由谁完成。非阻塞只保证数据未准备好时不等待，数据准备好后用户线程仍要负责拷贝；异步 I/O 从等待到拷贝都由内核完成，用户线程收到通知时数据已经在用户空间。

#### 提问：Java NIO 是真正的异步 I/O 吗？

回答：不是。Java NIO 是同步非阻塞加 I/O 多路复用。Channel 可配置为非阻塞，但 `Selector.select()` 会阻塞等待事件，而且 `Channel.read()` 的数据拷贝仍由用户线程同步完成。

#### 提问：为什么 Linux 原生 AIO 实现得不理想？

回答：早期 Linux AIO 主要支持 `O_DIRECT`，绕过 Page Cache，对普通文件不友好；部分场景仍可能阻塞，POSIX AIO 还常用线程池模拟。当前 Linux 更常用 `io_uring` 或 epoll 多路复用。

#### 提问：Reactor 和 Proactor 有什么区别？

回答：Reactor 是同步 I/O 事件驱动，事件就绪后通知应用，读写仍由应用执行；Proactor 是异步 I/O 事件驱动，内核完成读写后再通知，数据已准备好。Netty、Nginx 使用 Reactor，Windows IOCP 是 Proactor。
