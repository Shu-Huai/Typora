# 什么是软中断、什么是硬中断？

## 回答重点

**硬中断**是硬件设备发给 CPU 的信号，例如网卡收到数据、键盘按键或定时器到期。CPU 收到信号后会暂停当前任务，跳转执行对应的中断处理程序。

**软中断**有两层含义：

1. **软件中断（Software Interrupt）**：程序主动触发，例如 x86 的 `int` 指令、ARM 的 `svc` 指令，系统调用可通过它进入内核。
2. **Linux SoftIRQ**：硬中断的下半部机制。硬中断处理必须快速结束，耗时任务交给 SoftIRQ 延后处理。

![软中断与硬中断](Z:/Public/images/CHZbKvS6_image_mianshiya.webp)

核心区别：硬中断来自外部设备；软件中断是程序主动请求内核；SoftIRQ 是内核内部的延迟处理机制。

## 扩展知识

### 硬中断处理流程

硬件中断先由中断控制器接收并排序，再通知 CPU。x86 早期使用 8259A，现在主要使用 APIC。

CPU 处理流程：

1. 保存当前程序计数器和寄存器等上下文。
2. 根据中断号查询中断向量表。
3. 跳转执行中断处理程序。
4. 恢复上下文，继续执行被打断的程序。

硬中断有优先级，高优先级中断可以打断低优先级处理程序。

### Linux 的中断上下半部

硬中断处理期间通常会关闭中断。如果处理时间过长，其他设备就无法及时得到响应，因此 Linux 将中断处理拆为上下半部：

| 部分 | 执行时机 | 特点 | 典型工作 |
| --- | --- | --- | --- |
| 上半部 Top Half | 硬中断触发时立即执行 | 关中断，必须很快 | 搬运数据、标记下半部 |
| 下半部 Bottom Half | 上半部结束后适当时机 | 中断已开启，可以较慢 | 网络协议栈、拷贝到用户空间 |

### SoftIRQ 类型

Linux 常见 SoftIRQ 包括：

1. `HI_SOFTIRQ`：高优先级 tasklet。
2. `TIMER_SOFTIRQ`：定时器。
3. `NET_TX_SOFTIRQ`：网络发送。
4. `NET_RX_SOFTIRQ`：网络接收。
5. `BLOCK_SOFTIRQ`：块设备。
6. `IRQ_POLL_SOFTIRQ`：I/O 轮询。
7. `TASKLET_SOFTIRQ`：普通 tasklet。
8. `SCHED_SOFTIRQ`：调度器负载均衡。
9. `HRTIMER_SOFTIRQ`：高精度定时器。
10. `RCU_SOFTIRQ`：RCU 回调。

SoftIRQ 静态注册，不能动态添加；内核模块通常使用 tasklet 或 workqueue 实现类似的延迟处理。

### ksoftirqd 内核线程

SoftIRQ 通常在硬中断返回时处理。如果积压过多，内核会为每个 CPU 创建 `ksoftirqd` 线程处理，避免软中断长期占用 CPU 而饿死用户进程。`ksoftirqd/0`、`ksoftirqd/1` CPU 占用很高，通常说明网络或驱动产生了较重的软中断负载。

### 网卡 NAPI 机制

高速网卡如果每个数据包都触发一次硬中断，会造成很大开销。NAPI 的做法是第一个包到达时触发硬中断，随后暂时关闭网卡中断，改由软中断轮询网卡 ring buffer，批量处理完后再开启中断，从而显著减少中断次数。

## 面试官追问

#### 提问：软中断处理时能被硬中断打断吗？

回答：能。软中断运行时通常开着硬中断，硬中断可以随时进入；硬中断返回时会检查是否有待处理的软中断。但同一个 CPU 上软中断不能嵌套，同时只运行一个软中断处理流程。

#### 提问：为什么系统调用从 `int 0x80` 改成 `syscall` 指令？

回答：`int 0x80` 要经过完整的中断处理流程，保存和恢复内容较多；`syscall` 是专门为系统调用设计的快速指令，减少了不必要的保存恢复，开销更低。

#### 提问：什么是中断亲和性，怎么设置？

回答：中断亲和性是指定某个中断由特定 CPU 核心处理。可以通过 `/proc/irq/中断号/smp_affinity` 写入十六进制掩码设置。网卡多队列时把不同队列绑定到不同核心，可减少锁竞争、提高吞吐。

#### 提问：怎么查看系统中断统计？

回答：`/proc/interrupts` 查看各中断在每个 CPU 上的次数，`/proc/softirqs` 查看各类软中断次数，`vmstat` 的 `in` 列查看每秒中断总数。
