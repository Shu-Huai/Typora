# 操作系统在进行线程切换时需要进行哪些动作？

## 回答重点

线程切换就是把 CPU 控制权从一个线程交给另一个线程。同一进程内的线程共享地址空间和资源，因此不需要切换页表，通常比进程切换轻量。

核心动作分四步：

1. 保存当前线程上下文，包括 CPU 寄存器、栈指针和程序计数器，写入线程控制块（TCB）。
2. 更新当前线程状态，例如从运行态变为就绪态或阻塞态。
3. 调度器根据调度算法选择下一个线程。
4. 恢复目标线程上下文，将寄存器、栈指针和程序计数器恢复，使其从上次暂停处继续运行。

线程切换最耗时的是上下文保存和恢复。Linux 上一次线程切换大约需要 1～10 微秒，高频切换时累积开销很大。

## 扩展知识

### 线程上下文包含什么

1. **CPU 寄存器状态**：程序计数器 PC、栈指针 SP、通用寄存器、浮点和向量寄存器等。
2. **程序状态字 PSW**：记录中断开关、特权级和条件码等 CPU 运行状态。
3. **线程栈**：包括用户栈和内核栈，分别保存应用函数调用链以及线程陷入内核后的调用信息。

![线程上下文](Z:/Public/images/0cWLtBoc_Pn3Vn2Zmi4_mianshiya.webp)

### TCB 中的关键内容

TCB 是操作系统管理线程的核心结构，通常包含线程状态、程序计数器、寄存器内容、栈指针、线程优先级、线程 ID 和调度信息（调度策略、时间片等）。

### 线程切换与进程切换

同一进程内线程切换不需要切换页表，因此不会导致 TLB 全部失效；跨进程切换必须切换页表和地址空间，开销更大。

| 切换类型 | 页表切换 | TLB 失效 | 上下文保存 | 典型耗时 |
| --- | --- | --- | --- | --- |
| 同进程线程切换 | 不需要 | 通常不失效 | 寄存器、栈指针 | 1～10 微秒 |
| 进程切换 | 需要 | 可能全部失效 | 寄存器、栈指针、页表 | 10～100 微秒 |

不同进程之间的线程切换本质上仍是进程切换，不能享受同进程线程切换的低开销。

### 用户级线程与内核级线程

- **内核级线程**由操作系统直接管理，切换需要进入内核。Linux pthread 通常是 1:1 模型。
- **用户级线程**由运行库在用户态调度，切换时直接保存栈指针和寄存器，无需系统调用。Go 的 goroutine 是典型实现，采用 M:N 模型，多个 goroutine 映射到少量内核线程上。

### 线程切换的优化

- **减少切换次数**：锁持有时间很短时可使用自旋锁，避免阻塞和唤醒带来的切换。
- **CPU 亲和性绑定**：把线程固定在特定 CPU 核心，减少跨核切换导致的缓存失效。
- **批量处理**：一次处理一批请求或 I/O 事件，降低切换频率。Netty 的 EventLoop 就采用类似思路。

## 面试官追问

#### 提问：不同进程的线程切换，开销和进程切换一样吗？

回答：基本一样。不同进程的线程切换必须切换地址空间和页表，TLB 也可能失效；所谓线程切换快，通常指同一进程内线程之间的切换。

#### 提问：Linux 怎么查看线程切换次数？

回答：`vmstat` 的 `cs` 列可以查看系统整体上下文切换次数，`pidstat -w` 可以查看具体进程。每秒几万次通常可接受，达到几十万次就要排查锁竞争和线程数过多等问题。

#### 提问：Go 的 goroutine 切换为什么很快？

回答：它运行在用户态，不需要陷入内核；初始栈很小，保存恢复的数据少；同时 Go 调度器使用 work stealing 和本地队列等机制减少锁竞争。

#### 提问：自旋锁什么时候不应该使用？

回答：自旋锁适合临界区很短的场景。临界区较长时，自旋会持续占用 CPU，使用互斥锁让出 CPU 更划算；单核 CPU 上也不适合使用，因为持锁线程无法获得 CPU 执行。
