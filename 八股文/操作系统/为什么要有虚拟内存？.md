# 为什么要有虚拟内存？

## 回答重点

虚拟内存主要解决三个问题：

1. **让程序使用比物理内存大得多的地址空间**：不常用的页面可以换到磁盘 Swap，活跃页面留在内存，程序无需感知。
2. **进程之间相互隔离**：每个进程有独立虚拟地址空间，进程 A 和 B 的相同虚拟地址可以映射到不同物理内存，一个进程的野指针不会直接破坏另一个进程。
3. **隐藏物理内存布局**：程序只使用虚拟地址，操作系统通过页表把它映射到任意物理位置。

工作原理：

1. 每个进程看到独立的地址空间。
2. MMU 根据页表把虚拟地址转换为物理地址。
3. 页面不在内存时触发缺页异常，由操作系统从磁盘加载。
4. 物理内存不足时，将不活跃页面换出到 Swap。

## 扩展知识

### 地址翻译流程

CPU 将虚拟地址交给 MMU，MMU 把它拆成虚拟页号和页内偏移，查页表找到物理页框号，再拼接页内偏移得到物理地址。

CPU 使用 **TLB** 缓存最近使用的页表项。TLB 命中时无需访问页表，地址转换很快；未命中时才访问内存中的页表，并将结果放入 TLB。

### 缺页异常

页表项中的有效位表示页面是否在物理内存中。访问有效位为 0 的页面会触发缺页异常：

- 地址不在进程有效范围内：发送 `SIGSEGV`，终止进程。
- 地址合法但页面不在内存：找到空闲页框，从磁盘加载页面，更新页表后重新执行指令。
- 内存已满：根据页面使用情况换出不活跃页面。Linux 使用活跃/非活跃链表等机制近似 LRU。

### 多级页表为什么节省内存

32 位系统使用 4KB 页面时，4GB 虚拟地址空间需要约 100 万个页表项，单级页表约占 4MB。多级页表把页表本身也分页，只有实际使用到的地址范围才分配下级页表，大量空地址空间不占用页表内存。64 位系统通常使用四级甚至五级页表，TLB 命中时不需要逐级查询。

### 写时复制（COW）

`fork()` 创建子进程时，操作系统只复制页表，让父子进程暂时共享物理页，并将页面标记为只读。任一进程尝试写入时触发写保护异常，操作系统才复制该页，让两个进程各自拥有副本。

COW 避免了 fork 后紧接 `exec` 时的大量无效复制，Redis RDB 持久化也利用了这一机制。

## 面试官追问

#### 提问：物理内存和 Swap 都满了会怎样？

回答：Linux 会启动 OOM Killer，按照 `oom_score` 等指标选择进程终止以释放内存。生产环境可以调整 `vm.overcommit_memory`，或通过 `oom_score_adj` 降低关键进程被杀的概率。

#### 提问：为什么访问 Swap 会导致性能急剧下降？

回答：磁盘访问比内存慢几个数量级。频繁换页时 CPU 大量时间都在等待磁盘 I/O，系统会出现 thrashing（抖动）。如果监控中 `si/so` 持续升高、load average 很高而 CPU 利用率不高，通常就是内存抖动。

#### 提问：64 位系统虚拟地址空间有多大，能全部使用吗？

回答：理论上 64 位可寻址 16EB，但当前 x86-64 通常只使用 48 位虚拟地址，即 256TB，低 128TB 给用户态，高 128TB 给内核态。没有使用完整 64 位，是因为页表层级更深、TLB 效率会下降，而且实际程序通常不需要这么大的地址空间。
