# 进程之间的通信方式有哪些？

## 回答重点

进程间通信（IPC）主要有管道、消息队列、共享内存、信号量、信号和套接字，适用场景各不相同。

- **管道**：数据从一端写入、另一端读出，通常是单向字节流。匿名管道用于有亲缘关系的进程，命名管道通过文件系统路径让无亲缘进程通信。
- **消息队列**：发送和接收带类型的消息，消息在队列中排队，接收方可按类型选择性读取，比管道更灵活。
- **共享内存**：多个进程直接读写同一块物理内存，数据无需拷贝，速度最快；但没有内置同步机制，需配合信号量或互斥锁。
- **信号量**：本身不传递数据，用于控制进程对共享资源的访问顺序，实现互斥或限流。
- **信号**：异步通知机制，只传递信号编号，例如 `SIGINT`、`SIGKILL`，不能传递复杂数据。
- **套接字**：既能实现本机通信，也能跨网络通信。Unix 域套接字用于本机，TCP/UDP 套接字用于网络通信。

## 扩展知识

### 管道的底层实现

管道本质是内核中的环形缓冲区，默认大小约 64KB。缓冲区满时写进程阻塞，缓冲区空时读进程阻塞。

```c
// 匿名管道：父进程写，子进程读
#include <unistd.h>
#include <stdio.h>
#include <string.h>

int main() {
    int pipefd[2];
    pipe(pipefd);
    if (fork() == 0) {
        close(pipefd[1]);
        char buf[100];
        read(pipefd[0], buf, sizeof(buf));
        printf("子进程收到: %s\n", buf);
        close(pipefd[0]);
    } else {
        close(pipefd[0]);
        char *msg = "hello from parent";
        write(pipefd[1], msg, strlen(msg) + 1);
        close(pipefd[1]);
    }
    return 0;
}
```

命名管道可用 `mkfifo` 创建，互不相关的进程只要知道路径即可通信：

```bash
# 终端 1
mkfifo /tmp/myfifo
echo "hello" > /tmp/myfifo

# 终端 2
cat /tmp/myfifo
```

### 共享内存为什么最快

管道、消息队列需要在用户空间和内核空间之间进行两次数据拷贝；共享内存则让多个进程的页表指向同一块物理内存，读写无需内核参与，因此接近零拷贝。

```c
// 共享内存示例
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <string.h>

int main() {
    int fd = shm_open("/my_shm", O_CREAT | O_RDWR, 0666);
    ftruncate(fd, 4096);
    char *ptr = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (fork() == 0) {
        sleep(1);
        printf("子进程读到: %s\n", ptr);
    } else {
        strcpy(ptr, "data from parent");
        wait(NULL);
        shm_unlink("/my_shm");
    }
    return 0;
}
```

共享内存的典型流程是 `shm_open` 创建、`ftruncate` 设置大小、`mmap` 映射；另一个进程打开并映射同一对象后即可直接读写。因为内核不负责同步，实际使用必须配合信号量或互斥锁。

### 消息队列与管道

管道是没有消息边界的字节流，消息队列有明确边界，一条消息要么完整读取，要么不读取；消息队列还支持按类型读取。`System` V 消息队列较老，现代 Linux 更推荐 POSIX 消息队列。

### Unix 域套接字

Unix 域套接字专用于本机进程间通信，不经过网络协议栈，效率通常高于 TCP。MySQL、Docker daemon、Nginx 与 PHP-FPM 都常使用 Unix 域套接字。它还可以通过 `SCM_RIGHTS` 传递文件描述符。

### IPC 方式对比

| 通信方式 | 是否需要亲缘关系 | 数据量限制 | 是否需要同步 | 典型场景 |
| --- | --- | --- | --- | --- |
| 匿名管道 | 是 | 约 64KB 缓冲区 | 否 | Shell 管道 |
| 命名管道 | 否 | 约 64KB 缓冲区 | 否 | 简单跨进程通信 |
| 消息队列 | 否 | 单消息通常有限制 | 否 | 结构化消息 |
| 共享内存 | 否 | 可配置 | 是 | 高性能数据交换 |
| Unix 域套接字 | 否 | 通常较灵活 | 否 | 本地服务通信 |

## 面试官追问

#### 提问：为什么说共享内存最快？

回答：管道和消息队列要将数据从用户空间拷到内核，再拷到另一个进程的用户空间；共享内存让多个进程的页表指向同一块物理内存，数据写入后另一进程即可看到，不需要额外拷贝。缺点是必须自己解决同步问题。

#### 提问：实际项目中什么时候用管道，什么时候用共享内存？

回答：数据量小、通信不频繁时用管道，简单省事；数据量大、通信频繁时用共享内存，例如视频解码和渲染进程之间传输大量帧数据。

#### 提问：跨机器的进程通信一般用什么？

回答：跨机器底层都是 Socket。同步调用通常使用 gRPC、Dubbo、Thrift 等 RPC 框架；异步通信使用 Kafka、RocketMQ、RabbitMQ 等消息队列。需要实时响应时选 RPC，需要削峰填谷和解耦时选消息队列。

#### 提问：信号和信号量有什么区别？

回答：信号是异步通知，只传递一个信号编号；信号量是同步原语，本质是计数器，用 P 操作减一、V 操作加一来控制共享资源访问，常用于保护共享内存或实现生产者消费者模型。
