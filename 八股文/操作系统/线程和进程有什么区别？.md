# 线程和进程有什么区别？

## 回答重点

进程是操作系统**分配资源的最小单位**，线程是 **CPU 调度的最小单位**。

每个进程有独立的内存空间，包括代码段、数据段和堆等，可以看作一个正在运行的程序实例。线程属于进程，一个进程可以包含多个线程；线程共享进程的内存和资源，但每个线程拥有独立的栈和寄存器。

![进程与线程](Z:/Public/images/0u90POTm_jinchen.drawio_mianshiya.webp)

可以把操作系统比作工厂：进程是独立车间，线程是车间里的工人，共享车间资源但有自己的工位和工作进度。

主要区别：

1. **内存空间**：进程之间相互隔离；同一进程的线程共享堆、代码段和全局变量，但栈和寄存器私有。
2. **开销**：创建进程、进程间上下文切换成本高；线程创建和切换更轻量。
3. **通信方式**：进程间需要管道、消息队列、共享内存等 IPC；线程可直接读写共享变量，但必须注意同步。
4. **稳定性**：一个进程崩溃通常不会影响其他进程；一个线程破坏进程内存可能导致整个进程及其所有线程退出。

## 扩展知识

### 线程与进程的底层实现

Linux 内核中进程和线程都用 `task_struct` 表示。线程本质上是共享地址空间等资源的进程，因此常被称为轻量级进程。

创建进程使用 `fork()`，现代内核通过写时复制减少开销；创建线程使用 `clone()`，通过不同 flag 控制共享哪些资源。

```c
// fork() 创建进程：子进程有独立地址空间
pid_t pid = fork();
if (pid == 0) {
    // 子进程
} else {
    // 父进程
}

// clone() 创建线程：共享地址空间
clone(thread_func, stack_top, CLONE_VM | CLONE_FS | CLONE_FILES, arg);
```

### Java 中的线程模型

早期 JVM 使用绿色线程，由 JVM 在用户态调度，轻量但不能充分利用多核。现在 HotSpot 主要采用 **1:1 模型**，一个 Java 线程对应一个操作系统线程，在 Linux 上通常通过 `pthread_create()` 创建。

```java
// 继承 Thread
Thread t1 = new Thread() {
    @Override
    public void run() {
        System.out.println("线程执行");
    }
};

// 实现 Runnable
Thread t2 = new Thread(() -> System.out.println("线程执行"));

// 线程池（推荐）
ExecutorService pool = Executors.newFixedThreadPool(10);
pool.submit(() -> System.out.println("线程执行"));
```

### 协程：比线程更轻量

协程完全在用户态调度，一个线程可以运行大量协程，切换时只需保存少量寄存器，开销远小于线程。Go 的 goroutine 使用 M:N 模型；Java 21 引入了虚拟线程，本质上也是轻量级用户态执行单元。

```java
// Java 21 虚拟线程
Thread.startVirtualThread(() -> {
    System.out.println("虚拟线程执行");
});

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(() -> {
        Thread.sleep(1000);
        return null;
    });
}
```

### 上下文切换

线程切换需要保存和恢复寄存器、栈指针等执行状态；进程切换还要切换页表，导致 TLB 失效。真正影响性能的往往是缓存失效：新线程访问的数据不在 CPU 缓存中，需要重新从内存加载。

| 切换类型 | 保存/恢复内容 | 额外开销 |
| --- | --- | --- |
| 协程切换 | 少量寄存器、栈指针 | 很小 |
| 线程切换 | 全部寄存器 | 内核态切换、缓存可能失效 |
| 进程切换 | 全部寄存器 | 内核态切换、页表切换、TLB 失效 |

## 面试官追问

#### 提问：一个进程最多能创建多少个线程？

回答：受虚拟内存、`ulimit -u` 和 `/proc/sys/kernel/threads-max` 等限制。32 位系统用户空间较小，线程栈占用也会限制数量；64 位系统主要受系统参数和内存限制。线程太多还会增加上下文切换开销，性能可能下降。

#### 提问：为什么说线程共享堆但不共享栈？

回答：堆用于存放动态对象，进程内通常只有一个堆，所以线程可以共享；栈保存函数调用链和局部变量，每个线程的执行路径不同，必须各自拥有独立栈，否则会互相覆盖栈顶和局部数据。

#### 提问：多线程一定比单线程快吗？

回答：不一定。CPU 密集型任务的线程数超过 CPU 核心数后会增加切换开销；I/O 密集型任务中，一个线程等待 I/O 时其他线程可以继续工作，多线程才更有优势。锁竞争激烈时，多线程也可能不如单线程。

#### 提问：Java 线程的 `start` 和 `run` 有什么区别？

回答：`start()` 会创建新的操作系统线程，并在新线程中执行 `run()`；直接调用 `run()` 只是普通方法调用，仍在当前线程执行。一个 `Thread` 对象只能调用一次 `start()`，重复调用会抛出 `IllegalThreadStateException`。
