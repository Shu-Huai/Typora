# 什么是用户态和内核态？

## 回答重点

用户态（User Mode）和内核态（Kernel Mode）是操作系统中的两种运行模式，用于区分应用程序与操作系统内核的权限级别。

- **内核态是 Ring 0**：拥有最高权限，可以访问硬件、管理内存和进行进程调度。系统调用、异常或硬件中断发生时，CPU 会切换到内核态。
- **用户态是 Ring 3**：权限受限，不能直接访问硬件，必须通过系统调用让内核代为执行敏感操作。应用程序出错通常只影响自身进程。

![用户态与内核态](Z:/Public/images/8qR9sUx2_yonghutai.drawio_mianshiya.webp)

可以把操作系统想象成银行：用户态是大厅里的客户，只能填单和办理普通业务；内核态是柜台工作人员，拥有金库钥匙。客户要存取款必须通过窗口提交申请，即发起系统调用，办理完成后再返回用户态。

两者主要区别：

1. **权限不同**：内核态 Ring 0，用户态 Ring 3。
2. **资源访问不同**：用户态只能访问受限内存，内核态可访问所有内存和设备。
3. **稳定性不同**：用户态程序崩溃通常只影响自身；内核态出错可能导致系统 Panic 或蓝屏。

## 扩展知识

### 什么时候会触发态切换

1. **系统调用**：如 `read()`、`write()`、`fork()`、`open()`。Java 的 `FileInputStream.read()` 底层最终会进入 Linux `read()`。
2. **异常**：如除零、非法内存访问、缺页异常，CPU 会切换到内核态处理。
3. **硬件中断**：如时钟中断、键盘输入、网卡收到数据、磁盘 I/O 完成。

### 系统调用过程

以 Linux x86-64 的 `read()` 为例：用户程序将系统调用号放入 `rax`、参数放入其他寄存器，执行 `syscall` 指令进入内核；内核根据系统调用号找到 `sys_read()`，执行完成后把结果放入 `rax`，通过 `sysret` 返回用户态。

```c
#include <unistd.h>
#include <sys/syscall.h>

int main() {
    char buf[100];
    // 直接发起 read 系统调用
    long ret = syscall(SYS_read, 0, buf, 100);
    return 0;
}
```

### 为什么系统调用慢

- **上下文切换**：保存用户态寄存器，切换到内核栈，执行后再恢复。
- **权限检查**：内核要验证调用者是否有权执行操作。
- **缓存失效**：用户态和内核态切换可能导致 CPU Cache 或 TLB 失效。

因此 Netty 使用 `epoll` 一次监听大量连接，并通过零拷贝 `sendfile()` 减少系统调用和数据拷贝。

### CPU 特权级

x86 架构设计了 Ring 0 到 Ring 3 四个特权级，但 Linux 和 Windows 通常只使用 Ring 0（内核）和 Ring 3（用户程序）。当前特权级保存在 CS 寄存器低位的 CPL 中：内核态 CPL=0，用户态 CPL=3。权限不足时，CPU 会抛出异常。

虚拟化场景下，Intel VT-`x` 和 AMD-V 提供额外的虚拟化支持，使虚拟机内核可以在受控环境中运行，实际由 Hypervisor 管理。

![CPU 权限级别](Z:/Public/images/zNpbkn8N_quanxiandengji.drawio_mianshiya.webp)

### 微内核与宏内核

- **宏内核**：文件系统、驱动、网络协议栈等都在内核态，性能高，但驱动 Bug 可能导致整个系统崩溃。Linux 属于宏内核。
- **微内核**：内核态只保留调度、内存管理和 IPC 等核心功能，文件系统和驱动放到用户态，稳定性好，但跨态 IPC 较多，性能可能下降。Minix、QNX、seL4 是典型代表。

| 特性 | 宏内核 | 微内核 |
| --- | --- | --- |
| 代表系统 | Linux、FreeBSD | Minix、QNX、seL4 |
| 内核态代码量 | 大 | 小 |
| 性能 | 高 | 较低，IPC 开销大 |
| 稳定性 | 驱动 Bug 可能导致系统崩溃 | 用户态服务崩溃通常不影响内核 |
| 扩展性 | 常需修改或重新编译内核 | 可动态加载用户态服务 |

## 面试官追问

#### 提问：Java 程序里哪些操作会触发系统调用？

回答：涉及操作系统资源的操作都可能触发，例如文件读写、网络 `Socket.accept()` 和 `InputStream.read()`、线程创建 `clone()` 或 `pthread_create()`、线程休眠 `nanosleep()`。`System.currentTimeMillis()` 在现代 Linux 上通常由 vDSO 优化为用户态读取。

#### 提问：为什么说 Netty 性能高？

回答：Netty 使用 epoll 做 I/O 多路复用，一个线程通过一次 `epoll_wait()` 就能获取大量就绪事件；使用 `sendfile()` 零拷贝减少用户态与内核态之间的数据复制；同时配合内存池和堆外内存，减少 GC 和拷贝开销。

#### 提问：内核态程序出 Bug 会怎样？

回答：轻微错误可能产生 Oops 日志并终止当前进程；如果破坏关键数据结构、发生死锁或栈溢出，可能触发 Kernel Panic，系统只能重启。服务器通常会配置 Panic 后自动重启。

#### 提问：用户态能不能直接访问硬件？

回答：正常情况下不能，但可以通过 `iopl()`、`ioperm()` 开放特定 I/O 端口，或通过 `mmap()` 把设备内存映射到用户空间。DPDK 等框架还会将网卡寄存器和内存映射到用户态，以绕过内核协议栈降低网络延迟。
