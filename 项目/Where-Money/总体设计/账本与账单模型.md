# 账本与账单模型

本文说明核心业务对象（账本、分类、账单、资产）的建模方式、字段语义和相互关系。

本文不讨论账单增删改的事务细节，见 [[模块/账单/账单与余额|账单与余额]]。不讨论预算如何利用这些对象，见 [[模块/预算/预算计算|预算计算]]。

源码范围：`entity/`、`type/`、`src/main/resources/schema.sql`。

## 四个核心对象

| 对象 | 表 | 说明 |
|---|---|---|
| 用户 | user | 注册登录主体，用户名唯一 |
| 账本 | book | 记账容器，一个用户多个账本，至少保留一个 |
| 分类 | bill_category | 属于账本，按类型分收入/支出/转账三组 |
| 资产 | asset | 资金/信用卡/充值/投资理财四种账户 |
| 账单 | 四张表 | 收入、支出、转账、退款，见下 |

账单是唯一会产生资产余额变化的对象。资产余额是账单的投影，永远由账单增删改同步维护，没有独立的余额修正入口。

## 账单四表与分类

### 账单四表

| 表 | 独有字段 | 余额影响 |
|---|---|---|
| income_bill | income_asset_id | 入账资产 +amount |
| pay_bill | pay_asset_id、refunded | 出账资产 -amount；被退款后 refunded=1 |
| transfer_bill | in_asset_id、out_asset_id、transfer_fee | 出账资产 -(amount+fee)，入账资产 +amount |
| refund_bill | pay_bill_id、refund_asset_id | 资产 +amount，并把原支出单 refunded=1 |

公共字段：book_id、bill_category_id、amount、bill_time、remark、image、image_content_type。

### 退款模型

退款是独立账单，不是支出的状态。一笔支出可以被多笔退款部分退款，也可以全额退款。规则：

- 退款总额 ≤ 原支出金额，校验在事务里用行锁（select for update）读原支出单
- 原支出单被全额退款后 refunded=1，统计"支出"时扣掉已退款部分
- 删除支出单会级联删除它的退款单，并回滚退款单曾经造成的余额变化
- 修改支出单（金额改小到小于已退金额）会触发校验失败

退款链条只有一层：退款单不能再退款。

### 分类模型

分类绑定账本和类型。type 枚举在库表里只有收入/支出/转账三种（退款单不挂分类，它继承原支出单的分类上下文）。43 个默认分类来自 `json/DefaultBillCategory.json`，注册建账本时写入。

删除分类时账单不删除，迁移到名为"已删除的"兜底分类。分类有 svg 图标字段（Iconify 图标名），前端用图标选择器维护。

## 资产、时间与归属

### 资产模型

| 类型 | 特殊字段 | 语义 |
|---|---|---|
| 资金 | — | 现金/银行卡余额 |
| 信用卡 | bill_date、repay_date、quota | 额度、账单日、还款日；余额为负数表示欠款 |
| 充值 | — | 饭卡/会员卡类 |
| 投资理财 | — | 只记账面金额，不算收益 |

`in_total` 字段控制该资产是否计入总资产。总资产 = 各资产余额之和（信用卡按负余额计入负债）。

日统计（资产曲线）的算法是从当前总资产回溯：按天倒推所有账单对余额的影响，得到历史每一天的净值快照。这条路径在 [[后端/后端分层|后端分层]] 的 AssetServiceImpl 说明里有细节。

### 时间语义

- 账单时间 `bill_time`：记账归属时间，可以改，统计按它聚合
- 账本 `begin_date`：1-28 的整数，预算周期从每月这一天开始
- 后端时间统一 GMT+8（Jackson 时区和 TimeComputer 都按东八区处理），数据库连接串未显式带时区参数

### 数据归属

所有表都通过 user_id 或 book_id 链到用户。归属校验在 Service 层做（如删账本先比对 book.userId == 当前 userId），没有行级安全策略。book_id 是跨页面共享的"当前账本"（前端 localStorage `__BOOK_ID__`），前端每个业务请求都带它。

## 已知边界

- 账单四表拆分导致列表查询要合并排序，无法数据库分页
- book.title 的唯一性只在应用层校验，数据库没有唯一约束，并发下可能撞标题
- bill_category 表枚举缺"退款"类型，退款单的分类归属只能从原支出单间接推导
- budget 表没有外键，删除分类后预算行可能悬挂（rebuild 逻辑需要容忍）
- 资产余额没有审计流水：只有账单作为变动依据，没有独立的余额变动日志，出问题只能从账单表反推
