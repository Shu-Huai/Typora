# 配置与部署

本文汇总全部配置项、构建方式和部署路径。

本文不讨论配置的业务含义联动，见 [[总体实现/实现总览|实现总览]] 和各模块文档。

源码范围：后端 `application.properties.example`；前端 `.env*.example`、`vite.config.mts`、`scripts/`、`harmony-app/`；后端 `deploy/deploy.ps1`。

## 后端配置与部署

### 后端配置

`application.properties` 被 .gitignore 排除，仓库只有 `.example`。关键项：

| 配置 | 说明 |
|---|---|
| spring.datasource.url | MySQL 连接串，含 createDatabaseIfNotExist=true |
| spring.datasource.username/password | 当前本地文件里是明文，example 提示可用 ENC 加密 |
| spring.sql.init.mode | always，每次启动执行 schema.sql |
| server.port | 5050 |
| spring.data.redis.* | 默认 redis.lvshuhuai.cn，本地开发要改 |
| token.privateKey | JWT HMAC256 密钥（当前值是弱密钥 1234567890） |
| token.youngToken / oldToken | 1000000 / 3000000000 ms，双阈值续期 |
| redis.bill.expire / asset.expire / billCategory.expire | 缓存 TTL，均为 7 天 |
| jasypt.encryptor.* | PBEWithMD5AndDES，可加密敏感配置 |
| spring.ai.openai.* | base-url、api-key、model（deepseek-v4-flash）、temperature 0.7 |
| ai.bill.parse.limit-per-minute | 5，AI 限流 |
| ai.bill.parse.timeout-ms | 配置值是 12000000000（异常大），代码默认 12000，需修正 |
| spring.servlet.multipart.* | 单文件 100MB、请求 200MB |

Jackson 输出格式 `yyyy-MM-dd HH:mm:ss`，时区 GMT+8。

### 后端部署

Windows 计划任务方式，`deploy/deploy.ps1`：切到 `C:\Where-Money\Where-Money-Backend` → git pull → 停计划任务 `Where-Money-Backend` → mvn clean/compile/package → 启动任务。

注意脚本里的路径是作者机器路径，别的机器要改。

部署注意事项：

- jar 部署时 `JsonOperator` 的默认分类路径（user.dir/src/main/resources/json）会失效，注册新用户会失败。发布前要解决这个依赖（把 json 打进 classpath 或改用 classpath 读取）
- 账单图片在数据库里，数据库备份即全部数据备份，没有文件系统需要同步

## 前端配置与部署

### 前端配置

| 变量 | 说明 |
|---|---|
| VITE_APP_INTERFACE_URL | 接口基地址，开发 http://localhost:5050/api/，生产 /api/ |
| VITE_APP_BASE_URL | 部署子路径，默认空 |
| VITE_STORAGE_PREFIX | localStorage key 前缀，默认空 |
| VITE_IS_VERCEL | 置 1 时路由切 hash 模式 |

env 文件由 `scripts/ensure-env.ps1` 从 .example 复制生成。localStorage 关键 key：`__TOKEN__`（token）、`__BOOK_ID__`（当前账本）、`__THEME_COLOR__`、`__TAB_ROUTES__`（多页签，AES 加密）。

### 前端部署

| 场景 | 命令 | 产物 |
|---|---|---|
| 生产 Web | npm run build | dist/（terser 压缩、无 sourcemap、去 console） |
| 类型检查 | npm run typecheck | — |
| Vercel | npm run build:vercel | hash 路由 |
| HarmonyOS | npm run harmony:build + harmony:sync | 内联产物拷入 harmony-app/entry/.../rawfile/www/ |

Web 产物交给任意静态服务器，接口路径 `/api/` 需要反代到后端 5050。仓库里没有 nginx 配置，README 提过的 deploy/deply.ps1 已删除。

## 数据库变更与测试

### 数据库变更

没有迁移工具。schema.sql 是唯一建表来源，每次启动执行，索引通过 information_schema 判断后动态创建。

变更表的正确做法：把 DDL 加进 schema.sql（保持幂等），已有环境手工执行 ALTER。风险：schema.sql 与线上库漂移，新环境建出的表和线上不一致，目前没有检测工具。

### 测试

- 后端：JUnit 4 测试硬编码数据 ID（账本 23、账单 181 等），依赖真实数据库，只对作者的数据有效，换环境跑会失败
- 前端：tests/ 下三个 node:test 用例（主题持久化、移动端头部、关于页删除），没有 npm 脚本，用 `node --test` 手动跑
- 测试文件的 .http 请求里 token claim 是旧版 userName 结构，路径 `/api/book/get-book` 也已废弃
