# 实现总览

本文说明后端实际的服务结构、调用链、配置来源、缓存策略和当前实现边界。

本文不讨论各模块业务细节，见 [[模块/账单/账单与余额|账单]]、[[模块/AI 记账/AI 自动记账|AI 记账]]、[[模块/账本/账本与分类|账本]]、[[模块/预算/预算计算|预算]]。

源码范围：`src/main/java/shuhuai/wheremoney` 全部包。

## 包结构与调用链

| 包 | 内容 |
|---|---|
| `controller/` | 7 个控制器：User、Asset、Bill、Book、Budget、Manage、Base（BaseController 是异常处理的父类） |
| `service/` + `impl/` | 7 个业务接口与实现，核心是 BillServiceImpl（1198 行） |
| `service/excep/` | 异常层级：BaseException 下分 ai/book/common/user 四组 |
| `mapper/` | 10 个 Mapper 接口 + resources/mapper 下 10 个手写 XML |
| `entity/` | 11 个实体（含 BaseBill 基类和四种账单子类） |
| `type/` | 枚举与 TypeHandler（AssetType、BillType 自定义映射） |
| `config/` | 鉴权、CORS、Redis、SpringDoc 四个配置类 |
| `utils/` | Token 校验、Hash、Json、Redis 封装、时间、请求上下文、BeanGetter |
| `response/` | 统一返回 + 各模块 VO |

主调用链三条：

```
记一笔：BillController → BillServiceImpl.addBill(@Transactional)
  → 四类分支 → Mapper insert → AssetMapper 余额同步 → BudgetMapper 相对更新（预留）

改一笔：BillController → changeBill(@Transactional)
  → 读旧单 → 回滚旧余额 → 应用新余额 → 退款状态反转时递归处理

查询：BillController → getBill → Redis 缓存旁路 → Mapper 按类型查 → 回填缓存
```

## 配置来源

分四层：

1. `application.properties`（本地文件，被 .gitignore 排除，仓库只有 `.example`）：数据源、Redis、token 密钥、AI 参数
2. `schema.sql`：`spring.sql.init.mode=always`，每次启动自动建表（CREATE TABLE 加索引的动态 SQL）
3. `json/DefaultBillCategory.json`：43 个默认分类，注册时经 `JsonOperator` 从 `user.dir` 相对路径读取
4. Jasypt 加密配置（`ENC(...)`），当前本地配置实际是明文

配置项含义见 [[开发文档/配置与部署|配置与部署]]。

## 缓存与异常

### 缓存策略

全部手工操作 Redis，没有 @Cacheable（`@EnableCaching` 开着但没注解）。key 与策略：

| key | 内容 | TTL | 写策略 |
|---|---|---|---|
| asset:{id} | Asset JSON | 7 天，读写都刷新 | 更新后覆盖 |
| pay_bill:{id} / income_bill:{id} / transfer_bill:{id} / refund_bill:{id} | 账单 JSON（image 置空） | 7 天 | 更新后覆盖，删除时删 key |
| bill_category:{id} | 分类 JSON | 7 天 | 更新后覆盖，删除时删 key |
| ai:bill:parse:limit:{userId}:{yyyyMMddHHmm} | 计数器 | 120 秒 | INCR |

缓存旁路：读先查缓存，未命中查库回填。列表类查询（按账本、按时间区间）不缓存。图片永远不进缓存。

账单更新后缓存覆盖有一个已知坑：getBill 的缓存值和数据库可能有短暂不一致（更新事务提交前缓存已写）。提交历史里有"修复缓存不一致 bug"（91e96fd），说明踩过。

### 异常与错误码

统一返回 `Response{code, message, data}`，HTTP 状态码恒为 200，code 是业务码：

| code | 异常 |
|---|---|
| 400 | 用户名/标题占用 |
| 401 | 密码错误、token 过期 |
| 403 | 无权限（数据归属校验失败） |
| 404 | 用户不存在 |
| 422 | 参数错误、AI 结果不完整/无关/歧义/资产或分类找不到 |
| 429 | AI 限流 |
| 500 | 服务器错误、AI 调用失败/超时/响应格式错 |

参数类异常（缺失、类型错、JSON 读失败）统一 422；数据库异常区分完整性约束（422）和其他（500）。兜底 Exception 500。异常处理集中在一个方法里 switch 异常类，AI 异常按语义细分了 9 个子类。

## 实现边界

- 无定时任务、无 @Async、无消息队列。AI 调用用虚拟线程执行器（Executors.newVirtualThreadPerTaskExecutor，@PreDestroy 关闭）
- 无逻辑删除、无乐观锁、无自动填充。并发保护只有退款校验的 select for update
- 无角色体系，归属校验散落在各 Service 方法里
- 测试依赖真实数据库硬编码 ID，不能重复跑，见 [[开发文档/配置与部署|配置与部署]]
- 根目录遗留 derby.log、hs_err、replay 崩溃日志，与本项目运行无关
- ThreadLocal 未清理、CORS 全开放、MD5 密码、`JsonOperator` 依赖 user.dir（jar 部署后默认分类读取会失败）等边界在各文档中均有标注
