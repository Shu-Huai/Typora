# 数据模型

本文说明 10 张表的结构、约束、删除策略，以及 MySQL 与 Redis 的事实边界。

本文不讨论业务对象语义，见 [[总体设计/账本与账单模型|账本与账单模型]]。ORM 细节见 [[后端/后端分层|后端分层]]。

源码范围：`src/main/resources/schema.sql`、`entity/`、`resources/mapper/*.xml`。

## 表清单

![](Z:\Public\images\where-money-er-diagram.svg)

| 表 | 实体 | 业务意义 |
|---|---|---|
| user | User | 账号，user_name 唯一 |
| book | Book | 账本，含总预算两列 |
| asset | Asset | 四类资金账户 |
| bill_category | BillCategory | 账本下的收支分类 |
| income_bill | IncomeBill | 收入账单 |
| pay_bill | PayBill | 支出账单（带 refunded） |
| transfer_bill | TransferBill | 转账账单（带手续费） |
| refund_bill | RefundBill | 退款账单（关联原支出） |
| budget | Budget | 分类预算（used/times 系统维护） |
| ai_bill_parse_log | AiBillParseLog | AI 调用审计日志 |

所有表 InnoDB、自增主键、无逻辑删除、无乐观锁、无自动填充。时间戳字段由业务代码写。

## 关键约束与枚举

### 关键约束

| 约束 | 位置 | 用途 |
|---|---|---|
| unique(user_name) | user | 登录标识防重 |
| 外键 user_id / book_id | asset/book/bill_category | 归属链 |
| 外键 book_id / asset 外键 / category 外键 | 四张账单表 | 关联完整性 |
| 动态索引 | schema.sql 运行时判断创建 | 账单表按 book_id、category、asset 建索引 |
| title 唯一 | 无数据库约束，仅应用层 | 见下 |

外键无 ON DELETE 行为，删除全靠应用层级联（删账本时显式删四类账单+预算+分类）。budget 表没有任何外键。

四类账单表结构几乎相同：book_id、金额、时间、备注、图片（mediumblob + content_type varchar63）、各自的资产外键。图片按 100MB 上限直接存库。

### 枚举存储

枚举走自定义 TypeHandler 按 name 映射到 varchar：

- asset.type：资金 / 信用卡 / 充值 / 投资理财
- bill_category.type：收入 / 支出 / 转账（库表枚举缺"退款"）
- ai_bill_parse_log.type：收入 / 支出 / 转账 / 退款

`pay_bill.refunded` 是 tinyint(1) 布尔，1 表示已全额退款。

## 删除策略与事实边界

### 删除策略

全部物理删除：

- 删账单：真删，退款关联级联删
- 删账本：级联删四类账单 + 预算 + 分类
- 删分类：账单不删，bill_category_id 迁移到"已删除的"兜底分类
- 删资产：接口没有提供（前端没有入口），资产只能改不能删

### 与 Redis 的事实边界

| 事实 | 所在 |
|---|---|
| 全部业务数据（账单、资产、余额、预算、图片） | MySQL |
| 实体查询缓存（asset/{id}、四类 bill/{id}、bill_category/{id}） | Redis，7 天 TTL |
| AI 限流计数 | Redis，120 秒 |
| 余额的权威值 | MySQL asset.balance（由账单同步） |

Redis 是纯缓存和计数器，全部丢失不影响正确性，只会让首轮查询变慢。图片不进缓存（写缓存前置空）。

## 已知边界

- book.title 无唯一约束，并发建账本可能重名（应用层查了再插）
- 账单四表拆分，跨表统计和列表合并在 SQL 里各做各的，排序在内存
- 图片存库导致表体积膨胀，单表备份困难
- ai_bill_parse_log 只增不删，长期运行持续膨胀
- 状态字段（type、status）无 CHECK 约束，非法值靠 TypeHandler 拦
- 无迁移工具，schema 演进见 [[开发文档/配置与部署|配置与部署]]
