# 前端架构

本文说明前端的技术栈、目录结构、路由、状态管理和请求层。

本文不讨论页面交互细节，见 [[前端/页面与流程|页面与流程]]。接口定义见 [[接口/接口总览|接口总览]]。

源码范围：`src/` 全部、`vite.config.mts`、`package.json`、`build/`。

## 技术栈

Vue 3.4（Composition API + script setup）、TypeScript 5.3（strict）、Vite 5、Naive UI 2.37、Pinia 2.1、Vue Router 4.2、axios、Windi CSS、ECharts 5 + G2Plot 2.4（图表）、Iconify 图标、dayjs、crypto-js（多页签 AES 加密）、qs（表单序列化）。

工程骨架参考 Soybean Admin 演进：AdminLayout（@soybeanjs/vue-materials）、多页签、主题配置抽屉、明暗模式。

依赖里有 tailwindcss、@antv/g2、clipboard、ua-parser-js 等，但没有对应配置文件或源码引用，是残留依赖。

## 目录与路由

| 路径 | 内容 |
|---|---|
| `apis/` | 6 个 API 模块（user/book/bill/asset/budget/index），返回类型全是 any |
| `views/` | home/bill/asset/budget 四个业务页 + system-view（登录注册）+ 异常页 |
| `layouts/` | BasicLayout（侧栏+页签+头部）、BlankLayout、GlobalContent（全局记一笔入口） |
| `components/` | common（暗色切换、HoverContainer）、custom（SvgIcon、图标选择器、页签） |
| `store/modules/` | app/route/tab/theme 四个 store + subscribe |
| `stores/store.ts` | main store：bookId、currentBill 等跨页面业务状态 |
| `router/` | 路由表 + guard（权限守卫链）+ 滚动位置 |
| `utils/` | request/http/storage/crypto/dateComputer 等 |
| `settings/` | theme.json、color.json 主题预设 |
| `plugins/` | naive 组件注册、assets |

路由表：

| 路径 | 页面 | 登录要求 |
|---|---|---|
| /home | 首页统计 | 需要 |
| /bill | 账单 | 需要 |
| /asset | 资产 | 需要 |
| /budget | 预算 | 需要 |
| /login、/register | 登录注册 | 公开 |
| /no-permission、/not-found、/service-error | 异常页 | 公开 |
| 其他 | 404 兜底 | 公开 |

守卫逻辑：已登录访问登录页跳首页；需要登录的路由无 token 时跳 `/login?redirect=原路径`；token 存在即放行。没有角色概念。路由组件用 import.meta.glob eager 收集，构建时全量打包（不是真懒加载）。

## 状态管理与持久化

Pinia store 分两类：

- 框架类：app（侧栏、抽屉）、theme（暗色、主题色、布局，写回 localStorage）、tab（多页签+滚动位置）、route（菜单）
- 业务类：main store 的 bookId、currentBill、currentBillType，跨页面共享但不持久化（bookId 从 localStorage `__BOOK_ID__` 初始化）

localStorage key 前缀 `VITE_STORAGE_PREFIX`：

| key | 内容 |
|---|---|
| __TOKEN__ | JWT token |
| __BOOK_ID__ | 当前账本 id |
| __THEME_COLOR__ | 主题色 |
| __TAB_ROUTES__ | 多页签，AES 加密（密钥硬编码 __CryptoJS_Secret__），7 天过期 |
| __LAYOUT__、__TAB_VISIBLE__ | 布局与页签开关 |

登录页"记住我"把用户名密码明文存 cookie 7 天。

## 请求层与构建

axios 实例 baseURL 取 `VITE_APP_INTERFACE_URL`，timeout 600 秒。

请求拦截：token 存在则加 `Authorization: Bearer`；post/patch 且路径不是 `/bill/bill` 时用 qs 转 form-urlencoded。

响应拦截：code 200 返回 data；非 200 按 code 分支弹错——401 清 token，token 相关跳登录，密码错误留原地；403/405 等静默；所有失败 loadingBar 置错。`skipErrorMessage` 配置可跳过弹错（AI 解析用）。

Naive UI 的 message/dialog 等通过 NaiveProviderContent 挂到 window 上，守卫和非组件代码直接用 `window.$message`。

### 构建与多端

- 普通 Web：`npm run build` → dist（terser 去 console、无 sourcemap）
- Vercel：`build:vercel` 注入 VITE_IS_VERCEL 切 hash 路由
- HarmonyOS：`harmony:build`（内联产物）+ `harmony:sync`（拷入 harmony-app 的 rawfile/www），前端有 ArkWeb 适配（暗色同步事件、安全区 CSS）

浏览器兼容：无 browserslist 配置，遵循 Vite 5 默认目标（Chrome 87+ 级别）。代码里有 Safari HEIC 预览检测和 1280px 桌面断点适配。

### 已知边界

- 无 WebSocket、无轮询、无 SSE，跨页面数据新鲜度靠手动刷新和切页重新请求
- 路由组件 eager 收集，全部打进主包，无分包
- apis 层返回类型全部 any，类型安全靠不住
- 异常页有两套实现（views/exception 与 system-view 下重复），路由只用了 system-view 版本
- request 超时硬编码 600 秒，service.ts 里的常量表是死配置
- Income 组件分类提交用 name 字段、Pay 用 billCategoryName，字段名不一致，疑似 bug
- 部分 API 路径缺前导斜杠（asset/asset、book/income-month），依赖 axios baseURL 拼接行为，风格不统一
