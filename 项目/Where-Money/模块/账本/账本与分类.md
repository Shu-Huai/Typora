# 账本与分类

本文说明多账本管理、分类体系、默认分类导入和删除迁移。

本文不讨论账本下的账单事务，见 [[模块/账单/账单与余额|账单与余额]]。预算与账本的关系见 [[模块/预算/预算计算|预算计算]]。

源码范围：`service/impl/BookServiceImpl.java`、`service/impl/BillCategoryServiceImpl.java`、`json/DefaultBillCategory.json`。

## 账本生命周期

创建：`addBook(title, beginDate)`。校验两条：标题在该用户名下不重复（应用层查重，无数据库唯一约束）、beginDate 在 1-28 之间。新账本没有分类和预算，是全空状态。

读取：`getBook(id)` 除了返回账本自身，还顺带触发预算全量重建（rebuildBudgetByBook），见 [[模块/预算/预算计算|预算计算]]。`getBookList` 返回该用户全部账本。

删除：`deleteBook(id)` 四条规则：

- 校验归属（book.userId == 当前用户），否则 403
- 至少保留一个账本，最后一个删不掉
- 级联删四类账单 + 预算 + 分类（物理删除）
- 删除顺序代码里是账单 → 预算 → 分类，避免外键约束报错

账本没有修改标题、修改 beginDate 的接口。beginDate 定了就不能改（改预算周期会让历史统计错位）。

## 分类体系与删除迁移

### 分类体系

分类表字段：book_id、bill_category_name、svg（Iconify 图标名）、type（收入/支出/转账）。

来源两条：

1. 注册时建默认账本并导入 43 个默认分类（`json/DefaultBillCategory.json`，经 JsonOperator 读取）
2. 用户在分类管理里手动新增（两个入口：账单侧 POST /api/bill/category、账本侧 POST /api/book/bill-category，功能重叠）

分类查询有 Redis 缓存（7 天），批量查询会回填缓存。

### 删除迁移

删除分类时不删账单，把该分类下的账单 bill_category_id 改指向"已删除的"兜底分类。兜底分类的创建时机：删除分类时如果不存在就先建一个。

这个设计保住了历史账单的统计口径（它们还在某个分类下），代价是"已删除的"分类会随时间积累旧账单。

## 图标、月统计与边界

### 图标与前端

分类图标存 Iconify 图标名字符串（如 `ic:baseline-account-balance-wallet`），前端用 IconifyPicker 选。默认 svg 值配置在 `default.svg` 属性里。图标只影响展示，不参与统计。

### 月统计

BookController 的四个统计（pay-month/income-month/balance-month/refund-month）按账本和时间区间聚合：

- 收入月、支出月：当月收入/净支出（扣退款）
- 结余月：收入 - 支出 + 退款回入
- 退款月：当月退款总额

这些是首页三张卡的数据源。

### 已知边界

- 两个建分类入口并存（/api/bill/category 和 /api/book/bill-category），行为应该一致但代码是两份
- 改账单账本时分类不迁移，孤儿分类，见 [[模块/账单/账单与余额|账单与余额]]
- beginDate 不可改，用户月初建账本后发现周期不对只能重建账本
- 账本标题唯一性靠应用层查重，并发窗口下可能重复
- JsonOperator 依赖 user.dir，jar 部署后新用户注册的默认分类导入会失败
- "已删除的"兜底分类会出现在分类统计里，用户会看到来源不明的支出
