# 账单与余额

本文从代码角度说明四类账单的增删改、资产余额同步和退款处理。

本文不讨论业务对象语义，见 [[总体设计/账本与账单模型|账本与账单模型]]。异常行为见 [[总体实现/异常与失败处理|异常与失败处理]]。

源码范围：`service/impl/BillServiceImpl.java`、`controller/BillController.java`、`resources/mapper/*.xml`。

## addBill：四类分支

`addBill` 是 @Transactional 方法，按 type 走四个分支：

![](http://public.file.lvshuhuai.cn/images\where-money-bill-flow.svg)

```
收入：insert income_bill → 入账资产 balance += amount
支出：insert pay_bill → 出账资产 balance -= amount
转账：insert transfer_bill → 出账资产 balance -= (amount + transferFee)
                          → 入账资产 balance += amount
退款：selectPayBillByIdForUpdate（行锁）→ 校验可退金额
      → insert refund_bill → 资产 balance += amount
      → 全额退款时原支出单 refunded = 1
```

退款分支的关键点：

- 行锁串行化同一支出单的并发退款，防止超退
- 可退金额 = 原支出金额 - 已退款总额
- 退款单入账资产是 refund_asset_id（退款回到哪个账户由用户选）

资产余额更新用 `changeBalanceRelative`（balance = balance + x），mapper 层是相对更新 SQL，天然并发安全。

## changeBill 与 deleteBill

### changeBill：回滚再应用

`changeBill` 同样是 @Transactional：

1. 按 id + type 读旧账单，记下旧资产影响
2. 回滚旧账单对各资产的影响（余额反方向加回）
3. 按新字段重新插入式更新（selective update）
4. 应用新账单对各资产的影响
5. 退款状态反转处理：
   - 支出单被改成"已退款"状态反转（refunded 由 1 改 0）时，需要把关联退款单的余额影响撤销——代码是递归删退款单再重算
   - 支出单金额改小到低于已退款总额：校验拒绝

账本迁移（改 bookId）时，账单要连分类、预算一起级联迁移，代码里账单迁移只处理账单本身四表，分类归属可能悬挂（边界见下）。

### deleteBill：级联与回滚

- 删支出单：级联删它的退款单，回滚退款单曾造成的余额变化，再回滚支出单本身
- 删其他类型：回滚自身余额影响即可
- 图片随行删除（图片在行内）

## 查询统计与缓存

### 查询与统计

| 方法 | 逻辑 |
|---|---|
| getBill | Redis 旁路：缓存 → 库 → 回填；缓存值 image 置空 |
| getBillByBook | 四表各查全量，内存按 billTime 倒序合并 |
| getBillByBookAndTime | 同上加时间过滤 |
| categoryPayStatisticTime | 分类聚合，支出扣退款，算占比 |
| getDayPayStatisticTime | 按日聚合 |
| getMaxMinPayBill | 周期内最大/最小支出单 |

统计里"支出扣退款"的实现：支出金额减去该支出单已退金额。所以统计口径是净支出。

### 缓存一致性

写路径：add/change 后覆盖写缓存（key 为 `{type}_bill:{id}`）；delete 后删缓存。图片在写缓存前置空。

已知顺序问题：缓存覆盖在事务提交前后都出现过（提交历史里 91e96fd 修过缓存不一致 bug），当前实现是 Service 方法内事务外操作缓存。事务回滚时缓存可能留下未提交的值，7 天 TTL 内只能等下一次写入纠正。

## 已知边界

- 改账单的账本（bookId 变更）时，账单四表迁移了，但 bill_category_id 指向旧账本的分类，新账本里该分类不存在，统计时按分类聚合会出现"孤儿分类"
- 转账手续费计入出账资产扣减，但统计口径里手续费没有单独维度，报表上看不到手续费总额
- 四表合并没有分页，账单量大后 /bill/all 会变慢
- 删除账单后预算不即时重建，下次读账本才生效（惰性一致）
- 退款单没有独立的分类和时间过滤逻辑，它跟随原支出单出现在统计里（退款扣减支出）
