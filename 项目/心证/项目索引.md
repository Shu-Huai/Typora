## 项目模型

心证是一个本机独立启动的心脏病理辅助分析初版。普通用户在对话界面提交自然语言；Controller LLM 基于本轮消息、已审计的病例事实和已验证 SVS 引用，自主选择是否调用工具。工具的执行记录、公开摘要和证据会保存到 MySQL，并通过 SSE 推送给浏览器。

| 问题 | 当前实现 |
| --- | --- |
| 谁使用 | 普通用户发起会话；管理员管理用户和医学 PDF 知识库 |
| 主要输入 | 自由文本、SVS 的文件名或相对路径、管理员上传的 PDF |
| 主要输出 | Agent 回答、模型公开摘要、工具轨迹、证据记录 |
| 事实存储 | MySQL 保存会话、消息、病例上下文、运行、工具与证据 |
| 文件存储 | SVS 位于配置的唯一共享目录；PDF 位于 `knowledge-storage.root-path` |
| 检索存储 | Qdrant 保存 PDF 分块向量；SearXNG 提供受领域限制的公开搜索 |
| 异步部分 | Agent Run 在 Spring 线程池执行；浏览器用 SSE 接收事件 |
| 部署形态 | 三个本机进程，当前没有 Docker、消息队列或多实例实现 |

[已实现] Controller 的工具选择不是 Java 写死的固定顺序；但 Java 仍对路径、权限、最大步数和总时限施加硬边界。详细机制见 [[总体实现/运行时边界]]。

[已知边界] 文本诊断和多模态诊断返回演示性随机结果；它们不能作为医学判断。SVS 元数据读取使用 OpenSlide，属于真实文件读取能力。

## 维护规则

1. 文档以当前源码、配置和运行验证为准；设计记录不能覆盖源码事实。
2. 修改 API、表结构、配置键或状态枚举时，必须同步更新对应文档和此索引链接。
3. 不在此目录记录密钥、真实病例内容、SVS 绝对路径或远程数据库口令。
4. 运行时不使用“数据集仓库”概念；SVS 只能通过唯一共享目录下的相对路径引用。
