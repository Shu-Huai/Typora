## PDF 到检索证据

```text
管理员上传 PDF
  → 校验扩展名、非空、≤50MB
  → 计算 SHA-256 并查重
  → 保存 PROCESSING 文档记录
  → 原子写入 knowledge-storage.root-path
  → PDFBox 按页提取文本并按 chunk-size/chunk-overlap 分块
  → FastAPI Embedding
  → Qdrant 写入向量和 payload
  → 文档置为 READY
```

Qdrant payload 至少包含 `documentId`、`fileName`、`page`、`enabled` 和分块文本。检索前会加 `enabled=true` 过滤；返回内容、文件名、页码和相似度。

| 操作 | 持久化变化 | 文件与向量副作用 | 失败行为 |
| --- | --- | --- | --- |
| 上传 | 创建 `knowledge_document` | 先保存 PDF，再写 Qdrant | 标记 `FAILED` 并删除本次文件 |
| 停用 | `enabled=false`、状态 `DISABLED` | 更新 Qdrant payload | Qdrant 失败会返回错误 |
| 重建 | 先置 `PROCESSING` | 删除旧向量，再从原 PDF 重建 | 标记 `FAILED`，可能需要人工检查向量状态 |
| 删除 | 删除记录 | 先删除 Qdrant，再删除 PDF | 向量删除失败时不删文件和记录 |

[已知边界] PDFBox 对某些字体会产生 Unicode 映射警告；若没有提取到任何文本，上传被拒绝。重建期间若删除旧向量后写入失败，文档记录会标记失败，管理员需要重试重建。

## SVS 共享目录

运行时只有 `slide-storage.shared-path` 指向的一条共享目录。用户不可提交绝对路径、UNC 路径或越界 `..` 路径；Java 规范化路径并检查符号链接真实路径仍在根目录内。Python 在读取元数据前再次进行相对路径、扩展名、目录边界和普通文件检查。

| 能力 | 触发 | 实际输出 | 数据归属 |
| --- | --- | --- | --- |
| 核验/登记 | 用户提供文件名或相对路径 | 有效性、大小、警告、规范相对路径 | 会话表 `conversation_slide_resource` |
| 枚举 | Agent 请求列出共享目录 | 至多 `max-files` 条 `.svs` 逻辑引用 | 不保存目录快照 |
| 元数据 | Agent 请求具体切片 | 宽高、层级、倍率、MPP、厂商、公开属性 | 工具证据，不复制 SVS |
| 多模态诊断 | Agent 策略允许 | 已验证引用组成请求 | 不上传 SVS 文件本身 |

[已知边界] OpenSlide 无法导入、格式不支持、文件损坏或共享目录不可达时，只有元数据相关工具失败；三个服务仍可启动。Python 和 Java 的共享目录必须是同一实际位置，否则会出现“Java 已验证、Python 找不到文件”的不一致。
