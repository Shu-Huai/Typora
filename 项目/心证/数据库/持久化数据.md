## 当前业务表

| 表 | 业务含义 | 主键/关键约束 | 主要写入方 |
| --- | --- | --- | --- |
| `sys_user` | 系统账号 | `username` 唯一 | `UserServiceImpl`、启动管理员初始化 |
| `agent_conversation` | 用户会话 | 用户与更新时间索引 | `ConversationServiceImpl` |
| `agent_message` | 会话消息 | `(conversation_id, sequence_no)` 唯一 | 会话服务、运行时 |
| `conversation_case_context` | 当前已审计病例事实 | `conversation_id` 唯一 | `ConversationStateTools` |
| `conversation_slide_resource` | 当前会话已登记的 SVS 引用 | `(conversation_id, path_hash)` 唯一 | `ConversationStateTools` |
| `agent_execution` | 一轮 Agent 运行 | 会话与创建时间索引 | 会话服务、运行时、恢复服务 |
| `tool_execution` | 某次工具调用 | `run_id` 与开始时间索引 | `ToolExecutionAspect` |
| `agent_evidence` | 可追溯结果摘要 | `run_id` 索引 | `ToolExecutionAspect` |
| `knowledge_document` | 已上传 PDF 的元数据 | `sha256` 唯一 | `KnowledgeServiceImpl` |

`conversation_case_context` 的 `source_message_id` 表示最近一次变更来自哪条用户消息，`version_no` 每次修改递增。`image_mode` 为 `UNKNOWN`、`TEXT_ONLY` 或 `WITH_SLIDES`，它是会话资源状态，不是用户表单字段。

## 状态、事务与删除

| 对象 | 主要状态 | 重启/失败语义 |
| --- | --- | --- |
| `agent_execution` | `PENDING`、`RUNNING`、`COMPLETED`、`WAITING_USER`、`FAILED` | 启动时 `RUNNING` 置失败；`PENDING` 重新入队 |
| `tool_execution` | `RUNNING`、`SUCCEEDED`、`FAILED` | 执行切面在异常时写错误码和公开失败摘要 |
| `knowledge_document` | `PROCESSING`、`READY`、`DISABLED`、`FAILED` | 上传/重建失败会写错误信息 |
| `sys_user` | `enabled` 布尔值 | 停用后认证被拒绝；不能停用当前管理员自身 |

[已实现] 发送消息的数据库事务创建用户消息和 `PENDING` Run；只有事务提交后才调度 Agent。会话行通过 `selectByIdForUpdate` 与活动 Run 查询阻止同会话并发执行。

[已知边界] `medical_case`、`slide_resource`、`agent_run` 与 `case_reference_annotation` 仍在 schema 中，属于早期结构化病例设计的遗留表；当前对话式 Agent 主流程不读写它们。不要把这些表当作运行时病例仓库，也不要向 `case_reference_annotation` 输入盲测答案。

## MySQL 之外的事实

| 位置 | 保存内容 | 可否由数据库重建 |
| --- | --- | --- |
| Qdrant | PDF 分块向量与检索 payload | 可从 `knowledge_document` 对应原 PDF 重建（原 PDF 存在时） |
| `knowledge-storage.root-path` | 管理员上传的原 PDF | 不应只依赖数据库；需要备份文件目录 |
| SVS 共享目录 | 外部原始切片 | 不由本系统保存或恢复 |
| 后端内存 | SSE 票据、订阅者、事件缓冲、序号 | 进程重启即丢失 |
