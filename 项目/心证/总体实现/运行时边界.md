## 进程与依赖

```text
浏览器
  → Vue 开发服务 :25000
  → Spring Boot :25001
       ├→ MySQL：会话、运行、审计、用户、知识文档
       ├→ FastAPI :8002：Controller 网关、诊断、Embedding、OpenSlide
       ├→ Qdrant：PDF 分块向量
       ├→ SearXNG：心脏病理公开检索

```

[已实现] 前端开发服务器把 `/api` 代理至 `127.0.0.1:25001`。后端以 Spring AI 调用 `127.0.0.1:8002/v1/chat/completions`，FastAPI 再依配置转发到在线或本地 OpenAI 兼容 Controller LLM。

[已知边界] Redis 连接参数存在于后端配置，但当前业务代码未读写 Redis。SSE 票据、订阅者、事件缓冲与序号均在单个后端进程内存中。

## 一轮 Agent 运行

| 阶段 | 当前状态或产物 | 持久化位置 |
| --- | --- | --- |
| 发送消息 | `AgentMessage`、`AgentExecution(PENDING)` | MySQL |
| 提交后调度 | 线程池执行 `AgentRuntimeServiceImpl.execute` | 内存线程池 |
| 模型回合 | Controller 流式响应、可选公开摘要 | SSE；最终回答入库 |
| 工具调用 | `ToolExecution(RUNNING/SUCCEEDED/FAILED)` | MySQL 与 SSE |
| 证据 | 诊断、RAG、SVS、互联网成功结果的摘要 | `agent_evidence` |
| 完成 | `COMPLETED`、`WAITING_USER` 或 `FAILED` | MySQL 与 SSE |

Java 通过 `agent.max-steps`（默认 8）限制每轮工具数量，并通过 `agent.run-timeout`（默认 3 分钟）限制总运行时间。工具失败会形成可观察结果；Controller 可以改用其他工具、降低结论或追问，但不能绕过 Java 的硬限制。

## 重启、并发和事实边界

[已实现]

- `ConversationServiceImpl.sendMessage` 在事务内锁定会话，并检查活动运行，保证一个会话只有一个 `PENDING/RUNNING` Run。
- 进程启动时，`AgentRunRecoveryService` 将遗留 `RUNNING` 标为失败；遗留 `PENDING` 再次调度。
- 会话事实存在 `conversation_case_context`；切片引用存在 `conversation_slide_resource`。两者均以会话为作用域，不写入历史数据集表。
- PDF 原文件可从磁盘和 Qdrant 重建；SVS 原文件不复制、不受系统管理。

[已知边界]

- 运行中的 Controller 调用会在重启后中断，不能从中间步骤恢复。
- SSE 内存缓冲在重启后丢失；数据库中已完成的消息、工具和证据仍可读取。
- 当前线程池为核心 2、最大 4、队列 50；无跨进程并发协调。
