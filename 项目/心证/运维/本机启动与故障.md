# 本机启动与故障

## 文档范围

本文让开发者在 Windows 本机启动、配置和排查三个服务，不覆盖容器、Kubernetes 或多实例部署。

- 源码范围：三目录的启动脚本、YAML、`AsyncConfig`、`SseEventServiceImpl`
- 描述状态：[已实现]；生产部署项标为 [待改造]。
- 相关文档：[[项目索引]]、[[模型服务/网关与模型接口]]、[[后端/知识库与切片资源]]。

## 配置和启动

不要提交 `application-local.yml`、密钥、真实病例内容或可访问的共享目录凭据。后端和模型服务各自读取同目录的本地覆盖文件。

| 服务 | 目录 | 默认端口 | 启动方式 |
| --- | --- | --- | --- |
| 模型服务 | `E:\Agent\model_provider` | 8002 | `./启动.ps1` |
| 后端 | `E:\Agent\backend` | 25001 | `./启动.ps1` |
| 前端 | `E:\Agent\frontend` | 25000 | `./启动.ps1` |

建议顺序：模型服务 → 后端 → 前端。前端启动后访问 `http://127.0.0.1:25000`；Knife4j 位于 `http://127.0.0.1:25001/doc.html`；FastAPI 文档位于 `http://127.0.0.1:8002/docs`。

启动前必须确认：

1. MySQL 可连接，账户有建表/读写当前库的权限；后端以 `schema.sql` 初始化表。
2. Qdrant 可连接，`qdrant.vector-size` 与 Embedding 返回维度一致。
3. Java 的 `slide-storage.shared-path` 与 Python 的 `slide.shared-path` 是同一目录。
4. 在线 Controller/Embedding 模式已在 Python 本地配置写入正确的 Base URL、API Key 和模型名；本地模式对应的 OpenAI 兼容服务或 `sentence-transformers` 依赖可用。
5. `token.private-key` 至少 32 位，管理员初始密码仅保存在本地覆盖文件。

## 常见故障

| 现象 | 首先检查 | 处理方式 |
| --- | --- | --- |
| Agent 运行失败，提示网关请求 | Python `:8002` 是否存活；后端 Base URL 是否为网关根地址 | 检查 `/v1/chat/completions` 实际路径和上游配置；重启后端加载配置 |
| Agent 无流式内容 | 浏览器 SSE 请求、一次性票据、后端日志 | 查看 `DONE/ERROR` 事件；刷新会话确认最终消息是否已持久化 |
| SVS 在 Java 通过、Python 找不到 | 两个共享目录配置是否相同 | 修正为同一目录，确认进程账户有读权限 |
| OpenSlide 503 | Python 虚拟环境是否安装 `openslide-python` 与 `openslide-bin` | 修复虚拟环境后重启模型服务；不要设置临时 DLL 环境变量作为长期方案 |
| PDF 上传 500 | PDF 是否含可提取文本、目录可写、Embedding/Qdrant 是否可达 | 阅读后端 `KnowledgeServiceImpl` 错误日志；失败记录可重建或删除 |
| Qdrant 维度错误 | `qdrant.vector-size`、Python Embedding dimensions、现有 Collection | 统一维度；不要对已有数据随意覆盖 Collection |
| 互联网检索空结果 | SearXNG 上游引擎状态/限流 | 空结果是有效观察；不伪造内容，可稍后重试 |
| 重启后 Run 失败 | `agent_execution` 状态 | 运行中的任务会被标记中断；用户重新发送继续 |

## 观测、发布与回滚

[已实现]

- 后端控制台记录 AOP 接口日志；日志脱敏器不输出密码、Token、病例正文、诊断正文和服务器绝对路径。
- `GET /actuator/health` 可检查后端健康；管理员可读 `/actuator/metrics`。
- Agent 运行、工具和证据可从会话详情读取；这是排查 Agent 决策和工具失败的第一入口。

[待改造]

- 当前没有统一日志文件、集中监控、数据库迁移工具、发布包版本登记或自动回滚脚本。
- 发布时应先备份 MySQL 与 `knowledge-storage.root-path`，停止三个进程，替换构建产物，启动模型服务和后端后执行健康检查，再启动前端。回滚就是恢复上一个已验证构建和配置；SVS 不由项目回滚。
- 不要在多实例运行后端：SSE 票据和缓冲为实例内存，且当前没有共享协调层。
