# 权限边界

本文说明角色体系、鉴权链路、token 生命周期和管理操作的权限约束。

本文不讨论用户账号本身的增删改，见 [[模块/认证与用户/认证与用户|认证与用户]]。不讨论接口层的具体注解位置，见 [[接口/接口总览|接口总览]]。

源码范围：

- `auth/RequireRole.java`
- `utils/TokenValidator.java`
- `config/AuthWebConfig.java`、`config/TokenConfig.java`
- `enm/UserRole.java`

## 角色与继承

两个角色：`USER`、`ADMIN`。ADMIN 继承 USER 的全部权限：`hasRole` 判定为"角色相同，或当前是 ADMIN 且要求的是 USER"。

角色来源有两处，优先级不同：

1. JWT payload 的 `role` 声明：所有请求的基础判断
2. 数据库 `user_account.user_role`：仅当接口标注 `@RequireRole(dbCheck = true)` 时查库复核

dbCheck 的用途是降权即时生效：管理员被降级为 USER 后，已经签发的 token 里的 role 还是 ADMIN，但管理接口每次查库会发现角色变了，立即拒绝。目前只有 ADMIN 接口（AdminController 全部端点、支付 mock-success）开了 dbCheck。

## 鉴权链路与 token 生命周期

### 鉴权链路

没有 Spring Security，没有切面。全部逻辑在 `TokenValidator` 这个 HandlerInterceptor 里，由 `AuthWebConfig` 注册到 `/**`。

每个请求：

1. 路径在白名单则放行：`/auth/login`、`/auth/register`、`/doc.html`、`/v3/api-docs/**`、`/webjars/**`、`/swagger-resources/**`、`/test/generate-token`、`/user/protocol`。后两个路径在代码里没有对应端点，是遗留排除项
2. 请求头必须 `Authorization: Bearer <token>`，缺失或格式错误返回 TOKEN_INVALID
3. JWT 验签（HS256，`token.privateKey`），失败返回 TOKEN_INVALID
4. 读取类和方法上的 `@RequireRole`（方法级覆盖类级），角色不满足返回 FORBIDDEN
5. dbCheck 为 true 时查库复核角色，不通过返回 FORBIDDEN
6. 通过后把 userId、role、issuedAt 放进 ThreadLocal，`afterCompletion` 清理

认证信息不存 Redis、不存 session，没有 token 黑名单。登出只在前端清 localStorage，token 本身到 oldToken 阈值才失效。

### token 生命周期

双阈值机制，JWT 里没有 exp 声明，靠 `issuedAt` 计算年龄：

| 年龄 | 行为 |
|---|---|
| < youngToken（默认 1000000ms ≈ 16.7 分钟） | 正常通过 |
| youngToken ≤ 年龄 < oldToken（默认 3000000000ms ≈ 34.7 天） | 通过，响应头 `Authorization` 回写新 token，前端拦截器自动替换 |
| ≥ oldToken | TOKEN_EXPIRED |

前端只负责两件事：localStorage 存 token（key `bf_token`），响应头带 `Authorization: Bearer` 前缀时自动替换本地 token。旧 token 无黑名单，过期前一直有效。

## 管理操作的权限约束

权限校验有两层，管理接口都带 dbCheck：

| 操作 | 约束 |
|---|---|
| 修改/删除用户 | ADMIN 不可改、删其他 ADMIN；可以改自己 |
| 删除用户（ADMIN） | 一律禁止 |
| 用户自助销户 | ADMIN 账号不能自助删除 |
| 修改系统配置 | 仅 ADMIN，且有业务校验（时间约束、变更窗口），见 [[模块/管理端/管理功能|管理功能]] |
| mock 支付成功 | 仅 ADMIN |

## 权限边界

- 前端路由守卫只检查"有没有 token"，不检查角色。管理员 tab 靠 JWT 的 role 声明渲染，未登录的 ADMIN token 过期后前端会误显示管理入口，点击接口调用才被 403 拦截，前端没有统一的 403 提示
- 密码 MD5 大写存储，无盐。数据库泄露后密码可离线破解
- token 无黑名单：销户后已签发的 token 在 oldToken 阈值内仍然有效。用户自助销户后前端会清 token，但被管理员删除的用户手里的 token 仍可用到过期
- 白名单里的 `/test/generate-token`、`/user/protocol` 对应端点不存在，属于死配置
- 若未来接真实微信支付，回调接口必须加在鉴权白名单（微信服务器无 token），验签改由微信侧机制承担
