# 前端架构

本文说明前端的技术栈、目录结构、路由、状态管理和 HTTP 层。

本文不讨论每个页面的交互细节，见 [[前端/页面与流程|页面与流程]]。不讨论接口定义，见 [[接口/接口总览|接口总览]]。

源码范围：`src/` 全部、`vite.config.ts`、`package.json`。

## 技术栈

Vue 3.5（Composition API + script setup）、TypeScript 5.9（strict）、Vite 7、Naive UI 2.43、Pinia 3、Vue Router 4、axios、Tailwind CSS 4。

没有 ESLint、没有测试框架、没有 WebSocket 依赖。

构建目标没显式配置，即 Vite 7 默认（baseline-widely-available，现代浏览器）。样式做了移动端适配（min-width 320px + 断点布局），这是"校园项目学生用手机抢票"的考虑。

## 目录与路由

| 路径 | 内容 |
|---|---|
| `api/` | 8 个 API 模块 + http.ts 拦截器。booking.ts 是遗留 stub，无页面引用 |
| `components/` | MessageBridge（错误提示桥）、AppEmptyState（空状态）、user/ 5 个面板、admin/ 3 个面板 |
| `router/index.ts` | 路由与守卫 |
| `stores/` | auth.ts（token 和角色）、booking.ts（遗留 stub） |
| `types/api.ts` | 全部接口类型和枚举，与后端 DTO 对应 |
| `utils/` | authToken（localStorage 与 JWT 解析）、message（提示桥）、query（查询参数）、theme（主题） |
| `views/` | AuthView（登录注册）、DashboardView（单页控制台） |

路由只有两条：

| 路径 | 组件 | 说明 |
|---|---|---|
| /auth | AuthView | 已登录访问会重定向到 / |
| / | DashboardView | 未登录重定向到 /auth |
| 其他 | — | 重定向到 / |

守卫不校验角色。管理员功能不是独立路由，是 DashboardView 内部的 tab（`admin-config`、`admin-session`、`admin-user`），靠 `authStore.isAdmin` 决定菜单是否渲染。这意味着前端只有登录墙，没有角色墙。

## 状态管理与 HTTP 层

Pinia 只有 auth store 在用：

- `token`：来自 localStorage `bf_token`
- `role`：来自 JWT payload 的 role 声明（base64 解码，前端不做签名校验）
- `isAuthenticated`：token 非空
- `isAdmin`：role === 'ADMIN'
- `syncRole`：进入 Dashboard 后调 `/user/me` 拿服务端角色覆盖本地（服务端是权威）

用户信息不持久化，每次进 Dashboard 拉一次。主题存 localStorage `bf_theme_mode`，浅色主色 #0a7f6f，深色 #22c55e。

### HTTP 拦截器

axios 实例 baseURL 取 `VITE_API_BASE_URL`（生产用），空则走相对路径由 Vite 代理转发。timeout 15000ms。

请求拦截器：有 token 就加 `Authorization: Bearer`。

响应拦截器：

1. 响应头带 `Authorization: Bearer ...` → 替换本地 token（续期）
2. `code !== 200` → 弹错（3 秒），TOKEN_EXPIRED/TOKEN_INVALID 额外清 token，抛 ApiError
3. `code === 200` → 直接返回 data

注意两个事实：HTTP 401 状态码没有专门分支，判断靠响应体 enumCode；清 token 后不立即跳登录，下次导航时守卫生效。

错误提示的桥接：axios 拦截器在组件外，不能直接 useMessage，MessageBridge.vue 挂载时把 message 实例注册到 utils/message.ts，卸载时注销。

### 轮询与实时

没有 WebSocket。唯一的轮询在 SlotReservePanel：点"自动轮询结果"后每 1200ms 查一次 `GET /reserve/result/{traceId}`，非 PENDING 即停，组件卸载也停。

支付状态没有轮询，用户手动点"查看支付状态"。

## 已知边界

- 前端 README 写端口 50096，实际 vite.config.ts 是 10096，README 过时
- 角色判断靠 JWT role 声明，且前端不验签：改 localStorage 里的 payload 就能看到管理 tab（但接口有 dbCheck 兜底，数据动不了）
- 403 没有统一处理：权限不足时只弹通用错误消息，不引导重新登录
- booking.ts、stores/booking.ts、types/booking.ts 三个遗留 stub 可以删
- 无 ESLint/Prettier，代码风格靠提交前的"格式化"手工维持
