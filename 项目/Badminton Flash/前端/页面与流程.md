# 页面与流程

本文说明前端每个面板做什么、调用哪些接口、状态怎么展示。

本文不讨论前端技术细节，见 [[前端/前端架构|前端架构]]。接口参数细节见 [[接口/接口总览|接口总览]]。

源码范围：`views/`、`components/user/`、`components/admin/`、`api/`。

## 页面结构

整个应用只有两个页面视图，业务功能都是 DashboardView 里的 tab：

```
AuthView（/auth）
  ├── 登录 tab
  └── 注册 tab

DashboardView（/）
  ├── 用户 tab：场次浏览 / 球场浏览 / 时间槽预约 / 我的订单 / 账户设置
  └── 管理 tab（isAdmin）：系统配置 / 场次管理 / 用户管理
```

桌面端左侧 n-menu，移动端顶部 n-select 和按钮胶囊。主色浅色 #0a7f6f、深色 #22c55e。

## 抢票流程（前端视角）

1. 场次浏览（SessionBrowser）：8 个筛选条件查场次列表，每行可单独刷新开闸状态（GET /browse/open/{id}），点"去预约"把 sessionId 带给时间槽面板
2. 时间槽预约（SlotReservePanel）：sessionId 必填（可来自上一步），筛选后列表每行一个"预约"按钮
3. 提交：POST /reserve 返回 traceId，进入"预约结果"卡片
4. 结果展示：n-alert 按 ReserveResultVO.status 映射——PENDING 警告"预约处理中"、SUCCESS 成功"预约成功，订单号：{reservationId}"、FAILED 错误"预约失败，请更换时间槽重试"。可手动刷新或 1200ms 自动轮询

提交预约只提示"预约请求已提交"，真实结果必须靠轮询。这是同步只回 traceId 的架构决定的，见 [[总体设计/预约内核|预约内核]]。

## 订单、支付与管理面板

### 我的订单（ReservationPanel）

条件筛选（sessionId、slotId、状态多选、日期区间）查本人订单。按钮按状态渲染：

| 订单状态 | 可用操作 | 接口 |
|---|---|---|
| PENDING_PAYMENT | 取消订单、立即支付 | DELETE /reserve/{id}、POST /pay/wechat/{id} |
| CONFIRMED | 申请退款 | POST /pay/refund/{id} |
| 任意 | 查看支付状态 | GET /pay/reservation/{id} |

管理员额外看到"手动标记支付成功"工具（POST /pay/wechat/mock-success/{outTradeNo}）。

支付凭据展示在"最近一次支付创建结果"卡片（outTradeNo、prepayId、paySign 等），支付状态展示在"最近一次支付状态"卡片。注意：没有任何拉起微信支付的实现，凭据只是展示。这是待改造项。

### 管理面板

| 面板 | 功能 |
|---|---|
| SystemConfigPanel | 6 个配置项的展示、批量保存、单项改（text/plain） |
| SessionAdminPanel | 场次增删改 + 行内动作：预热、开闸、生成时间槽 |
| UserAdminPanel | 用户列表、详情、创建（选角色）、改、删 |

场次管理的三个行内动作对应定时任务的三个手动入口，开发联调时常用：建场次 → 预热 → 开闸，跳过等定时任务。

## 状态展示与账户

### 状态展示约定

- 加载：所有列表/按钮用 loading ref，try/finally 复位
- 空态：统一 AppEmptyState 组件，标题 + 描述 + 提示
- 错误：全局 message.error（3 秒，悬停保持），参数校验用 message.warning，成功用 message.success
- 订单状态 n-tag：PENDING_PAYMENT 警告色、CONFIRMED 成功色、CANCELLED 错误色、PENDING 默认色
- 危险操作确认：只有自助销户有 dialog.warning 确认。删场次、删用户没有确认弹窗

### 账户设置（ProfilePanel）

展示当前信息（id、学号、角色、状态），改学号/改密码（改密码要填旧密码），销户（确认后退出登录回 /auth）。

### 已知边界

- 删除场次、删除用户无确认弹窗，误点即生效
- 支付无拉起、无倒计时、无过期提示：用户看到 PAYING 但不知道 15 分钟超时，超时后要手动刷新订单页才知道被取消
- 抢票结果轮询没有超时上限（手动模式下会一直轮询下去，自动模式也不设次数上限，与 k6 脚本的 20 次不同）
- 抢票失败（FAILED）提示"更换时间槽重试"，但 UNGATED/DUP_REQ 等业务错误码前端不做区分，都归为失败提示
