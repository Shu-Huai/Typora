# 后端分层

本文说明后端的分层约定、各层职责、公共组件。

本文不讨论业务逻辑，见各模块文档。包结构总览见 [[总体实现/实现总览|实现总览]]。

源码范围：`src/main/java/shuhuai/keypulsebackend` 全部包。

## 分层约定

Controller → Service（接口 + serviceimpl 实现）→ Mapper（MyBatis-Plus 注解 SQL）。没有 Repository 层、没有 XML。

- Controller 只做参数接收、Principal 提取、返回包装
- Service 接口与实现一一对应，业务校验在 Service（OtpEntry 的 validate 在 Service 层而非 Bean Validation）
- DTO 分两层：Request（控制器入参，带校验注解）→ Command（服务层入参，附 RequestMetadata：IP、User-Agent）
- 异常统一抛 BusinessException（携带 ResponseCode），GlobalExceptionHandler 转 ApiResponse
- 实体直接出 Controller 的情况少，多数走 VO（CurrentUser、OtpEntryVO 等，隐藏内部字段）

## Controller 与 Service

### Controller

| 控制器 | 端点 |
|---|---|
| AuthController | register / login / refresh / me / change-password / logout |
| OtpEntryController | CRUD + counter + pin，全部从 Principal 里的 AccessTokenPayload 取 userId |

### Service

| 服务 | 核心方法 | 要点 |
|---|---|---|
| AccountServiceImpl | register / login / getById / changePassword | 注册建账号；登录限流+审计；改密是多表事务核心 |
| SessionServiceImpl | issue / rotate / revoke / refresh / logout | refresh token 全生命周期 |
| OtpEntryServiceImpl | list / get / create / update / delete / updateCounter / updatePinned | 越权防护 + validate |
| AuditLogServiceImpl | 8 个 recordXxx 方法 | 快照无敏感值 |
| SecurityRateLimitServiceImpl | allow(key, limit, window) | Redis + 进程内回退 |

## 安全、数据与公共组件

### 安全组件

| 类 | 作用 |
|---|---|
| SecurityConfiguration | SecurityFilterChain、BCrypt、JwtService、JwtAuthenticationFilter、CORS，5 个 Bean |
| JwtService | HS256 签发/解析，claims：sub、tokenVersion、iat、exp |
| JwtAuthenticationFilter | OncePerRequestFilter，验签后构造 principal，authorities 为空列表 |
| AccessTokenPayload | principal 的 payload 载体 |

Spring Security 6 只做基础设施（过滤链、401/403 JSON 输出、CORS），业务鉴权逻辑全在 JwtAuthenticationFilter 里，没有 UserDetailsService，没有角色。

### 数据层

MyBatis-Plus 3.5.17，注解 SQL（@Select/@Update/@Insert/@Delete），无 XML：

- UserMapper.findByEmail
- OtpEntryMapper 六个带 user 隔离的方法 + updateCounter（SQL 内限 HOTP）+ updatePinned
- RefreshTokenMapper.deleteByUserId / findByTokenHash
- PasswordOtpEntryMapper.updateCiphertextForUser（改密重加密专用）

MybatisConfiguration 带 @ConditionalOnBean(SqlSessionFactory.class)，是测试环境排除 DataSource 后的兼容产物。

### 公共组件

| 类 | 作用 |
|---|---|
| ApiResponse | 统一返回 record：code + enumCode + message + data |
| ResponseCode | 9 个错误码枚举，code 即 HTTP 状态码 |
| GlobalExceptionHandler | 参数校验 400、BusinessException 透传、兜底 500 |
| RequestLoggingFilter | X-Request-Id 透传/生成，请求日志（方法/路径/耗时/IP/UA） |
| SensitiveDataSanitizer | 正则脱敏 password/secret/token 等关键值 |

## 日志约定与已知边界

### 日志约定

- 请求日志：RequestLoggingFilter 每条请求一行，UA 经脱敏
- 审计日志：AuditLogService 写库（audit_logs），是安全事件的历史，不是排查日志
- 业务日志：无额外约定，默认 logback 控制台输出
- 没有日志文件轮转、没有日志级别动态调整配置

### 已知边界

- AccountServiceImpl 5 个构造函数、SessionServiceImpl 2 个，部分依赖允许 null（迁移期防御写法，新增代码不要学）
- AuditLogServiceImpl.recordOtp 的 targetType 先设 "USER" 再覆盖 "OTP_ENTRY"，冗余赋值
- GlobalExceptionHandler 不返回泛化异常的细节，排查问题只能靠日志
- 无分页插件、无拦截器（除 OncePerRequestFilter）、无 @Async
