# 需求与范围

本文说明项目要解决什么问题、核心约束、使用场景和功能边界。

本文不讨论实现细节，见 [[总体设计/系统架构|系统架构]] 和各模块文档。

需求来源：后端 `docs/requirements/keypulse-product-requirements.md`（产品需求）、后端 `docs/design/keypulse-backend-design.md`（后端设计）、前端 `docs/`（PRD、前端设计、UI 规范）、两个仓库的 README 和源码行为。本文以源码为准。

## 项目目标与用户角色

### 项目目标

给个人一个自己掌控的 OTP 验证码管理器。用户把各种网站的两步验证配置收进一个带密码保护的密码库，随时查看动态验证码，在手机、电脑、桌面端之间同步（通过后端存储密文）。

两条贯穿所有决策的约束：

1. 零知识：后端不接触 secret 明文，不生成不校验验证码。后端泄露数据库也拿不到任何可用的 OTP 密钥
2. 自己掌控：secret 加密密钥从用户主密码派生，改密即全库重加密；登出、改密都会清掉本设备的解锁状态

### 用户角色

单角色个人系统。一个账号对应一个密码库，没有共享、没有管理员、没有团队。

账号：邮箱 + 密码（8~128 位）。`emailVerified` 字段已预留但 V1 恒为 false，没有邮件验证流程。

## 核心场景

### 首次使用

1. 注册（邮箱、昵称、密码）
2. 登录后进入 OTP 列表（空态）
3. 添加第一条配置：手动填表单，或粘贴 `otpauth://` URI，或上传/扫描二维码
4. 保存时前端用主密码派生的密钥加密 secret，密文提交后端

### 日常使用

- 打开应用，列表展示所有配置，每 1 秒本地重算全部验证码
- 点验证码复制到剪贴板
- TOTP 显示 30 秒倒计时；HOTP 显示当前 counter，用完点"生成下一次"递增并同步后端
- 搜索（issuer + accountName 模糊匹配）、置顶常用配置

### 会话与安全事件

- 登录：access token + refresh Cookie；15 分钟后 access 过期，自动用 Cookie 换新（只重放一次请求）
- 换设备登录：旧设备的 refresh token 不受影响（各自独立），改密才会全设备失效
- 登出：撤销当前设备会话，本机清除 vault 解锁状态
- 改密：前端把所有条目用新密钥重加密，连同新密码提交；后端改哈希、tokenVersion+1、删全部 refresh token

### 多端

同一套前端代码构建为四种形态：Web（HTTPS 或 localhost）、Electron 桌面、Android WebView 壳、鸿蒙 ArkWeb 壳。原生壳提供摄像头扫描和剪贴板图片粘贴能力。

## 功能范围与明确不做

### 功能范围

已实现：

- 认证：注册、登录、当前用户、登出、改密、refresh 轮换
- OTP：配置 CRUD、搜索、置顶、HOTP counter 更新、TOTP/HOTP 本地计算
- 导入：手动表单、otpauth:// URI 解析、二维码（文件/剪贴板/摄像头）
- 密码库：PBKDF2 + AES-GCM vault、IndexedDB 设备恢复、改密全量重加密
- 安全：BCrypt 密码、审计日志、登录/刷新限流、请求日志脱敏
- 多端壳：Electron、Android、鸿蒙

### 明确不做（当前版本）

- 邮件验证、找回密码、删除账号（后端无对应接口）
- 多设备会话管理界面（看不到其他设备，只能改密全踢）
- OTP 分享、导入导出文件
- 生物识别解锁（指纹/面容）
- WebAuthn/Passkey
- 备份码、恢复码
- 桌面端自动填充、浏览器插件
- 消息推送、异常登录提醒

## 非功能要求与数据保留

### 非功能要求（事实，非目标）

- 零知识：数据库泄露不含任何明文 secret（见 [[总体设计/安全模型|安全模型]]）
- 审计：8 类事件落库，快照不得含密码、secret、密文、验证码、token
- 限流：登录 10 次/分钟、刷新 30 次/分钟，Redis 不可用时回退进程内
- 越权防护：所有 OTP SQL 强制带 user_id 条件
- 测试：后端 17 个测试类、前端 12 个 vitest 文件（契约、迁移、加密、会话轮换都有覆盖）

没有 SLA、监控告警、性能预算指标。个人应用的数据量（每用户几十条 OTP）下，性能不是当前关注点。

### 数据保留

- 业务数据在 MySQL 持久化，物理删除（无逻辑删除、无回收站）
- refresh token 只存 SHA-256 哈希，轮换即删旧记录
- 审计日志只增不删，没有归档或清理策略
- 前端 vault 材料在 IndexedDB（设备本地），登出/改密会清除
- access token 仅内存，不落盘
- Redis 限流计数 1 分钟 TTL，丢失无影响（回退进程内）
