# 实现总览

本文说明后端实际的服务结构、调用链、配置来源，以及实现与设计文档的差距。

本文不讨论业务细节，见各模块文档。包结构总览同样在 [[后端/后端分层|后端分层]]。

源码范围：`src/main/java/shuhuai/keypulsebackend` 全部包。

## 包结构与调用链

| 包 | 内容 |
|---|---|
| `controller/` | AuthController、OtpEntryController 两个控制器 |
| `service/` + `serviceimpl/` | Account、Session、OtpEntry、AuditLog、SecurityRateLimit 五个服务 |
| `mapper/` | 5 个 Mapper（含 PasswordOtpEntryMapper，专用于改密重加密） |
| `entity/` | User、OtpEntry、RefreshToken、AuditLog 四个实体 |
| `model/dto` + `model/vo` | 命令/请求对象与响应对象（Command 是服务层入参，Request 是控制器入参） |
| `security/` | JwtService、JwtAuthenticationFilter、AccessTokenPayload |
| `common/` | ApiResponse、BusinessException、GlobalExceptionHandler |
| `config/` | SecurityConfiguration、MybatisConfiguration |
| `log/` | RequestLoggingFilter、SensitiveDataSanitizer |
| `constant/` | ResponseCode |

主调用链：

```
登录：AuthController.login → AccountServiceImpl.login（限流→BCrypt→签发双token→审计）
      → SessionServiceImpl.issue（随机 token→哈希入库）
      → JwtService.createAccessToken（HS256，userId+tokenVersion）

查询 OTP：OtpEntryController.list → OtpEntryServiceImpl.list
      → OtpEntryMapper.findByUserId（SQL 内 AND user_id=#{userId}）

改密：AuthController.changePassword → AccountServiceImpl.changePassword（@Transactional）
      → 旧密码校验 → PasswordOtpEntryMapper.updateCiphertextForUser 逐条
      → BCrypt 更新 + tokenVersion+1 → refreshTokenMapper.deleteByUserId → 审计
```

DTO 分两层：控制器接收 Request（带校验注解），服务层用 Command（附加 RequestMetadata 含 IP 和 UA）。

## 配置来源

- `application.properties`：应用名 + `spring.profiles.active=local`
- `application-local.properties`：本地实配（被 .gitignore 排除，仓库只有 `.example`）——端口 17897、MySQL、Redis、jwt-secret、CORS、token TTL
- Flyway：`db/migration/V1__create_core_tables.sql` 唯一迁移
- 自定义配置项：`keypulse.security.jwt-secret`、`keypulse.cors.allowed-origins`、`keypulse.security.access-token-ttl`、`keypulse.security.refresh-token-ttl`（有 spring-configuration-metadata.json）

没有环境变量注入、没有 Jasypt。密钥管理靠 gitignore + example 文件。

## 设计差距与运行时依赖

### 与设计文档的差距

后端 `docs/design/keypulse-backend-design.md` 是较完整的设计文档，与源码有几处实质出入：

| 设计文档声称 | 源码事实 |
|---|---|
| 每次鉴权校验 token version（6.5 节） | JwtAuthenticationFilter 只验签，不查库比对 tokenVersion |
| 响应码含 TOKEN_INVALID、DB_ERROR | ResponseCode 枚举里没有这两个 |
| Redis key：kp:login-fail:{email}:{ip}、kp:refresh-rate:{userId}:{ip} | 实际是 kp:rate:{email}:{ip}、kp:rate:refresh:{ip} |
| 三层日志含"操作日志"（注解/AOP） | 未实现，只有请求日志 + 审计日志 |

其余差距是重构遗留：AccountServiceImpl 有 5 个构造函数、SessionServiceImpl 有 2 个，部分依赖允许为 null 并带运行时 null 判断，是服务拆分合并期间的防御式写法。AuditLogServiceImpl.recordOtp 里 targetType 先设 "USER" 再覆盖为 "OTP_ENTRY"，冗余赋值。

### 运行时依赖

| 依赖 | 用途 | 故障影响 |
|---|---|---|
| MySQL | 全部持久化 | 系统不可用 |
| Redis | 仅限流计数 | 自动回退进程内限流，功能不受影响 |

Redis 是弱依赖，这是设计中明确要的：限流不是核心功能，不能用它卡死登录。

## 实现边界

- 无定时任务、无 @Async、无消息队列、无缓存（Redis 不缓存业务数据）
- 无角色体系：principal 的 authorities 是空列表，权限模型是占位
- 物理删除：OTP 删除即真删，无回收站
- 注册接口没有限流（登录和刷新有）
- 后端不校验验证码、不接触 secret 明文，这一约束在代码层面靠"没有相关代码"来保证，而不是靠校验拦截
- 测试 17 个类覆盖注册/登录/轮换/改密/隔离/限流/契约/迁移/脱敏，是三个项目中测试最完整的
