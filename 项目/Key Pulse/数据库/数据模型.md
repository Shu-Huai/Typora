# 数据模型

本文说明 4 张表的结构、约束、删除策略和 MySQL 与前端的事实边界。

本文不讨论业务语义，见 [[总体设计/系统架构|系统架构]] 和各模块文档。ORM 细节见 [[后端/后端分层|后端分层]]。

源码范围：`src/main/resources/db/migration/V1__create_core_tables.sql`、`entity/`。

## 表清单

![](Z:\Public\images\key-pulse-er-diagram.svg)

| 表 | 实体 | 业务意义 |
|---|---|---|
| users | User | 账号，email 唯一，tokenVersion 控制全设备失效 |
| otp_entries | OtpEntry | OTP 配置（密文 secret + 协议参数 + 元数据） |
| refresh_tokens | RefreshToken | 会话凭据，只存 SHA-256 哈希 |
| audit_logs | AuditLog | 安全审计事件，只增不删 |

所有表 InnoDB、utf8mb4、自增主键、物理删除（无逻辑删除）、无乐观锁、无自动填充。created_at/updated_at 由数据库 DEFAULT CURRENT_TIMESTAMP 维护。

## 表结构与约束

### users

email（唯一键 uk_users_email）、password_hash（BCrypt）、nickname、email_verified（V1 恒 0）、token_version（改密递增）、password_changed_at。

### otp_entries（核心表）

| 字段组 | 字段 | 说明 |
|---|---|---|
| 归属 | user_id | 外键 ON DELETE CASCADE，索引 idx_otp_entries_user_id |
| 标识 | issuer、account_name、label | 展示与搜索字段 |
| 协议 | otp_type、algorithm、digits、period、counter | TOTP/HOTP 参数，明文存储（非秘密） |
| 密文 | encrypted_secret | TEXT，AES-GCM 密文 |
| 加密元数据 | secret_salt、secret_iv、encryption_algorithm、kdf_algorithm、kdf_params | 解密所需全部上下文，全部 NOT NULL |
| 展示 | notes、pinned、sort_order | |

加密元数据与密文同等重要：丢任何一项都无法解密，所以 schema 里它们和 encrypted_secret 一样是 NOT NULL，Service 层 validate 也逐项检查非空。

### refresh_tokens

user_id（FK CASCADE）、token_hash（唯一键 uk_refresh_tokens_token_hash）、expires_at、last_used_at、ip_address、user_agent。

### audit_logs

user_id（FK ON DELETE SET NULL，删号后日志保留）、event_type、target_type、target_id、target_snapshot、ip_address、user_agent、success、created_at。复合索引 (user_id, created_at)。

## 删除策略与事实边界

### 约束与删除策略

- 外键：otp_entries 和 refresh_tokens 随用户 CASCADE 删除；audit_logs 用户置 NULL 保留日志
- 物理删除贯穿所有表：删 OTP 真删，无回收站；refresh token 轮换即删旧行
- otp_entries 的越权防护在 SQL 层：update/delete/select 全部带 `AND user_id = #{userId}`

### 与前端的事实边界

| 事实 | 所在 |
|---|---|
| secret 明文 | 只存在于前端内存（解密瞬间） |
| secret 密文 + 加密元数据 | 后端 otp_entries 表 |
| vault 密钥材料（wrappedKey/deviceKey） | 前端 IndexedDB（设备本地） |
| access token | 前端内存 |
| refresh token 原文 | 前端 Cookie；后端只存哈希 |
| 验证码 | 前端本地实时计算，永不过网络 |

一句话：后端是密文的保险柜，前端是唯一持有钥匙的保险箱主人。

## 已知边界

- 无逻辑删除，误删 OTP 无法恢复（前端有 ConfirmDialog 二次确认，是唯一防线）
- 审计日志只增不删无归档
- email_verified 字段存在但没有任何流程会置 1
- encrypted_secret 是 TEXT，单条上限 64KB，AES-GCM 密文加 base64 后远小于此，无实际风险
- 无分页：OTP 列表全量返回（个人数据量级，几十条，无压力）
