# 页面与流程

本文说明前端每个页面的职责、调用链、状态展示和关键交互。

本文不讨论技术实现，见 [[前端/前端架构|前端架构]]。加密流程见 [[模块/密码库/密码库与密钥|密码库]]。

源码范围：`src/views/`、`src/components/otp/`、`src/components/common/`。

## 页面结构

```
/login              登录
/register           注册
/otp                OTP 工作台（核心页，AppShell 布局）
/settings           账户设置
/settings/password  修改密码
```

## OTP 工作台（/otp）

核心页面，四块内容：

1. 搜索框：绑定 store.search，按 issuer + accountName 过滤
2. 配置列表（OtpCard）：issuer、accountName、验证码（等宽大字号）、TOTP 倒计时或 HOTP counter、备注、置顶徽章；操作：复制、置顶、编辑、删除、HOTP 递增
3. 编辑抽屉（OtpEntryDrawer）：三种输入模式 tab——手动 / URI（otpauth:// 解析）/ 二维码（文件上传、剪贴板、摄像头扫描）；编辑时先解密 secret 回填表单
4. 空态：无配置时引导添加第一条

1 秒轮询：onMounted 时 load() → refreshCodes()，之后 setInterval(1000ms) 更新 now 并重算全部验证码，onUnmounted 清除。纯本地计算，无网络请求。

保存流程：表单收集 → vaultStore.encrypt(secret) → POST/PUT 提交密文。secret 明文只在加密瞬间存在于内存。

## 登录注册与账户

### 登录（/login）

- 本地校验：邮箱含 @、密码 ≥ 8 位
- 非 HTTPS 环境（且非 localhost）显示警告横幅
- 提交：authStore.login → otpStore.load（拿第一条条目的 salt）→ vaultStore.unlockWithPassword → toast + 跳 /otp

登录的耗时主要在 PBKDF2 30 万次迭代，按钮进入"登录中…"状态。

### 注册（/register）

邮箱/昵称/密码表单，成功后 700ms 跳登录页。注册不触发 vault 初始化（vault 在首次登录时建立）。

### 账户设置（/settings）

展示昵称和邮箱；入口到修改密码页；退出登录：authStore.logout（调后端撤销会话）+ vaultStore.clear() → /login。

## 修改密码、状态与边界

### 修改密码（/settings/password）

三步编排：

1. otpStore.load 拉全量条目
2. vaultStore.reencryptEntries(newPassword, entries)：逐条旧密钥解密 → 新密钥加密
3. authStore.changePassword({oldPassword, newPassword, entries}) 提交
4. 成功后 vaultStore.clear() → /login（重新登录解锁）

任何一条解密失败会中断流程，用户留在页面看到错误。

### 状态展示约定

- 加载：store.loading 显示"正在加载配置…"；表单提交按钮 disabled + 文案切换（登录中…/提交中…）
- 错误：列表页红色告警条（role=alert）+ toast；表单字段级错误（AppInput error prop）+ 页面级红字；验证码计算失败弹 toast 并清该条缓存
- 空态：OtpListView 空态引导
- toast：notificationStore 四类型（success/error/info/warning），3 秒自动消失（error 4 秒）
- 危险操作：删除 OTP 有 ConfirmDialog 二次确认；登出无确认

### 已知边界

- 无键盘快捷键（复制验证码要点按钮）
- 验证码复制失败只提示手动复制，无自动重试
- 摄像头扫描在 Web 端需要 HTTPS 或 localhost，否则降级手动输入
- 修改密码表单没有"确认新密码"字段
- 列表无排序调整（只有置顶），sortOrder 字段后端有但前端不暴露
