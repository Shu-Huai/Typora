# 前端架构

本文说明前端的技术栈、目录结构、路由、状态管理和请求层。

本文不讨论页面交互细节，见 [[前端/页面与流程|页面与流程]]。接口定义见 [[接口/接口总览|接口总览]]。

源码范围：`src/` 全部、`vite.config.ts`、`package.json`、`electron/`。

## 技术栈

Vue 3.5（Composition API + script setup）、TypeScript 6、Vite 8、Tailwind CSS 4（自研语义 class 设计系统，无第三方组件库）、Pinia 3、vue-router 5、原生 fetch 封装、Web Crypto API（PBKDF2/HMAC/AES-GCM）、@zxing/browser（二维码）、Vitest 4。

特点：没有 axios、没有 UI 组件库、没有图表库。依赖极简，加密和验证码算法都是本地实现（RFC 4226/6238），不依赖第三方 OTP 库。

## 目录与路由

| 路径 | 内容 |
|---|---|
| `views/` | LoginView、RegisterView、OtpListView（核心工作台）、SettingsView、PasswordSettingsView |
| `stores/` | auth、vault、otpEntry、theme、notification 五个 store |
| `services/api/` | apiClient（fetch 封装）、authApi、otpEntryApi |
| `modules/crypto/` | vaultCrypto（PBKDF2+AES-GCM）、vaultStorage（IndexedDB） |
| `modules/otp/` | totp.ts、hotp.ts、base32.ts、otpUriParser.ts |
| `components/` | common（AppButton/AppInput/AppSelect/ConfirmDialog 等）、otp（OtpCard、OtpEntryDrawer） |
| `platform/` | nativeBridge.ts（原生壳桥接） |
| `app/` | AppShell（顶栏布局） |

路由表（全部静态 import，无懒加载）：

| 路径 | 组件 | 公开 |
|---|---|---|
| / | redirect → /otp | — |
| /login、/register | LoginView、RegisterView | 是 |
| /otp、/settings、/settings/password | 三个业务页 | 否 |

守卫在 main.ts 的 beforeEach：先 `authStore.initialize()`（首次用 Cookie 换 token 并拉 /me），未认证跳 /login，已认证但 vault 未解锁则 `vaultStore.restore()`（IndexedDB 恢复），失败清 session 回登录页。已登录访问登录页会跳 /otp。

## 状态管理与持久化

| store | 关键状态 | 持久化 |
|---|---|---|
| auth | accessToken、currentUser、initialized | 仅内存，明确不落盘 |
| vault | vaultKey、deviceKey、saltValue、isUnlocked | IndexedDB `keypulse-vault`（包裹密钥） |
| otpEntry | entries、codes（验证码缓存）、search、loading、error | 无 |
| theme | mode（system/light/dark） | localStorage `keypulse.theme` |
| notification | toast 栈 | 无 |

vault 是安全核心：解锁时 PBKDF2（30 万次）派生 rawKey，随机 deviceKey 包裹后存 IndexedDB；登出/改密清空。验证码缓存（codes）按条目 id 存计算结果的字符串，页面卸载不清，内存级。

## 请求层与多端构建

fetch 封装（apiClient.ts）：

1. 有 token 加 `Authorization: Bearer`，始终 credentials: include
2. 401 且允许 refresh 时调 refreshClient（不带 token）换新 access，重放原请求一次
3. refresh 失败调 onAuthenticationLost（清 session）
4. 非 2xx 抛 Error(body.message)，成功返回 body.data

authStore 创建两个 client：主 client（带 refresh 回调）和 refreshClient（getAccessToken 返回 null，防止 refresh 请求自带过期 token）。

### 构建与多端

- vite.config.ts 按 mode 分支：electron-/harmony/android 模式 base `./` + hash 路由
- 原生容器模式通过 vite-plugin-electron 构建 Electron 主进程和 preload
- Android/鸿蒙由 sync 脚本把 dist 拷入壳工程并内联 JS/CSS（ArkWeb rawfile 的 origin 限制）
- 原生桥接：window.keypulseNative（摄像头）、CustomEvent（剪贴板图片、系统深色），Web 端自动降级

### 已知边界

- 无懒加载：所有路由组件静态 import，单包
- IconButton 组件零引用，是遗留
- otpEntryApi.get 未被 UI 使用，仅接口层存在
- Electron preload 的 electronAPI 未被 Web 代码引用
- 前端不校验 JWT 签名
- 验证码每 1 秒全量重算所有条目：条目数百条时每秒 HMAC 计算量可观，当前数据量无感
- 浏览器兼容：依赖 Web Crypto、IndexedDB、clipboard API，现代浏览器；无 browserslist 配置
