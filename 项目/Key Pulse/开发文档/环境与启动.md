# 环境与启动

本文说明新开发者如何从零把前后端跑起来：环境要求、启动顺序、联调步骤、常见错误。

本文不讨论配置项含义与生产部署，见 [[开发文档/构建与部署|构建与部署]]。

源码范围：后端 `pom.xml`、`application-local.properties.example`；前端 `package.json`、`.env.development`、`vite.config.ts`。

## 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 23 | pom 里 java.version=23 |
| Maven | 3.9+（仓库自带 mvnw wrapper 3.9.16） | |
| MySQL | 8.x | 连接串 createDatabaseIfNotExist 自动建库 |
| Redis | 6.x（可选） | 缺了会自动回退进程内限流 |
| Node.js | 20+ | 前端 |
| Android 构建 | SDK 36 + JDK 17 | 仅构建 Android 壳时需要 |
| 鸿蒙构建 | DevEco Studio + HarmonyOS SDK | 仅构建鸿蒙壳时需要 |

## 启动顺序与后端启动

顺序：MySQL → （Redis，可选）→ 后端（17897）→ 前端（17898）。

```bash
# 后端
cp src/main/resources/application-local.properties.example src/main/resources/application-local.properties
# 改数据源、Redis、jwt-secret、CORS
./mvnw spring-boot:run
```

Flyway 启动时自动执行 V1 建表。库名 `keypulse` 自动创建。

```bash
# 前端
npm install
npm run dev   # 端口 17898
```

前端无 Vite 代理，`.env.development` 直连 `http://localhost:17897/api`。跨域靠后端 CORS（默认 `*` + credentials）。

## 本地联调

1. `POST /api/auth/register` 注册（或走前端注册页）
2. 登录页登录，观察浏览器 Cookie 里的 `KP_REFRESH`
3. 添加 OTP：粘贴任意 `otpauth://totp/Example:user@example.com?secret=JBSWY3DPEHPK3PXP&issuer=Example`（RFC 文档标准测试向量）
4. 列表页 1 秒刷新验证码，对照手机 Authenticator 应用确认一致
5. 改密流程：改完登录确认其他设备（另开浏览器）会话已失效

curl 示例见 [[接口/接口总览|接口总览]]。

## 常见启动错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 数据库连接失败 | 连接串/账号/密码错 | 检查 application-local.properties |
| Flyway 报错 | 迁移文件被改或数据库有脏数据 | 检查 flyway_schema_history，必要时 repair |
| Redis 连接失败但能用 | Redis 是可选依赖 | 忽略即可，限流走进程内 |
| 前端所有请求 401 | refresh Cookie 没带上 | 确认同源/同 host（Cookie SameSite 限制），本地用 localhost 或 127.0.0.1 访问 |
| 前端登录后跳回登录页 | vault restore 失败（IndexedDB 数据损坏或浏览器隐私模式） | 清站点数据重试 |
| 验证码计算失败 | 密文与本地密钥不匹配（改密后旧设备/数据被改） | 重新登录解锁 |
| 摄像头无法调用 | 非 HTTPS 且非 localhost | 浏览器限制，用 localhost 或 HTTPS 部署 |
| 构建报 vue-tsc 错误 | 类型不通过 | 先 npm run build 的 typecheck 部分单独看错误 |
