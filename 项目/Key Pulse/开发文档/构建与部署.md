# 构建与部署

本文说明后端部署方式、前端四端构建流程、配置管理和测试。

本文不讨论本地启动，见 [[开发文档/环境与启动|环境与启动]]。

源码范围：后端 `pom.xml`、`.gitignore`；前端 `package.json`、`vite.config.ts`、`scripts/`、`electron/`、`android-app/`、`harmony-app/`。

## 后端部署

后端没有部署脚本（无 deploy 目录、无 Dockerfile）。当前的事实路径是：git 拉取 → `./mvnw clean package` → `java -jar target/*.jar`，本地 profile 配置由部署机上手工维护的 `application-local.properties` 提供。

发布注意：

- 真实配置被 .gitignore 排除，部署机上要单独放置
- jwt-secret 是 Base64 的 HS256 密钥，当前本地值是弱口令，部署前必须更换（换密钥后所有已签发 token 立即失效，用户需要重新登录）
- CORS 的 allowed-origins 要收窄为实际域名列表
- Flyway 迁移文件是库结构的唯一事实来源，改库先加新版本迁移（V2__...），不要改 V1

## 前端四端构建

| 目标 | 命令 | 产物 |
|---|---|---|
| Web | npm run build | dist/（typecheck + vite） |
| 本地预览 | npm run serve | 17898 端口静态服务 |
| Electron | npm run electron:build（win/mac/linux 变体） | release/（nsis/dmg/AppImage） |
| Android | npm run android:sync | dist → android-app assets + JS/CSS 内联 |
| 鸿蒙 | npm run harmony:sync | dist → harmony-app rawfile/www + JS/CSS 内联 |

模式差异：Web 用 history 路由 base `/`；Electron/Android/鸿蒙用 hash 路由 base `./`。原生壳内联 JS/CSS 的原因：ArkWeb rawfile 以 resource:// 加载，外部模块脚本会被判为跨域子资源而拒绝。

Electron 主进程：480x720 窗口、禁用菜单、contextIsolation + sandbox。Android：minSdk 24 / targetSdk 36，WebViewAssetLoader。鸿蒙：ArkTS + ArkWeb。

生产 env 文件（.env.production / .env.harmony / .env.electron-production / .env.android）被 gitignore，部署时各自准备，只有 `VITE_API_BASE_URL` 一个变量。

## 数据库变更与测试

### 数据库变更

Flyway 管理，`db/migration/` 下 V 前缀版本脚本。当前只有 V1。变更流程：新增 V2__描述.sql（幂等、可重复执行由 Flyway 保证不重复）→ 本地跑迁移验证 → 提交。禁止修改已应用的旧版本文件，会破坏 checksum 校验。

测试环境（application-test.properties）排除了 DataSource/Flyway 自动配置，迁移本身的正确性靠 `CoreSchemaMigrationTests` 断言关键表/唯一键/索引存在。

### 测试

- 后端：`./mvnw test`，17 个测试类。分层：@WebMvcTest（控制器+Cookie 行为）、Mockito 单测（服务）、契约测试（统一 400 响应）、迁移测试、限流回退测试
- 前端：`npm test`（vitest run），12 个测试文件。覆盖：store 四个、apiClient、vaultCrypto、vaultStorage、TOTP/HOTP/base32 算法（含 RFC 测试向量）、otpUriParser、OtpCard/OtpEntryDrawer 组件、nativeBridge

前端算法测试里有 RFC 4226/6238 标准向量，是对验证码计算正确性的直接保障。

## 已知边界

- 后端无 CI、无自动发布流水线
- 前端无 Docker、无 nginx 配置，Web 部署方式未固化
- dist 构建产物在 harmony-app 的 rawfile 里有历史残留（favicon.svg 等旧文件），sync 脚本只增不删
- Electron preload 暴露的 electronAPI 在 Web 侧未被引用，是预留
- 测试 profile 与本地 profile 的差异（DataSource 排除）意味着"测试能过但启动能过"之间还有一层未被覆盖
