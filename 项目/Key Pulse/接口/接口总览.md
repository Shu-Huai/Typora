# 接口总览

本文列出全部 HTTP 端点、鉴权要求、Cookie 约定和错误码。

本文不讨论业务逻辑，见各模块文档。

源码范围：`controller/AuthController.java`、`controller/OtpEntryController.java`、`constant/ResponseCode.java`。

## 通用约定

- 统一返回 `ApiResponse<T>`：`{code, enumCode, message, data}`，code 即 HTTP 状态码语义
- 认证：`Authorization: Bearer <accessToken>`；refresh 靠 Cookie `KP_REFRESH`（HttpOnly，Path=/api/auth）
- 所有请求 JSON 入参；前端 fetch 带 credentials: include
- 错误码枚举名在 enumCode 字段里，前端按 code 和 message 处理

## 端点清单

### 公开端点

| 端点 | 说明 |
|---|---|
| POST /api/auth/register | RegisterRequest{email, nickname, password}，返回 RegisteredUser |
| POST /api/auth/login | LoginRequest{email, password}，返回 LoginResponse{accessToken} + Set-Cookie KP_REFRESH |
| POST /api/auth/refresh | 凭 Cookie 轮换，返回新 LoginResponse + 新 Cookie |
| POST /api/auth/logout | 凭 Cookie 撤销当前设备，清 Cookie |

### 需认证端点：账户

| 端点 | 说明 |
|---|---|
| GET /api/auth/me | CurrentUser{id, email, nickname, emailVerified} |
| POST /api/auth/change-password | ChangePasswordRequest{oldPassword, newPassword, entries: ReencryptedOtpEntry[]} |

change-password 的 entries 是前端重加密后的全量 OTP 密文集合，每条含新密文、salt、iv、加密算法、KDF 算法和参数。服务层逐条带 user 隔离更新。

### 需认证端点：OTP 配置（/api/otp-entries）

| 端点 | 说明 |
|---|---|
| GET /api/otp-entries?keyword= | 列表，issuer/accountName 模糊搜索，排序 pinned DESC + issuer + accountName + id |
| GET /api/otp-entries/{id} | 单条（前端 UI 目前未调用） |
| POST /api/otp-entries | OtpEntryRequest 16 字段，见下 |
| PUT /api/otp-entries/{id} | 全量更新 |
| DELETE /api/otp-entries/{id} | 物理删除 |
| PATCH /api/otp-entries/{id}/counter | CounterRequest{counter}，仅 HOTP 生效 |
| PATCH /api/otp-entries/{id}/pin | PinRequest{pinned} |

OtpEntryRequest 字段：issuer、accountName、label、otpType（TOTP/HOTP）、algorithm（SHA1/SHA256/SHA512）、digits（6/8）、period、counter、encryptedSecret、secretSalt、secretIv、encryptionAlgorithm、kdfAlgorithm、kdfParams、notes、pinned、sortOrder。

## Cookie 约定

| 属性 | 值 | 条件 |
|---|---|---|
| HttpOnly | true | 恒 |
| Secure | true | 请求是 HTTPS 或 X-Forwarded-Proto=https |
| SameSite | None / Lax | HTTPS 时 None，HTTP 时 Lax |
| Path | /api/auth | 恒 |
| maxAge | 180 天 | 登出时置 0 |

前端不读 Cookie（HttpOnly），refresh 请求靠浏览器自动携带。

## 错误码

| enumCode | code | 场景 |
|---|---|---|
| SUCCESS | 200 | 成功 |
| PARAM_ERROR | 400 | 参数校验失败 |
| UNAUTHORIZED | 401 | 未认证 / token 无效 |
| USERNAME_OR_PASSWORD_ERROR | 401 | 密码错误 |
| FORBIDDEN | 403 | 权限不足（当前无角色体系，预留） |
| NOT_FOUND | 404 | 资源不存在 |
| EMAIL_EXISTED | 409 | 邮箱已注册 |
| TOO_MANY_REQUESTS | 429 | 限流 |
| ERROR | 500 | 服务器内部错误 |

Spring Security 的 401/403 也以同样 JSON 结构写出（entry point 配置），所以前端拿到的错误格式始终一致。

### 前端请求约定

- 401 自动触发一次 refresh 并重放原请求，refresh 也失败则清 session 回登录页
- 后端 message 直接作为前端错误提示展示
- 前端不校验 JWT 签名，按后端响应为准
