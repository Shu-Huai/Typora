# 前端架构

本文说明前端的技术栈、目录结构、路由、状态管理和请求层。

本文不讨论页面交互细节，见 [[前端/页面与流程|页面与流程]]。接口定义见 [[接口/接口总览|接口总览]]。

源码范围：`src/` 全部、`vite.config.ts`、`package.json`。

## 技术栈

Vue 3.2（script setup）、TypeScript 4.5、Vite 4.2、Naive UI 2.26、Pinia 2、vue-router 4、axios 0.26、ECharts 5、WindiCSS + Sass、vuejs-avataaars（球员头像）、keymaster（空格键快捷键）。

代码基底是 soybean-admin 模板 0.9.x，保留了模板的工程骨架（布局、主题、mock、两套 store），业务代码在其上生长。

## 状态与请求层

### 状态与持久化

业务 store（src/stores/store.ts，无 actions 无持久化）：

- playerData/perfData：球员列表和表现数据（BasicLayout 加载后全局共享）
- gamePveData：整场 PvE 比赛数据
- playerNameId/clubNameId：id→中文名缓存
- nextGame：下场比赛信息

localStorage（utils/storage.ts，key 前缀 VITE_STORAGE_PREFIX 未定义，实际 key 是裸的 token/saveId）：

- token：JWT
- saveId：当前存档 id

登录页"记住我"用 cookie 存明文用户名密码 7 天。

### 请求层

axios 实例（utils/request.ts）：

- baseURL = VITE_APP_INTERFACE_URL，超时 600 秒
- 请求拦截：加 Bearer token；自动附带 save_id（POST 走 params，GET 合并 params）
- 响应拦截：直接 resolve response.data（后端无包装）；401 按 detail 分支（密码错/凭证失效）；400 重复邮箱分支；404/500/502 提示
- 错误统一 window.$message + loadingBar

注意：save_id 由前端统一附带而不是后端从会话推导，意味着后端信任客户端传的存档 id——用户改 localStorage 就能操作别的存档（后端 verify_token 只验证 token，save 归属校验依赖 get_current_save 的实现深度）。

## 构建部署与已知边界

### 构建与部署

- 无代理、无 Docker、无 nginx；Vercel 构建切 hash 路由
- 队徽图床独立（VITE_TEAM_IMAGE_BASE_URL）
- 端口 19232

### 已知边界

- soybean 遗留代码量大：mock 模块、第二套 axios（service/）、旧登录组件（PwdLogin/CodeLogin）、两个 enum storage 体系，维护时要分清哪套是活的
- BasicLayout 硬编码 club_id=1 拉"我的球员"
- game-result 内嵌 620 行样例比赛数据（开发期假数据）
- 大量 catch 静默吞错误
- VITE_STORAGE_PREFIX 未定义，storage key 是裸 token/saveId，与加密版 storages/local.ts 的 key 体系并存
- 无测试、无 CI、无 lint 强制
