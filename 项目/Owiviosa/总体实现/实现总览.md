# 实现总览

本文说明后端实际结构、调用链、配置来源和实现边界。

本文不讨论业务细节，见各模块文档。包结构同样见 [[后端/后端分层|后端分层]]。

源码范围：后端根目录平铺包。

## 实际结构与调用链

后端是根目录平铺式结构（无 src 目录）：

```
main.py                FastAPI 入口（uvicorn :::8080）
core/                  config（Settings）/ db（engine/session）/ dburl（选 MySQL）
models/                14 个 SQLAlchemy 模型
schemas/               12 个 Pydantic 校验
crud/                  13 个 CRUD 封装
routers/api_v1/        10 个路由模块 + api_test/test.py
modules/               业务引擎：generate/game/transfer/next_turn/computed
game_configs/          枚举 + 配置 JSON + ML 模型加载
machine_learning/      两套 ML 子系统
utils/                 logger/date/dependencies/token_validator/translator
```

调用链三条主干：

```
认证：POST /api/v1/login → token_validator 签发 JWT → 后续请求 Bearer → verify_token 依赖

世界推进：GET /next-turn → BackgroundTasks(next_turner.check)
  → 比赛模拟 → 转会 AI → 日期推进

比赛：POST /game-pve/start → GET /game-pve/next-turn（×N 回合）
  → 每回合 game_pve 引擎 → script 解说 → 终场落 Game 表
```

## 配置来源

| 来源 | 内容 |
|---|---|
| env.json（example） | DB_URL 多数据库连接串（当前 mysql_db_url="MySQL"） |
| game_configs/data/*.json | 五大联赛、超级联赛、阵型、位置权重、能力/国家潜力、头像概率 |
| game_configs/token_config.py | JWT 密钥（硬编码在代码里） |
| assets/*.txt/.json | 人名表、国家名 |
| machine_learning/model/*.pkl | 5 个随机森林模型 |

环境变量没有约定俗成的注入方式（env.json 手工维护），JWT 密钥在代码文件里，不是环境变量。

## 运行时依赖与数据库管理

### 运行时依赖

| 依赖 | 用途 | 故障影响 |
|---|---|---|
| MySQL | 全部持久化 | 系统不可用 |
| 队徽图床（独立静态服务） | 前端加载队徽 | 只影响图片显示 |
| pygtrans（Google 翻译） | 球员名翻译 | 已标注"暂时没有用"，不参与主流程 |

无 Redis、无队列、无缓存。ML 模型进程内加载，启动时 5 个 .pkl 读入内存。

### 数据库管理

- 无 alembic：`Base.metadata.create_all` 在启动时建缺失的表
- db.py 手工建索引 player_id_idx（game_player_data.player_id）
- db.py 里保留被注释的加列语句（Player.values 的历史迁移痕迹）
- sqlalchemy-utils 提供 database_exists/create_database 自动建库

## 实现边界

- 无测试：比赛引擎、生成器、转会逻辑全靠手工验证
- 无迁移：表结构变更 = 手工 ALTER + 改 models
- 无异常处理框架：FastAPI 默认行为 + 路由内 try/except，错误格式不统一
- 无定时任务：一切推进靠玩家操作触发
- 无日志采集：loguru 按天文件轮转（300 天），仅本机可查
- requirements.txt 与 pyproject.toml 并存，版本不一致（FastAPI ~=0.95 vs >=0.116、Pydantic ~=1.10 vs >=2.11），实际环境以 venv 里装的为准
