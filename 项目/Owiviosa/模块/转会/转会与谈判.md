# 转会与谈判

本文说明转会系统的完整链路：挂牌、搜索、报价、薪资谈判、AI 转会和职员升级。

本文不讨论资金模型，见 [[总体设计/游戏世界|游戏世界]]。接口清单见 [[接口/接口总览|接口总览]]。

源码范围：`routers/api_v1/transfer.py`、`modules/transfer_app/club.py`（AI 转会 390 行）、`modules/transfer_app/player.py`（谈判 142 行）。

## 报价流程与 AI 转会

### 报价流程

玩家买人：

```
make-offer-by-user（报价）
  → 资金校验：不足 → 'can not afford'
  → 重复校验：已报价 → 'repeat offer'
  → 对方俱乐部决策：接受 / 拒绝（报价进 rejected 列表）
```

接受后进入薪资谈判（negotiate-wage）：

```
谈判成功率 = 90 - (想要工资 - 报价) / 想要工资 × 100
  → 成功：球员转会，资金转移、工资调整、user_finance 记录
  → 失败：可再谈，2 次失败 → 谈判破裂（nf）
```

### AI 转会

"下一天"时 AI 俱乐部之间也会行动（transfer_app/club.py）：

- AI 挂牌球员、评估转会目标、报价、谈判
- 玩家球员被 AI 报价 → incoming-offers 列表 → dealing-offers 成交/拒绝
- 成交后资金入账（user_finance "球员卖出"）

调试端点 /test/all-* 系列可以手动批量触发这些流程（开发用）。

## 职员升级与状态流转

### 职员升级

upgrade-crew（scout/doctor/assistant/negotiator 四种），升级消耗资金，等级影响对应玩法（如 negotiator 等级影响谈判成功率——具体数值在谈判代码里硬编码）。

### 状态流转

| 状态 | 含义 |
|---|---|
| on_sale=1 | 挂牌中 |
| （报价） | 待对方决策 |
| r | 被对方拒绝 |
| rr | 已处理（deal-rejected-offers 批量转换） |
| nf | 谈判失败（negotiate-failed 标记） |
| 成交 | 球员归属变更 + 资金转移 |

## 已知边界

- 报价/谈判接口用 GET 执行写操作：浏览器预取、刷新页面都可能误触发重复请求（重复报价校验兜底）
- 转会成交无事务：资金转移、工资调整、球员归属三步中途失败会不一致
- 谈判成功率公式是线性硬编码，negotiator 等级的实际加成要读谈判代码确认
- 无转会窗概念：任何时间都能转会
- AI 转会逻辑在"下一天"里同步执行，存档大时推进会变慢
- 成交后没有"转会历史"页面：只能从 user_finance 流水里看资金变化
