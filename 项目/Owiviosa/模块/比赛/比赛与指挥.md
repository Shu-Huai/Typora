# 比赛与指挥

本文说明 PvE 比赛的完整链路：开始、逐回合推进、战术选择、跳过和结果落库。

本文不讨论引擎内部算法，见 [[总体设计/比赛引擎|比赛引擎]]。前端交互见 [[前端/页面与流程|页面与流程]]。

源码范围：`routers/api_v1/game_pve.py`、`modules/game_pve_app/`、`modules/computed_data_app/computed_game_pve.py`。

## 开始比赛

`POST /api/v1/game-pve/start`：

1. 前端提交阵容（lineup：{player_id: 位置}）和战术权重（5 项）
2. 后端校验（阵容 11 人、位置合法）
3. 生成 team_pve（双方队伍信息）和 player_pve（球员临时数据）
4. 返回 attacker_club_id（先攻方）

临时表的数据结构是正式 Game 的轻量版，供回合间快速读写。

## 逐回合推进与战术选择

### 逐回合推进

`GET /api/v1/game-pve/next-turn?tactic&is_clever`：

1. 玩家选择本回合战术（手动）或 is_clever=true 让引擎用 ML/教练权重自动选
2. 引擎模拟一个进攻回合：攻防事件、比分、球员评分、体力
3. 返回 GamePvEInfo：比分、回合数、解说新增段落、双方球员数据
4. 前端渲染后等待下一回合

回合上限 51：turns > 51 时前端跳 game-result。每回合一次 HTTP 请求，一场比赛最多 51 次。

### 战术选择

- 手动：前端 TacticalSelector 5 选 1，点击"推进"
- 自动：前端 setInterval 每秒调 next-turn（is_clever 或按权重随机）
- 无效战术（引擎判定该回合不适用）时 turns 不变，前端提示"战术选择无效！"

## 跳过比赛与结果落库

### 跳过比赛

`POST /api/v1/game-pve/skip`：不走回合交互，引擎直接模拟完整场比赛，返回终局信息，前端跳 game-result。

### 结果落库

比赛结束（回合耗尽或跳过）后，临时数据转为正式 Game 记录（script、mvp、winner_id、goal_record、GamePlayerData），之后 /game/{game_id} 和球员历史接口都能查到。

## 已知边界

- 临时表清理：浏览器中断比赛后 team_pve/player_pve 残留，下一次 start 是否覆盖旧数据需确认（以 computed_game_pve 的实现为准）
- 刷新 game-on 页面靠 show-game-info 恢复，但"下一回合"的战术选择状态不保存
- 51 回合上限写死，无伤停补时概念
- 自动模式每秒一个请求，网络慢时回合推进会明显滞后
- 比赛中断无惩罚：直接刷新就能弃赛重来（对玩家有利，但存档完整性不受影响）
