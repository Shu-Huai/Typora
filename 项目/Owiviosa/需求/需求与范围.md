# 需求与范围

本文说明项目要解决什么问题、游戏循环、功能边界。

本文不讨论实现细节，见 [[总体设计/系统架构|系统架构]] 和各模块文档。

需求来源：后端 README、源码行为、页面功能。项目没有正式需求文档，本文从源码反推并核实。

## 项目目标与用户角色

### 项目目标

做一个可玩的单机足球经理游戏（后端 README 原话："一款简单的足球经理游戏项目"）。玩家以俱乐部经理身份经营一支球队：每天推进赛程，比赛时逐回合指挥，场外通过转会市场买卖球员，赛季目标是联赛排名。

与商业足球经理游戏的区别：模拟粒度粗（回合制战术对抗而非实时），世界小（五大联赛或超级联赛两个剧本），全部 PvE（对手是 AI 模拟）。

### 用户角色

单角色：注册邮箱登录的玩家。没有管理员、没有多玩家交互（没有联机、没有好友）。

## 游戏循环

### 开局

1. 注册登录
2. 选剧本：五大联赛（真实俱乐部名单）或超级联赛
3. 选自己的俱乐部（看资金、声望、平均能力）
4. 系统生成完整世界：联赛、俱乐部、教练、球员、赛季赛程

### 日常循环

```
看主页（下场比赛倒计时、积分榜、财政、最佳球员）
  → 下一天（或度假 N 天）→ 世界推进：其他比赛模拟、转会 AI 行动
  → 轮到自己比赛 → 赛前准备（阵容 + 战术权重）
  → 逐回合指挥（手动选战术 或 自动每 1 秒推进）
  → 比赛结果（比分、MVP、技术统计）
  → 转会操作（搜球员、报价、薪资谈判、卖人）
  → 回到主页
```

### 赛季循环

赛季内积累积分排名 → 赛季末按排名拿转播奖金 → 转会窗补强 → 下一赛季。

## 功能范围与明确不做

### 功能范围

已实现：

- 账号：注册、登录
- 存档：多存档、选剧本、选俱乐部、存档日期
- 世界生成：联赛、俱乐部、教练、球员（中英日名）、赛程
- 比赛：赛前布阵、战术权重、回合制指挥、跳过比赛、解说脚本、技术统计、MVP
- 转会：挂牌、属性搜索、报价、薪资谈判、AI 俱乐部主动报价、职员升级
- 统计：积分榜、球员榜、赛季财政、战术统计、球员详情与历史数据
- 机器学习：位置能力计算、AI 战术选择

### 明确不做（当前版本）

- 联机、多玩家
- 真实球员版权（数据为生成或配置名单）
- 比赛画面渲染（只有文字解说和阵型示意，无 2D/3D 动画）
- 青训系统、球员伤病、停赛
- 杯赛深度模拟（league 表有 cup 字段，功能未展开）
- 存档云同步
- 移动端
- 自动化测试、数据库迁移

## 非功能要求与数据保留

### 非功能要求（事实，非目标）

- 单机数据量级：每存档几千球员、几十场比赛，MySQL 足够
- 世界推进用 BackgroundTasks 异步跑，接口先返回 state 提示
- 玩家比赛是回合制（turns ≤ 51），每回合独立请求，天然无长连接
- 无实时性要求：自动模式 1 秒轮询一次即可接受

### 数据保留

- 全部数据 MySQL 持久化（create_all 建表，无迁移）
- 存档互相独立，删除存档无接口（数据只增）
- 比赛记录（Game、GamePlayerData）保留全历史，球员详情页按赛季查询
- 转会报价（Offer/TargetPlayer）有状态流转（on_sale、待谈判 nf、被拒绝 r/rr）
- 日志：loguru 按天轮转，保留 300 天
