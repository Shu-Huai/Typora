# 游戏世界

本文说明游戏世界的构成：存档、联赛、俱乐部、球员、赛程，以及世界时间的推进方式。

本文不讨论比赛引擎细节，见 [[总体设计/比赛引擎|比赛引擎]]。数据表结构见 [[数据库/数据模型|数据模型]]。

源码范围：`modules/generate_app/`、`modules/next_turn_app/`、`game_configs/data/`、`assets/`。

## 世界构成与生成

### 世界构成

一个存档（Save）是一个独立世界：

```
Save（date、season、player_club_id、lineup）
├── League 多级联赛（points、cup、upper/lower_league 链）
│   └── Club（finance 万、reputation、职员等级）
│       ├── Coach（阵型、5 战术权重）
│       └── Player（11 能力、12 位置计数、周薪、头像参数）
└── Calendar（赛程）
```

两个剧本：五大联赛（five_leagues.json 1550 行，真实俱乐部名单）和超级联赛（super_leagues.json 260 行）。

### 世界生成

创建存档时 generate_app 依次生成：

1. 联赛结构（league_generator）
2. 俱乐部（club_generator）：资金、声望、职员等级
3. 教练（coach_generator）：姓名、年龄、阵型、战术权重
4. 球员（player_generator 303 行）：姓名来自中/英/日人名表（assets/），国籍按 country_potential.json 概率，能力按国家潜力 + 随机（ori_mean_capa=15、潜力均值 80），头像参数按 avatar.json 样式概率
5. 赛程（calendar_generator 828 行）：按联赛循环生成全赛季对阵

## 世界推进（next_turner）

![](http://public.file.lvshuhuai.cn/images\owiviosa-world-advance.svg)

`next_turner.check()` 是"下一天"的总入口（372 行）：

1. 日期 +1（Date 类管理）
2. 推进当天的 AI 比赛（引擎完整模拟）
3. AI 转会行动（挂牌、报价、谈判）
4. 判断今天是否有玩家比赛 → 返回 state（null 或 pve）
5. 赛季边界处理：积分结算、排名、进入下一赛季

度假（holiday）：循环执行 turn_num 天，同步阻塞直到完成。

## 经济系统

俱乐部财政以"万"为单位（finance 字段）：

- 收入：门票、广告、转播（按联赛名和排名硬编码奖金表）、赛事奖金
- 支出：球员工资（周薪）、职员工资
- 转会：买人扣资金、卖人加资金
- 赛季财政、历史收支通过 user_finance 记录查询

## 已知边界

- 赛程生成 828 行是纯逻辑代码，没有双循环对阵的配置化抽象，改赛制要读懂全函数
- 球员成长模型简单：能力按潜力随机，没有训练系统（values 字段存在但 db.py 里有"加列"的注释痕迹）
- 职员等级（scout/doctor/assistant/negotiator）可以升级，但等级对玩法的具体影响是硬编码在转会模块里的
- 度假没有进度反馈：N 天同步执行，天数大时接口长时间无响应
- 世界推进没有事务保护：几十场比赛模拟中途出错会留下半推进状态
- 赛季切换、降级升级等长期玩法链条的实现深度未知（积分榜按赛季查询，但升降级逻辑需在 next_turner 里确认）
