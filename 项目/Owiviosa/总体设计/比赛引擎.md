# 比赛引擎

本文说明比赛模拟引擎的设计：回合制模型、战术对抗、事件生成和统计口径。

本文不讨论 PvE 指挥的前后端交互，见 [[模块/比赛/比赛与指挥|比赛与指挥]]。不讨论 ML 选战术，见 [[模块/机器学习/机器学习子系统|机器学习子系统]]。

源码范围：`modules/game_app/`（game_eve_app、game_pve_app）、`modules/computed_data_app/`、`game_configs/`。

## 回合制模型

![](Z:\Public\images\owiviosa-game-flow.svg)

一场玩家比赛最多 51 回合（turns ≤ 51）。每回合：

1. 双方各选一个战术（5 选 1：下底传中/边路内切/倒三角/中路渗透/防守反击）
2. 引擎按战术权重和球员能力计算本回合事件
3. 事件转成文字解说（script），附带比分、球员评分、体力变化
4. 返回给前端展示

比赛之外的 AI 俱乐部之间比赛同样由引擎计算，但没有回合交互，直接完整模拟（next_turn 里跑）。

## 战术与球员模型

战术定义在 game_configs（枚举 Tactic 5 种）+ 教练（Coach 表的 5 个战术权重字段）。球员模型：

- 11 项能力：射门/传球/盘带/拦截/速度/力量/侵略/预判/任意球/体力/守门
- 12 个位置（ST/LW/RW/CAM/LM/RM/CM/CDM/LB/CB/RB/GK），每个位置有权重表（location_capability.json）把 11 项能力组合成位置能力
- 位置能力用线性回归计算（见 [[模块/机器学习/机器学习子系统|机器学习子系统]]），另有人工版本兜底
- 体力 real_stamina 在比赛中消耗

阵容（lineup）是存档里的 JSON 串 {球员id: 位置}，赛前准备时由玩家排布并提交。

## 事件、统计与分工

### 事件与解说

引擎内部按回合生成事件序列，映射成中文解说文本。script 的格式是前端解析约定：

```
解说内容@时间@等级
```

段落按 `\n\n` 分隔，前端 game-on 页解析渲染解说列表。进球记录（goal_record）单独结构化存储，比赛结果页画时间线。

### 技术统计与 MVP

computed_data_app 从比赛原始数据计算：

- 球员统计：评分、进球、助攻、传球成功率、拦截成功率、过人成功率
- 双方战术统计：5 种战术使用次数与成功率
- MVP：综合各项成功率选出的最佳球员（前端 getMvpDesc 展示）

比赛结束后 Game 表存完整结果（script、mvp、winner_id、goal_record、双方球员数据 GamePlayerData），球员历史数据接口按赛季聚合。

### PvE 与全量模拟的分工

| | game_pve_app | game_eve_app |
|---|---|---|
| 用途 | 玩家逐回合指挥 | AI 俱乐部之间完整模拟 |
| 交互 | 每回合请求一次 | 一次性算完 |
| 数据 | team_pve/player_pve 临时表 | Game/GamePlayerData 正式表 |
| 战术 | 玩家手动或 ML 自动 | 教练权重 + ML |

PvE 比赛结束时把临时数据落成正式 Game 记录，两条路径共享同一套事件生成核心。

## 已知边界

- 51 回合是写死的比赛长度，没有补时、加时、点球
- 战术效果无官方数值依据，权重来自配置 JSON 和主观调参
- 球员伤病、红黄牌停赛未实现（有体力但没有伤停模型）
- 杯赛字段（league.cup）存在但比赛引擎没有杯赛赛制
- 解说文本是模板拼装，长时间游玩会看到重复句式
- 随机数无种子：同一场比赛重跑结果不同，问题复现困难
