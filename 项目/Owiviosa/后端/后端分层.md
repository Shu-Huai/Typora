# 后端分层

本文说明后端的包结构、各层职责、公共组件。

本文不讨论业务逻辑，见各模块文档。调用链见 [[总体实现/实现总览|实现总览]]。

源码范围：后端根目录全部包。

## 分层约定

router → crud → model，业务引擎在 modules。没有 service 层命名，业务逻辑分布在 crud（数据操作）和 modules（领域逻辑）两处：

- routers：HTTP 层（FastAPI APIRouter，路径参数和依赖注入）
- crud：数据访问封装（每模型一个文件，函数式风格）
- models：SQLAlchemy declarative 模型
- schemas：Pydantic 校验（12 个）
- modules：领域引擎（generate/game/transfer/next_turn/computed），纯 Python 无框架依赖
- game_configs：枚举与常量配置
- utils：横切工具

### 数据访问

- core/db.py：engine、SessionLocal、ScopedSession、get_db/get_session
- 启动时 create_all + 手工建 player_id_idx
- crud 函数式风格：每模型一组 create/get/update 函数
- 无 ORM 关系加载策略约定（lazy 默认），统计接口用 pandas 读结果集

## 错误处理与已知边界

### 错误处理

- 无全局异常处理器：路由内 raise HTTPException（FastAPI 默认 {detail} 格式）
- 401 两种文案：登录错 "Incorrect username or password"、token 错 "Could not validate credentials"（前端按文案分支）
- 无业务错误码枚举，错误语义靠 HTTP 状态码 + detail 字符串

### 已知边界

- models/__init__.py 用 import * 全量导出，改动模型文件要小心循环导入
- 无 alembic、无迁移
- schemas 与 models 字段经常不一致（Pydantic 校验宽松）
- 无类型检查强制（无 mypy），大量字典和 pandas 数据结构
- crud 与 modules 的职责边界模糊：部分业务逻辑写在 crud 里
