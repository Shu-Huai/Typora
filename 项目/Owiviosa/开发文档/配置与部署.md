# 配置与部署

本文说明配置项、构建部署方式、数据库管理和训练流程。

本文不讨论本地启动，见 [[开发文档/环境与启动|环境与启动]]。

源码范围：后端 `env.json.example`、`game_configs/`、`main.py`；前端 `.env*.sample`、`vite.config.ts`、`package.json`。

## 后端配置与前端配置

### 后端配置

| 配置 | 位置 | 说明 |
|---|---|---|
| DB_URL | env.json | MySQL 连接串（当前 dburl.py 硬选 "MySQL"） |
| API_PREFIX | core/config.py | /api |
| JWT 密钥 | game_configs/token_config.py | 硬编码在代码里，部署前要改 |
| 联赛剧本 | game_configs/data/*.json | five_leagues/super_leagues 名单 |
| 位置权重 | location_capability.json | 12 位置 × 11 能力的权重表 |
| 能力/国家潜力 | capa_potential.json、country_potential.json | 球员生成概率 |
| ML 模型 | machine_learning/model/*.pkl | 启动时加载 |

后端部署：`python main.py`（uvicorn :::8080）。无 Docker、无 systemd 配置、无 CI。日志 loguru 按天轮转保留 300 天。

### 前端配置

| 变量 | 说明 |
|---|---|
| VITE_APP_INTERFACE_URL | 后端地址，如 http://localhost:8080/api/v1 |
| VITE_TEAM_IMAGE_BASE_URL | 队徽图床，如 http://localhost:1451/ |
| VITE_APP_BASE_URL | 路由基路径，默认 / |
| VITE_HTTP_ENV | test/prod（soybean 遗留 env-config.ts 用） |

构建：`npm run build`（typecheck + vite build）。Vercel 模式 `build:vercel`（hash 路由）。产物 dist/ 交给任意静态服务器，生产需要把 /api 反代到后端 8080（仓库没有 nginx 配置）。

## 部署检查清单

上线前逐项确认：

1. /api/v1/test 端点下线（clear-db 是公开删库接口）
2. token_config.py 的 JWT 密钥更换
3. env.json 数据库密码不再用默认值
4. CORS：FastAPI 是否配了 allow_origins（当前以源码为准确认，前端直连时代理层处理跨域）
5. 队徽图床部署到生产可达的域名
6. 前端 .env.production 配置真实接口地址
7. 数据库备份（无迁移工具，备份是唯一回滚手段）

## 数据库管理与 ML 训练

### 数据库管理

- 建表：启动时 create_all 自动完成，无 alembic
- 变更：手工 ALTER 生产库 + 同步改 models（db.py 有历史加列注释痕迹）
- 回滚：无迁移文件，只能靠数据库备份恢复
- 清理：/test/clear-db 会 drop_all（开发期用）

### ML 训练

模型训练是离线流程：

1. `simulate_eve.py`：多线程跑 base_game 模拟器产训练数据（CSV）
2. `machine_learning/*/starter.py`：读 CSV 训练
   - linear_weight：LinearRegression 学位置能力权重
   - success_guess：RandomForest 学 5 战术成功率
3. joblib 序列化成 .pkl 放进 model/ 目录
4. 重启后端加载新模型

训练数据来自模拟器本身（base_game 是比赛引擎的轻量复刻），引擎逻辑改动后要重跑训练，否则模型和引擎脱节。

## 已知边界

- 无 CI/CD，发布靠手工
- 无监控告警
- 图床是独立服务，队徽文件的管理方式未固化（按队名.png 的约定散落）
- soybean 模板的 husky/commitlint 配置还在，但 git 提交历史显示并未严格执行
