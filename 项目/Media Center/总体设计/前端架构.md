# 前端架构


Media Center 前端是一个 Vue 3 单页应用。它不直接理解 NAS、MySQL 或模块内部路径，只通过 Gateway 暴露的 HTTP、WebSocket 和媒体 URL 使用后端能力。本文件描述前端页面怎样组织、状态怎样流动、模块差异在哪里，以及为什么播放器不能被普通列表页面的写法替代。

## 应用分层

### 页面层

`src/views` 按路由组织页面：登录、首页、配置、Book、Movie、Series、Music、Picture。页面负责组合数据、控制生命周期和展示状态，不应直接拼接服务地址或复制 JWT 处理。

```text
views
  -> apis / composables
  -> store / utils
  -> HTTP / WebSocket / media element
```

### 契约层

`src/apis` 保存请求路径和参数，`src/interface` 保存响应类型、枚举和表单 schema。接口响应的 `data`、`code`、`message` 必须在统一 HTTP 封装中解包；二进制响应使用 `blob` 或 `Resource`，不能沿用 JSON 解包逻辑。

### 状态层

Pinia 保存登录态、主题、布局、tab 和跨页面状态。媒体 currentTime、HLS 实例、ASS renderer、heartbeat timer 属于播放页生命周期，不应长期塞进全局 store；后端 user_progress 才是多设备共享的持久状态。

### 公共组件

`components/common` 负责 Naive UI provider、主题和基础交互，`components/custom` 负责 BetterScroll、ButtonTab、ChromeTab、图标和站点链接。播放器、阅读器和媒体时间轴不能为了复用而强行变成一个“大组件”，它们依赖的媒体模型不同。

## 路由生命周期

### 登录保护

`router/guard/permission.ts` 根据 token 和路由元数据决定是否允许进入页面。未登录请求跳转登录页并保留 redirect；token 过期时清理本地身份，不能让页面继续发送带失效 token 的无限重试。

### 页面进入

进入列表页先加载配置和分页数据，进入详情页再加载关系、文件和派生资源，进入播放页最后创建 session。页面不能在 setup 阶段无条件启动长连接或定时器，必须在卸载时清理。

### 页面退出

普通页面取消请求、关闭 socket、清理 pending 状态。Movie/Series 播放页还要发送最后一次 heartbeat、停止 HLS load、销毁 media source、ASS renderer 和隐藏控制器 timer，避免返回列表后旧页面仍改写进度。

### 错误页面

`exception/403`、`404`、`500` 表示路由或服务错误，不等同于媒体资源错误。播放器要在页面内部显示 PREPARING、FAILED、字幕失败和缓存过期，不能把所有问题重定向到 500。

## 模块界面

### Book

Book detail 根据 `BookFileType` 选择 `PdfViewer`、`EpubViewer` 或 `TxtViewer`。三种 viewer 的进度坐标不同，页面只提供统一的打开、保存、返回入口，不能让 PDF 页码逻辑进入 EPUB 组件。

### Movie

Movie play 由 `hls.js`、`ASS` renderer、`playbackTimeline` 和播放器控制器共同工作。SOURCE、HIGH1080、LOW1080 只改变后端 variant；用户切换后先保存 currentTime，等待新清单可用，再恢复同一媒体时间。

### Series

Series play 在 Movie 播放器基础上增加选集、季筛选、自动下一集和集级进度。切集必须更换 episodeFileId、session、字幕上下文和 resumePosition，不能只替换标题。

### Music Picture

Music 页面围绕 Track、Playlist、Lyric 和原始音频 Range 流；Picture 页面围绕 Folder、File、thumbnail、metadata、semantic search 和 illustration。二者都不应复用 HLS 播放器的 session 假设。

## 媒体状态

### Movie Series

前端区分 `currentTime`、`playbackStartPositionSec`、`resumePositionSec` 和当前 segment 的相对起点。后端返回的是媒体绝对坐标，HLS 的局部加载点不能直接显示在进度条上。

### ASS 字幕

ASS 通过 `assjs` 根据 video media time 渲染；VTT 或普通文本使用 cue 区间查找。切换 session 或 subtitle track 时先销毁旧 renderer，旧事件不能继续写入新播放器的字幕容器。

### 音频状态

播放器音量、静音和播放速率属于浏览器状态，使用 `playerControls.ts` 统一归一化。它们不应和服务端播放 variant、音轨或进度状态混为一谈。

### WebSocket

Book refresh、summary、illustration 和 Music summary 使用独立 socket/composable。连接失败只影响对应长任务提示，列表和已存在资源仍可读取；重连后通过 requestId、资源 ID 和状态版本过滤迟到消息。

**构建边界**

#### 环境变量

`.env.development`、`.env.production` 和 example 文件只定义前端 API、WebSocket、资源前缀等地址。密钥不能写入前端构建产物；生产环境改变 Gateway 地址而不是在每个 API 文件中改端口。

#### Vite 输出

Vite 负责 Vue、TypeScript、SVG、WindiCSS 和按页面拆包。`dist` 是构建产物，不作为源码文档依据。媒体资源 URL 在运行时拼接 Gateway 地址，不能被构建时静态替换成个人 NAS 路径。

#### 浏览器边界

播放器能力判断基于 MSE、codec 和实际错误。不要根据 User-Agent 自动回退画质，也不要把 Edge 能播放当作所有内嵌浏览器都能播放的证据。

#### 部署入口

`deploy/deply.ps1` 负责前端产物部署。部署前确认目标 Web 根目录、缓存策略和 Gateway 反向代理；旧 JS 缓存会造成前后端契约不一致，需要版本化资源或正确的 cache-control。
