# 系统蓝图

本文说明 Media Center 的应用边界、服务职责、数据流和技术选择。模块文档描述具体业务，基础设施文档描述部署和运维；这里关心的是它们如何组成一套系统。

## 总体架构

### 请求入口

客户端是 Vue 单页应用。用户登录后通过同一个界面进入图书、电影、剧集、音乐、图片和配置页面。浏览器只认识 HTTP、WebSocket 和媒体播放协议，不直接访问服务器磁盘、MySQL 或 RabbitMQ。

主要路由：

```text
/home
/book                  /book-detail/:id/:type
/movie                 /movie-detail/:id
                        /movie-play/:movieId/:movieFileId
/series                /series-detail/:id
                        /series-play/:seriesId/:seriesEpisodeFileId
/music
/picture
/config
/login                 /register
```

Gateway 是对外 API 入口。它根据 `/auth`、`/book`、`/movie` 等前缀找到 Nacos 中的服务实例，并用 StripPrefix 转成模块内部路径。前端不保存每个微服务的端口；环境切换只改变统一 API 和 WebSocket 地址。

媒体请求分为两类。普通列表、详情和配置返回统一 JSON；PDF、音频、图片、HLS 清单和分片返回二进制或媒体 MIME。HTTP 封装层不能把两类响应混用，否则会把 `.m4s` 当 JSON 解析或漏掉 Range header。

### 业务服务

五个业务服务围绕内容类型拆分：

| 服务 | 主实体 | 主要消费方式 | 特有依赖 |
| --- | --- | --- | --- |
| Book | Book、BookFile | PDF/EPUB/TXT 阅读 | PDFBox、EPUB、字符集探测 |
| Movie | Movie、MovieFile | HLS/fMP4 播放 | FFmpeg、ffprobe |
| Series | Series、Episode、EpisodeFile | 单集 HLS/fMP4 播放 | FFmpeg、ffprobe |
| Music | Track、Artist、Album、File | HTTP 音频流 | Range、音频标签/歌词 |
| Picture | Folder、File、Metadata | 缩略图与原图 | Thumbnailator、EXIF、Qdrant |

拆分依据是业务模型和资源处理方式。Book 与 Movie 都有“文件”，但一个关心章节/页，另一个关心音视频时间轴，把它们塞进一个通用 MediaService 会产生大量类型判断。Movie 与 Series 的播放底层相似，适合共享播放组件或契约测试，但内容实体不能强行合并。

每个业务服务负责自己的数据库表、目录规则、列表详情、刷新和用户操作。它不实现通用模型协议和第三方网页解析，而是通过 Feign 调 LLM、Spider、OSS。

### 公共服务

| 模块 | 运行形态 | 职责 |
| --- | --- | --- |
| Auth | 独立服务 | 注册、登录、JWT 签发 |
| Gateway | 独立服务 | 外部路由、服务发现、接口聚合 |
| Framework | Maven 共享模块 | 响应、异常、日志、安全、Feign DTO |
| LLM | 独立服务 | 问答、图像生成、文本/图像嵌入 |
| Spider | 独立服务 | 豆瓣与 QQ 音乐访问和解析 |
| OSS | 独立服务 | MinIO 上传、删除、前缀清理 |

Framework 不应变成“所有服务都能随便放代码”的杂物模块。只有没有业务归属、协议稳定且被多个模块复用的代码进入其中。播放分片算法即使 Movie 和 Series 都使用，也更适合作为明确的 playback 子模块，而不是塞进 Common。

### 外部资源

系统依赖三组外部资源：

- 业务数据：NAS/本地媒体、MySQL、MinIO。
- 协调组件：Nacos、Redis/Redisson、RabbitMQ。
- 计算与检索：FFmpeg/ffprobe、模型服务、Qdrant、豆瓣和 QQ 音乐。

依赖按必要性降级。MySQL 或媒体目录不可用时主要业务无法完成；Qdrant 失败只影响图片语义搜索；Spider 失败只影响新外部资料；模型失败只影响新生成内容。边界由服务层显式处理，不能让一个 Feign 异常从首页一直冒泡成全站不可用。

## 应用设计

### 前端分层

前端技术栈为 Vue 3.4、TypeScript 5.3、Vite 5、Vue Router、Pinia、Naive UI 和 Axios。目录职责应保持：

```text
views/          页面组合与路由级生命周期
components/     可复用界面和播放器/阅读器组件
apis/           模块 HTTP 契约
store/          登录态、主题、播放器等跨页面状态
router/         路由表与守卫
utils/          无业务状态的通用工具
```

页面负责协调，不在单个 `.vue` 中重新实现路径拼接、JWT、WebSocket 重连和错误翻译。API 文件按 auth、book、movie、series、music、picture 等模块组织，与后端边界一致。

媒体相关依赖有明确用途：

- hls.js 把 HLS 清单送入 MSE，处理 fMP4 音视频轨道。
- assjs 渲染 ASS 字幕，并跟随 video currentTime。
- EPUB.js 解释 EPUB 容器和章节。
- PDF Viewer 展示 PDF 页面。
- SockJS/STOMP 或原生 WebSocket 接收异步状态。
- Pinia 保存跨页面播放器和登录状态，不代替后端持久化。

浏览器能力存在差异。功能判断要基于真实 API、MSE codec 和播放错误，而不是 User-Agent 猜测。Edge 与 Codex 内置浏览器结果不同，应比较两者 MSE、codec、origin 和缓存，不能据此自动改画质。

### 后端分层

后端使用 Java 23、Spring Boot 3.2.4、Spring Cloud 2023.0.1、Spring Cloud Alibaba 2023.0.1.0。典型层次如下：

```text
Controller
  处理路径、DTO、权限和 Response<T>
        ↓
Service / Domain component
  业务规则、事务、任务准入、路径与媒体算法
        ↓
Mapper | File system | Feign | RabbitMQ | Redis
```

Controller 不直接遍历目录或拼 FFmpeg 命令。复杂流程拆成有含义的组件，例如路径解析器、媒体探测器、分段计划生成器、缩略图服务、外部匹配器。拆分目标是可单测和职责清楚，不是每十行创建一个类。

MyBatis-Plus 用于常规 CRUD 与查询，复杂批量同步可以使用专用 Mapper。Druid 管理连接。Service 事务只包数据库修改，不把模型调用、FFmpeg 或网络抓取放进长事务。

### 通信方式

系统有四种通信方式：

| 方式 | 适用 | 不适用 |
| --- | --- | --- |
| HTTP JSON | 查询、短命令、配置 | 数小时扫描的完整等待 |
| HTTP 媒体流 | 图片、电子书、音频、HLS | 任务状态广播 |
| OpenFeign | 内部同步请求 | 无界批量调用 |
| RabbitMQ + WebSocket | 长任务命令和状态 | 强一致事务 |

例如图片重绘的请求流：

```text
Vue → Picture Controller：提交 fileId/style/requestId
Picture → Redis：获得重复任务锁
Picture → LLM Feign：图生图
Picture → MySQL：保存 Illustration
Picture → RabbitMQ/Handler：发布 SUCCESS
WebSocket → Vue：更新当前卡片
```

全量刷新更适合 RabbitMQ；播放分片请求则不经过消息队列，因为播放器需要低延迟的按需 HTTP 响应，后端内部用有界执行器协调 FFmpeg。

### 错误处理

业务 JSON 使用 `Response<T>`，包含 code、message 和 data。异常由公共处理器转成稳定错误码。二进制接口使用 `ResponseEntity<Resource>` 等原生响应，不套 JSON。

错误设计关注调用方动作：

```text
401/403          重新登录或提示权限
PARAM_ERROR      修正输入
NOT_FOUND        刷新列表/资源已不存在
DUPLICATE        观察已有任务
PREPARING/503    播放器稍后重试
DEPENDENCY_FAIL  对应功能降级
FAILED           用户重试或查看错误
```

日志切面记录操作与耗时，但媒体二进制和模型大响应关闭响应体打印。异常日志保留 requestId 和资源 ID，前端消息不暴露服务器路径、SQL 或命令行敏感信息。

## 运行流程

### 媒体刷新

所有媒体模块都有“配置目录 → 扫描 → 写索引”，但解析器不同。公共部分是任务准入、RabbitMQ、状态和 WebSocket；目录解释留在模块。

```text
前端配置页
  → 管理接口验证 requestId 与模块状态
  → 发布 refresh command
  → 消费者取得分布式 leader lock
  → 模块扫描器构造磁盘快照
  → 与 MySQL 做差异同步
  → 触发模块派生任务
  → 发布统计与最终状态
```

Book 解析电子书，Movie/Series 解析影视目录，Music 解析标签与歌手关系，Picture 同步目录树、元数据和向量。刷新框架可以共用状态协议，但不能强制五个模块使用同一“文件名即内容名”策略。

### 用户进度

进度读写走同步 HTTP，因为单次操作短小。前端按间隔上报，Service 从 SecurityContext 得到 userId，并按资源 ID upsert。

```text
打开消费页 → 查询进度 → 校验资源/时长 → 恢复
播放或阅读 → 周期上报 → 限频写入
暂停/退出 → 最后一次提交
完成 → 应用模块完成阈值
```

进度坐标由格式决定：电影、剧集、音乐用秒/微秒语义；PDF 用页；EPUB 用 CFI；TXT 用页与字符位置。数据库可以使用不同表或类型字段，但接口不能假装它们都是同一种整数。

### 视频播放

Movie 和 Series 使用 prepare + HLS + heartbeat。后台先通过 ffprobe 建立媒体时长和关键帧计划，SOURCE 视频 copy、音频转 AAC，1080p 重编码。每次只生成当前位置附近的 fMP4 分片。

选择 fMP4 而不是固定 TS copy 的原因不是“新格式更高级”，而是 SOURCE 必须尊重原视频随机访问边界。固定 6 秒强切 stream copy 会让 FFmpeg seek 到相邻关键帧，导致分片实际 PTS 重叠或缺口，表现为重复、跳跃和不同步。真实计划使清单时长、分片内容和媒体时间有同一依据。

视频和音频分轨，浏览器在 MSE 中组合。字幕使用原媒体时间，独立加载。所有换轨、拖动和恢复都围绕同一个 currentTime，后端用整数微秒查计划段。

完整设计见 [[模块文档/Movie/播放业务|Movie 播放]]。

### 图片处理

Picture 刷新先让文件在 MySQL 中可见，再异步补充元数据、缩略图和向量。文本搜索由 LLM 生成向量，Qdrant 返回 ID 和分数，Picture 回查 MySQL，避免把向量库当业务主库。

AI 生成链路把输入校验、模型调用、对象存储和业务记录分开。模型返回临时 URL不等于最终成功，只有稳定对象已保存且数据库关联完成后才发布 SUCCESS。

## 技术决策

### 主要技术选择

| 技术 | 选择原因 | 需要避免的误用 |
| --- | --- | --- |
| Vue + Vite | 单页媒体界面、组件生态、开发构建快 | 页面复制业务协议 |
| Naive UI | 统一表单、列表、通知与主题 | 深层组件 CSS 无约束覆盖 |
| Spring Boot/Cloud | 多服务配置、网关、安全、Feign | 为简单逻辑过度拆服务 |
| MyBatis-Plus | CRUD 与查询清晰 | 把全部业务塞进 Mapper |
| Nacos | 配置与服务发现 | 把注册成功当健康成功 |
| Redis/Redisson | 分布式锁和短状态 | 保存不可恢复主数据 |
| RabbitMQ | 长任务解耦和状态消息 | 用消息队列假装强事务 |
| MinIO | 自托管对象资源 | 存放所有 NAS 原媒体副本 |
| Qdrant | 图片向量检索 | 当作图片详情数据库 |
| FFmpeg/ffprobe | 成熟媒体探测与处理 | 固定时间 stream copy 强切 |

技术选型服务于当前业务。若以后部署从单机变成多节点，本地缓存共享、FFmpeg 调度和 NAS 一致视图需要重新评估；当前文档不假装已经解决分布式媒体计算的全部问题。

### 配置边界

仓库 `application.yml` 保存无敏感默认值和模块参数，环境连接由 Nacos/环境变量提供。配置分三类：

- 启动必要：端口、服务名、数据库、Redis、RabbitMQ、Nacos。
- 业务必要：媒体根目录、允许扩展名、MinIO/Qdrant/模型地址。
- 调优参数：线程数、队列、超时、播放分片、缓存 TTL、缩略图尺寸。

修改调优参数前记录基线。以 Movie 为例，把 `preheatAheadWindowCount` 从 1 改到 5 会明显增加跳播浪费；把 FFmpeg 并发从 2 改到 10 可能让每个任务都更慢。配置中心变更是否热生效要按具体 Bean 验证，不能默认所有 `@ConfigurationProperties` 都立即刷新。

### 证据层次

```text
单元测试
  路径、名称解析、关键帧查找、状态机、匹配规则
        ↓
模块集成测试
  临时目录 + H2/MySQL + Mock 外部服务
        ↓
服务联调
  Nacos/Gateway/Redis/RabbitMQ/真实 FFmpeg
        ↓
浏览器验收
  真实 NAS 文件、字幕、Range、WebSocket、暂停/拖动
```

测试 fixture 使用临时目录，不依赖某台机器固定的 Z 盘；真实验收再使用用户媒体。生产校验需要目录真实存在时，单元测试也创建真实临时目录，而不是 Mock 一个不存在路径。

前端 `vite build`、TypeScript 检查和后端 Maven 测试分别报告。某个工具自身兼容性错误不能隐瞒，也不能因此把另一项通过说成“全部通过”。

### 架构验收

架构是否正确不能只看类图。至少验证：

1. 浏览器所有 API 通过 Gateway，服务发现与 StripPrefix 正确。
2. 业务服务故障被限制在对应模块，公共首页或其他媒体仍可使用。
3. 长任务不长期占 HTTP 线程，状态可重连查询。
4. 文件系统、MySQL 和派生索引在刷新及写操作后达到一致。
5. 用户数据不随媒体刷新、缓存清理或外部同步丢失。
6. Movie 与 Series 播放契约一致，真实浏览器无时间轴问题。

如果实现与本文不一致，先判断是代码缺陷还是已决定的新需求，再同步修改代码和文档。文档不用于粉饰现状，也不应在没有源码或测试证据时写“系统已经保证”。
