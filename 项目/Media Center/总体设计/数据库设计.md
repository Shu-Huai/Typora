# 数据库设计

![](http://public.file.lvshuhuai.cn/images\database-domain-relations-1786601764741-3.svg)


Media Center 使用 MySQL 保存业务事实。数据库不是文件系统镜像的临时索引，也不是 Redis、Qdrant 或对象存储的替代品。主键、外键、业务唯一键和状态字段共同决定数据能否在重复刷新、文件移动和进程重启后继续使用。

## 表域划分

### 内容域

Movie 使用 `movie`、`movie_file`、`movie_info`、`movie_source` 和关系表；Series 使用 `series`、`series_episode`、`series_episode_file`、`series_info`、`series_source` 和关系表；Book 使用 `book`、`book_file`、`author`、`publisher`。

### 用户域

`user`、`role`、`permission`、`user_role`、`role_permission` 保存访问控制。`user_progress` 保存跨设备阅读、播放和音乐位置，它是用户事实，不能被媒体刷新、缓存 TTL 或派生任务清掉。

### Music 域

`music_track` 表示曲目，`music_file` 表示音频文件，`music_artist`、`music_album` 和关系表保存归属；`music_source`、`music_lyric`、`music_playlist` 和 `music_playlist_track` 分别保存外部来源、歌词和用户歌单。

### Picture 域

`picture_folder`、`picture_file` 是主索引，`picture_metadata`、`picture_illustration`、`picture_embedding_index` 保存派生结果。Qdrant point 是外部索引，数据库记录 collection、point、model、dimension 和 embedding_status。

## 身份约束

### 文件身份

影视和图书文件使用受管根目录下的相对路径；音乐使用路径加 Track 关系；图片使用 folder 加 relative path。路径唯一索引要和 `is_active` 语义一起审查，软删除后重新出现的文件不能创建无法解释的重复业务对象。

### 作品身份

Movie 通常以主表 ID 表示作品；Series 以 category、title、season_no 形成唯一身份；Book 的作者和出版社是外键关系；Music 不能只以 title 形成 Track 身份。

### 外部来源

Movie/Series 的 source 绑定作品，Music 的 source 通过 entity_type/entity_id 绑定 Track、Album 或 Artist。source_id 的唯一范围必须包含 source 类型，不能让不同平台恰好相同的数字 ID 冲突。

### 用户位置

`user_progress` 的业务键由 user、mediaType、mediaId 或具体 file 身份组成。当前 schema 中 progress/sub_progress 是通用整数，服务层必须解释它的格式语义，不能让前端把 PDF 页码发送给电影接口。

## 写入策略

### Upsert

刷新先查稳定身份，再更新已存在行，最后插入新行。主对象提交后才写关系和派生状态；关系同步要区分本轮可信空集合和解析失败，失败时不能清空旧资料。

### 软删除

`is_active` 允许暂时保留用户进度、来源和审计关联。软删除不是永远不清理，后续清理任务必须有明确条件，不能在每次刷新中物理删除主键。

### 事务边界

数据库事务覆盖同一资源的主对象和关系写入，不覆盖 FFmpeg、NAS 移动、模型调用、Qdrant 网络调用。外部副作用使用任务状态和补偿，而不是持有数据库事务等待。

### 并发写入

数据库唯一键是最后防线，Redis lock 是减少竞争的协调手段。消费者重投、两个实例同时刷新和前端重复点击都必须在没有锁时仍不会生成错误主数据。

## 迁移治理

### SQL 顺序

`sql/create.sql` 提供基础表，`alter_*.sql` 表示后续结构调整。新增列先允许旧代码继续工作，再发布写入逻辑，最后在确认旧数据已补齐后收紧约束。

### 数据回填

回填脚本按批次执行，记录开始时间、影响行数、失败主键和可重试位置。大表不要一次性更新全部行，也不能在业务高峰锁住文件、进度或 Playlist 表。

### 索引变更

索引要对应真实查询：列表筛选、路径查找、source 匹配、embedding 状态和用户进度。重复或失效索引会增加刷新写入成本；删除索引前先确认 mapper SQL 和线上执行计划。

### 回滚

DDL 回滚不等于数据回滚。每个 migration 需要写明可逆 DDL、不可逆数据变化、备份要求和异常处理；无法安全回滚的变更先采用新增列或新表兼容方案。

**数据边界**

#### Redis

Redis 保存 session、锁、任务短状态和去重窗口。Redis 清空后允许重建 session，不能因此丢失作品、文件、进度或歌单。

#### Qdrant

Qdrant 只保存向量检索数据，搜索结果必须回查 MySQL。collection 删除或模型升级时，数据库 embedding 状态应变为待重建，而不是继续报告 READY。

#### OSS

MinIO 保存封面、插图等对象资源，数据库保存 URL、object key 和业务归属。对象不存在时详情应报告派生资源失效，不能删除仍有效的 Book、Movie 或 Picture 主记录。

#### NAS

NAS 是媒体原文件事实来源。数据库记录路径、文件版本和探测结果，但不保存完整电影、音频或图片副本；源文件短暂不可访问时，刷新必须防止级联误删。
