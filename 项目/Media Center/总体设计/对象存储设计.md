# 对象存储设计

Media Center 的原始媒体保留在 NAS，MinIO/OSS 只保存封面、插图和其他派生对象。两者的访问模型、清理风险和生命周期不同，不能把 OSS 当作另一份完整媒体库。

## 对象范围

### 封面

Movie、Series、Book、Music 的封面是资料派生对象。数据库保存 object key 或稳定 URL，页面通过受控接口获取，不把 OSS bucket 直接暴露给浏览器。

### 插图

Book illustration 和 Picture illustration 保存模型生成结果。对象 key 应包含模块、资源 ID、样式、模型或版本，重复 requestId 不应产生无法归属的对象。

### 媒体缓存

HLS init、m4s、字幕和 segment-plan 属于播放缓存，不默认放入 MinIO；它们需要低延迟、临时 TTL 和与 FFmpeg 同机/共享盘可见性。若未来迁移到对象存储，需要单独设计 Range、原子发布和 CDN 缓存。

### 原始文件

电影、剧集、音频、电子书和照片的源文件由 NAS 管理。OSS 清理、上传失败或网络抖动不能删除或隐藏 NAS 主文件。

## Key 规则

### 命名

```text
movie/covers/<movieId>/<version>.<ext>
series/covers/<seriesId>/<version>.<ext>
book/covers/<bookId>/<version>.<ext>
book/illustrations/<bookId>/<requestId>.<ext>
picture/illustrations/<fileId>/<style>/<requestId>.<ext>
music/covers/<trackId>/<version>.<ext>
```

Key 不包含用户上传的任意 `../`，名称经过长度和字符校验。

### 版本

内容替换或模型升级时生成新 key，再更新数据库指针；不要覆盖旧对象后让正在使用的 URL 内容突然变化。旧对象按引用检查和保留策略清理。

### URL

数据库优先保存 object key，访问 URL 由 OSS 配置生成。私有 bucket 使用短期签名 URL，前端过期后重新请求，不把长期 token 写入页面。

### MIME

上传前校验扩展名、声明 MIME 和实际文件头；下载时返回真实 Content-Type。模型临时 URL 的 MIME 不能直接作为最终对象类型。

## 上传流程

### 临时对象

```text
生成/提取结果
  -> 校验大小、MIME、图像可读性
  -> 上传 temporary key
  -> HEAD 校验长度和 checksum
  -> 数据库更新 object key
  -> 发布 SUCCESS
```

数据库更新失败时保留待清理 temporary key，不能返回一个数据库没有记录的“成功 URL”。

### 删除流程

先检查对象引用，再删除 OSS 对象，最后清理数据库状态或标记删除。删除失败要可重试，不把网络错误吞成成功。

### 前缀清理

按模块、资源 ID 和明确版本清理；禁止空前缀、bucket 根和用户可控的任意 prefix。执行前记录预计对象数，执行后记录实际结果。

### 迁移

更换 bucket、endpoint 或 CDN 时先复制对象，再切换 key/URL 生成配置。旧对象保留到所有实例和浏览器缓存过期后再清理。

## 访问边界

### 后端代理

前端优先通过业务接口获取对象，业务层检查资源是否存在、用户是否有权访问、对象是否仍被当前记录引用。

### 缓存头

带版本 key 的静态对象可以长缓存；可变的 latest URL 使用短缓存或 no-cache。HLS 临时文件不沿用封面对象的长期缓存策略。

### 容错

OSS 不可用时，主媒体列表、NAS 原文件和已存在数据库事实继续工作；封面或插图显示占位和重试。不能因为一个对象 URL 失败返回整个详情 500。

### 审计

记录 object key、业务资源、requestId、上传者、大小、MIME、结果和错误。日志不记录签名 URL 全文或外部临时 token。
