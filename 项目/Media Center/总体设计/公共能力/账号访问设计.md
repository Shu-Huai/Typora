# 账号访问

账号模块负责确认“谁在使用系统”，安全框架负责把身份传递给业务服务，Gateway 负责统一入口。前端路由守卫可以改善体验，但真正的访问控制必须在后端执行。

## 账号生命周期

### 注册

注册页面先读取用户协议，再提交用户名和密码。前端校验只用于即时提示，服务端仍需完成：必填检查、长度和字符规则、用户名唯一性、密码安全哈希以及默认角色分配。

```text
GET /user/protocol
  → 展示协议
POST /auth/register
  → 参数校验
  → 检查用户名
  → PasswordEncoder 哈希
  → 创建用户与默认角色
```

重复用户名返回稳定业务错误。日志可以记录用户 ID 和结果，不记录原密码、哈希或完整请求体。若协议要求同意记录，应保存协议版本和同意时间，而不是只依赖前端勾选框。

### 登录令牌

`POST /auth/login` 验证凭据后签发 JWT。令牌至少包含用户身份、角色和失效时间；业务服务通过共享安全组件验证签名并建立 `LoginUser`。

登录失败不应透露“用户名存在但密码错误”之类可用于枚举的信息。连续失败限流可由网关、Redis 或安全组件完成，但不能误伤正常媒体流请求。

前端保存令牌并由 Axios 附加 `Authorization`。如果当前实现把令牌放在 localStorage，要承认它受 XSS 影响；部署时需配合 CSP、输入输出转义和第三方脚本控制。若改用 HttpOnly Cookie，还要补充 CSRF 设计，不能只换存储位置。

### 修改账号

修改用户名检查新名称合法、唯一，并更新当前会话显示。修改密码至少验证当前密码或使用一次性身份确认；成功后明确处理已有 JWT：

- 简单方案允许旧令牌自然过期，用户体验好但撤销不及时。
- 安全方案保存 token version 或撤销时间，让旧令牌立即失效。

项目应选定一种并写入接口行为。不能出现密码已改、其他设备令牌却永久有效的状态。账号接口只能操作当前用户，除非另有管理员用户管理模块。

## 请求鉴权

### HTTP 保护

公开页面包括登录、注册和异常页；`/home`、各媒体页和 `/config` 需要身份。路由守卫的基本流程是：

```text
进入受保护路由
  → 本地是否有令牌
  → 无：跳转 /login?redirect=原地址
  → 有：允许进入并由接口确认有效性
  → 接口 401：清理登录态，重新登录
```

不能因为本地存在字符串就认定登录有效。后端 401 是最终判断。403 表示身份有效但权限不足，前端进入无权限页，不应把它也当成登录过期。

Axios 统一处理 API 基址、令牌、超时和响应结构。媒体分片、原图等二进制响应不一定使用普通 JSON 拦截器，但仍要通过授权 URL 或受控会话访问。

### Spring Security

Auth 负责凭据，Framework-Security 提供 JWT 过滤器、用户上下文和通用配置。业务 Controller 使用 `@PreAuthorize` 或统一规则限制角色；Service 中涉及资源归属的操作仍要检查当前 userId。

```text
Gateway 转发
  → JWT filter 解析 Authorization
  → 验证签名、有效期和用户状态
  → 写入 SecurityContext
  → 方法级角色判断
  → Service 资源归属判断
```

“具有 ROLE_USER”只能证明是普通用户，不能证明某个歌单或进度属于他。后者必须查询资源 owner。

### 服务间身份

Book、Movie、Series、Music、Picture 通过 OpenFeign 调用 LLM、Spider、OSS。内部调用使用 `security.internal.caller` 和内部 token，与普通用户 JWT 分离。

每个内部接口验证：caller 是否在允许列表、token 是否正确、调用是否来自预期网络边界。开发配置中的固定 token 不能直接用于公网部署；通过 Nacos 密文、环境变量或密钥系统注入，并避免出现在 Git 与日志中。

业务服务不应把前端传入的 caller header 原样转发为可信身份。内部 header 由 Feign interceptor 在服务端添加，Gateway 对来自公网的同名 header 做剥离或覆盖。

### Gateway 路由

Gateway 以 `23000` 为统一入口，当前路由包含 Auth、Book、OSS、LLM、Movie、Series、Music、Picture 和 Spider。外部前缀经 `StripPrefix=1` 后进入模块 Controller。

例如：

```text
浏览器 GET /movie/movie/831
Gateway 匹配 /movie/**，去掉第一个 /movie
Movie 服务收到 GET /movie/831
```

路径命名存在模块前缀和 Controller 前缀重复的情况，开发时必须从实际 route 推导，不能只看 Controller 猜前端 URL。WebSocket 若没有走同一 route，需要在反向代理和前端环境变量中单独配置。

## 资源边界

### 用户数据隔离

用户数据至少包括阅读进度、电影/剧集/音乐进度和歌单。所有查询与更新都包含当前 userId；DTO 中即使出现 userId，也不能覆盖 SecurityContext 得到的身份。

共享媒体资料、缩略图和转码分片不按用户隔离，因为它们来自同一原文件且可重建。共享缓存只能暴露媒体内容，不能包含用户观看位置、令牌或私人歌单。

### 文件访问

用户不能直接提交服务器绝对路径读取文件。合法链路是：业务 ID → 数据库受管文件记录 → 模块根目录解析 → 边界校验 → 流式返回。

对 HLS session URL，也要确认 session 是由已授权 prepare 建立，或采用不可猜且短期有效的 sessionId。仅用连续 fileId 拼公开 URL 容易绕过详情接口权限。

### 跨域代理

开发前端通常在 `23100`，Gateway 在 `23000`，属于跨源访问。CORS 必须允许实际前端 origin、方法和必要 header；正式环境优先同源反向代理，减少宽泛配置。

当前 WebSocket handler 使用 `setAllowedOrigins("*")` 便于开发，但公网部署应限制来源并校验身份。WebSocket 握手可能无法使用与 Axios 完全相同的 header，需使用 Cookie、查询 token 或首条认证消息中的一种明确方案。

代理需支持 `Upgrade`/`Connection` header，并为 HLS、音频 Range 和长任务状态设置合适超时。普通 API 能通不代表 WebSocket 和媒体流一定能通。

## 安全验收

### 权限矩阵

| 场景 | 预期 |
| --- | --- |
| 未登录访问媒体列表 | 401，前端跳登录 |
| 普通用户浏览和播放 | 允许 |
| 普通用户发起管理员刷新 | 403 |
| 用户 A 查询用户 B 歌单/进度 | 拒绝或查无数据 |
| 无内部 token 调 LLM 内部接口 | 拒绝 |
| 外部请求伪造 caller header | 不被信任 |
| 令牌过期 | 401，清理前端登录态 |

交付检查覆盖 Controller 授权和 Service owner 校验；浏览器验收覆盖 redirect 回跳、401/403 展示和多标签页退出。

### 安全检查

- 修改 JWT payload、签名和过期时间均被拒绝。
- 注册与登录日志不包含密码和 token。
- 文件 ID 被篡改时不能访问根目录外内容。
- CORS 只允许配置来源，预检请求正常。
- WebSocket 未认证或来源不合法时握手失败。
- 修改密码后的旧令牌行为符合已选定策略。

### 故障诊断

出现“连接服务器失败”时先区分网络失败、Gateway 不可用、路由失败和业务 401：

```text
浏览器 Network
  → 请求是否发出、目标端口是什么
  → TCP 是否连接
  → Gateway 是否返回 404/502
  → 业务是否返回 401/403/500
  → Nacos 中目标服务是否有实例
```

不要在没有响应证据时直接让用户重新登录或重启客户端。Edge 能播放而内置浏览器不能播放时，还要比较 origin、User-Agent、MSE/codec 能力和缓存，不应首先改业务转码规则。

### 配置要求

生产环境必须外置 JWT 密钥、内部 token、数据库和中间件密码。密钥轮换需要兼容短暂双 key 验证或安排所有用户重新登录。接口文档聚合在 Gateway，生产是否开放 Knife4j 应由环境配置决定。
