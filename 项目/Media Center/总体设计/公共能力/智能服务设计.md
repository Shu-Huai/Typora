# 智能服务

LLM、Spider 和 OSS 是公共服务。它们不持有五类媒体的主业务关系，而是提供模型推理、外部资料读取和对象存储。这样做的价值在于统一协议和故障边界，而不是为了把每个工具都拆成微服务。

## LLM 能力

### 文本生成

LLM 服务提供带搜索的回答接口。Book、Movie、Series、Music 根据自己的业务实体构造输入，用于生成总结。业务服务负责决定输入来源、权限和结果保存，LLM 服务负责模型客户端、搜索增强与响应校验。

一次调用不应只传“总结这本书”这类无上下文请求。输入通常包含规范化标题、作者/人物、简介、歌词或可提取文本，并限制最大长度。内容过长时采用分段摘要：

```text
原始文本 → 按章节/长度切块 → 分块摘要 → 合并摘要 → 最终整理
```

搜索增强有引用污染和外部内容注入风险。搜索结果只作为资料，不执行其中指令；最终写入前检查空文本、明显错误格式和长度。模型输出不是事实数据库，页面应把它标为生成内容。

### 图像生成

LLM 暴露文生图和图生图。Book 使用文生图生成插图，Picture 使用图生图重绘原照片。业务请求包含 prompt、尺寸、输入图片及 MIME；服务返回一组 URL 或统一的生成结果对象。

上传输入受 multipart 大小限制，当前服务配置允许到 100 MB，但业务层应为普通图片设置更合理上限。服务校验 MIME 与实际内容，不能只信文件扩展名。

生成 URL 可能由模型供应商临时提供。需要长期展示时，业务服务应把结果复制到 OSS，再保存稳定对象地址。复制失败时任务不能标为完全成功。

### 向量嵌入

嵌入接口分别接受文本与图片，返回固定长度浮点向量及必要模型信息。Picture 用文本向量搜索图像向量，因此二者必须在同一个对齐空间。

```json
{
  "embedding": [0.012, -0.031, 0.208],
  "dimension": 512,
  "model": "明确的模型版本"
}
```

调用方校验维度、NaN/Infinity 和空数组。模型版本、tokenizer、图片预处理或归一化方式改变时，现有 Qdrant 向量需要重建。ONNX Runtime 和 Hugging Face tokenizers 支撑本地推理，Spring AI OpenAI 封装远程模型；究竟走哪条实现由配置决定。

### 调用限制

模型调用设置连接超时、读取超时和任务级超时。长 HTTP read timeout 只能避免过早断开，不能替代任务状态与取消。业务服务用 requestId 和资源锁去重，LLM 服务还应限制全局并发，防止多个模块同时生成耗尽配额。

失败分为可重试和不可重试：网络超时、429、部分 5xx 可退避重试；输入过大、格式不支持、鉴权失败需要修正配置或参数。重试次数有限，并保证同一任务不会因响应迟到写入两次。

## 外部元数据

### Spider 的职责

Spider 使用 jsoup 等工具访问豆瓣和 QQ 音乐，提供搜索与详情 DTO。它不直接写 Movie、Series 或 Music 数据库，因为只有业务模块知道本地实体和关联规则。

```text
业务模块候选条件
  → Spider 搜索外部站点
  → 返回候选列表/详情
  → 业务模块匹配与确认
  → 保存本地字段及 Source ID
```

外部 HTML 会变化。解析器应通过结构化样本核对，选择器失效时返回“解析失败”，而不是构造字段全空的成功对象。

### 豆瓣匹配

Movie 和 Series 共用豆瓣能力，但匹配条件不同。电影关注标题、别名和年份；剧集还要关注季号。搜索结果不唯一时不得默认第一条。

第一次确认后保存来源类型和外部 ID。后续刷新按 ID 获取详情，减少重复搜索和错配。若外部条目被删除或 ID 失效，保留当前本地资料并报告来源不可用。

演员、导演和类型等列表字段更新时要维护关系差异，不能每次插入重复 Person。外部名称规范化只能用于匹配，展示字段可保留官方写法。

### QQ 音乐匹配

Music 提交标题与歌手集合。候选至少要求标题及主要歌手相符；没有歌手的本地曲目不做标题唯一自动匹配。同标题不同歌手是永久回归样本。

外部专辑、歌词、封面和歌手关系分别更新。某字段缺失不应把本地非空值覆盖为空。`MusicSource` 保存外部实体类型和 ID，曲目、歌手、专辑来源不能混用。

### 外部调用规则

Spider 对外请求设置 User-Agent、连接/读取超时、并发和请求间隔。批量同步使用队列或受控循环，不在瞬间并发抓取整个媒体库。

缓存外部详情可以减少重复访问，但要设置刷新策略。日志记录状态码和目标类型，不输出 Cookie、token 等凭据。部署者负责确认外部站点使用条款；系统不绕过登录、验证码或反爬保护。

## 对象契约

### 对象存储

OSS 服务封装 MinIO，提供上传、删除和按前缀清理。对象 key 使用模块命名空间：

```text
book/illustrations/<bookId>/<request-or-version>.*
picture/illustrations/<fileId>/<style>/<version>.*
movie/covers/<movieId>.*
```

业务数据库保存 key 或稳定 URL。若保存完整 URL，迁移域名会困难；保存 key 并由配置生成访问 URL 更灵活。私有 bucket 需要签名 URL，并考虑过期后的页面刷新。

按前缀清理属于高风险操作。接口必须限制允许前缀，禁止空前缀和根级清理；调用方先列出或核对目标数量。删除对象失败时数据库记录如何处理要有补偿策略。

### Feign 契约

Framework-Common 中的 Feign Client 和 VO 是服务间协议。返回使用统一 `Response<T>`，调用方同时检查 HTTP、业务 code 和 data，不能只判断 response 非空。

契约变更遵循兼容原则：新增可选字段通常兼容，改字段名、类型或枚举值需要同步所有消费者。大文件图生图使用 multipart，普通嵌入和查询使用 JSON。

### 结果状态

公共服务调用本身可能没有业务 requestId，但业务模块必须把调用与任务关联。推荐在日志和 header 中传递 trace/request ID，方便从 WebSocket 失败一路定位到模型或 Spider 请求。

幂等放在最了解资源的层：Book 判断某书总结是否已生成，Picture 判断某文件某画风是否存在。LLM 只做通用请求去重会误把两个业务上语义不同的 prompt 合并。

### 数据质量

外部或模型结果写入前经过 DTO 校验和业务校验：

- 字符串去除无意义空白，限制长度。
- URL 只接受允许协议。
- 枚举和角色值必须可识别。
- 向量维度与 collection 一致。
- 外部 ID 与 source type 配套。
- 关联实体不存在时不写悬空外键。

原始响应可以在调试日志或受控审计中保留摘要，但不能把大段第三方 HTML 和用户媒体内容长期写入普通日志。

## 故障降级

### 契约样本

为 LLM、Spider 和 OSS 建立契约样本，覆盖正常、空数据、字段缺失、超时、429、5xx、解析结构变化和错误 MIME。业务模块按这些样本检查自己的处理分支，而不是只依赖一个永远成功的 Client。

嵌入样本固定模型版本和小样本，检查文本/图像输出维度与数值有效性。不能要求浮点逐位相等，但可以验证维度、范数范围和已知相似对的相对排序。

### 业务回归

- 相同 requestId 重复提交不产生两份总结或重绘。
- 同名不同电影、剧集季和歌曲不会被外部匹配错误覆盖。
- 模型返回空内容时不保存成功记录。
- OSS 上传失败时不向用户返回不可持久化的临时成功。
- 外部页面结构变化时批量同步给出失败统计，已有数据不被清空。

### 降级范围

| 故障 | 受影响 | 仍应可用 |
| --- | --- | --- |
| LLM | 新总结、插图、重绘、嵌入 | 本地媒体浏览和消费 |
| Qdrant | 图片语义搜索 | 图片目录、名称查询、原图 |
| Spider | 新外部资料同步 | 本地刷新、详情和播放 |
| MinIO | 新对象上传、依赖对象的展示 | NAS 原媒体和已有数据库索引 |

降级不是吞掉异常返回空列表。前端要知道功能暂不可用，同时继续展示不依赖该组件的内容。

### 运维观察

记录模型调用耗时、成功率、429 数、生成任务队列、Spider 目标站点状态、MinIO 上传失败和 Qdrant 查询耗时。费用相关至少按模型和任务类型统计调用次数，便于发现页面重复触发。

密钥、endpoint 和模型名由外部配置注入。切换模型前先在独立 collection 或测试环境验证嵌入兼容性，再决定是否全量重建。
