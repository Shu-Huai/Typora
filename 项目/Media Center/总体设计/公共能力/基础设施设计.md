# 基础设施

Media Center 同时依赖数据库、中间件、对象存储、媒体目录和本机工具。它不是只启动一个 Spring Boot jar 就能工作的应用。基础设施文档需要说明数据放在哪里、服务按什么顺序启动，以及故障时哪些业务可以继续。

本文件回答组件怎么部署和运维；实例之间谁执行任务、锁如何使用以及重复操作怎样收敛，分别见 [[总体实现/分布式能力/多实例部署|多实例部署]]、[[总体实现/分布式能力/分布式锁模型|分布式锁模型]] 和 [[总体实现/分布式能力/幂等规则|幂等规则]]。

## 数据存储

### 媒体目录

五类媒体的原文件位于配置根目录。Windows 部署常见三种路径：本地盘符、映射盘符和 UNC。服务作为不同账号或系统服务启动时，看到的映射盘可能与桌面用户不同，因此“资源管理器能打开”不能证明后端进程有权限。

启动或刷新前检查：

```powershell
Test-Path 'Z:\影视作品'
Get-Acl 'Z:\影视作品'
Get-ChildItem 'Z:\影视作品' -File | Select-Object -First 1
```

读取型模块只需要读权限；Picture 的目录管理需要创建、移动和删除权限。不要给服务账号超过媒体根目录的磁盘权限。根目录变更后，数据库相对路径可以继续使用，但需触发一次一致性检查。

NAS 短暂断开和用户删除整个媒体库在扫描结果上都表现为“路径不存在”。系统先检查根目录健康；根目录本身不可访问时整次刷新失败并保留旧索引，不能把它解释为所有文件已删除。

### MySQL

MySQL 保存媒体实体、文件索引、人物/歌手/类型等关系、外部来源、用户进度、歌单和生成内容记录。大文件本体不存入 MySQL。

表设计需要：

- 文件相对路径或模块定义的稳定键有唯一约束。
- 多对多关系避免重复行。
- 用户数据索引包含 userId 与资源 ID。
- 外部来源索引包含 source type 与 external ID。
- 分页、排序和常用关联字段有索引。
- 物理删除前理解外键级联影响，尤其是进度与歌单。

全量刷新使用批量读写和有限事务。一个覆盖十万文件的单事务会长时间持锁；逐行无事务又会暴露大量半成品。实践上按阶段或批次提交，并用刷新版本/状态控制何时对外可见。

备份至少覆盖不可重建数据：账号、进度、歌单、人工元数据和生成资源关系。只备份 NAS 原文件而不备份数据库，会丢失用户状态。

### Redis 状态

Redis/Redisson 保存短期协调数据：分布式锁、任务准入、状态、播放 session 或临时结果。业务主数据不以 Redis 为唯一副本。Redis 清空会造成活跃任务/会话丢失，但不应删除电影、歌单或进度。

共享 Redis 不等于实例本地状态和本地磁盘也被共享。多实例使用播放缓存时，要么挂载同一共享缓存目录，要么让播放 session 和媒体请求稳定路由到缓存 owner；不能让 Redis 宣称分片已完成，却把请求随机转发到没有该文件的实例。

锁 key 包含模块和资源，例如：

```text
media-center:movie:refresh:lock
media-center:picture:illustration:user:<userId>
media-center:playback:segment:<fileId>:<variant>:<track>:<index>
```

锁需要租约和 owner 语义，不能使用无过期的普通 SET。业务方法退出时释放自己持有的锁；任务超时后允许新请求恢复。

Qdrant 只保存 Picture 的向量索引。collection 的向量维度、距离函数和模型版本有记录。Qdrant 数据可由原图与嵌入模型重建，因此备份优先级低于 MySQL，但全量重建可能很慢，需要容量和任务计划。

### 对象缓存

MinIO 保存封面或 AI 生成图片等对象。bucket、endpoint、凭据和公开/私有访问策略由环境配置。服务账号采用最小权限，OSS 清理只能操作自己的命名空间。

本地缓存包括 Movie/Series fMP4、Picture 缩略图等。缓存目录与原媒体目录物理区分，避免清理脚本误碰原文件。目录需要足够空间和写权限。

| 缓存 | 默认位置 | 生命周期 |
| --- | --- | --- |
| Movie HLS/fMP4 | `D:/Media-Center/movie-hls-cache` | 默认 TTL 72 小时 |
| Series HLS/fMP4 | `D:/Media-Center/series-hls-cache` | 默认 TTL 72 小时 |
| Picture 缩略图 | `D:/media-center/picture-thumbnail-cache` | 文件版本变化时失效，可重建 |

缓存清理只删除派生文件。用户进度在 MySQL，字幕按业务可长期保留；清理任务不能用一个宽泛根目录递归删除。

## 服务调用

### Nacos

各服务通过 Nacos 读取环境配置并注册实例。`spring.application.name` 必须与 Gateway 中的 `lb://Media-Center-*` 一致。Nacos 至少保存数据库、Redis、RabbitMQ、MinIO、模型等连接配置，敏感值不写进仓库默认 yml。

服务启动时配置加载失败应直接报错并指出 dataId/group/namespace，不要带着空连接参数继续启动成“看似在线”的实例。注册成功也不代表依赖健康，Gateway 可能转发到一个无法连接 MySQL 的服务，因此需要 Actuator 健康信息。

### 消息通知

RabbitMQ 传递刷新命令与状态。典型拓扑由 command exchange/queue 和 status exchange/queue 组成；不同模块使用独立 routing key，消息包含 requestId、操作类型、资源 ID 和发起时间。

```text
AdminController
  → 校验并登记请求
  → publish refresh command
  → consumer 获得模块 leader lock
  → 扫描/同步并发布状态
  → status listener
  → WebSocket handler 广播给前端
```

消费者要幂等。消息已经处理成功但 ack 前连接断开时，RabbitMQ 可能再次投递；第二次不能重建整库或重复生成。业务拒绝或格式错误的消息不无限 requeue，必要时进入死信队列。

WebSocket 只负责通知。浏览器连接断开不会撤销任务；重连后要通过状态存储查询当前结果。广播消息包含 requestId，前端只处理与自己操作相关的事件。

### 网关端口

Gateway 默认端口 `23000`。Movie `23003`、LLM `23009`、Series `23010`、Picture `23011`；其他服务由各自配置确定。外部访问统一走 Gateway，直接模块端口仅用于本机诊断。

Gateway 路由使用服务发现和 StripPrefix。新增模块接口时同时更新 route、反向代理和前端基址。Knife4j 聚合 API 文档依赖服务发现，生产环境是否公开由安全配置决定。

媒体响应需要特殊代理设置：音频 Range header 不被剥离；HLS `.m3u8/.m4s` MIME 正确；WebSocket Upgrade 可用；长任务普通 HTTP 不设置无限超时。

### 内部调用

Framework 子模块提供统一响应、异常、日志、安全、公共 VO 和 Feign Client。它是编译时共享库，不作为独立业务服务启动。

公共响应示意：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

Feign 调用通过 Nacos 服务名和负载均衡定位。连接/读取超时按调用类型设置，不能给所有接口统一十分钟。内部 token interceptor 只对受信 Feign Client 添加，重试仅用于幂等操作。

## 媒体运行环境

### 媒体工具

Movie、Series 在 PATH 或配置位置找到 FFmpeg/ffprobe。ffprobe 读取流、packet/frame 时间戳和关键帧；FFmpeg 执行音频 AAC、1080p 编码和 fMP4 输出。

部署前记录版本和可用编码器：

```powershell
ffmpeg -version
ffprobe -version
ffmpeg -hide_banner -encoders | Select-String 'h264_nvenc|libx264|aac'
```

NVENC 还依赖 NVIDIA 驱动和硬件会话能力。GPU 编码不可用时是否回退 CPU 由 1080p 编码策略决定；SOURCE 视频 copy 不需要 GPU。进程启动参数使用明确参数数组，避免路径空格和 shell 注入。

每个任务设置超时，捕获 stdout/stderr 并限制日志体积。停止任务时终止对应进程树；不能用全局 `taskkill ffmpeg` 误杀其他用户任务。

### 资源容量

容量规划观察 CPU、GPU 编码器、NAS 顺序/随机读取、缓存盘写入、网络出口和 JVM。视频任务通常是最大负载，但 Picture 全量嵌入和大量缩略图也会争用磁盘。

采用有界队列而不是无限接受：

- 队列有空位：返回已接受/准备中。
- 队列满：快速返回明确繁忙状态。
- session 已失活：尚未开始的预热任务可取消。
- 已在执行的共享分片：允许完成并缓存。

磁盘空间设置预警。TTL 清理不能保证突发流量下永不满盘，可增加高水位清理：先删最久未使用的可重建缓存，并保留安全余量。

### 启动顺序

推荐顺序：

1. 挂载并验证媒体目录、缓存目录。
2. 启动 MySQL、Redis、RabbitMQ、Nacos。
3. 按需启动 MinIO、Qdrant 和模型依赖。
4. 启动 Auth、OSS、LLM、Spider 与业务服务。
5. 确认服务注册和健康后启动 Gateway。
6. 启动前端或反向代理。

顺序不是绝对要求，但能减少服务反复注册和首个请求失败。生产可使用依赖健康检查与自动重启，不用人工死等固定秒数。

### 运行监控

日志至少带时间、服务、请求/任务 ID、用户或资源 ID 和错误码。文件路径可能包含隐私，普通 INFO 日志可记录相对路径或脱敏值，DEBUG 再提供诊断细节。

重点指标：

- HTTP 错误率和延迟。
- RabbitMQ 队列深度、消费失败和死信。
- Redis 内存、锁等待和过期。
- MySQL 连接池与慢查询。
- FFmpeg 活跃数、队列、失败与平均速度。
- 缓存目录大小和剩余磁盘。
- Qdrant 查询/写入失败及待嵌入数量。

## 运维恢复

### 健康检查

一次完整检查不能只看 Java 进程：

```text
端口监听
  → Nacos 有健康实例
  → Gateway 路由返回业务健康
  → 数据库与消息组件可用
  → 媒体目录由服务账号可读
  → FFmpeg/ffprobe 可执行
  → 前端实际 API/WebSocket/媒体请求成功
```

“连接服务器失败”先看 Gateway 端口和浏览器 Network；“列表为空”再看业务服务和数据库；“只有播放失败”重点看 Movie/Series、FFmpeg、缓存权限和媒体响应。

### 备份恢复

备份范围：MySQL 全量与增量、Nacos 配置、MinIO 中不可轻易再生成的对象，以及部署配置。Redis、HLS/fMP4 和缩略图通常不备份。

恢复演练比备份文件存在更重要。恢复后检查用户 ID/外键、媒体相对路径、MinIO key、JWT 密钥和外部来源绑定。NAS 路径改变时修改根目录配置并刷新，不用改写每条绝对路径。

### 故障隔离

| 故障 | 处理 |
| --- | --- |
| Nacos 不可用 | 已加载配置的实例可短期运行；新启动/发现受影响 |
| MySQL 不可用 | 业务查询失败，停止有写入的刷新任务 |
| Redis 不可用 | 锁/session/任务准入受影响，不冒险并发执行 |
| RabbitMQ 不可用 | 不接受异步刷新，普通只读查询可继续 |
| MinIO 不可用 | 对象上传失败，NAS 原媒体不受影响 |
| Qdrant 不可用 | 语义搜索失败，图片目录仍可用 |
| 缓存盘满 | 停止新转码/缩略图并清理可重建缓存，保护原盘 |

### 发布检查

发布前运行后端构建和前端构建，检查 Nacos 配置差异、数据库迁移和端口冲突。涉及播放代码时使用真实文件做浏览器验收；涉及路径操作时用临时目录执行创建、移动、删除和越界检查。

发布后先验证只读接口，再验证单个小任务，最后执行全量刷新或长视频播放。这样发生配置错误时不会一上来就修改整个媒体库。
