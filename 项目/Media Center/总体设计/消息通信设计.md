# 消息通信设计

Media Center 同时使用 HTTP、WebSocket、RabbitMQ、Feign 和文件事件。它们的可靠性、时延和语义不同，不能因为都叫“消息”就使用同一套重试或成功判断。

## 通道职责

### HTTP

短查询、配置、进度、prepare 和媒体读取使用 HTTP。请求应在可接受时间内返回，长扫描和模型生成返回任务接收状态，不让连接等待最终结果。

### WebSocket

WebSocket 向已连接页面推送刷新、summary、illustration 等状态。它不是任务主库；断线后前端通过状态查询恢复。每条消息带资源 ID、requestId、状态和版本。

### RabbitMQ

RabbitMQ 传递刷新 command 和 status、长任务通知及跨实例解耦事件。command 是可重投的，consumer 必须幂等；status 可重复广播，客户端拒绝状态倒退。

### Feign

Feign 适合业务服务到 LLM、Spider、OSS 的同步调用。设置超时、错误映射和 requestId，避免在一个 HTTP 请求中无限递归调用其他服务。

## 刷新消息

### Command

command 包含 module、requestId、发起人、触发来源和配置快照。非 leader 收到后按设计重投或等待 leader，不应每个实例同时扫描。

### Status

status 包含 taskId、module、state、processed、failed、errorCode 和 version。状态写入 MySQL 或 Redis 的持久/短期位置，WebSocket 只是通知。

### Ack

consumer 完成幂等检查并记录可恢复状态后再 ack。FFmpeg、NAS 或外部服务失败时按错误类型重试或进入 FAILED，不把异常吞掉后 ack 成功。

### 重投

重复 messageId 不产生第二个实体、第二个外部对象或第二个刷新任务。request-gate 只是入口优化，唯一键和任务记录才是最终防线。

## WebSocket

### 连接

连接 URL、origin、token/cookie 和 Gateway proxy 必须明确。前端不同 composable 使用不同路径，不能把 Movie 播放 HLS URL 当成 WebSocket 地址。

### 重连

指数退避并设置上限；连接恢复后重新订阅或查询当前任务。重连期间用户操作可保存在 pending 状态，但不能自动重复提交模型任务。

### 过滤

消息按 requestId、资源 ID、用户 ID 和状态版本过滤。旧页面、旧 Track、旧 Movie session 的消息不能更新当前组件。

### 关闭

页面卸载释放 socket 引用；共享 socket 只有在没有订阅者时关闭。后台断开不应阻塞普通列表读取。

## 故障语义

### 可重试

连接超时、Rabbit consumer 暂时不可用、HTTP 502、外部 429 和部分 5xx 可以退避重试。重试必须有上限、requestId 和幂等键。

### 不可重试

参数非法、权限不足、文件根目录越界、格式不支持和 schema 不兼容应立即失败，重复重试只会制造噪声。

### 超时接管

任务状态 RUNNING 超过 lease 后由新 owner 接管。旧 owner 的迟到结果使用版本或 fencing token 拒绝，不能用最后写入时间覆盖新结果。

### 前端提示

把 PREPARING、重试中、FAILED、权限错误和依赖不可用分开显示。WebSocket 断线不是任务失败，任务失败也不一定意味着页面不可用。
