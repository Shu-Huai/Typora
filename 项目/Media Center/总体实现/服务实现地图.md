# 服务实现地图

后端仓库不是只有五个业务服务，还包含 Gateway、Auth、Framework、LLM、Spider、OSS 等公共服务。理解启动顺序和调用方向，比记住每个 Controller 名称更适合定位“连接服务器失败”、数据为空或异步任务不更新的问题。

## 服务目录

### 外部入口

`Media-Center-Gateway` 暴露统一 HTTP/WebSocket 入口，使用 Nacos 服务发现和 StripPrefix 路由到业务模块。`Media-Center-Auth` 负责用户身份、JWT 和权限数据，前端不直接访问业务服务端口。

### 内容服务

`Media-Center-Book`、`Media-Center-Movie`、`Media-Center-Series`、`Media-Center-Music`、`Media-Center-Picture` 分别拥有自己的 Controller、Service、Mapper、配置和刷新监听。它们共享公共协议，不共享内容表和本地业务身份。

### 能力服务

`Media-Center-LLM` 提供模型调用和 embedding，`Media-Center-Spider` 访问豆瓣、QQ Music 等外部资料，`Media-Center-OSS` 管理 MinIO 对象。业务服务保存本地关联，能力服务不直接写业务模块主表。

### Framework

Framework 子模块提供 Response、异常、安全、日志、Feign DTO 和公共配置。业务规则、Movie 分片算法、Picture 路径解析不能因为多个模块都“看起来需要”就无边界塞进 Framework。

## 启动顺序

### 基础设施

先准备 MySQL、Redis、RabbitMQ、Nacos、MinIO、Qdrant 和 NAS 访问。基础设施连通不代表服务健康：还要确认数据库 schema、Rabbit exchange、Nacos 配置和文件根目录已准备。

### 注册层

启动 Nacos 和 Gateway 后，再启动 Auth、能力服务和业务服务。业务服务启动日志应能看到服务名、端口、配置、数据库、Redis、RabbitMQ 和必要外部依赖的最终状态。

### 前端

前端只需要 Gateway API base 和 WebSocket base。开发环境可以 Vite 代理，生产环境使用 Nginx 或 Gateway 统一转发；不要让浏览器直接访问业务服务端口。

### 监听任务

业务服务启动后重新参与 leader 选举。只有 leader 注册文件 watcher，其他实例保持查询和任务接管能力。启动校准刷新与 watcher 事件必须使用同一 admission 规则。

## 调用方向

### 查询

```text
Browser -> Gateway -> business Controller -> Service -> MySQL/NAS
```

查询不应绕过业务 Service 直接从公共数据库表拼数据。详情、文件和进度需要使用模块自己的资源权限校验。

### 长任务

```text
Browser -> business Controller
  -> Rabbit command
  -> leader consumer
  -> scanner / generator / external client
  -> MySQL + status exchange
  -> WebSocket / status query
```

消息只解耦任务执行，不替代数据库事实。发起实例断开后，任务仍应能查询终态。

### 媒体请求

Movie/Series 的 playlist 和分片请求不经过 RabbitMQ，因为播放器需要低延迟响应；HTTP 请求进入缓存状态检查和受控 FFmpeg 生成。Book PDF、Music 音频和 Picture 原图使用 Range 或 Resource 流。

### 外部服务

Spider、LLM、OSS 调用必须从业务 Service 发出，带 requestId、资源 ID 和超时。外部失败按功能降级：本地媒体索引和已有内容不能因为一个 summary 或封面失败而不可用。

## 状态位置

### MySQL

保存主实体、关系、来源、用户数据、派生任务终态和必要版本。它是刷新完成后可恢复事实的首选位置。

### Redis

保存锁、leader、request-gate、session、window status 和短期 pending。每个 key 需要明确 owner、TTL、重建方式和 Redis 不可用时的拒绝策略。

### 文件系统

NAS 保存源媒体；本地或共享缓存保存计划、HLS 分片、字幕、thumbnail 和临时文件。READY 状态必须与最终文件同时可见，不能先写 Redis 再慢慢生成文件。

### 消息

RabbitMQ 保存传输中的 command/status，不应被当作历史任务表。消息丢失、重复和消费者重启都需要由数据库状态、唯一键和下一次校准刷新兜底。

**变更边界**

#### 新增接口

先确定资源归属，再在业务模块增加 Controller、DTO、Service 和前端 API；只有稳定跨模块协议才进入 Framework。Gateway 只增加路由，不复制业务逻辑。

#### 新增派生能力

先写主数据和状态，再接入 LLM、OSS、Qdrant 或 FFmpeg。派生能力失败时必须能重试、能显示原因、能保留旧成功结果。

#### 新增配置

配置 key 必须有默认值、校验规则、生产来源和变更影响。线程数、缓存 TTL、预热窗口和外部超时属于运行参数，不应散落在 Controller 常量中。

#### 服务拆分

只有存在独立部署、独立依赖或稳定边界时才拆服务。为了文件大小把一个业务类拆成多个服务，会增加 Gateway、Nacos、MQ 和部署故障面。
