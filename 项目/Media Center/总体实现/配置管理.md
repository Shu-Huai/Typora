# 配置管理

配置决定服务连接哪里、扫描哪些文件、生成多少派生资源。配置错误经常表现为“前端连接失败”“列表为空”“播放找不到文件”，因此配置必须有来源、校验、作用域和回滚说明。

## 配置来源

### 本地文件

各模块 `application.yml` 和 example 文件保存无敏感默认值、服务名、端口、配置 key 和基础参数。example 只能作为模板，不能直接当作已经适合个人 NAS 的运行配置。

### Nacos

数据库、Redis、RabbitMQ、Gateway 路由和外部服务地址通常由 Nacos 或环境变量提供。启动日志要记录配置加载成功的 dataId、group 和 profile，但不要打印密码、JWT secret 或 token。

### 前端环境

`.env.development`、`.env.production` 只提供前端运行时地址和构建标识。Vite 会把变量编译进 JS，任何 secret 放入 `VITE_` 变量都等于公开发布。

### 用户配置

媒体根目录、允许扩展名、播放参数和清理参数通过各模块 Config 表或管理接口保存。用户提交的配置由后端枚举和范围校验，不能仅依赖前端 select。

## 模块配置

### Movie Series

需要媒体根目录、允许扩展名、缓存根目录、FFmpeg/ffprobe、segment/window、预热、AAC、1080p、TTL 和并发上限。Movie 与 Series 的缓存根目录、Redis key 前缀和文件身份必须分离。

### Book

需要 `bookBaseLocate` 和允许的 PDF/EPUB/TXT 类型。阅读格式是业务能力，不应通过把扩展名加入列表就声称支持 MOBI、CBZ 或其他格式。

### Music

需要 `musicBaseLocate`、音频扩展名、默认文件选择规则、Spider/歌词来源和扫描参数。文件名解析规则变更要记录影响范围，避免配置字段和代码正则不一致。

### Picture

需要 `pictureBaseLocate`、图片类型、thumbnail 根目录、尺寸限制、Qdrant collection、模型名和向量维度。根目录和派生目录不能重叠，避免清理器删除源图片。

## 校验规则

### 路径

启动时确认路径存在、可读、是目录，并记录规范化绝对路径。Windows 映射盘在服务账号下可能不可见；生产部署优先使用服务账号可访问的 UNC 路径或明确挂载。

### 数值

线程数、队列大小、TTL、预热窗口、segment 时长和码率必须有上限。0、负数、极大并发和空缓存根目录都应在配置阶段失败，而不是等用户播放时才报错。

### 枚举

文件类型、variant、角色、状态和 module type 使用后端枚举或白名单。未知值返回配置错误，不能静默忽略导致“刷新成功但没有文件”。

### 依赖

FFmpeg、Qdrant、OSS、Spider、LLM 地址要通过健康检查或首次调用验证。可选依赖失败时要明确哪些页面降级，不能把依赖错误包装成数据库错误。

## 变更流程

### 预发布

先在开发 profile 修改并记录旧值、新值、影响模块和预期结果。涉及根目录、缓存根目录或数据库连接的变更先停后台任务，确认没有正在写入的 FFmpeg/文件操作。

### 生效方式

区分启动读取、请求读取和动态刷新。Watcher、线程池和 `@ConfigurationProperties` 不一定能安全热更新；不确定时重启单个业务服务并观察 leader、session 和 MQ 接管。

### 回滚

配置回滚要恢复旧值并清理因新配置生成的不兼容缓存。variant、planVersion、Qdrant model 和 database schema 变化不能只回滚 yml，还要决定旧派生数据是否继续可用。

### 审计

保存配置变更人、时间、key、旧值摘要、结果和错误。敏感值只保存 hash 或“已设置”状态；日志不得打印完整 token、密码和 NAS 凭据。
