# 运行实现

本文描述 Media Center 当前代码在运行时如何组织服务、消息、数据库和文件系统。它不是目标架构，而是开发人员排查问题时使用的实现地图。模块自己的扫描细节、播放细节和运行边界分别放在模块目录。

## 服务边界

### 模块进程

每个业务模块是独立的 Spring Boot 工程，Gateway 负责统一入口，业务模块负责本模块的 Controller、Service、Mapper 和后台任务。模块之间不直接读取对方的数据库表，跨模块关系通过 HTTP、RabbitMQ 或公共表约定完成。

```text
浏览器
  -> Gateway
     -> Movie / Series / Book / Music / Picture
        -> MySQL
        -> Redis
        -> RabbitMQ
        -> NAS 文件系统
```

### 数据职责

MySQL 保存可重建之前仍需保留的业务事实：媒体实体、文件路径、外部来源、用户进度和任务终态。Redis 保存 session、锁、短期状态和去重窗口。NAS 保存原始媒体与模块派生文件，缓存文件不应反向成为数据库的唯一事实来源。

### 配置边界

`application.yml` 和配置中心提供文件根目录、缓存根目录、RabbitMQ、Redis、FFmpeg、外部服务和清理策略。启动阶段应校验目录、可执行文件和必需参数；运行中不要把用户请求中的任意路径直接拼接成文件系统路径。

### 请求线程

Controller 只做参数校验、鉴权和调用服务。长时间扫描、元数据同步、缩略图、向量和转码任务进入受控线程池或消息消费者。同步接口返回任务标识后，前端通过轮询、WebSocket 或状态接口获取结果，不应让 HTTP 连接承担整库扫描时长。

## 运行链路

### 刷新链路

模块刷新统一遵循“入口准入—leader 执行—扫描解析—事务写库—派生任务—状态广播”的顺序。监听器只负责触发增量刷新；全量扫描是修正事件丢失、重启和 OVERFLOW 的最终手段。

```text
HTTP / 启动 / 文件事件
  -> request-gate
  -> RabbitMQ command
  -> leader listener
  -> scanner + parser
  -> transaction upsert
  -> derived jobs
  -> status exchange / WebSocket
```

### 播放链路

Movie 和 Series 的播放入口都先解析具体文件身份，再创建 session。prepare 只准备首个窗口；m3u8、init.mp4 和 m4s 请求触发按需生成。完成文件使用临时目录加原子发布，避免 HTTP 线程读取半成品。

### 读取链路

列表接口从数据库读取分页数据，详情接口再装配关系和派生资源 URL。文件下载接口必须验证数据库记录与规范化路径的关系，并限制在配置根目录内；不能因为请求参数包含绝对路径就直接访问 NAS。

### 状态链路

任务状态至少区分 ACCEPTED、RUNNING、SUCCEEDED、FAILED、CANCELLED。状态消息是通知，不是唯一事实；消费者重启后要能从数据库或持久任务记录恢复。Redis 中的短状态过期后，业务仍应通过数据库重新构建可用状态。

## 故障处理

### 重复执行

入口 request-gate 只减少重复请求，不能替代数据库唯一约束。消费者可能因为 ack 丢失重试，写库必须使用业务键 upsert；外部 API、文件写入和向量写入要分别设计幂等键。详见 [[总体实现/分布式能力/幂等规则|幂等规则]]。

### 进程重启

进程重启会丢失本机线程、future 和 watcher 对象，因此启动时要重新注册监听、重新参与 leader 选举，并把未完成任务标为可恢复或失败。播放 session 可以重建，但不能把已完成 global 缓存误删。

### 文件不可见

多实例部署中 Redis READY 不代表所有实例都能看到文件。缓存要使用共享盘，或者由 owner instance 稳定承接媒体请求；仅复制 Redis 状态会导致 m3u8 成功而 m4s 404。部署和验证要求见 [[总体实现/分布式能力/多实例部署|多实例部署]]。

### 数据派生不一致

删除数据库记录前先确认文件状态和关联任务；删除派生文件失败时保留可重试状态，不要静默报告成功。原始文件移动通常表现为旧路径删除加新路径创建，刷新过程不能依赖文件名推断“同一个对象”。

## 运行证据

### 运行证据

排查刷新问题时同时记录：请求响应、任务状态、消费者日志、数据库行数、Redis key、目标文件路径和文件 mtime。只看到前端“成功”不能证明数据库已一致；只看到 Redis 状态也不能证明文件可读。

### 变更检查

每次改动至少确认：

- 入口是否仍然具备准入和幂等保护；
- 重启、重复消息和 leader 切换是否仍可恢复；
- 文件路径是否经过根目录校验；
- 派生任务失败是否留下可诊断状态；
- 构建结果、浏览器行为和真实运行环境是否分别记录。
