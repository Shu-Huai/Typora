# 公共服务实现

公共服务决定业务模块如何进入系统、如何取得身份、如何调用外部能力和如何保存派生对象。它们不拥有 Movie、Series、Book、Music、Picture 的主业务关系，但任何一个边界错误都可能表现为所有页面不可用。

## Gateway Auth

### Gateway

`Media-Center-Gateway` 使用 Spring Cloud Gateway、Nacos 服务发现和 StripPrefix 路由。浏览器只访问统一入口，Gateway 不读取媒体数据库，也不拼接业务资源路径。

```text
/auth/**    -> Auth
/movie/**   -> Movie
/series/**  -> Series
/book/**    -> Book
/music/**   -> Music
/picture/** -> Picture
```

路由配置必须同时覆盖 HTTP、WebSocket 和长媒体响应。普通 API 能通不代表 HLS、Range 或 WebSocket 一定能通，代理超时、Upgrade header 和缓存策略要分别配置。

### Auth

`Media-Center-Auth` 负责注册、登录、JWT 签发、用户状态和角色权限。密码只在服务端校验和哈希，JWT secret、内部 token 和数据库密码从外部配置注入。

### Security

Framework-Security 在业务服务中解析 JWT、写入 SecurityContext 并执行方法权限。角色只能说明“能做哪类操作”，资源 owner 仍由业务 Service 根据 userId 查询确认。

### Internal caller

业务服务调用 LLM、Spider 和 OSS 时使用内部身份，不信任浏览器转发的 caller header。Feign interceptor 添加内部 header，Gateway 对公网同名 header 做覆盖或剥离。

## Framework

### Common

Framework-Common 提供 Response、异常、枚举、分页和稳定 DTO。公共 DTO 只表达跨服务协议，不把某个模块的 MovieFile、Playlist 或 Qdrant 细节泄漏给所有服务。

### Log

Framework-Log 统一 requestId、操作日志和异常日志。媒体二进制、模型大响应、密码、token 和 NAS 凭据不进入普通日志。

### Security module

Security module 负责 token filter、用户上下文、权限注解和内部调用验证。它不负责 Book 进度、Movie playback lock 或 Picture path resolver。

### Error mapping

公共异常处理器把参数错误、未认证、无权限、资源不存在、依赖失败和业务失败转换成稳定 code。二进制接口保留原生 ResponseEntity，不强行套 JSON。

## LLM Spider OSS

### LLM

LLM 服务提供文本生成、图像生成和 embedding。业务服务决定输入上下文、资源归属、任务幂等和结果保存；LLM 只负责模型调用、超时、限流和结果基本校验。

### Spider

Spider 通过豆瓣、QQ Music 等外部站点提供候选和详情 DTO。它不写业务主表，外部页面解析失败返回明确错误，业务模块决定是否保留旧资料。

### OSS

OSS 封装 MinIO 的上传、删除和前缀清理。对象 key、引用、用户权限和版本由业务模块控制；OSS 不知道一个对象是否属于 Book 插图或 Picture 重绘。

### 调用状态

公共调用通过 requestId、资源 ID、source、model 和版本关联业务任务。临时 URL、外部 source、向量和对象都不能在业务数据库中留下无法追溯的孤儿记录。

## 运维边界

### 启动

先启动 Nacos、MySQL、Redis、RabbitMQ，再启动 Auth、Gateway、LLM、Spider、OSS 和业务模块。每个服务启动日志确认 profile、端口、注册状态、依赖连接和关键目录。

### 降级

LLM、Spider、OSS、Qdrant 失败时只影响对应派生能力；Auth 或 Gateway 失败会影响入口；MySQL、Redis、RabbitMQ 的影响按具体任务区分。降级必须向前端返回可解释状态，不能返回空成功。

### 配置

公共服务地址、超时、内部 token、bucket、模型和外部站点参数由 Nacos/环境变量提供。服务名、route prefix 和 dataId 变更要同时调整 Gateway、Feign 和前端环境。

### 发布

公共服务先于业务模块发布，Framework 协议变更遵循向后兼容。Gateway 路由和前端 API 只有在目标服务已注册且可访问后才切换。
