# 本地开发

本文给第一次进入 Media Center 仓库的开发者一条可重复的工作路径。它不写测试教程，重点是代码定位、服务启动、前后端联调、媒体文件准备和改动收束。

## 仓库准备

### 后端

后端根目录是 `E:\JetBrains\IDEA\Media-Center-Backend`，使用 Maven reactor 管理 Gateway、Auth、业务模块和公共服务。修改前先确认当前分支、工作区状态和正在运行的旧进程，避免把旧构建产物当成新代码。

### 前端

前端根目录是 `E:\JetBrains\WebStorm\Media-Center-Frontend`，使用 Node、Vite、Vue、TypeScript 和 npm。`node_modules`、`dist`、日志和个人 `.env` 不属于业务文档或源码改动。

### 文档

项目文档位于 `Z:\Typora\项目\Media Center`。模块需求、设计、实现和专项文档必须与源码边界一致；接口、配置、数据库和前端行为变更时同步更新对应文档。

### 路径约定

本地媒体可以来自 NAS、UNC 路径或映射盘。开发者不能把个人盘符写入代码、SQL、前端 URL 或测试 fixture；代码只接受配置根目录下的相对路径。

## 启动流程

### 基础服务

先准备 MySQL、Redis、RabbitMQ、Nacos；需要图片语义搜索、对象资源、Spider 或 LLM 时再启动 Qdrant、MinIO 和对应服务。启动后记录端口、profile、配置来源和健康状态。

### 后端服务

先启动 Gateway 与 Auth，再启动需要联调的业务模块。Movie/Series 播放还要确认 FFmpeg、ffprobe、源文件根目录和缓存目录；Picture 还要确认 thumbnail、Qdrant 和 LLM 配置。

### 前端服务

在前端根目录执行 `npm run dev`，浏览器访问 Vite 地址。确认 API base、WebSocket base 和 Gateway 端口一致；如果页面能加载但请求失败，先看 Network 的实际 URL，不要先改组件逻辑。

### 登录状态

前端登录后 token 进入统一存储，刷新页面验证路由守卫、请求拦截器和 WebSocket 重连。切换后端端口或 profile 时要清理旧 token 与旧页面 session，避免用旧身份排查新服务。

## 联调路径

### 普通模块

先访问列表，再进入详情，最后执行文件读取或用户操作。这样能区分 Gateway、数据库索引、文件路径和派生资源问题。配置页修改后重新读取配置，确认保存接口和实际扫描使用的是同一值。

### Movie Series

使用已入库的具体 MovieFile 或 EpisodeFile 进入播放，不直接把源文件路径传给前端。观察 prepare、master、playlist、init、m4s、subtitle、heartbeat 请求，再检查暂停、seek、清晰度和切集行为。

### Book

准备 PDF、EPUB、TXT 各一种，分别从详情页进入对应 viewer。PDF 观察 Range，EPUB 观察资源加载，TXT 观察 charset 和分页；不能用 PDF 能打开推断三种格式都已兼容。

### Music Picture

Music 先验证 track、artist、file、lyric 和 Range；Picture 先验证 folder、file、thumbnail、metadata，再验证移动、删除、semantic search 和 illustration。派生功能失败时主数据仍应可用。

## 改动收束

### 代码边界

前端改 API 契约时同步 interface、页面和错误处理；后端改字段时同步 entity、mapper、SQL 和前端响应类型；数据库改结构时先写 migration 说明，再改读写逻辑。

### 运行清理

结束联调后停止 Vite、Java、FFmpeg、watcher 和消息消费者，检查监听端口与临时缓存。未清理的播放任务会影响下一次 session，未清理的旧服务会让浏览器请求落到错误版本。

### 交付记录

记录改动文件、配置变化、数据库变化、启动方式、实际请求和已知未覆盖环境。不要只写“已修复”；要能让另一个开发者重现同一条链路。

### 分支状态

提交前检查 `git status --short`、`git diff --check` 和前后端工作区。生成产物、个人配置、日志和无关模块不要混入提交；文档改动也要保持目录链接有效。
