# 发布部署

Media Center 的发布不是单纯替换一个 Jar。Gateway、Nacos 配置、业务服务、前端静态资源、数据库迁移、Redis/MQ 状态和 NAS 缓存都可能影响结果。发布过程必须按依赖关系推进，并保留回滚边界。

## 发布单元

### 后端

每个 Spring Boot 模块独立构建和启动。需要确认 Jar 包包含正确的 Spring Boot launcher、profile 和配置来源，不能把 `.jar.original` 当成可部署产物。

### 前端

执行 Vite production build 后部署 `dist` 静态资源。HTML、JS、CSS 和 worker 需要一致版本；旧 HTML 引用新资源或旧浏览器缓存引用旧 API 都会造成难以判断的契约错误。

### 数据库

结构 migration 与代码发布有先后顺序。向后兼容的新增列可先发布 schema，再发布代码；删除列、改变类型和收紧唯一键必须经过数据检查和停机/灰度计划。

### 外部资源

确认 NAS 可见、缓存根目录可写、FFmpeg 可执行、Redis/MQ/Nacos 可连接，必要时检查 MinIO、Qdrant、Spider 和 LLM。依赖不全时先发布不使用该能力的模块，避免全站启动失败。

## 发布顺序

### 迁移阶段

备份数据库，执行兼容 migration，记录影响表、行数和耗时。迁移期间暂停高风险全量刷新和批量文件操作，避免旧代码读到半完成结构。

### 服务阶段

先发布公共 Framework 依赖和能力服务，再发布 Auth、Gateway 和业务服务。启动后验证服务注册、路由、鉴权和配置 profile；不要只看到 Java 进程存在就继续发布。

### 前端阶段

前端静态资源最后切换，确保 API 契约已在 Gateway 和业务模块生效。必要时使用带版本目录的静态文件和短 HTML 缓存，避免浏览器继续加载旧播放器逻辑。

### 任务阶段

发布后观察 leader 选举、watcher 注册、MQ consumer、Redis lock 和清理任务。播放缓存 READY 状态与文件可见性要一起确认，不能在旧实例仍写文件时启动新清理器。

## 运行检查

### 入口

从登录、首页、一个列表、一个详情开始验证 Gateway 和 Auth。然后按模块验证文件读取、配置保存和一个派生能力，最后才执行全量刷新或长视频播放。

### 媒体

Movie/Series 验证 prepare、m3u8、init、m4s、字幕和 heartbeat；Book 验证 PDF Range、EPUB、TXT；Music 验证音频 Range；Picture 验证原图、thumbnail 和目录操作。

### 多实例

两实例部署时确认只有一个 watcher leader，另一个实例仍可查询、接管任务和读取共享缓存。若使用本地缓存盘，必须配置 owner 路由，不能随机转发媒体请求。

### 监控

保留 Gateway access log、业务 requestId、任务状态、MQ messageId、FFmpeg stderr、文件路径和数据库 migration 日志。敏感 token、密码和完整媒体内容不进入日志。

## 回滚策略

### 前端回滚

保留上一版 dist 和 HTML 入口，播放器契约异常时先切回前端，确认后端接口仍向后兼容。清理浏览器缓存前先记录实际加载的 JS 版本。

### 服务回滚

停止新实例前确认旧版本能够读取当前数据库结构和缓存。涉及新字段时保留兼容列；涉及播放 planVersion、Qdrant model 或缓存布局时不能只替换 Jar。

### 数据回滚

可逆 DDL 使用 down migration；不可逆数据变更从备份或专用补偿脚本恢复。回滚期间暂停刷新、清理、转码和图片派生，避免新旧代码同时改同一事实。

### 事件恢复

发布中断后重新确认 MQ 未确认消息、Redis RUNNING 状态和文件临时目录。旧 owner 退出后由 lease 接管；不要人工删除所有 Redis key 来“恢复服务”。
