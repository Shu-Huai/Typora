# 数据库变更

本文规定修改 MySQL 表、索引、字段或初始 SQL 时如何组织工作。数据库变更必须同时考虑旧代码、刷新任务、用户进度、外部来源和派生索引，不能只让本地启动通过。

## 变更分类

### 表结构

新增表、列、索引、外键和唯一键属于结构变更。先明确主键、业务键、null 语义、软删除规则、字符集和时区，再决定 SQL 顺序。

### 数据修复

回填旧路径、重新绑定 source、修正重复关系和补齐派生状态属于数据变更。脚本必须幂等，按主键批次执行，保存影响行数和失败范围。

### 兼容调整

新增列先允许 null 或默认值，代码先兼容旧列，再逐步写新列，最后收紧约束。不要一次提交“删旧列、改 API、改前端、改刷新”而无法判断失败层。

### 索引调整

索引服务列表、路径查找、进度 upsert、source 匹配和状态清理。建立前检查重复、基数和写入代价；删除前确认 MyBatis XML、注解 SQL 和后台任务没有隐式依赖。

## 模块表变更

### Movie Series

MovieFile、SeriesEpisodeFile 的路径、媒体信息和版本变化会影响播放 plan、字幕、缓存和 progress。新增媒体字段时要同步 ffprobe 写入、prepare 返回和前端时间轴。

### Book

BookFile 的类型、路径和作者出版者外键影响三种 reader。增加格式或位置字段时先定义格式专属语义，不能把 PDF 页码、EPUB CFI 和 TXT offset 共用一个未经说明的整数。

### Music

MusicTrack、MusicFile、Artist、Album 和 playlist 关系容易出现重复身份。修改唯一键前先统计同名不同歌手、同一 Track 多文件和歌单重复项，决定是允许、合并还是清理。

### Picture

PictureFile 的 relative_path、metadata、embedding index 和 illustration 是不同事实。变更向量模型时新增 model/dimension/status 字段，不能覆盖旧点后失去重建依据。

## 执行流程

### 编写 SQL

SQL 文件命名包含动作和对象，说明前置 schema、锁风险、是否可重复执行和回滚方法。生产脚本不要依赖个人盘符、客户端工具隐含变量或手工复制粘贴。

### 预检查

执行前检查数据库版本、表行数、重复业务键、长事务和备份可用性。涉及路径或 progress 的变更先导出受影响 ID 和当前值，确保异常时能定位。

### 执行记录

记录开始结束时间、脚本 hash、数据库、影响行数、异常、重试和操作者。长回填按批次提交，避免持有全表锁阻塞列表、播放进度和刷新。

### 发布配套

同一变更必须列出后端 entity/mapper/service、前端 interface/API/page、配置和文档。只改 create.sql 不会改变已经运行的数据库，只改后端也可能让旧数据库启动失败。

## 故障处理

### 重复数据

先导出冲突行，再确定保留对象、迁移外键和删除方式。不要直接加唯一键让 migration 失败，更不要随机删除一行导致用户进度或 source 丢失。

### 部分回填

脚本中断后根据批次游标继续，已成功行再次执行不应产生副作用。失败行保留原因，修复输入后单独重跑，而不是反复全表扫描。

### 旧实例

多实例发布期间旧实例可能仍在写旧字段。使用 expand-contract 顺序，确认所有实例已切换后再删除兼容列或旧状态。

### 派生同步

数据库变更不自动修复 Redis、Qdrant、OSS 和 NAS。明确哪些派生状态需要重建、清理或迁移，避免主表成功后页面继续读到旧缓存。
