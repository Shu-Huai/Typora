# 电影实现

本文对应 `Media-Center-Movie`。业务规则见 [[模块文档/Movie/需求分析|电影模块]]，播放专项说明见 [[模块文档/Movie/播放业务|Movie 播放]]。本文按源码调用链解释电影库刷新、元数据、播放 session、fMP4 分片、字幕和缓存清理，不重新描述产品需求。

## 请求入口

### 电影查询

`MovieController` 负责电影分页、详情和类型查询，调用 `IMovieService` 的 `MovieServiceImpl`。查询结果使用 `GetMovieVO`，实体层由 `MovieMapper`、`MovieFileMapper`、`MovieGenreMapper`、`MoviePersonMapper` 和 `MovieSourceMapper` 组合。

```text
GET /movie/**
  → MovieController
  → MovieServiceImpl
  → MovieMapper + relation mappers
  → GetMovieVO
```

电影实体与文件实体分离：`Movie` 保存标题、封面和 summary，`MovieFile` 保存原始路径、媒体信息和文件身份，Genre/Person/Source 使用关系表连接。详情查询必须以 fileId 进入播放链，不能只用电影标题选择物理文件。

### 播放准备

`PlaybackController` 接收 `PreparePlaybackDTO`，调用 `IPlaybackService.preparePlayback`。服务校验用户、movieFileId、variant、音轨和起始位置，创建或恢复 `PlaybackSession`，返回 `PreparePlaybackVO`，其中包含 sessionId、master.m3u8 URL、时长、恢复进度和字幕轨道。

```text
POST /movie/playback/prepare
  → PlaybackController
  → PlaybackServiceImpl.preparePlayback
  → Redis active-session/session
  → PlaybackTranscodeManager.prepareInitialWindow
  → PreparePlaybackVO
```

用户级 playback lock 防止同一用户同时 replace/heartbeat/close 破坏 session。prepare 不代表整个电影已转完，只保证清单、分片计划和首个播放窗口具备可用状态。

### 媒体请求

`HlsController` 负责 master.m3u8、variant playlist、init.mp4、m4s 分片和字幕响应。它读取缓存状态，判断文件是否已完成；正在准备返回 503，session 或资源过期返回 410，路径非法或不存在返回 404。控制器不直接启动任意 FFmpeg，转码由 `PlaybackTranscodeManager` 和 lazy fMP4 组件负责。

浏览器请求顺序通常是：

```text
master.m3u8
  → variant.m3u8
  → init.mp4
  → segment-000001.m4s / segment-000002.m4s
  → subtitle/default
```

### 播放关闭

`PlaybackController` 的 heartbeat 接收 `PlaybackHeartbeatDTO`，调用 `PlaybackServiceImpl.heartbeat` 更新 Redis session 并持久化用户进度；close/replace 由同一服务处理。播放进度最终写入公共 `user_progress`，媒体类型固定为 MOVIE。

心跳不能被当成转码继续信号。session 活跃只决定保留哪些状态和清理保护；按需转码任务只由 prepare、segment 请求和预热调度触发，暂停或关闭后不应无条件转到影片结尾。

## 核心播放链

### 分片计划

`MovieSegmentPlanResolver` 读取或生成 `segment-plan.json`，由 `Fmp4PlaybackSupport`/ffprobe 提取源文件的实际时间边界和关键帧信息，形成 `MovieSegmentPlan` 与 `MovieSegment`。前端 currentTime 以小数秒传入，后端转换为整数微秒，再查找覆盖该时间点的 segment。

SOURCE copy 模式不能按固定墙钟时间强切。计划使用实际可 seek 的关键帧锚点；HIGH1080/LOW1080 虽然需要视频编码，也沿用同一分段计划和时间单位，保证清晰度切换时进度条不换坐标系。

### Lazy fMP4 生成

lazy 链路由四个组件分工：

| 类 | 责任 |
| --- | --- |
| `LazyFmp4PlaybackEngine` | 根据请求窗口决定要加载哪些 segment |
| `LazyFmp4SegmentCoordinator` | 竞争分布式 segment/window 锁并调度任务 |
| `LazyFmp4MediaGenerator` | 组织 FFmpeg 参数，生成 init 与 m4s 临时文件 |
| `LazyFmp4SegmentCache` | 检查 global/session 文件、状态和发布结果 |

本机 `ConcurrentHashMap` 只做 single-flight 优化；跨实例真正的互斥依赖 Redis lock。FFmpeg 先写临时目录，完成后执行校验和原子移动，HlsController 只发布最终文件，避免浏览器读到半写入 m4s。

### 三档画质

`PlaybackVariant` 区分 SOURCE、HIGH1080、LOW1080。SOURCE 的视频参数使用 copy，音频按浏览器兼容策略转 AAC；配置中没有启用 unsafe codec 自动回退，HEVC/H265 copy 是 SOURCE 的设计前提。1080p 档位使用视频编码和目标码率，但输出仍进入同一 fMP4 session/segment 协议。

典型参数决策由 `MoviePlaybackProperties` 提供：源文件根目录、缓存目录、segment/window 时长、预热范围、AAC 参数、1080p 编码参数、TTL 和线程池上限。配置对象必须在启动时校验，避免服务接受请求后才发现 ffmpeg 或缓存目录不可用。

### 媒体轨道

字幕由 `PlaybackTranscodeManager` 使用 subtitle lock 提取到 session/global 缓存，字幕文件一次完整生成，不按视频 segment 切割。`PlaybackSubtitleFile` 和 `PlaybackSubtitleTrackVO` 保存轨道 id、语言、格式和 URL。

音频与视频在 fMP4 的媒体时间轴中由浏览器组合。音频转 AAC 不能自行产生独立的墙钟起点，生成器必须使用同一 segment 计划的 start/end 和时间戳修正；HLS 清单与字幕 URL 也必须引用同一个 session 的媒体时间基准。

## 缓存管理

### 电影库刷新

`AdminController` 调用 `AdminServiceImpl` 执行全量刷新。request-gate 防止重复 HTTP admission；RabbitMQ command/status 负责跨实例执行和通知；`MovieLeaderCoordinator` 使用 `movie:watcher:leader:lock` 选出目录监听和 command listener 的 leader。

刷新扫描会解析电影文件、写入电影及关系表，并处理文件删除。watcher 只作为增量触发信号，事件丢失或 `OVERFLOW` 后应靠扫描校正；当前源码仍有事件只存在 JVM、OVERFLOW 处理不充分等边界，详见 [[总体实现/分布式能力/文件监听选主|文件监听选主]]。

### Redis 状态

Movie 播放相关 key 包括 session、active session、window status、window lock、subtitle lock、source pretranscode job 和 cache cleanup leader。状态 bucket 带 TTL，锁带 watchdog 或明确 lease；删除 session 不能删除 global 已完成分片，避免用户 A 的缓存被用户 B 的会话操作误删。

```text
movie:playback:user:<userId>:lock
movie:playback:session:<sessionId>
movie:playback:window:<fileId>:<variant>:<window>
movie:playback:subtitle:<fileId>:<trackId>:lock
movie:playback:cache:cleanup:leader:lock
```

具体 key 以 `RedisKeys` 当前实现为准，文档中的结构用于理解作用域，不应直接替换源码字符串。

### Session 缓存

global 缓存存放已经可共享的计划、字幕和完成分片；session 缓存存放当前播放所需的清单和临时文件。拖动进度或切换清晰度时不能删除正在被 FFmpeg 使用的目录，因此 session 可被替换，global 只在 TTL/清理策略允许时删除。

多实例部署还必须解决文件可见性：Redis 里标记 READY 但文件在实例 A 的本地盘，Gateway 把请求转到 B 时仍会 404。当前文档要求共享缓存目录，或将媒体 URL 稳定路由到 owner instance；只共享 Redis 不足够。

### 清理器

`PlaybackCacheCleaner` 使用 `movie:playback:cache:cleanup:leader:lock` 保证一轮只有一个清理 leader。清理前检查文件 mtime、Redis window status、相关锁和 session 活跃状态。删除对象必须限制在配置的缓存根目录，不能递归触碰源媒体目录。

清理器只负责派生缓存；MySQL 进度、电影元数据和字幕业务记录不能按同一 TTL 删除。磁盘高水位策略应优先删除最久未访问、已完成且没有 active session 引用的 global 文件。

## 运行边界

### 分片边界

运行记录覆盖时间点到 segment 的定位、ffprobe/计划生成、FFmpeg 命令和输出、锁竞争与状态，以及 final/temp/global/session 文件边界。

### 接口边界

运行记录覆盖 prepare、heartbeat、session、用户锁、清单、分片、字幕响应、窗口预热、SOURCE 预转码、失败状态、TTL 和活跃状态保护。

### 媒体验收

```powershell
```

真实媒体验收必须使用 ffprobe 和浏览器 Network：检查 init.mp4/m4s 的 codec、duration、start_time，连续播放、暂停后继续、seek、切换 SOURCE/HIGH1080/LOW1080、字幕轨道和心跳恢复。NAS 权限、Edge 解码器和 Gateway Range 请求需单独记录。

### 已知实现边界

当前实现最需要继续改造的地方是持久化转码任务、跨实例缓存可见性、锁过期后的 fencing、进度唯一约束和任务状态恢复。不要通过自动回退把 SOURCE copy 失败伪装成 1080p；先保留错误码、日志和真实媒体证据，确认失败发生在路径、权限、FFmpeg、清单还是浏览器请求层。
