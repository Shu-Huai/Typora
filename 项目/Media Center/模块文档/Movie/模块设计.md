# Movie 模块设计

Movie 模块分为电影库、播放和派生缓存三条链路。电影库负责把 NAS 上的文件变成 Movie/MovieFile 事实；播放负责把一个 MovieFile 变成浏览器可读的 HLS/fMP4；派生链路负责字幕、摘要、外部 metadata 和清理。三者通过稳定 fileId、文件指纹和 Redis session 连接。

## 领域边界

### 电影身份

`Movie` 是用户看到的逻辑电影，`MovieFile` 是可播放的实际文件。标题、封面、summary、genre、person、source 属于电影层；路径、duration、codec、size、lastModified 属于文件层。播放只能从 MovieFile 进入，不能根据标题再次模糊找文件。

### 播放身份

播放业务键由 fileId、文件指纹、variant、音轨、planVersion 和 segmentIndex 构成。SOURCE、HIGH1080、LOW1080 使用同一时间坐标，但不能共享不兼容的媒体文件。

### 外部服务

豆瓣和 LLM 是派生数据来源，不能成为电影主索引的唯一依赖。外部调用失败时电影列表、文件路径和已有播放缓存仍应可用。

## 组件协作

### 查询链路

`MovieController → MovieServiceImpl → MovieMapper/关系 Mapper → GetMovieVO`。Controller 只做参数和权限边界；Service 负责分页、详情和关系组装；Mapper 只负责数据库访问。

### 播放链路

```text
PlaybackController
  → PlaybackServiceImpl
  → MovieSegmentPlanResolver
  → LazyFmp4PlaybackEngine
  → LazyFmp4SegmentCoordinator
  → LazyFmp4MediaGenerator
  → HlsController
```

播放准备创建/恢复 session，分片请求触发窗口任务，HlsController 只发布已完成的最终文件。前端 heartbeat 写进度，不负责决定转码是否继续。

### 刷新链路

`AdminController → AdminServiceImpl → MovieLibrary scan/ingestion → Movie/relations`。Leader 负责 watcher 和 command listener；刷新总规则见 [[总体设计/刷新数据库设计|刷新数据库设计]]，电影差异见 [[模块文档/Movie/刷新数据库|电影刷新数据库]]。

### 清理链路

`PlaybackCacheCleaner` 使用独立 leader lock 扫描派生缓存，检查 session、window status 和活动锁后删除。清理器不访问 MovieFile 源路径，不清理 MySQL 进度。

## 运行约束

### 时间基准

分片计划使用整数微秒保存 source/presentation/decode 时间。前端 currentTime 转微秒后查找半开区间 `[startUs, endUs)`；边界点只命中一个 segment，避免重复播放或跳段。

### 文件发布

FFmpeg 写入临时目录；ffprobe 或输出校验通过后原子移动到 global/session 最终路径。浏览器只能读取完成标记对应的文件，不能读取正在写入的 m4s。

### 配置边界

`MoviePlaybackProperties` 管理缓存根目录、窗口、预热、AAC、1080p、TTL 和线程池。SOURCE 视频 copy 是业务约束，不能通过 unsafe codec 配置自动改成重新编码。

## 设计验收

必须覆盖：MovieFile 与标题身份分离、三种 variant 时间轴一致、SOURCE HEVC copy、暂停/seek 不循环、字幕与 episode/movie file 对齐、缓存 TTL 不删除活跃分片、双实例共享缓存可读。
