# Movie 前端播放

Movie 播放页是前端最复杂的页面。它同时管理 HTMLVideoElement、hls.js、ASS/VTT 字幕、后端 playback session、heartbeat、seek 和 variant 切换。页面代码位于 `src/views/movie-play/index.vue`，时间计算工具位于 `src/utils/movie`。

## 页面状态

### 会话变量

页面至少区分 movieId、movieFileId、sessionId、currentVariant、durationSec、resumePositionSec、playbackStartPositionSec 和 prepare status。路由标题只用于展示，不能成为播放身份。

### 播放器对象

`videoRef` 是浏览器媒体元素，`hlsInstance` 是当前清单控制器，ASS renderer 是当前字幕渲染器。切换资源前先停止旧 HLS load、解绑 media、销毁 renderer，再创建新对象；只改 URL 不足以清理旧事件。

### 时间坐标

后端返回的 prepare 起点可能是 source plan 的锚点，前端显示位置仍以绝对 movie time 为准。`playbackTimeline.ts` 负责归一化起始位置，避免把 segment 内局部时间直接显示到总进度条。

### 交互状态

loading、preparing、playing、paused、seeking、switchingVariant、failed 是互斥或有明确优先级的 UI 状态。暂停时停止 HLS 加载和正常 heartbeat，但保留最后进度；重新播放时从当前 video currentTime 恢复，不重建不必要的 session。

## HLS 生命周期

### 首次打开

```text
route movieFileId
  -> prepare variant + position
  -> receive master.m3u8
  -> create hls.js
  -> attach video
  -> load source
  -> wait metadata
  -> set absolute currentTime
  -> play
```

prepare 返回 FAILED 时显示 errorCode 和重试入口，不在页面内部自动改成 1080p。

### 暂停继续

暂停时记录 `pausedMovieTimeSec`，发送一次带 paused 状态的 heartbeat，停止后续加载。继续播放时先确认 hls instance 仍然有效；若已销毁，重新加载同一 session/URL 并把 currentTime 作为起点，不能直接使用过期的 buffer 时间。

### Seek

滑块输入阶段只更新预览值，change 阶段调用 prepare/seek。旧请求返回后必须比较 load token，迟到响应不能覆盖用户最新的目标位置。HLS startLoad 的参数是加载锚点，video.currentTime 仍设置为用户的绝对目标。

### 画质切换

切换前保存 currentTime、paused 状态和字幕轨道。新 variant prepare 成功后替换 HLS，等待 metadata，再 seek 回原时间；失败时保留旧播放器继续播放，显示切换失败，不能静默修改下拉框值。

## 字幕渲染

### ASS

ASS 内容通过 session subtitle URL 获取，`assTimeline.ts` 和 `assjs` 负责渲染。读取视频 metadata 后再初始化 renderer，避免字幕画布尺寸为 0。切换 session、variant 或 track 时销毁旧 renderer。

### VTT

VTT 或普通文本解析为 startSec/endSec cue，按 video currentTime 选择当前行。边界使用明确的包含规则，不能在每个 timeupdate 中重复解析整个文件。

### 双语文本

双语 ASS 的事件字段可能包含逗号，必须按 format 字段数量拆分；不能简单 `split(',')` 破坏正文。重叠双语行的清洗只影响展示，不修改后端字幕原文。

### 失败处理

字幕 404、解析失败和网络重试只影响字幕 overlay，不能把 video 标记为播放失败。字幕请求使用 load token，旧字幕响应不能显示在新 track 上。

## 事件清理

### 事件来源

play、pause、timeupdate、loadedmetadata、canplay、ended、error 和 hls.js ERROR 都可能更新页面状态。每个 handler 先确认当前 load token 和 sessionId，避免旧资源事件写入新资源。

### Heartbeat

正常播放按后端 heartbeatIntervalSec 定时发送；暂停、seek、切换 variant、页面卸载前补发最后一次。heartbeat 失败不应让播放器自动跳到 0，页面保留本地显示并在下一次合适时机重试。

### 卸载

`onBeforeUnmount` 清理 heartbeat timer、paused timer、subtitle poll、HLS、ASS renderer、键盘监听和控制器隐藏 timer。清理顺序先停止请求，再销毁对象，避免 teardown 期间触发新的 prepare。

### 浏览器差异

`Hls.isSupported()`、MediaSource codec 和实际播放错误共同决定能力。Edge、Codex 内嵌浏览器和其他 WebView 的结果可能不同，前端不根据浏览器名称做业务回退。
