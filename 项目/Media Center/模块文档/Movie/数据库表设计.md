# Movie 数据表

Movie 数据库把“作品资料”和“实际文件”分开。播放、刷新和外部资料同步必须理解这条边界，否则最常见的结果是同名文件串播、文件移动后进度丢失或外部资料覆盖本地事实。

## 主表关系

### Movie

`movie` 保存 title、original_title、summary、cover_url 和生命周期字段。它不保存可播放文件的唯一路径，也不保存某个 variant 的媒体时间轴。

### MovieFile

`movie_file` 通过 movie_id 关联作品，保存 local_file_path、ext、variant、file_size、duration_sec、bitrate、video_width 和 video_height。播放入口必须从 MovieFile 开始，不能根据 title 模糊反查。

### 资料关系

`movie_info` 保存 rating、language、country、release_date 和 intro；`movie_source` 保存豆瓣、IMDB、TMDB 等 source；genre/person 关系表保存类型、导演、演员和角色。资料失败不能删除 MovieFile。

### 公共关系

`user_progress` 使用 mediaType 和 mediaId 保存用户位置。播放缓存、字幕、segment plan 不在 MySQL 主表中，它们通过 fileId 和 fingerprint 与 MovieFile 关联。

## 约束规则

### 路径

`local_file_path` 是配置根目录下的相对路径。重复扫描按规范化路径查找；移动文件通常表现为旧行失效、新行写入，若要迁移 progress 必须额外记录 fingerprint 关系。

### 版本

当前表的 file_size、duration、last update 等字段用于检测变化。播放实现还需要稳定 fingerprint；不能仅凭 update_time 判断源内容，因为 NAS 和数据库时间精度可能不同。

### 外部来源

`movie_source` 的业务唯一键是 movie 加 source，source_id 还要在来源范围内唯一。迟到的旧 Spider 响应不能覆盖新的 source payload。

### 关系删除

刷新同步关系时区分可信空集合和探测失败。失败不清空旧 genre/person/source；确认删除后按 is_active 或关系清理策略处理。

## 播放关联

### 计划

segment-plan JSON、global m4s、session playlist 和字幕都必须携带 movieFileId、fingerprint、variant 或 trackId。数据库删除 MovieFile 前先停止新的 prepare，并使 Redis session 进入失效状态。

### 进度

电影进度以具体 MovieFile 的时间轴为准。切换不同文件或源版本时，前端不能继续使用旧 duration；服务端校验 currentTime 不超过当前文件时长。

### 清理

缓存清理只删除派生目录和过期状态，不删除 movie、movie_file、user_progress 或有效 source。原始文件删除由刷新确认，不由播放 TTL 决定。

### 查询

列表按 movie 主表分页，详情装配 files、genres、persons、sources；播放使用详情返回的 fileId。查询 SQL 不应通过 title join 选取“第一个文件”。

## 迁移要点

### 新媒体字段

新增 codec、audio track、fingerprint 或 plan version 时先允许旧数据为空，刷新和 prepare 逐步补齐，再决定是否加约束。

### 旧数据回填

回填按 movie_file 分批执行，记录无法读取的路径。FFmpeg 探测失败不能写默认 duration 或 codec 冒充成功，否则后续计划定位会出现系统性错误。

### 软删除恢复

文件重新出现时恢复原行还是创建新行，取决于路径和 fingerprint 规则。无明确规则时保留旧进度并创建可追踪的新文件版本，不随机复用主键。

### 兼容发布

后端 entity、mapper、prepare VO、前端 MoviePlaybackResponse 和缓存键必须同步变更。只迁移表结构不会让旧缓存理解新计划。
