# Picture 模块设计

Picture 模块把 NAS 目录树作为主数据源，MySQL 保存目录和文件索引，缩略图、EXIF、embedding、Qdrant point 和 AI 插图作为派生结果。文件系统安全和路径一致性优先于搜索体验。

## 领域边界

### 文件身份

`PictureFolder.relativePath` 和 `PictureFile.relativePath` 是目录树和文件身份。filename 只是展示字段；移动/重命名要同步 folder、relative path 和派生缓存。

### 派生对象

`PictureMetadata`、thumbnail、`PictureEmbeddingIndex`、Qdrant point、`PictureIllustration` 都可以重建或重试。它们失败不能删除 PictureFile 主索引。

### 文件安全

所有请求路径必须经过 `PicturePathResolver`：normalize、startsWith 根目录、拒绝穿越和非法扩展名。Controller 和其他 service 不得自行拼接磁盘路径。

## 组件协作

### 查询链路

`PictureController → PictureServiceImpl → PictureFile/Folder mapper`。语义搜索先由 LLM 生成查询向量，再由 `QdrantPictureVectorClient` 查询 point，最后回查 MySQL 确认文件仍有效。

### 刷新链路

`AdminController → AdminServiceImpl → PictureLibraryScanner → PictureLibraryIngestionService → metadata/thumbnail/embedding`。共同刷新规则见 [[总体设计/刷新数据库设计|刷新数据库设计]]，图片差异见 [[模块文档/Picture/刷新数据库|图片刷新数据库]]。

### 文件操作链路

PictureService 先验证所有源和目标，再调用 Files.move/delete/create，最后更新数据库。跨系统失败记录 source/target，下一次 reconciliation 负责恢复。

## 运行约束

### Qdrant 生命周期

`ensureCollection` 在首次成功 embedding 时创建 collection；全量刷新可能删除 collection，后续成功任务重新创建。MySQL embedding index 记录 collection、point、模型、维度和状态。

### 缩略图缓存

缩略图写临时文件，校验尺寸和格式后原子发布。缓存可以清理，原图和数据库索引不能被缩略图清理器误删。

### AI 重绘

用户级 illustration lock 限制并发，但不等于 fileId/style/model 级幂等。已有结果复用、模型版本和重复计费控制要由后续任务表完善。

## 设计验收

验证路径穿越、目录移动、文件删除、EXIF、缩略图、Qdrant 不可用、collection 重建和同一图片多用户重绘，确保主索引与派生结果边界清楚。
