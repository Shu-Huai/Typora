# 图片模块


图片模块既是浏览器相册，也是受管文件目录。Movie、Book 等模块主要读取 NAS，Picture 还允许用户在页面中创建目录、改名、移动和删除文件。这意味着数据库与文件系统的一致性、路径安全和批量操作完整性是模块的首要要求。

## 文件系统

### 数据模型

`PictureFolder` 保存目录树，`PictureFile` 保存图片文件，`PictureMetadata` 保存尺寸和 EXIF 等信息，`PictureEmbeddingIndex` 记录向量索引状态，`PictureIllustration` 记录 AI 重绘结果。

```text
PictureFolder
 ├──< PictureFolder
 └──< PictureFile
        ├── PictureMetadata
        ├── PictureEmbeddingIndex ── Qdrant point
        └──< PictureIllustration ── 对象存储 URL
```

文件系统是原图的权威来源，数据库是检索索引。根目录在配置中确定，库中保存相对路径及必要属性。查看原图时，服务端根据记录解析绝对路径并再次检查边界。

### 目录浏览

前端先请求根目录，再按 folderId 获取直接子目录和当前目录图片。目录查询只返回一层，避免一次加载整个大树；图片使用分页接口，支持名称查询、排序字段和升降序。

分页响应应包含当前页、页大小、总数和 records。排序至少增加 ID 作为稳定兜底，否则相同拍摄时间的照片会在翻页时漂移。

允许的排序字段由枚举限制，例如名称、文件大小、创建或拍摄时间。不能把客户端传入的字符串直接拼到 SQL `ORDER BY`。页面大小设上限，防止一个请求加载数万条缩略图。

### 路径校验

所有写操作先经过统一 `PicturePathResolver`。基本判断如下：

```java
Path root = configuredRoot.toRealPath();
Path target = root.resolve(relativePath).normalize();
if (!target.startsWith(root)) {
    throw new PathOutsideRootException();
}
```

实际实现还要考虑 Windows 大小写、映射盘、符号链接或 junction。对已存在目标可以用 `toRealPath` 验证；对待创建路径验证其最近存在父目录的真实路径。文件名禁止路径分隔符、`.`、`..` 和 Windows 保留名称。

数据库中的 folderId/fileId 也不代表天然安全。解析时确认实体存在、父子关系正确，并且最终路径位于当前配置根目录。接口不接受任意绝对路径。

### 文件操作

支持创建目录、目录改名、移动目录、删除目录、文件改名、批量移动和批量删除。每个操作先完成预检，再产生写入：

- 源文件/目录存在且仍与数据库记录一致。
- 目标父目录存在并可写。
- 目标名称不冲突，大小写变化在 Windows 上特殊处理。
- 目录不能移动到自身或后代。
- 非递归删除非空目录时拒绝。
- 批量操作中所有 ID 合法且目标统一通过校验。

文件系统与 MySQL 无法参加同一个本地事务。推荐顺序是先把计划和所有前置条件确定，再执行原子移动/改名，最后在数据库事务中更新路径；数据库更新失败时尝试把文件移回并记录补偿事件。删除比移动更难恢复，条件允许时使用回收站或隔离目录，再由后台清理。

## 派生数据

### 元数据

刷新时解析图片宽高、格式、文件大小、时间以及可用 EXIF。GPS、相机和方向信息只有文件实际包含时才展示，解析异常不能阻止图片入库。

EXIF orientation 会影响缩略图显示。缩略图生成和原图预览需要统一处理旋转，否则详情宽高与用户看到的方向不一致。日期字段要区分文件修改时间和拍摄时间；排序“拍摄时间”缺失时采用明确兜底。

原图修改后，元数据和向量均需重新计算。可通过相对路径、大小、最后修改时间或内容哈希组成文件版本；仅检查路径会误用旧结果。

### 缩略图

当前配置的默认尺寸是 512，允许尺寸为 256、512、1024。接口只接受白名单，不能允许任意 `size=2371`，否则攻击者可以制造无限缓存文件。

缓存键至少包含文件 ID/版本和尺寸：

```text
picture-thumbnail-cache/
└── file-123/
    ├── version-<fingerprint>-256.jpg
    ├── version-<fingerprint>-512.jpg
    └── version-<fingerprint>-1024.jpg
```

首次请求未命中时由 Thumbnailator 生成，后续直接返回。并发请求同一缩略图需要 single-flight 或临时文件 + 原子重命名，防止多个线程同时写出损坏文件。缓存删除后可重建，绝不影响原图。

响应设置正确 MIME、内容长度和合理缓存头。原图不存在时返回资源错误，并把该记录留给刷新或修复流程，不返回一张无声的空图伪装成功。

### 语义检索

语义搜索步骤为：

```text
query 文本
  → LLM /embedding/text
  → 得到固定维度向量
  → Qdrant collection 相似度搜索(topK, scoreThreshold)
  → 返回 pictureFileId + score
  → MySQL 回查有效 PictureFile/Metadata
  → 过滤已删除项并组装结果
```

图片入库或内容变化时生成图像向量并 upsert 到 Qdrant；删除图片时删除对应 point。`PictureEmbeddingIndex` 记录是否待处理、处理中、成功或失败，便于刷新后补偿。collection 不存在时由服务以既定维度和距离度量创建。

文本向量与图片向量必须来自兼容模型。模型版本、归一化或向量维度变化后执行全量重建，并在索引记录中保存版本。把新旧向量混在一个 collection 会得到表面有分数、实际无意义的结果。

搜索接口的 `topK` 和阈值有上下限。Qdrant 返回的 ID 可能对应已删除数据库记录，必须过滤；过滤后条数少于 topK 是正常结果，不要用无关图片补足。

### AI 重绘

用户选择原图和画风，提供 requestId。服务端先检查同一文件和画风是否已有结果，再用 Redisson 限制并发，读取原图并调用 LLM 图生图接口。当前生成尺寸为 2K，结果 URL 写入 `PictureIllustration`。

状态通过 `/ws/picture-illustration-status` 推送：

```json
{
  "fileId": 321,
  "requestId": "7f...",
  "status": "GENERATING|SUCCESS|FAILED",
  "url": "成功时的对象地址"
}
```

重绘不覆盖原图，也不混入普通目录扫描结果，除非用户明确保存为新图片。删除原图时如何处理历史插图必须固定：可以随关联删除，也可以保留为生成资源，但不能留下无法解释的悬空记录。

## 刷新机制

### 全量刷新

刷新通过 RabbitMQ 异步执行，`/ws/refresh-picture-status` 返回状态。完整过程包括：

1. 验证根目录和权限。
2. 构建当前磁盘目录/文件快照。
3. 与 PictureFolder/PictureFile 比对。
4. 写入新增与变化，处理缺失记录。
5. 解析或更新元数据。
6. 使旧缩略图失效。
7. 调度向量 upsert/delete。

向量生成可能远慢于目录入库，不应阻塞普通图片可见。刷新可以先完成 MySQL 同步，再让 EmbeddingIndex 表示待处理；前端语义搜索只返回已完成向量的图片。

### 实时变更协调

页面写操作和全量刷新可能竞争。同一时刻如果用户移动目录，扫描器可能看到源路径消失、目标路径出现，然后错误地创建新记录。模块需要一个全局索引写锁，或让写操作提交事件并由单一协调者串行应用。

锁的范围不能覆盖图片内容响应，否则扫描时用户无法查看原图。只保护结构变更和索引提交；耗时向量生成在锁外执行，以版本检查防止旧任务覆盖新图片。

### 删除恢复

删除文件需要同时处理：原文件、PictureFile、Metadata、EmbeddingIndex/Qdrant point、缩略图和可能的 Illustration。执行次序依可恢复性设计：

```text
预检全部目标
  → 原文件移入隔离区/回收站
  → 数据库事务删除或标记
  → 删除 Qdrant 与缓存
  → 最终清理隔离文件
```

Qdrant 或缓存删除失败不应回滚原文件和数据库主操作，可记录待补偿清理；原文件移动失败则不应删除数据库记录。批量删除返回每项结果或保证全批事务语义，不能静默半成功。

### 技术依赖

- Thumbnailator 生成缩略图。
- metadata-extractor 读取 EXIF。
- MyBatis-Plus、MySQL 管理目录、文件和派生记录。
- LLM 嵌入接口与 Qdrant 提供语义检索。
- RabbitMQ、Redis/Redisson、WebSocket 管理刷新和 AI 任务。
- OSS/模型返回地址保存生成图片。

普通目录浏览只依赖 MySQL 与文件系统。Qdrant、LLM 或对象存储故障不应把 `/picture/root`、目录列表和原图接口一起拖死。

## 故障验收

### 目录操作矩阵

| 操作 | 正常用例 | 必测异常 |
| --- | --- | --- |
| 创建目录 | 中文名、空目录 | 重名、非法字符、越界 |
| 改名 | 文件与目录 | 大小写-only、目标存在 |
| 移动目录 | 跨父目录 | 移入自身/后代、目标无权限 |
| 删除目录 | 空目录、递归目录 | 非递归非空、部分文件锁定 |
| 批量移动 | 多文件同目标 | 某 ID 无效、名称冲突 |
| 批量删除 | 全部成功 | 中途 IO 失败、补偿记录 |

每次操作后同时检查磁盘、MySQL、缩略图和 Qdrant，而不是只看接口响应。

### 搜索验收

1. 首次请求 256/512/1024 缩略图能生成，再次请求命中同一缓存。
2. 修改原图后不返回旧缩略图和旧向量。
3. 并发请求同一缩略图不会产生损坏文件。
4. 使用自然语言查询，结果按 score 降序且低于阈值的图片不出现。
5. 人工在 Qdrant 留下无效 ID，搜索会过滤且不报整页失败。
6. 删除 Qdrant collection 后能按配置重建，普通目录浏览始终可用。

### 路径安全验收

构造 `../`、绝对盘符、UNC 路径、混合分隔符、编码后的分隔符、符号链接/junction 和 Windows 保留名。所有操作都必须被限制在根目录内。

安全验收不只调用 Controller DTO 校验，还要直接检查 PathResolver 和实际文件操作。数据库中预置一个恶意相对路径，读取原图同样应拒绝，证明系统不盲信已有数据。

### 故障降级

- Qdrant 不可用：语义搜索返回可理解失败，目录和名称查询正常。
- LLM 不可用：新向量和重绘进入失败/待重试，原图正常。
- 缩略图缓存不可写：可以按受控方式返回原图或明确错误，不能破坏原文件。
- NAS 短暂离线：刷新先失败并保留旧索引，不把全库当作用户删除。
- WebSocket 断开：任务继续执行，重连后可查询实际状态。
