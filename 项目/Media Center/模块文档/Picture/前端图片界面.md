# Picture 前端界面

Picture 前端把目录浏览、图片资源、缩略图、原图、EXIF、语义搜索、AI 插图和文件操作放在一个模块中。页面必须区分“主文件可见”和“派生能力可用”。

## 目录浏览

### 树形状态

页面从 root 开始加载子 folders 和当前 folder files。folderId 是导航身份，relativePath 只用于显示面包屑，不参与接口拼接。

### 分页

文件列表按 page/pageSize 请求，滚动容器和列数是展示问题。切换目录时取消旧请求，避免父目录迟到响应覆盖子目录。

### 缩略图

卡片使用 thumbnail URL，点击详情再加载原图和 metadata。thumbnail 404 不应让整个列表空白，卡片显示占位和重试。

### 搜索

目录搜索和 semantic search 使用不同接口。semantic search 返回结果后页面按 fileId 回查详情或直接使用完整 VO，不从相似度分数推断文件路径。

## 文件操作

### 创建重命名

表单只提交名称和父 folderId。成功后重新读取目录树和当前列表；本地仅修改卡片名称会掩盖后端 NAS/数据库不同步。

### 移动

移动文件和移动目录提交 source IDs 与 target folderId。操作期间锁定相关行，响应成功后清理旧目录和新目录的缓存。

### 删除

删除前显示递归范围和受影响文件数。失败时保留原列表并显示 requestId；不能先从 UI 永久移除再假设后端一定成功。

### 冲突

目标同名、权限不足、NAS 断开和路径越界分别展示。前端不接受绝对路径输入，也不把服务器错误详情原样放入提示。

## 派生资源

### Metadata

详情区显示尺寸、方向、拍摄时间、相机和镜头。字段为空表示原图没有该 EXIF 或提取未完成，页面区分两者需要状态字段支持。

### Thumbnail

size 是受控枚举或范围，前端不允许用户输入任意超大尺寸。图片加载失败使用当前 fileId 和 fingerprint 重试，不改变主文件身份。

### Semantic search

搜索框提交 query 后显示 pending、结果、Qdrant 不可用和无结果。空结果不能和依赖失败共用同一提示，用户需要知道是没有匹配还是搜索服务不可用。

### Illustration

生成插图表单包含 style、prompt 和 requestId。已有 pending 时禁止重复提交；WebSocket 返回 pending/success/failed 后按 fileId、requestId 和 style 更新卡片。

## 生命周期

### 订阅

进入 Picture 页面建立需要的 refresh/illustration socket，离开后释放订阅。socket 重连不自动重复提交生成请求，只重新查询任务或结果。

### 图片预览

原图预览使用后端 content URL，关闭预览清理 blob URL、键盘监听和缩放状态。原图加载失败不影响目录列表和 thumbnail。

### 缓存

目录、文件详情和 semantic search 结果可以短时缓存，但 rename/move/delete/refresh 后必须失效相关 folder/file 缓存。AI 插图结果不能被普通列表缓存覆盖。

### 权限

所有操作遵循后端鉴权。403、404 和 409 显示操作结果，不能因为本地缓存仍有卡片就继续发送删除请求。
