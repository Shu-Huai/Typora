# 图片刷新数据库

本文说明 `Media-Center-Picture` 如何扫描图片目录、写入 PictureFolder/PictureFile 并生成缩略图、元数据和向量派生数据。公共规则见 [[总体设计/刷新数据库设计|刷新数据库设计]]，路径和派生资源边界见 [[模块文档/Picture/模块设计|图片模块设计]]。

## 刷新入口

### 管理请求

`AdminServiceImpl` 提供图片刷新入口，`PictureRefreshRequestManager` 管理请求状态，`PictureRefreshCommandListener` 执行命令，`PictureRefreshStatusListener` 广播状态。准入状态保证重复请求不会并行启动多轮全量扫描。

### 监听选主

`PictureFolderWatcher` 由 `PictureLeaderCoordinator` 选主后注册。事件丢失、OVERFLOW、批量复制和服务重启都由全量扫描校准；非 leader 只提供查询，不应各自消费 WatchService 事件。

### 路径配置

扫描根目录来自 `pictureBaseLocate`，格式由 `pictureFileType` 约束。`PicturePathResolver` 负责规范化、根目录限制和派生路径计算，所有 Controller、扫描器和清理器必须使用同一解析器。

### 消息重放

RabbitMQ command 可能因确认失败重投。数据库路径唯一约束、文件 fingerprint 和派生任务业务键保证重放幂等；状态 WebSocket 断开后，调用方仍可通过任务查询恢复结果。

## 扫描入库

### 文件发现

`PictureLibraryScanner` 遍历根目录并生成 `ScannedPictureFile`，过滤临时文件和不支持格式。扫描结果包含规范化路径、目录身份、大小、mtime 和可用于变化检测的 fingerprint。

```text
picture root
  -> PictureLibraryScanner
  -> ScannedPictureFile
  -> PictureLibraryIngestionService
  -> PictureFolder + PictureFile
```

### 基础实体

`PictureLibraryIngestionService` 先 upsert PictureFolder，再写 PictureFile；路径唯一性和 folder 关系必须在同一业务边界内保持。文件元数据解析失败时保留文件记录和失败状态，不能让一张可读图片因 EXIF 异常从列表消失。

### 派生资源

`PictureMetadataService` 读取尺寸、EXIF 等元数据，`ThumbnailServiceImpl` 生成缩略图，`PictureEmbeddingSyncService` 写入向量。派生任务在基础实体提交后执行，任务键包含 pictureFileId 和 fingerprint，重复任务覆盖同一版本。

### 向量库

`QdrantPictureVectorClient` 维护图片向量集合。当前实现的全量刷新会删除旧 collection，首次成功 embedding 时重新创建；因此刷新状态不能在 collection 删除后立即宣称“搜索可用”。数据库图片记录和向量集合是两个可恢复边界，必须分别报告状态。

## 删除恢复

### 文件集合

全量扫描比较 PictureFile 路径集合。确认缺失后删除或标记文件，再清理空目录对象；删除一个文件不能误删同目录其他 PictureFile。移动按旧路径删除、新路径创建处理。

### 路径安全

删除、移动、缩略图读取和向量清理全部经过 `PicturePathResolver`。目标路径必须解析后仍位于配置根目录或明确派生根目录，拒绝 `..`、符号链接越界和用户直接传入的任意绝对路径。

### 派生清理

文件 fingerprint 变化时，旧 thumbnail、metadata 和 embedding 标记过期。派生文件删除失败要留在重试队列或失败状态，不能为了显示刷新成功而吞掉 IOException。Qdrant 删除失败也要与 MySQL 删除结果分开记录。

### 异常恢复

图片损坏、权限不足和 EXIF 解码异常分别记录路径。基础文件入库成功后，缩略图或向量失败可以重试；下一轮扫描发现 fingerprint 未变时应复用成功派生结果，避免每次刷新重复计算。

## 验证证据

### 运行检查

重点记录扫描、路径解析、派生文件和 Qdrant 状态；数据库刷新成功不能单独作为语义搜索成功的证据。

### 文件场景

覆盖新增、重复事件、删除、移动、越界路径、损坏图片、EXIF 异常和 fingerprint 变化。检查 folder/file 数量、缩略图路径、元数据状态和失败原因。

### 向量场景

执行全量刷新并观察 collection 删除、首次 embedding 重建、重复 embedding 和 Qdrant 不可用。数据库刷新成功不能单独作为语义搜索成功的证据，必须记录 collection 状态和向量数量。

### 运行证据

保存任务响应、leader 日志、数据库查询、文件 mtime、派生目录和 Qdrant 操作结果。浏览器图片列表、缩略图和语义搜索分别验收，不能用列表可见代替全部派生能力可用。
