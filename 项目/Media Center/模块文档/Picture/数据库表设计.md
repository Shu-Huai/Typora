# Picture 数据表

Picture 的数据库主线是目录和文件，派生线是 metadata、thumbnail、embedding、Qdrant point 和 illustration。表结构必须让主文件在派生服务不可用时仍然可浏览。

## 表关系

### Folder

`picture_folder` 使用 parent_id、name、relative_path 和 is_root 表示目录树。relative_path 是受管目录内路径，不能把 NAS 绝对路径返回给前端。

### File

`picture_file` 保存 folder_id、filename、relative_path、ext、file_size、last_modified_time、width 和 height。文件可读是主索引事实，thumbnail 不存在不影响 File。

### Metadata

`picture_metadata` 保存 taken_time、camera、lens、aperture、ISO、GPS、orientation 和 raw_payload。EXIF 为空、解析失败和原图无 EXIF 要有可区分状态。

### Derived

`picture_embedding_index` 保存 collection_name、point_id、model_name、embedding_dimension、status、file version 和 retry_count；`picture_illustration` 保存风格、prompt、url 和用户可见结果。

## 约束规则

### 路径

Folder/File relative_path 必须与 PicturePathResolver 同一规范化规则。目录重命名时子树路径和外部派生路径要一起处理，不能只更新顶层 name。

### 文件版本

file_size、last_modified_time 和必要时 hash 识别源变化。fingerprint 变化后 metadata、thumbnail、embedding 和 illustration 的旧结果不能继续显示为当前版本。

### 向量键

picture_file_id、collection_name、point_id 和模型版本共同决定向量结果。Qdrant 删除 collection 后，embedding_status 应进入待重建，而不是保留 READY。

### 插图权限

picture_illustration 必须能区分发起用户、公共资源或访问范围。仅依赖 Redis lock 不能提供数据库权限隔离。

## 操作关联

### 移动重命名

文件系统操作成功后更新 Folder/File 路径，派生资源按 fingerprint 判断迁移或重建。数据库没有 NAS 事务，需记录操作阶段和补偿状态。

### 删除

删除主 File 后再清理 thumbnail、metadata、embedding point 和 illustration。派生删除失败不应回滚已经确认的源文件删除，但必须保留重试记录。

### 浏览

列表从 Folder/File 分页，详情装配 Metadata、illustration 和资源 URL。语义搜索回查 MySQL，过滤已删除或路径失效的结果。

### 刷新

全量刷新校验目录快照，watcher 只提供增量触发。Qdrant collection 重建和 MySQL 文件入库是两个状态，不在同一事务中假设原子完成。

## 迁移要点

### EXIF 扩展

新增 GPS、orientation 或镜头字段时保留 raw_payload，方便重跑解析。敏感 GPS 是否向普通用户展示需由权限和脱敏策略决定。

### 向量模型

模型或维度变化使用新 collection 或版本字段，批量重建完成前保留旧索引的可用状态。不能在同一 point 上混入不同维度向量。

### 路径长度

NAS 深层目录可能超过普通 varchar 预期。扩大 relative_path 前检查前端、Mapper、文件系统和索引长度，避免数据库扩容后路径校验仍截断。

### 兼容发布

PicturePathResolver、folder/file mapper、thumbnail URL、semantic search VO 和 Qdrant client 必须同步审查。
