# 图片文件系统

Picture 不只是“列出图片”。它允许用户创建目录、重命名、移动和删除文件，任何一步都可能同时影响 NAS、MySQL、缩略图、EXIF 和向量索引。文件系统操作必须先定义失败时哪个系统是真实状态。

## 路径解析

### 根目录

`PicturePathResolver` 将数据库中的 relativePath 解析到 `pictureBaseLocate` 下。用户请求不接受任意绝对路径；规范化后必须满足 `resolved.startsWith(root)`，并拒绝 `..`、越界符号链接和非法扩展名。

```text
request fileId
  -> load PictureFile
  -> relativePath
  -> resolve(root, relativePath)
  -> normalize
  -> root containment check
  -> filesystem operation
```

### 目录身份

目录 ID、相对路径和父目录共同决定 PictureFolder。重命名父目录时，子目录和文件的相对路径都要更新；只改显示名会导致数据库能看见、文件请求却 404。

### 目标冲突

移动或重命名前检查目标是否存在、是否与源相同、是否跨越根目录、是否覆盖已有数据库记录。默认拒绝覆盖，不把 Windows 的大小写差异当成两个安全路径。

### 并发操作

同一文件的 rename、move、delete 需要资源锁或条件版本。两个实例同时移动时，一个成功后另一个应返回明确冲突，而不是把数据库写成不存在的目标路径。

## 操作事务

### 创建目录

先验证父目录和名称，再创建 NAS 目录，成功后写 PictureFolder。数据库写入失败时记录补偿任务；不能在目录创建失败时先插入“假目录”。

### 重命名移动

推荐顺序：锁定源对象 → 校验源存在 → 执行 Files.move → 更新数据库路径 → 标记派生资源待更新。跨系统没有真正的分布式事务，必须保存 source、target、requestId 和阶段状态。

### 删除文件

先确认用户权限和目标文件，再删除源文件或进入回收站策略，最后删除主索引和派生引用。删除缩略图失败不应阻止数据库记录进入待清理状态。

### 回滚边界

NAS move 成功、数据库更新失败时，不能盲目把文件移回去覆盖用户的新操作。记录待修复任务，下一轮 reconciliation 以文件系统和 requestId 证据决定收敛方向。

## 刷新协作

### watcher 事件

自身 API 产生的 move/rename 也会触发 WatchService 事件。事件处理必须识别 requestId 或短时间重复路径，避免一次用户操作变成两轮互相覆盖的刷新。

### 外部变更

用户直接在 NAS 上复制、移动或删除文件时，watcher 只提供提示；全量刷新通过目录快照校正数据库。OVERFLOW 后不能假设每个增量事件都已处理。

### 派生失效

路径变化通常不改变图片内容，但派生文件名可能包含 relativePath。fingerprint 不变时可以迁移缩略图和 embedding，fingerprint 改变时必须重新提取 metadata 和向量。

### 多实例

只有 leader 监听目录，写操作锁仍需跨实例。实例 A 执行 move 后，实例 B 收到旧 watcher 事件时必须通过路径和版本判断是否为迟到事件。

## 安全验收

### 路径用例

```text
正常文件：photo/a.jpg
越界：..\secret.jpg
绝对路径：D:\other\a.jpg
符号链接：root/link -> outside
大小写冲突：A.jpg / a.JPG
```

所有越界和冲突输入都应拒绝，日志记录 requestId 和 fileId，不把服务器绝对路径返回前端。

### 操作用例

覆盖创建目录、重命名目录、移动目录树、移动多文件、递归删除、重复请求、目标已存在和 NAS 中途断开。检查文件系统、PictureFolder/PictureFile、缩略图和向量状态。

### 操作记录

`PicturePathResolverTest` 验证根目录和越界；`PictureFilesystemOperationTest` 验证 Files 操作；`PictureFolderWatcherTest` 验证事件；`PictureServiceImplTest` 验证权限、冲突和数据库更新。
