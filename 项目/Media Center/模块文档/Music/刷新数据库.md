# 音乐刷新数据库

本文说明 `Media-Center-Music` 的扫描、解析、入库和元数据同步链路。公共刷新规则见 [[总体设计/刷新数据库设计|刷新数据库设计]]，音乐实体和播放设计见 [[模块文档/Music/模块设计|音乐模块设计]]。

## 刷新入口

### 管理请求

`AdminServiceImpl` 提供管理刷新入口，`MusicRefreshRequestManager`、`MusicRefreshCommandListener` 和 `MusicRefreshStatusListener` 负责请求、命令和状态。准入状态负责拦截重复刷新，状态通知不能替代持久任务记录。

### 监听选主

`MusicFolderWatcher` 由 `MusicLeaderCoordinator` 选主后注册。监听事件只触发增量提示；复制大量文件、事件溢出或服务重启后通过全量扫描校准。只有 leader 执行刷新写库，避免多个 JVM 同时解析相同目录。

### 直接服务调用

音乐页面存在直接调用服务的刷新路径时，也必须复用同一 request-gate、任务键和扫描器，不能因为入口不同就绕过 MQ、锁或状态发布。所有入口最终都应落到 `MusicLibraryScanner` 和 ingestion 链路。

### 配置快照

扫描根目录来自 `musicBaseLocate`，受支持扩展名由 `MusicFileType` 决定。刷新开始时固定配置快照，记录本轮根目录和解析规则，避免扫描中途配置变更造成结果不可复现。

## 扫描入库

### 文件扫描

`MusicLibraryScanner` 发现文件后生成扫描 DTO，过滤临时文件、封面和不支持格式。`MusicFilenameParser` 从文件名提取标题、艺术家、专辑和轨道号；解析失败的文件要进入可诊断结果，不应凭标题静默入库。

```text
music root
  -> MusicFileType filter
  -> MusicLibraryScanner
  -> MusicFilenameParser
  -> scanned track DTO
  -> MusicLibraryIngestionService
```

### 入库顺序

`MusicLibraryIngestionService` 先 upsert MusicTrack/MusicFile，再处理 Artist、Album 和关系。业务键应包含规范化路径和文件 fingerprint；同标题不同艺术家不得复用同一轨道。`G_E_M_ 邓紫棋` 等名称必须保留原有语义，分隔符清洗只按已验证规则执行。

### 元数据同步

`MusicMetadataSyncService` 负责外部匹配和来源写入。匹配必须优先使用标题、艺术家和专辑组合，禁止无艺术家条件下的 title-only fallback；同名歌曲必须通过 singer relation 区分。外部调用失败不能回滚已确认的本地文件身份。

### 派生资源

歌词、封面、音频指纹和 summary 在基础实体提交后异步处理。派生任务要带 track/file 业务键和 source version，重复消息覆盖同一版本而不是新增孤儿资源。用户歌单和播放进度不能被一次失败的外部匹配清空。

## 删除恢复

### 文件集合

全量扫描比较 MusicFile 规范化路径。缺失文件先按策略标记，再处理 Track；一首歌可能有多个格式文件，删除一个文件不能直接删除整首 Track。歌单引用和用户进度要单独决定保留时间。

### 文件变化

路径相同但 fingerprint 变化时更新媒体信息并使旧歌词、封面或指纹任务失效。移动按旧路径删除、新路径创建处理；若保留播放进度，必须有明确迁移键，不能只凭标题迁移。

### 名称回归

解析器规则修改必须保留历史反例。尤其是带下划线的艺名、多人合作和标题中包含分隔符的文件，不能使用过宽的正则把合法艺名拆开。修复后重跑扫描，比较 track、artist relation 和 source 版本。

### 异常处理

权限、格式、解析和外部 API 异常分别记录。扫描部分失败时保留上一版可信 metadata；下一轮成功再更新。清理歌词或封面时限制在配置派生目录，不得根据数据库标题拼接任意路径。

## 验证证据

### 运行检查

重点记录扫描、解析、入库、外部匹配和准入的输入输出，不把状态 WebSocket 的到达当作数据库已提交的证明。

### 解析场景

准备同名不同歌手、多人合作、带下划线艺名、缺少专辑、重复文件和扩展名大小写场景。检查 MusicFile 数量、track identity、artist relation、album relation 和原始名称。

### 重复消息

重复发布 command、重启消费者和 watcher 溢出后再次全量刷新。期望数据库无重复文件和关系，外部匹配不会重复创建 source，状态最终收敛。

### 页面证据

刷新完成后从列表进入歌曲详情、歌词和播放接口，检查返回的 fileId、歌词版本和实际路径。页面显示歌曲不等于音频文件可读，必须保存接口响应和服务器日志。
