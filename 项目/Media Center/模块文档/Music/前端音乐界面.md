# Music 前端界面

Music 前端围绕 Track、MusicFile、Artist、Album、Lyric 和 Playlist 组织。它不使用 Movie 的 HLS session，而是通过音频元素和 HTTP Range 流完成播放。

## 曲库页面

### 列表

列表展示 Track 的标题、艺术家、专辑、时长和可播放文件数量。卡片点击使用 trackId，文件选择后再得到实际 musicFileId；页面不能把文件路径暴露给浏览器。

### 详情

详情显示多个音频版本、歌词、summary 和来源状态。外部匹配失败只影响资料区，不能隐藏本地可播放文件。

### 艺术家

多人艺术家关系按 role_type 和 sort_order 展示。前端不从 displayName 字符串自行拆分歌手，避免和后端解析规则不一致。

### 分页

分页查询使用稳定 sort 和 pageSize。搜索标题、艺术家和专辑时，取消旧请求或按 request token 忽略迟到响应。

## 音频播放器

### 文件选择

用户选择文件后把实际 musicFileId 交给 audio 元素。按 Track 快速播放则调用后端默认文件选择，接口返回的 fileId 作为当前播放身份。

### Range

浏览器原生 audio 负责 Range 请求。前端不把整个 FLAC 转成 ArrayBuffer；错误响应按 206、416、404 和 MIME 失败分别提示。

### 进度

currentTime、duration、paused 和 volume 是播放器状态；user_progress 是后端持久状态。暂停、切歌、页面隐藏和卸载时写最后位置。

### 多版本

从 MP3 切换到 FLAC 时确认是否共享进度。若文件时长不同，前端把旧位置限制在新 duration 内，不直接把旧秒数原样写入。

## 歌词界面

### 加载

歌词请求与音频播放解耦。歌词失败显示“暂无歌词”或“加载失败”，音频仍保持播放。

### 时间匹配

歌词行按 audio currentTime 查找，边界时间使用半开或明确包含规则。暂停时不推进高亮，恢复后从音频实际位置重新计算。

### 多语言

原文、翻译和罗马音是不同显示轨道。切换轨道只改变渲染，不重新请求或切换音频文件。

### 偏移

如果提供用户歌词偏移，将其保存在播放器偏好；不要修改原歌词时间，也不要让 offset 影响音频 currentTime。

## 歌单页面

### 所有权

列表和修改接口都携带当前用户上下文。前端收到 403 时清理操作状态，不把其他用户的 playlist 继续显示成自己的。

### 重复曲目

页面必须遵循后端是否允许同一 Track 重复出现的规则。允许重复时删除操作使用 playlist track entry；不允许重复时对重复键显示已存在。

### 排序

拖拽重排提交完整 sort order 或明确移动操作。保存中禁用重复拖拽，响应返回后重新读取列表，避免本地 optimistic 顺序和服务端不同。

### 删除

删除歌单不删除 Track、MusicFile 或歌词；删除歌单曲目只删除关系。成功后清理当前列表缓存，不清理全局曲库。

**资源清理**

#### 页面退出

清理 audio event listener、heartbeat、歌词 timer、Object URL 和 pending 请求。全局播放器若要跨页持续播放，必须明确由 store 持有，不能半数状态在页面、半数状态在全局。

#### 外部状态

QQ Music、summary 和歌词异步消息通过 requestId/trackId 过滤。旧 Track 的成功消息不能更新当前 Track 卡片。

#### 失败恢复

网络中断时保留当前曲目和位置，恢复网络后重新请求 Range 或歌词；不自动跳到下一首，除非播放器确实收到 ended。
