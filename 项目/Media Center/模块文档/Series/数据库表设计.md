# Series 数据表

Series 数据库比 Movie 多出季集身份。表结构的重点不是把一季的所有视频拼成一个文件，而是让每一集、每一个物理文件都能独立刷新、播放、保存进度和绑定字幕。

## 层级关系

### Series

`series` 以 category、title、season_no 形成作品季级身份，保存 original_title、summary 和 cover_url。不同季是不同 Series 记录，这是当前模型的关键边界。

### SeriesEpisode

`series_episode` 通过 series_id 保存 episode_no、title、intro、air_date 和 duration。唯一约束是 series_id 加 episode_no；集号只在同一季内有意义。

### SeriesEpisodeFile

`series_episode_file` 保存 local_file_path、ext、variant、file_size、duration、bitrate、video_width 和 height。播放 session、字幕、计划和进度必须落到这个表的 ID。

### 资料关系

series_info、series_source、series_genre 和 series_person 保存外部资料。外部 source 绑定 Series，不替代 EpisodeFile 的本地身份。

## 一致性规则

### 季集解析

扫描先 upsert Series，再 Episode，最后 EpisodeFile。目录模板解析出的 seasonNo、文件模板解析出的 episodeNo 和规范化路径必须一起校验，不能先按标题插入再补集号。

### 路径唯一

`local_file_path` 是文件物理身份。路径移动需要处理旧记录和新记录；如果一个文件被误挂到另一集，必须生成诊断冲突，而不是 silently 更新 episode_id。

### 时长独立

每集 duration 可能不同。前端和播放服务不能从 SeriesInfo 的 runtime_minutes 推断当前文件 duration；prepare 必须读取 EpisodeFile 的媒体事实。

### 软删除

缺集、NAS 掉线和模板失败不能直接级联删除整季。确认文件缺失后先处理 EpisodeFile，再按空集、空季策略处理上层记录。

## 播放关联

### Session

Redis session key 包含 seriesEpisodeFileId 和 fingerprint。切集创建新 session，旧集的 m3u8、subtitle、segment plan 和 heartbeat 不得写入新集。

### 进度

user_progress 以 episodeFile 身份或产品定义的集身份保存。Series 列表上的完成状态是聚合展示，不能把整季百分比写成某一集 currentTime。

### 计划

每集独立 segment-plan，index 从 0 开始也不影响隔离，因为缓存键还包含 episodeFileId、variant、fingerprint 和 planVersion。

### 字幕

字幕提取结果绑定 episodeFileId 和 trackId。不能使用 seriesId/seasonNo 作为唯一文件名，否则同一季多个集会互相覆盖。

## 迁移要点

### 特别篇

当前 schema 的 episode_no 是整数。引入 specials 前需决定独立 season、负数、扩展字段或新表，不能把特别篇随意写成普通第 0 集。

### 多文件一集

若同一集有多个来源或剪辑，唯一约束不能只允许一个 EpisodeFile。前端选集接口要返回文件列表，播放进度规则也要明确按文件还是按集共享。

### 来源更新

series_source 更新不应修改 episode file 路径和 fingerprint。数据库迁移要分开处理资料字段和媒体字段，避免 Spider 回填影响播放缓存。

### 兼容发布

后端 Series VO、prepare DTO、前端选集页和缓存前缀必须一起审查。Movie 的 fileId 不能被复用为 Series EpisodeFile 的兼容别名。
