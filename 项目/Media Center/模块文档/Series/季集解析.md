# 剧集季集解析

![](http://public.file.lvshuhuai.cn/images\series-identity-chain-1786601764741-15.svg)

Series 最难的部分不是复制 Movie 的 HLS，而是把不统一的文件夹和文件名解析为稳定的剧名、季号、集号和物理文件。解析结果一旦错误，后面的播放、字幕、进度和自动连播都会指向错误资源。

## 解析对象

### 三层身份

```text
Series(category, title, source)
  └─ SeriesEpisode(seriesId, seasonNo, episodeNo)
       └─ SeriesEpisodeFile(episodeId, localFilePath, mediaInfo)
```

Series 是作品，Episode 是排序和展示对象，EpisodeFile 是真正可以播放的文件。集号不能代替文件 ID，因为同一集可能存在多个来源、不同剪辑或不同码率文件。

### 模板参数

`AdminServiceImpl.PatternParser` 从配置模板读取目录和文件名字段，产生 `SeasonMatch`、`EpisodeMatch`。模板必须明确哪些字段是必需的，哪些字段可选；解析失败返回诊断信息，不用标题猜测 SxxExx。

### 文件版本

同一路径覆盖新文件时，EpisodeFile 的 media fingerprint 必须变化。旧的字幕、segment plan 和播放缓存跟随旧 fingerprint 失效；episodeNo 不变不代表媒体内容不变。

### 来源边界

豆瓣来源、文件来源和用户本地身份要分开保存。外部来源 ID 只能帮助补充 Series 资料，不能决定本地文件属于哪一集。外部请求失败时，已经解析成功的季集仍然可播放。

## 解析顺序

### 目录阶段

先解析目录得到 series title、seasonNo 和 category，再检查目录下允许的媒体扩展名。目录名无法匹配时，整目录进入失败清单；不要把目录下每个文件按标题创建孤立 Series。

### 文件阶段

文件名解析 episodeNo、optional title、source 和 variant。遇到 `S01E03E04`、`01-02`、特别篇、OVA 或多集合集时，必须按配置支持范围处理；不支持的形式明确标记，而不是把它误写成第 1 集。

### 入库阶段

```text
parse directory
  -> upsert Series
  -> parse file
  -> upsert SeriesEpisode
  -> upsert SeriesEpisodeFile
  -> sync source / person / genre
```

每一步使用业务唯一键。重复 watcher 事件不能新增 EpisodeFile，路径移动按旧路径删除、新路径创建处理，若要保留进度必须有独立迁移规则。

### 排序阶段

列表排序使用整数 seasonNo、episodeNo 和明确的特别篇规则，不按字符串排序。`S01E10` 必须排在 `S01E09` 后面，不能出现字典序 `E10` 在 `E2` 前面。

## 异常情况

### 同名冲突

两个目录解析出相同 category/title/season 时，不能凭扫描顺序覆盖。应记录冲突路径，并要求用户修正 category、source 或 season 配置。冲突期间已有正确记录不能被未知来源删除。

### 缺集情况

刷新不负责补齐不存在的集。第 1 集和第 3 集存在时，数据库可以保留缺失的第 2 集状态，但不能伪造一个可播放 EpisodeFile。自动播放下一集要根据实际可播放排序结果。

### 特别篇

特别篇不能强行塞进普通 episodeNo。若产品暂不支持 specials，显示为解析失败；若支持，应定义独立 season 或 special number，并在前端排序、进度和字幕 URL 中保持一致。

### 解析规则变更

修改 pattern 后必须重新运行历史文件夹 fixture，比较 Series、Episode 和 EpisodeFile 差异。解析规则升级不能直接删除旧数据，先输出变更清单，再执行受控同步。

## 验收样例

### 最小 fixture

```text
亿万地堡/
  Season 01/
    Billions.S01E01.2160p.mkv
    Billions.S01E02.2160p.mkv
  Season 02/
    Billions.S02E01.1080p.mkv
```

期望得到一个 Series、两个 Season 语义下的 Episode 集合，以及三个互不混淆的 EpisodeFile。播放请求必须携带具体 episodeFileId。

### 规则回归

解析规则的运行记录应覆盖目录和文件模板、扫描写库、文件变化和重复刷新。新增规则必须同时保留正例、负例和同名冲突例。

### 浏览器验证

打开第 1 集、暂停、跳转，再切换第 2 集，检查请求 URL 的 episodeFileId、duration、字幕轨道和 segment plan 指纹。返回第 1 集后应恢复第 1 集进度，而不是使用剧集级最后位置。
