# 剧集模块


剧集模块处理连续内容。它和电影都需要视频播放，但媒体组织不同：电影通常围绕一部作品和若干文件，剧集必须先识别剧名、季和集，再定位具体文件。播放主链路应复用 Movie 的规则，不能因为模块复制而逐渐产生不同的 seek、缓存或回退行为。

## 剧集组织

### 数据模型

当前模型中，一个 `Series` 表示一季，`SeriesEpisode` 表示该季中的一集，`SeriesEpisodeFile` 是实际视频。类型、人物、来源和详情分别由关联实体保存。

```text
Series（某剧的某一季）
 ├──< SeriesEpisode
 |       └──< SeriesEpisodeFile
 ├──< SeriesGenre >── Genre
 ├──< SeriesPerson >── Person
 ├──< SeriesSource
 └── SeriesInfo
```

用户看到的“亿万地堡 第 1 季 第 3 集”至少需要 seriesId、episodeId 和 episodeFileId 三层身份。播放进度和缓存以 episodeFileId 为准，集号只用于内容排序，不能作为全库唯一键。

### 集目录解析

扫描从配置根目录开始，解析分类、剧名、季目录和文件名。常见目录可表达为：

```text
电视剧根目录/
└── 科幻/
    └── 亿万地堡/
        ├── Season 01/
        │   ├── 01 第1集.mkv
        │   └── 02 第2集.mkv
        └── Season 02/
            └── S02E01.mkv
```

解析器需要支持项目已约定的中文集名、纯数字前缀和 `SxxExx` 等格式。缺少季目录时可以默认第一季，但一旦文件名明确包含季号，应以明确值为准并检查目录是否冲突。

集号按整数排序。使用字符串排序会得到 `1, 10, 11, 2`。特别篇、预告或无法识别的文件不能随便标为第 0 集；应按既定特殊类型保存，或报告无法解析等待人工处理。

### 扫描规则

刷新维护 Series、Episode 和 EpisodeFile 三层关系：

1. 找到或创建“剧名 + 季号”对应的 Series。
2. 在该 Series 中按集号找到 Episode。
3. 按相对路径找到 EpisodeFile，更新文件属性。
4. 扫描结束后处理缺失文件和失去文件的空集。

移动整季目录时，如果相对路径是唯一身份，会表现成大量删除和新增。若要保留 ID，可结合规范化剧名、季号、集号、文件大小和媒体时长做谨慎迁移识别。不能仅凭集号复用，因为每一季都有第 1 集。

刷新不清理用户进度、播放缓存或豆瓣资料。文件内容发生变化时，旧缓存需要通过文件指纹失效；路径短暂不可访问时，不应立刻级联删除整季资料。

### 选集查询

列表按季展示 Series，提供总数、分页、封面、剧名和季号。详情包含简介、类型、人物以及按集号排序的 Episode。每集存在多个 EpisodeFile 时，应显示足以区分版本的信息。

前端从 `/series-detail/:id` 选择集，再进入 `/series-play/:seriesId/:seriesEpisodeFileId`。进入播放前和 prepare 时都验证该文件属于该 Series。当前集切换到下一集时，应创建或准备新 session，而不是把旧 session 的 fileId 原地改掉。

## 内容播放

### 豆瓣资料

豆瓣同步按 Series 执行。匹配需要剧名、季号和可用年份；不能把第二季绑定到第一季的条目。若外部站点用一条资料代表整部系列，而本地按季建模，必须定义哪些字段可在季间共享、哪些是季特有数据。

单季同步和批量同步都保存外部来源 ID。失败不影响本地集列表和播放。系列总结通过 LLM 生成，状态由 `/ws/series-summary-status` 返回；输入范围要明确是当前季，而不是默认抓取所有季。

### Movie 播放契约

Series 的播放行为必须与 Movie 对齐：

| 事项 | Movie 与 Series 的共同规则 |
| --- | --- |
| SOURCE | 视频 copy，音频 AAC，HEVC/H.265 不自动回退 |
| 1080p | 用户主动选择 HIGH 或 LOW，视频 H.264，音频 AAC |
| 容器 | HLS + 独立音视频 fMP4，init.mp4 + m4s |
| 切分 | 使用真实时间戳与关键帧计划，不固定秒数强切 SOURCE |
| 调度 | 当前短分片 + 有限预热，暂停/关闭后不继续到结尾 |
| 缓存 | 同文件同画质分片跨用户共享，按 TTL 清理 |
| 进度 | 心跳保存，暂停、拖动、切换清晰度保持媒体时间 |

这不是“功能看起来类似”即可。两个模块的 `PlaybackController`、`HlsController`、properties 和前端播放器协议应逐项对应。Series 特有差异只能来自实体名、缓存根目录和单集上下文。

### 单集进度

prepare 输入具体 EpisodeFile 和画质，返回 sessionId、HLS URL、恢复位置、时长、状态、字幕轨道与心跳间隔。心跳只更新当前文件进度。

切换集时：

```text
保存旧集最后位置
  → 停止旧 session 的继续预热
  → prepare 新 EpisodeFile
  → 使用新集自己的恢复位置或从 0 开始
  → 加载新字幕上下文
```

不能沿用上一集的秒数、字幕轨道或清单。旧集已生成的全局缓存可以保留；之后回到旧集无需重复转码。

接近结尾的完成阈值按具体集时长计算。标为完成后，下次进入从头还是停在结尾要统一；自动播放下一集属于前端体验，但必须等当前集进度成功写入。

### 换集字幕

字幕来自当前 EpisodeFile。即使每集默认轨道 ID 都叫 `default`，其 URL 和提取文件也必须包含文件/session 上下文，不能让第 1 集字幕缓存覆盖第 2 集。

切换集时销毁旧字幕渲染实例，清除 cue 与时间监听，再绑定新视频。否则最常见的现象是视频已经进入下一集，字幕仍沿用上一集时间轴。

## 实现要求

### 主链路对应关系

Series 后端拥有与 Movie 对应的 prepare、heartbeat、subtitle context、subtitle parse、SOURCE 预转码和 lazy fMP4 HLS 接口。当前还可能存在旧 TS 路由；前端主链路不得因为 fMP4 暂未准备好而自动切到 TS 或 1080p。

对齐检查不能只比较 Controller 路径，还要比较：

- PlaybackTranscodeManager 的分片查找和调度逻辑。
- segment-plan.json 的生成、读取和文件指纹。
- 音视频 playlist、init 和 segment 响应头。
- SOURCE FFmpeg 参数和 `copy-unsafe-codecs`。
- session/global 缓存键与清理。
- 前端 hls.js 事件、画质切换和错误恢复。

如果 Movie 修复了时间轴 bug，Series 应通过共享组件或同步回归测试获得同一修复，而不是复制后忘记维护。

### 缓存并发

Series 使用独立缓存根目录 `series-hls-cache`，避免与 Movie ID 冲突。缓存内部仍按 EpisodeFile、画质、轨道和分片组织。`fmp4InitialBurstSec` 等 Series 特有配置若存在，必须说明它与按需预热的关系，不能让初始 burst 实际转完整集。

同一分片 single-flight、队列上限、HTTP 短等待、FFmpeg 超时、失败 TTL 和 72 小时缓存清理与 Movie 相同。用户快速换集会产生多文件请求，调度器要公平处理，不能让废弃旧集任务占满全部队列。

### 前端行为

Series 播放页应复用 Movie 播放器的稳定逻辑，差异集中在“当前集信息、选集和下一集”。不要复制一份经过修改的播放器再各自修补。

播放器至少显示：当前剧名/季/集、播放状态、三档画质、字幕、进度和错误提示。SOURCE 失败时显示失败原因与可选画质，不做自动回退。用户主动切换画质时保留 currentTime；切换集时则读取新集进度。

### 技术依赖

与 Movie 相同，使用 FFmpeg/ffprobe、hls.js、ASS 字幕、MyBatis-Plus、MySQL、Redis/Redisson、RabbitMQ 和 WebSocket。豆瓣资料由 Spider 提供，总结由 LLM 提供。

技术共享的目标是保证契约一致，不是强行让 MovieFile 与 EpisodeFile 使用同一数据库表。媒体实体不同，但播放输入可以抽象成“可定位文件 + 用户 + variant + current time”。

## 验收回归

### 目录用例

准备多季、无季目录、中文命名、`S01E02`、两位/三位集号、特别篇和无法识别文件。验证：

1. 每个文件进入正确剧名、季和集。
2. 第 10 集排在第 9 集之后，不按字符串错序。
3. 同一集多个文件不会覆盖，播放入口选择正确版本。
4. 整季移动或单集删除后刷新，其他季集关系不受影响。
5. 豆瓣第二季不会绑定到第一季来源。

### 播放用例

对同一批真实编码样本同时执行 Movie 与 Series 测试，比较结果：

- SOURCE 的 FFmpeg 命令都使用视频 copy、音频 AAC。
- master/video/audio 清单结构与时间语义相同。
- 暂停恢复、跨分片、随机拖动和画质切换都没有重复、跳跃、循环或不同步。
- 页面关闭后只完成已启动短任务，不继续到集尾。
- A 用户生成的分片能被 B 用户复用，进度互不共享。

Series 还要连续切换三集，确认旧 session、字幕和 currentTime 没有泄漏到新集。

### 差异审计

每次改动播放代码后，使用文件级差异或契约测试审计 Movie 与 Series。允许存在的差异要能解释为实体、路径或产品场景；出现“Movie 有此判断，Series 没有”时必须确认是否遗漏。

建议维护一组共享播放测试向量：给定计划、currentTime、variant 和缓存状态，两个模块返回相同的分片索引与准备范围。这样可以在不启动浏览器的情况下提前发现逻辑漂移。

### 故障边界

单集文件缺失只影响该 EpisodeFile，不让整季详情报错。NAS 短暂离线时先报告不可访问，避免一次刷新删除全部剧集。FFmpeg 或分片失败返回稳定 errorCode，用户可以重试同一画质或主动选择另一画质。

Movie 播放专题中的时间轴诊断方法同样适用：[[模块文档/Movie/播放业务|Movie 播放]]。Series 若出现仅本模块复现的问题，第一步是对照相同输入下 Movie 的请求、配置和日志，而不是另加自动回退。
