# 剧集跨集播放

这份文档专门说明“当前集播放状态”和“下一集切换”之间的边界。Series 可以复用 Movie 的分片协议，但不能把整个 Series 当成一部超长电影，否则字幕、进度和缓存会在切集时串联。

## 会话边界

### 一集一会话

一次播放 session 绑定 `seriesEpisodeFileId`、fingerprint、variant、audio track 和 subtitle track。切集必须关闭旧 session 或创建新 session，不能在旧 session 中替换 fileId。

```text
session A: series=126, episodeFile=4114, duration=2578
session B: series=126, episodeFile=4115, duration=2631
```

### 进度坐标

用户进度按 episodeFile 记录。剧集列表上的“已观看”是从各集进度计算出来的聚合状态，不应把聚合百分比写回某一集。切集时先读取新集进度，再设置播放器 currentTime。

### 画质切换

同一集内切换 SOURCE/HIGH1080/LOW1080，可以保留 currentTime；切集不能复用旧集的 currentTime、duration 或 m3u8。前端应抑制旧播放器实例的 timeupdate，避免旧集异步事件覆盖新集进度。

### 字幕身份

字幕 URL 至少包含 sessionId、episodeFileId 和 trackId。剧集标题、季号或集号单独作为字幕文件名都不够，特别是两个来源存在相同集名时。

## 切换流程

### 用户选择

```text
用户点击第 N 集
  -> 保存当前集最后心跳
  -> close session N-1
  -> prepare episodeFile N
  -> 加载新 master/playlist
  -> 等待首个可播放分片
  -> 恢复 episodeFile N 的进度
```

关闭旧 session 失败时不能直接把旧播放器当作新集使用；可以保留旧 session 的清理任务，但新集必须拥有独立身份。

### 自动下一集

播放完成事件不能直接用 `currentTime >= duration` 判断，因为浏览器可能提前触发 ended 或 duration 尚未稳定。后端进度先成功保存，前端再根据排序后的可播放 EpisodeFile 选择下一集。

### 失败重试

新集 prepare 返回 PREPARING 时只重试该集的 m3u8/segment 请求，不重新创建整个 Series session。SOURCE_PREPARE_FAILED 必须保持原错误，不自动跳到下一集或暗中切换画质。

### 返回上一集

返回上一集是一次新的 prepare，使用上一集的 progress。不得从前端内存中的全局 `lastPosition` 恢复，因为那通常属于刚播放完的另一集。

## 缓存隔离

### 计划键

计划键至少包含 episodeFileId、fingerprint、variant 和 planVersion。两个集的 segment index 都从 0 开始，因此 index 不能单独作为 global 文件名。

### session 文件

session 目录只保存当前集的 playlist、临时媒体和字幕引用；global 目录保存完成分片。切集时可以替换 session 目录，不删除其他用户可用的 global 分片。

### 多实例

Redis session 共享后，实例 B 仍必须能读取实例 A 生成的 m4s。生产环境使用共享缓存目录或 owner 路由；否则切集偶尔成功、偶尔 404，容易误判为播放器随机故障。

### 清理策略

清理器按 episodeFile fingerprint 和最后访问时间处理缓存。正在播放的 session、最近心跳和 READY 分片要受保护；清理不能删除源文件或 MySQL 中的 EpisodeFile。

## 运行场景

### 连续观看

从第 1 集开头播放到结尾，自动进入第 2 集，再进入第 3 集。检查每集 m3u8、字幕和 duration 都切换，播放请求没有重复使用上一集的 episodeFileId。

### 交互跳转

第 1 集中间暂停，跳到第 2 集中间，再返回第 1 集。期望第 1 集恢复原位置，第 2 集从自己的 resumePosition 开始，两集的心跳写入互不覆盖。

### 运行证据

浏览器 Network 记录 session 身份、计划隔离、集文件不存在、准备中和缓存过期时的真实 URL 与响应码；日志同时记录 episodeFileId，便于确认切集没有串用旧会话。
