# 图书格式兼容

![](http://public.file.lvshuhuai.cn/images\book-format-pipeline-1786601764741-2.svg)

Book 不是把所有文件都转换成一种格式。当前模块明确支持 PDF、EPUB、TXT 三种读取路径，每种格式的分页、资源加载、字符编码和封面来源都不同。兼容设计的目标是让前端获得统一的阅读入口，同时不把格式差异藏成不可诊断的错误。

## PDF 阅读

### Range 请求

PDF 使用 `FileController /pdf` 和 `FileServiceImpl.loadPDF`，支持 HTTP Range。浏览器或 PDF Viewer 可以只请求需要的字节，不必每次打开整本大文件。

```http
Range: bytes=1048576-2097151
Content-Range: bytes 1048576-2097151/7340032
Accept-Ranges: bytes
```

服务端必须校验范围边界，返回正确的 206、Content-Length 和 Content-Range。把 PDF 当普通 JSON 或一次性 byte[] 返回，会增加首屏等待和 JVM 堆压力。

### 封面提取

刷新时使用 PDFBox `Loader`、`PDDocument` 和 `PDFRenderer` 渲染第一页作为候选封面。渲染失败不能阻止 BookFile 入库；封面是派生结果，失败应记录并允许重试。

### 页面坐标

PDF 进度按页保存，不把字节偏移当作用户阅读位置。前端页码从 1 开始时，接口和数据库要明确转换规则，避免刷新页面后显示前后差一页。

### 资源释放

PDF 文档、RandomAccessFile 和 InputStream 必须在请求结束关闭。大文件并发 Range 读取时，不能把整个内容缓存到共享 Map 中。

## EPUB 阅读

### 容器特点

EPUB 是 ZIP 容器，章节、目录、CSS、图片和字体位于内部资源中。当前后端 `loadEPUB` 返回完整 EPUB，章节解析和排版由前端 EPUB 阅读器负责；后端不能把 EPUB 当成可直接嵌入页面的 HTML。

### EPUB 响应头

响应 Content-Type 使用 `application/epub+zip`，Content-Disposition 保持可下载文件名。错误 MIME 会导致浏览器下载、空白页或阅读器无法识别。

### 封面优先级

刷新提取 EPUB cover image 作为封面候选。若同一本书同时存在 PDF 和 EPUB，当前规则允许 PDF 封面优先，EPUB 在没有 PDF 封面时补充；这个优先级不能因扫描顺序变化。

### 章节进度

EPUB 的稳定阅读位置更适合保存 CFI 或章节加偏移，而不是假设每本书都有固定页数。当前接口若只保存粗粒度位置，要在文档中明确这是近似恢复，不要宣称可精确回到任意字符。

## TXT 阅读

### 字符集检测

`FileServiceImpl.getCharsetTXT` 使用字符集探测器判断 TXT 编码。GBK、UTF-8、UTF-16 等编码不能靠文件扩展名区分，前端第一次加载前应拿到 charset 或由后端统一转换成 UTF-8。

### 分页策略

TXT 没有天然页边界，分页由前端字符数、行数或后端切片策略决定。进度至少保存页号和偏移，文件内容变化后旧偏移可能失效，必须使用文件 fingerprint 判断是否允许恢复。

### 大文件

超大 TXT 不应一次性读入字符串。读取接口要限制单次范围或使用流，避免一个用户打开小说就占满堆。分页缓存键必须包含 bookFileId 和 fingerprint。

### 文本编码细节

解析时处理 UTF-8 BOM、CRLF/LF 和异常控制字符，否则不同平台生成的 TXT 会出现首字符乱码或页尾跳行。清洗规则不能悄悄改变原文内容，必要时只在展示层处理。

## 兼容验收

### 格式矩阵

```text
PDF  : Range、页码、封面、并发打开
EPUB : application/epub+zip、章节、CSS/图片、封面
TXT  : UTF-8/GBK、BOM、长文件、分页恢复
```

### 浏览器验收

真实浏览器分别打开三种文件，记录首包、页码和恢复位置；服务端同时记录 Range、MIME 和 charset 响应。

### 不支持的内容

扫描发现 MOBI、CBZ 或损坏 EPUB 时，不能把它们伪装成 TXT 入库。返回明确的不支持类型，等后续设计专门的解析器和阅读器适配。
