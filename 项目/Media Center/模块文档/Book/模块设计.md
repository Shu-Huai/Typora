# Book 模块设计

Book 模块把书籍逻辑对象、作者出版社关系和物理阅读文件分开保存。阅读服务只负责按文件类型提供内容和进度；总结、插图属于可重试的派生任务，不应阻塞书库查询。

## 领域边界

### 书籍身份

`Book` 保存书名、作者、出版社、封面和 summary；`BookFile` 保存 PDF/EPUB/TXT 路径与格式；`Author`、`Publisher` 通过外键关联。文件路径是扫描稳定身份，不能只按书名覆盖不同版本。

### 阅读身份

阅读进度使用 user + BOOK + book/file identity。刷新只更新文件和书籍索引，不能清空用户进度。格式读取由 FileService 处理，Controller 不直接打开任意路径。

### 派生任务

Book summary 使用 book 级锁和双检；插图使用用户级并发锁并写 BookIllustration。模型版本、描述哈希和任务结果属于后续幂等增强，不应和书籍主表混为一体。

## 组件协作

### 查询链路

`BookController → BookServiceImpl → Book/Author/Publisher/File mapper → BookVO`。`FileController → FileServiceImpl` 负责阅读流，`ProgressController → ProgressService` 负责进度。

### 刷新链路

`AdminController → AdminServiceImpl → BookFolderWatcher/scan → BookFile and relation write`。刷新共性见 [[总体设计/刷新数据库设计|刷新数据库设计]]，Book 落库见 [[模块文档/Book/刷新数据库|图书刷新数据库]]。

### 生成链路

`BookServiceImpl → Redis lock → LLM client → Book.summary/BookIllustration → status listener → WebSocket`。外部调用失败不能写入空成功结果。

## 运行约束

### 格式处理

扩展名先映射到 `BookFileType`，再选择 PDF、EPUB 或 TXT 读取方式。未知格式不入库为可读文件，日志保留路径和原因。

### 路径权限

`bookBaseLocate` 需要服务账号可读；映射盘在 Windows 服务账号下可能不可见。配置变更先停止旧 watcher，再验证新目录并启动。

### 状态通知

RabbitMQ status 和 WebSocket 只负责实时通知；发起实例重启后不能依赖本地 future 找回结果，任务持久化属于总体实现改造项。

## 设计验收

用 PDF、EPUB、TXT 各一份文件验证阅读、进度和重复刷新；并发总结只产生一次有效书籍结果；插图失败不会破坏 BookFile 和阅读功能。
