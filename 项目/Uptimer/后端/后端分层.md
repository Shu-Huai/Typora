# 后端分层

本文说明后端的分层约定、鉴权实现和公共组件。

本文不讨论业务逻辑，见各模块文档。模块清单见 [[总体实现/实现总览|实现总览]]。

源码范围：`src/modules/`、`src/lib/`、`src/actions/`、`src/app/api/`、`middleware.ts`。

## 分层约定

```
action / route handler（入口：zod 校验、会话校验、错误转换）
  → module.service（业务 + 事务 + advisory lock）
  → module.repository（Prisma 查询封装）
  → module.schemas（zod）+ module.types（类型）
```

规则：

- 每个业务域一个 module 目录，四文件：schemas / repository / service / types
- 事务边界在 service 层：$transaction 包裹"数据写入 + 积分变动 + 结算修正"
- repository 只做数据访问，不写业务判断
- 校验：zod schema 定义在 module 内，action 层或 service 层执行

## 鉴权

| 组件 | 位置 | 职责 |
|---|---|---|
| middleware | 根目录 | Cookie 存在性粗查 + 公开路径重定向 |
| getSession / requireUserId | lib/auth | jose 验签 HS256，payload {sub, email} |
| getCurrentUserId | lib/auth | API route 版本，失败抛 401 |

JWT 签发在登录（lib/auth 内），7 天过期，httpOnly Cookie `uptimer_session`。没有 refresh token、没有 token 轮换、没有 token version：改密不会作废已签发 token，只能等过期。

bcryptjs cost 12 做密码哈希。

## 数据、时间与错误处理

### 数据访问

- Prisma 单例（lib/prisma 或 lib/db），PrismaPg adapter，日志只开 warn/error
- 事务：service 层 `db.$transaction(async (tx) => ...)`，repository 方法接收 tx 参数（在事务内复用连接）
- advisory lock 在事务内获取：pg_advisory_xact_lock 的 SQL 通过 $executeRaw 或 $queryRaw 执行

### 时间与计算

- lib/time：date-fns 封装，日期边界、周期计算（周从周一开始）
- 时长：differenceInMinutes，至少 1 分钟
- 积分：round(回报率 × 分钟 / 60, 2)，decimal 运算在应用层算好后写入

### 错误处理

| 类型 | 处理 |
|---|---|
| 业务错误 | service 抛 Error（含消息）或自定义 ConflictError，action 捕获转页面 banner，route 转 JSON |
| zod 校验失败 | 400 + 校验消息 |
| 未登录 | redirect（页面）/ 401 JSON（API） |
| Prisma P2002 | 结算幂等捕获跳过 |

lib/errors 定义 ConflictError 等业务错误类。
