# 奖励与兑换

本文说明奖励模块的实现：商品管理、库存模型、兑换事务和记录。

本文不讨论积分体系本身，见 [[总体设计/积分模型|积分模型]]。

源码范围：`src/modules/reward/`、`src/actions/reward.actions.ts`。

## 商品模型

RewardItem：name、pricePoints、stockMode（LIMITED/UNLIMITED）、stock（限量时的库存数）、isEnabled、icon、color、note。

- 删除是硬删：有兑换记录时外键 Restrict 报错，service 捕获转 ConflictError"商品已有兑换记录，无法删除"
- update 接口把 isEnabled 固定写回 true：没有"停用/下架"入口，商品要么存在要么删除
- 库存编辑在 update 里（stock 字段可改，即"补货"）

## 兑换事务与记录

### 兑换事务（redeem）

```
输入：rewardItemId
  → $transaction：
      advisory lock(hashtext("reward-redeem:<userId>"))
      → advisory lock(hashtext("reward-redeem-item:<rewardItemId>"))
      → 商品存在且 isEnabled 校验
      → 库存校验：LIMITED 且 stock <= 0 → "库存不足"
      → 余额校验：pointBalance < price → "积分不足"
      → balance decrement（等价 increment 负值）+ 流水 REWARD_REDEEM
      → 限量商品 stock decrement
      → 写 Redemption（priceSnapshot + pointDelta = -price）
```

双锁的设计：用户锁防止同一用户并发兑换（余额竞态），商品锁防止同一商品并发兑换（库存竞态）。两把锁的获取顺序固定（先用户后商品），避免死锁。

### 兑换记录

Redemption：userId、rewardItemId、priceSnapshot、pointDelta、createdAt。

- 价格快照：兑换后商品改价不影响历史记录
- 没有"撤销兑换"功能：兑换即消费，积分流水永久保留

## 商品管理与已知边界

### 商品管理

- 创建：reward-editor-form（名称、价格、库存模式、库存数、图标）
- 修改：改价格/库存/名称（isEnabled 固定回 true）
- 删除：硬删，已有兑换记录的商品删不掉（外键 Restrict + ConflictError 提示）

### 已知边界

- 限量商品库存扣到 0 后自动不可兑换，补货靠编辑商品改 stock
- 兑换无确认弹窗：点兑换即执行（前端无 ConfirmDialog 逻辑）
- 没有"我的兑换记录"页面：兑换历史只能从积分流水（REWARD_REDEEM 类型）里看到
- 没有停用状态可用：想下架一个有兑换记录的商品，除了改价改库存没有别的办法
