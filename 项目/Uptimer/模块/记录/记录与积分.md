# 记录与积分

本文说明记录模块的实现：时间块创建、积分结算、冲突检测、修改删除的回滚。

本文不讨论积分体系的整体设计，见 [[总体设计/积分模型|积分模型]]。计时生成的记录路径见 [[模块/计时/计时会话|计时会话]]。

源码范围：`src/modules/record/`、`src/modules/points/`、`src/app/api/records/`。

## 创建记录（补录与计时的共同路径）

`createRecordInTransaction` 被两条路径复用：计时停止（source=TIMER）和补录表单（source=MANUAL）：

1. durationMinutes = differenceInMinutes(endAt, startAt)，至少 1 分钟
2. pointDelta = round(rewardRatePerHour × durationMinutes / 60, 2)
3. 快照：活动名、性质、回报率写入 Record
4. appendTransaction(RECORD_EARN, pointDelta)：余额 increment + 流水（balanceAfter）
5. reconcileSettlementsByRecordMutation：修正受影响的目标结算

冲突检测（ensureNoTimeConflict）：同用户 `startAt < end AND endAt > start` 的记录存在则 409 拒绝。

## 修改与删除

### 修改记录

`updateManual`（服务层不区分记录的 source，计时生成的记录同样可走修改路径）：

1. 锁用户时间轴（lockUserRecordTimeline，advisory lock）
2. 重算新 pointDelta，与旧 pointDelta 求差
3. 差额 ≥0.005 时补一条 RECORD_EARN 调整流水
4. 更新记录，快照按当前活动重写（activityNameSnapshot 等三个字段刷新）
5. 冲突检测 + 结算修正（reconcile 窗口取新旧时间的并集）

### 删除记录

`deleteManual`：

1. 删记录
2. 补等额负向 RECORD_EARN 回滚流水
3. 结算修正（删除可能让目标从达标变未达标）

API 返回 {id, delta, balance}，前端展示"已删除，积分变化 X，当前余额 Y"。

## 时间轴查询与快照

### 时间轴查询

`GET /api/records?date=YYYY-MM-DD` 返回三块：

- records：当天记录（按 startAt 排序）
- gaps：记录之间的空档（前端展示"空白时间"）
- range：当天的起止边界

### 活动快照的用途

记录存储 activityNameSnapshot 等三个快照，展示和分析都用快照而不是 join 活动表。活动改名、改回报率、软删除都不影响历史记录的显示和已结算积分。

## 已知边界

- 修改记录会按当前活动重写快照：改一条三个月前的记录，快照变成三个月后活动的当前样子，历史语义被破坏（这是刻意选择还是疏漏未定，见源码 record.service.ts:189-191）
- 时区：date-fns 按本地时区，跨时区用户的天边界会偏移
- 无分页：单日全量返回
- 补录没有上限校验：可以补一条 24 小时的学习记录（冲突检测会拦住重叠，但无单条上限）
- 负回报率活动的 RECORD_EARN 是负值流水，类型名"EARN"名不副实但语义统一
