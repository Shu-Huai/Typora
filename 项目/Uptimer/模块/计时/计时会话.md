# 计时会话

本文说明计时模块的实现：会话状态机、并发锁、冲突检测和 API。

本文不讨论积分结算本身，见 [[模块/记录/记录与积分|记录与积分]]。设计取舍见 [[总体设计/系统架构|系统架构]]。

源码范围：`src/modules/timer/`、`src/app/api/timer/`、`src/components/timer/timer-panel.tsx`。

## 会话状态机

![](http://public.file.lvshuhuai.cn/images\uptimer-timer-session.svg)

```
（无）→ RUNNING：startTimer 建会话（startedAt、activityId、status=RUNNING）
RUNNING → FINISHED：stop(mode=FINISH)，建记录+结算积分，会话置 FINISHED
RUNNING → CANCELED：stop(mode=CANCEL)，不产生任何记录和积分
```

约束：同一用户同时最多一个 RUNNING。开始计时时校验，违反抛 ConflictError"已有运行中的计时"。

## startTimer 与 stopTimer

### startTimer 的代码路径

```
POST /api/timer/start {activityId?, startedAt?}
  → getCurrentUserId 验签
  → timerService.startTimer(userId, input)
      → $transaction：
          pg_advisory_xact_lock(hashtext(userId))
          → 活动存在且 isEnabled 校验
          → 无 RUNNING 会话校验
          → 时间冲突检测（startedAt 与已有记录重叠）
          → create TimerSession(RUNNING)
      → 返回 {session}
```

activityId 可选：不传时允许"先开表再选活动"，随后通过 /api/timer/activity 切换。

### stopTimer 的代码路径

```
POST /api/timer/stop {mode, note?, endedAt?}
  → $transaction：
      lock(hashtext(userId))
      → 查 RUNNING 会话（无则 409）
      → FINISH：endAt 计算（<= startedAt 则 +1 秒）
        → recordService.createInTransaction（source=TIMER，note 默认"计时生成记录"）
        → session 置 FINISHED
      → CANCEL：session 置 CANCELED
  → 返回 {result}（含记录和积分结果）
```

## 前端秒表与并发边界

### 前端秒表

TimerPanel（CSR）：

- 开始后每 1 秒 setInterval 更新本地 elapsed 显示（纯展示，服务端无感知）
- 实际数据只在 stop 时一次性落库
- 刷新页面：GET /api/timer/current 恢复运行中会话，秒表从 startedAt 续算

### 并发与边界

- 用户维度 advisory lock：同一用户的开始/停止/切换串行，杜绝"两个并发 start 都通过单会话校验"的竞态
- 时间冲突：startedAt 与已有记录重叠抛 409，保证时间轴无重叠
- 时钟回拨：endAt <= startedAt 时 +1 秒，保证时长至少 1 分钟

## 已知边界

- 秒表运行期间服务端不保存中间状态：浏览器关了再开，会话还是 RUNNING（服务端），前端从 startedAt 续算，多出的时间是真实的（合理）；但用户可能忘了有个 RUNNING 会话，下次 start 被 409 拦住——前端有 /api/timer/current 的恢复引导，但若用户直接开新计时会困惑
- 切活动接口 /api/timer/activity 允许 activityId 为空（清空当前活动），此时停止仍可生成记录（活动为空则拒绝，走 CANCEL 或提示）
- 没有"最长计时"限制：跑一个星期的 RUNNING 会话，停止时生成超长记录，积分一次结算
- advisory lock 依赖 PostgreSQL，换库失效
