# 目标与结算

本文说明目标模块的实现：目标结构、周期计算、结算执行和修正。

本文不讨论结算的整体设计，见 [[总体设计/目标结算|目标结算]]。积分联动见 [[总体设计/积分模型|积分模型]]。

源码范围：`src/modules/goal/`、`src/app/api/goals/`、`src/app/records/page.tsx`。

## 目标结构与周期

### 目标结构

Goal：name、periodType（DAILY/WEEKLY/MONTHLY）、targetMinutes、rewardPoints、penaltyPoints、isEnabled。GoalActivity 关联参与统计的活动。

约束：

- 关联活动至少一个（没有活动的目标无法统计）
- 奖惩分 decimal(12,2)
- 停用（isEnabled=false）而不是删除，历史结算保留

### 周期计算

| periodType | 周期 | 说明 |
|---|---|---|
| DAILY | 自然日 | |
| WEEKLY | 周一到周日 | weekStartsOn: 1 固定 |
| MONTHLY | 自然月 | |

结算时计算 (periodStart, periodEnd) 时间窗口，统计窗口内关联活动的记录时长之和。

## 结算执行与修正

### 结算执行（settleGoalForPeriod）

```
输入：goal, periodStart, periodEnd, allowIncomplete
  → advisory lock(hashtext("goalId:periodStart:periodEnd"))
  → 查该周期是否已结算（@@unique 兜底）
  → 统计 totalMinutes（关联活动的 Record 求和）
  → 判定：
      达标 → isCompleted=true, delta=+reward
      未达标且关联活动全删 → delta=0
      未达标 → delta=-penalty
  → 写 GoalSettlement（含目标快照）+ PointTransaction
```

`settleOnRecordsVisit`（访问 /records 时）：结算上一个已结束周期（allowIncomplete=true）+ 当前周期（仅达标提前结）。

`settleExpiredGoals`（POST /api/goals/settle）：扫所有启用用户的过期周期，逐个结算，返回 {settledCount, scannedCount, settlements}。

### 结算修正（reconcileSettlementsByRecordMutation）

记录增删改后，找到时间与记录重叠的已结算周期：

1. 重算 totalMinutes
2. 重算 isCompleted 与 pointDelta
3. 新旧差额补 GOAL_REWARD/GOAL_PENALTY 调整流水
4. 更新 GoalSettlement

修正与结算共用同一个周期锁，防止结算和修正交错。

## 历史查询与已知边界

### 历史查询

GET /api/goals/[id]/history 返回最近 100 条结算（按 settledAt 倒序），字段含周期、总时长、是否达标、积分变动。

### 已知边界

- /api/goals/settle 无调用者鉴权：任何登录用户可触发全局结算
- 惰性结算依赖访问：不访问就不结算（见 [[总体设计/目标结算|目标结算]]）
- 未达标且活动全删的目标给 0 分：这个豁免规则在目标停用（isEnabled=false）但活动还在的场景不适用，仍会扣分
- 修正链长：改一个月前的记录会连锁修正多个周期
- 结算历史无分页（前 100 条截断），更早的永久不可见
- WEEKLY 周期不可自定义起始日
