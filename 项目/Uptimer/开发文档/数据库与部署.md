# 数据库与部署

本文说明数据库迁移、seed、构建部署方式和数据变更流程。

本文不讨论表结构细节，见 [[数据库/数据模型|数据模型]]。

源码范围：`prisma/`、`prisma.config.ts`、`package.json`、`next.config.ts`。

## 数据库迁移

Prisma Migrate 管理，`prisma/migrations/` 下 7 个迁移（从 init 到删 GoalGroup 共 7 次演进）。

日常命令：

```bash
npm run db:generate   # 改完 schema 后重新生成 client
npm run db:migrate    # 应用迁移
npm run db:seed       # 填充 demo 数据
```

变更流程：改 `prisma/schema.prisma` → `npx prisma migrate dev --name 描述`（生成迁移文件）→ 提交。不要手改已应用的历史迁移文件。

Prisma 7 注意点：datasource url 不在 schema 里，在 `prisma.config.ts` 读 `DATABASE_URL` 环境变量；engineType 是 binary。

## 构建与启动

```bash
npm run build    # next build
npm run start    # next start --hostname localhost --port 4399
```

Next.js 全栈应用，部署必须是 Node 环境：

- 产物：.next/（不是纯静态站）
- 生产域名线索：next.config.ts 的 allowedDevOrigins 含 `uptimer.lvshuhuai.cn`、`lvshuhuai.cn`、`192.168.1.50`，说明作者在自有服务器/内网部署
- git 远程是自建 GitLab（http://gitlab.lvshuhuai.cn/ShuHuai/Uptimer.git）

## 部署清单与数据变更

### 部署检查清单

上线前必须逐项确认：

1. AUTH_SECRET 换成随机强密钥（缺省值 "dev-auth-secret-change-me" 是公开的）
2. AUTH_COOKIE_SECURE 设为 true（HTTPS 环境）
3. 数据库备份策略（当前无归档、无备份脚本）
4. 反向代理配置（Next.js 需要 Node 进程守护，pm2/systemd）
5. 想清楚目标结算策略：无定时任务，惰性结算依赖用户访问；若要可靠结算，部署一个 cron 调 POST /api/goals/settle（注意该接口当前任何登录用户可触发，需要加保护）

### 数据变更与回滚

- 迁移是单向的：Prisma 支持 migrate reset 回空，但不支持部分回滚。生产环境回滚要写新迁移反向操作
- seed 的 demo 数据与用户数据混在同一库，删库重来的成本是丢失全部真实数据
- 无数据导出能力：用户数据只能从 PostgreSQL 层面备份

## 已知边界

- 无 Docker、无 CI、无自动部署，发布全靠手工
- 无日志收集：Next.js 控制台日志随进程，进程守护工具的日志就是全部
- 无监控告警：服务挂了没人知道
- 无备份策略：数据库是整个系统的唯一状态，丢失即全损
- README 还是 create-next-app 模板，没有部署文档
