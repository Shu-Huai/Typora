## 项目概况

Badminton-Flash 是校园羽毛球约场系统。管理员提前配置场次（抢票时间、场馆时间、时间槽间隔），系统在开抢前自动预热库存，学生在开闸瞬间抢时间槽，抢到后 15 分钟内完成支付，否则订单自动取消、库存回补。

当前实现是前后端分离的单体应用：

- 后端：Spring Boot 3.5.4 单体，Java 23，端口 25001，源码在 `\\driver.lvshuhuai.cn\Raid\JetBrains\IDEA\Badminton-Flash-Backend`
- 前端：Vue 3 + TypeScript + Vite 7 单页应用，端口 10096，源码在 `Z:\JetBrains\WebStorm\Badminton-Flash-Frontend`
- 依赖：MySQL、Redis（Redisson）、RabbitMQ
- 支付：全部走 mock，不调用真实微信支付接口

技术栈选型的细节见 [[总体设计/系统架构|系统架构]]。

## 关键事实速查与原有文档

- 后端端口 25001，前端开发端口 10096（前端 README 写 50096，与代码不符，以 vite.config.ts 为准）
- 数据库名 `badminton_flash`，Redis 使用 `database: 2`，所有 key 以 `bf:` 为前缀
- 一个时间槽库存为 1（RSemaphore permits=1），先到先得
- 预约接口同步只返回 traceId，结果通过 `GET /reserve/result/{traceId}` 轮询
- 支付超时默认 15 分钟（`PAY_TIMEOUT_MINUTE`），预热提前默认 5 分钟（`WARMUP_MINUTE`）
- 每用户每分钟预约请求上限 5 次（Bucket4j）
- 管理员账号 `root` 由 data.sql 初始化，密码为 MD5 大写存储值 `5A31893BE1B474502A046E74841E119B`

`docs/KernelProcess.md`、`docs/RBAC.md`、`docs/Scheduler.md` 仍在后端仓库内维护。本目录的文档是面向持续开发的重写版，覆盖范围更大（含前端、数据库、部署、压测），事实以源码为准。两者有不一致时，本目录的文档为准，并在对应位置标注。
