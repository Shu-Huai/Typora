# 后端分层

本文说明后端的分层约定、公共组件和各层职责。

本文不讨论业务逻辑，见各模块文档。包结构总览见 [[总体实现/实现总览|实现总览]]。

源码范围：`src/main/java/shuhuai/badmintonflashbackend` 全部包。

## 分层约定

Controller → Service（接口 + impl）→ Mapper（MyBatis-Plus BaseMapper）。没有独立的 Repository 层。

- Controller 只做参数接收和返回包装，业务判断全部在 Service
- Service 接口和实现一一对应，唯一例外是 IReserveService 有两个实现（redis/db 模式，靠 `@ConditionalOnProperty` 切换）
- Mapper 全是空接口，SQL 全靠 MyBatis-Plus 的 LambdaQueryWrapper 动态拼装，没有 XML 映射文件
- 实体直接当返回值出 Controller（browse 系列返回 entity 本身），VO 只用于用户信息、支付凭据、抢票结果、支付状态四种场景
- 异常统一抛 BaseException（带 ResponseCode），全局处理器转成 Response 结构

## Controller 与 Service 层

### Controller

| 控制器 | 职责 |
|---|---|
| AuthController | 注册、登录，签发 token |
| UserController | 本人信息查询和修改 |
| BrowseController | 全部只读查询，含开闸状态 |
| ReserveController | 抢票、查结果、取消 |
| PayController | 支付单创建、mock 成功、退款、查状态 |
| AdminController | 配置、场次、用户管理，全部 dbCheck |
| BaseController | 全局异常处理 + ResponseBodyAdvice 日志，不是端点 |

鉴权注解在类级统一声明（Browse/User/Reserve/Pay 为 USER，Admin 为 ADMIN + dbCheck），方法级覆盖（如 mock-success 单独标注 ADMIN）。

### Service

| 服务 | 关键方法 | 要点 |
|---|---|---|
| IReserveService | reserve / getReserveResult / cancel / cancelTimeoutPending | 双实现切换，见 [[模块/预约/预约实现|预约实现]] |
| IPayService | createWechatPay / mockWechatPaySuccess / refund / getPayResult | mock 支付，见 [[模块/支付/支付与退款|支付与退款]] |
| IUserService | register / login / getRole / getMe / updateMe / deleteMe + admin CRUD | 见 [[模块/认证与用户/认证与用户|认证与用户]] |
| IAdminService | getConfig / updateConfig / addSession / warmupSession / openSession / generateSlot / reconcileCourtsByConfigAtStartup | 见 [[模块/管理端/管理功能|管理功能]] |
| IBrowseService | 8 个查询方法 + isSessionOpen | 纯查询 |
| ITimeSlotService | generateForDate + session 联动 | 槽生成与幂等 |
| IRateLimitService | tryConsume | Bucket4j 封装 |

## 配置、DTO 与工具

### 配置与 Bean 装配

| 类 | 作用 |
|---|---|
| TokenConfig | token 密钥和双阈值 |
| WechatPayConfig | 微信支付参数（当前仅日志用） |
| TimeZoneConfig + TimeZoneInitializer | 启动时强制 Asia/Shanghai，注入 DateTimes |
| ReserveModeConfig | reserve.mode 切换 |
| JasyptConfig | 解密参数 |
| AuthWebConfig | 注册 TokenValidator 拦截器 |
| RabbitBean | 交换机/队列/模板/监听容器（重试与死信） |
| RedisBean | RedisTemplate 全家桶（业务主链路未用） |
| JasyptBean | jasyptComputer 加密器 |

没有 CORS 配置类（前端走代理或网关反代）、没有自定义 MyBatis 配置类（全默认）、没有 Knife4j 配置类（依赖自动装配）。

### DTO 与 VO

入参 DTO 全部在 `model/dto`：UserDTO、UserSelfUpdateDTO、ReserveDTO、FlashSessionDTO、ConfigDTO/ConfigItemDTO、ConditionBrowseSessionDTO/ConditionBrowseSlotDTO、AdminUserDTO。browse 的条件对象由 Controller 从请求参数手工组装。

出参 VO 在 `model/vo`：UserAccountVO（隐藏密码字段）、WechatPayCreateVO、ReserveResultVO、PayOrderResultVO。

### 公共工具

| 类 | 说明 |
|---|---|
| TokenValidator | 拦截器主体：验签、角色判定、dbCheck、token 续期回写、ThreadLocal 管理 |
| RequestGetter | 拿当前请求/响应、完整 URL（日志用） |
| RedisConnector | RedisTemplate 通用封装 + 过期时间枚举，业务主链路未使用 |
| JasyptComputer | 项目内解密器实现（PBEWithMD5AndDES） |
| HashComputer | MD5 大写哈希（密码） |
| DateTimes | 应用时区时间工具（nowMinute、ttlToEndOfDaySeconds、yyyymmdd） |

## 日志约定

- 全局成功日志由 BaseController 的 beforeBodyWrite 输出，前缀为请求 URL
- 异常日志按异常栈定位业务类的 logger，warn 级记录 BaseException，error 级记录未知异常
- yml 把 ReserveController/ReserveServiceImpl/ReserveConsumer 调成 ERROR 级，压测时避免日志洪峰
- 无日志框架扩展、无文件归档、无链路追踪 ID（traceId 只存在于预约领域，不进日志上下文）
