# 库存与预热

本文说明时间槽怎么生成、预热往 Redis 写了什么、开闸怎么发生、球场怎么对账。

本文不讨论调度时机，见 [[总体实现/定时任务|定时任务]]。不讨论抢票时怎么用这些 key，见 [[模块/预约/预约实现|预约实现]]。

源码范围：`service/impl/AdminServiceImpl.java`（warmupSession、openSession、generateSlot）、`service/impl/TimeSlotServiceImpl.java`、`scheduler/WarmupScheduler.java`、`constant/RedisKeys.java`。

## 时间槽生成与预热

### 时间槽生成

`TimeSlotServiceImpl.generateForDate(date, sessionId)`：按 `court × 时间段` 笛卡尔积生成。球场来自 court 表（配置里 COURT_COUNT 个），时间段按 `beginTime → endTime` 每 `slotInterval` 分钟切一段，跨零点算在开始那天。

幂等双保险：

- 库唯一键 `(slot_date, start_time, end_time, court_id, session_id)`，重复插入 DuplicateKeyException 吞掉
- Redis done 标记 `bf:slotgen:done:{ymd}:{sessionId}` + 锁（lease 120s）

时间槽与场次联动：新增场次时若场次未过期立即生成当天槽；改场次先删当天槽再按新参数生成；删场次删当天槽并清 Redis。

### 预热内容

`warmupSession(session)` 执行（带锁 `bf:warmup:lock:{ymd}:{sessionId}` lease 60s，加锁前后双重检查 done 标记）：

1. 先 `generateSlot`（补生成时间槽，幂等）
2. 取当天该场次全部 slot，逐个写：

| key | 类型 | 值 | TTL |
|---|---|---|---|
| bf:slot:session:{slotId} | Bucket | sessionId | 到当天结束 |
| bf:sem:{slotId} | Semaphore | permits=1 | 到当天结束 |
| bf:dedup:{slotId} | Set | 预置 -1 占位 | 到当天结束 |
| bf:warmup:done:{slotId} | Bucket | "1" | 到当天结束 |

3. 场次级：gate 不存在则置 "0"，`bf:gate:time:{sessionId}` 写今日 flashTime 的 epoch 秒
4. 全部完成后 `bf:warmup:done:{ymd}:{sessionId}` = "1"

TTL 计算 `ttlToEndOfDaySeconds`，到次日零点，且保证至少 60 秒。

dedup 预置 -1 占位的原因：RSet 为空时不存在于 Redis，占位保证 key 和 TTL 存在，也避免"集合刚建立就被回收"的边界。

## 开闸与球场对账

### 开闸

两个入口：

- 定时任务 `WarmupScheduler.openGate`：flashTime 到点的场次，未预热先补预热，done 标记存在后 `bf:gate:{sessionId} = "1"`
- 手动接口 `POST /admin/open/{sessionId}`：同样要求先预热

闸门只翻一次（"1" 后跳过）。没有"关闸"操作：当天开闸后直到 TTL 过期都保持开启。如果需要中途关闸，只能删 key 或等第二天。

### 球场对账

`reconcileCourtsByConfigAtStartup` 在应用启动时执行（`CourtBootstrapScheduler`，带锁 lease 180s）：

- court 表数量 ≠ COURT_COUNT：在允许窗口内修复（增删球场），否则告警跳过
- 球场名 ≠ COURT_NAME_FORMAT 模板：重命名修复
- 允许窗口：`00:00 ≤ now < 当天第一场预热开始`，超出不允许改

管理面板改配置时的球场同步（syncCourts）和启动对账共用这套约束逻辑。

## 完整时间线与运维要点

### 完整时间线

```
前一天或更早   管理员建场次（flashTime 08:00）
00:35          定时任务生成当天全部时间槽（默认 GENERATE_TIME_SLOT_TIME）
07:55          预热扫描启动（WARMUP_MINUTE=5）：写 sem/dedup/slot:session，gate="0"
08:00          自动开闸：gate="1"
08:00~         学生抢票
次日 00:00     全部 Redis key TTL 过期，库存消失（订单在库里，不受影响）
```

### 运维要点

- Redis 误清空后：重新调 `POST /admin/warmup/{sessionId}` 可重建该场次全部 key，不用改数据库
- 开闸状态丢失后重建预热会重置 gate 为 "0"，需要重新 open
- 删场次前先想清楚：当天槽物理删除，正在 PENDING_PAYMENT 的订单仍然存在，但槽没了，取消/超时释放时 sem.release 会报 key 不存在（Redisson 对不存在的信号量 release 会自愈，但需确认版本行为）
- 时间槽物理删除与逻辑删除混用：删场次时 time_slot 是物理删，其他表都是逻辑删

### 已知边界

- 预热锁 lease 60s，槽很多时预热可能超过 60s 导致锁提前释放，第二个预热者重入。done 标记双检缓解，但极端情况下会重复写 key（幂等，无害）
- TTL 到"当天结束"，但用 `ttlToEndOfDaySeconds` 和另一处"到 23:59:59"的版本并存，跨午夜前最后几秒行为有细微差异
- 没有"取消预热"和"关闸"接口，误开闸只能等第二天
