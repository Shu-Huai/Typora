# 认证与用户

本文说明注册登录、token 签发续期、账户规则和管理员的用户管理。

本文不讨论鉴权拦截链的实现，见 [[总体设计/权限边界|权限边界]]。不讨论前端 token 存储，见 [[前端/前端架构|前端架构]]。

源码范围：`controller/AuthController.java`、`controller/UserController.java`、`service/impl/UserServiceImpl.java`、`utils/TokenValidator.java`、`utils/HashComputer.java`。

## 注册登录与 token 签发

### 注册与登录

注册 `POST /auth/register`：body 只有 studentId 和 password。密码经 `HashComputer`（MD5 大写十六进制）哈希后存储，不存明文。学号重复时数据库唯一键抛 DuplicateKeyException，转成 USER_DUPLICATED。

注册和登录成功都直接签发 token 返回（`data` 字段就是 token 字符串），前端拿到后存 localStorage 并跳转。

账号规则：

- 注册默认 USER 角色
- 无邮箱、手机号、昵称字段
- 无密码强度校验、无验证码、无注册频控（批量注册脚本正是利用这一点）

### token 签发

JWT HS256，claims 只放 `userId`、`role`、`issuedAt`（epoch 毫秒）。没有 exp。密钥 `token.privateKey`，前端永远不接触密钥。

签发路径只有两处：注册、登录。续期不是重新签发，是校验通过时在响应头回写一个新 token（age 超过 youngToken 时），前端拦截器自动替换。

## 账户自助操作

| 操作 | 规则 |
|---|---|
| GET /user/me | 返回 UserAccountVO（不含密码） |
| PATCH /user/me | 改学号或改密码。改密码必须带 oldPassword 验证旧密码。三项都可选，至少一项 |
| DELETE /user/me | 自助销户（逻辑删除）。ADMIN 账号禁止自助删除 |

销户后 token 仍有效到 oldToken 阈值（前端会清 token，但服务端不主动作废），见 [[总体设计/权限边界|权限边界]]。

## 管理员操作与角色获取

### 管理员的用户管理

AdminController 提供完整 CRUD，Service 层做二次权限校验 `assertCanAdminUpdate`：

- ADMIN 不可改、删其他 ADMIN（防止管理员互相夺权）
- ADMIN 可以改自己
- 删除 ADMIN 一律禁止（包括自己操作自己）
- 创建用户可指定角色 USER 或 ADMIN

管理员创建的用户同样要保证学号唯一，密码同样 MD5 存储。

### 角色获取的两种方式

- token 声明：所有请求的默认来源
- 数据库：dbCheck 接口复核，见 [[总体设计/权限边界|权限边界]]

前端 DashboardView 进入时调 `/user/me` 拿 `userRole` 同步到 store，以服务端为准。管理 tab 的显示用的是 store 里 sync 后的角色，但路由守卫本身不检查角色。

## 已知边界

- 无验证码和注册频控，注册接口可被脚本刷
- 密码 MD5 无盐，弱口令+数据库泄露即等于明文泄露
- 无找回密码、无强制改密、无密码过期
- 学号修改即时生效但已签发 token 的 userId claim 不变：改学号不影响 token 有效性和数据归属（userId 是数字主键）
- 无账号冻结/封禁机制，只有逻辑删除，管理员只能"删"不能"停"
