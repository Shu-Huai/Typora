# 面试鸭 HTML 转个人规范 Markdown SOP

## 目标

将桌面上的面试鸭 HTML 面试题，解析为 `D:\Typora\八股文` 下符合个人写作习惯的 Markdown 文档，并将文档中的在线图片下载到 `Z:\Public\images`，把图片引用改为本地路径。

## 输入与输出

- 输入：`C:\Users\lvzhi\Desktop` 下的面试鸭 HTML 文件。
- 输出：`D:\Typora\八股文` 对应知识分类目录中的 `.md` 文件。
- 图片目录：`Z:\Public\images`。
- 图片引用统一使用：`Z:/Public/images/文件名`。
- 解析工具：`D:\Typora\reparse_html.py`。

## 操作流程

### 1. 定位原始 HTML

不要手写或猜测文件名。使用通配符在桌面递归查找：

```powershell
$src = Get-ChildItem -LiteralPath 'C:\Users\lvzhi\Desktop' -Recurse -File |
  Where-Object { $_.Name -like '题目关键词*html' } |
  Select-Object -First 1 -ExpandProperty FullName
```

如果找不到原始 HTML，应停止并报告，不能凭空生成答案。

### 2. 确定输出目录和文件名

- 根据主题选择已有分类目录，例如 `Java后端\Spring`、`Java后端\消息队列\RabbitMQ`、`数据库\Redis`。
- Markdown 文件名以正文首个 H1 的显示文本为准。
- 去除 HTML 文件名中的“面试鸭”、日期和其他来源后缀。
- Markdown 语法反引号不放入文件名。
- Windows 不允许文件名包含 `\ / : * ? " < > |`。标题中的 `/` 用 `_` 替代，并在最终结果中说明。
- 先检查目标文件是否已存在，避免覆盖已有正文。

### 3. 从 HTML 解析 Markdown

使用已有解析器：

```powershell
$dst = 'D:\Typora\八股文\分类\题目.md'
python D:\Typora\reparse_html.py $src $dst '题目 H1 文本'
```

解析器必须保留：

- 标题层级；
- 段落、列表、引用和表格；
- `<pre><code>` 中的完整代码、缩进和换行；
- 代码语言标识，例如 `java`、`yaml`、`bash`；
- HTML 中的链接和图片。

禁止把代码块当普通文本压成一行，也禁止用大规模正则直接重写全文。

### 4. 下载并替换图片

扫描生成的 Markdown 中的 `http://` 或 `https://` 图片引用：

1. 从 URL 提取文件名；
2. 下载到 `Z:\Public\images`；
3. 如果目标图片已经存在，直接复用；
4. 将引用改为 `Z:/Public/images/文件名`；
5. 使用 UTF-8 无 BOM 保存 Markdown。

图片引用示例：

```markdown
![示意图](Z:/Public/images/example.webp)
```

不能只替换引用而不实际下载文件。下载失败时要记录具体 URL。

### 5. Markdown 规范化

逐文件检查并修复以下规则：

1. 文件开头只能有一个一级标题，且第一行就是 H1。
2. 文件末尾不能有 `...`、多余空格或空行。
3. 中文与数字、英文之间通常保留一个空格；句首、句尾、标点和括号附近按语境处理。
4. 中文之间不插入空格，例如“生产者和消费者”。
5. 类名、方法名、注解、变量名、命令和其他代码标识符使用反引号，例如 `` `ArrayList` ``、`` `@Autowired` ``。
6. 普通链接必须使用 `[文字](URL)`，不能在正文中裸写 URL。
7. 中文语境使用中文括号、逗号、冒号、分号和引号；英文语境使用英文标点。
8. 完整超链接形式的标题，例如 `## [JMS vs AMQP](URL)`，改为 `## JMS vs AMQP`；标题中只有部分文字是链接时保留链接。
9. 连续的 `1）`、`2）` 等内容改为标准有序列表 `1.`、`2.`。
10. 表格必须使用 Markdown 管道格式，不能把表头和单元格压成连续文本。每个单元格中的中文与英文、数字之间也要按语境留空格；类名、方法名、变量名等使用反引号，例如 `LinkedHashMap`、`key`、`ConcurrentHashMap`。
11. 发现类似“场景推荐实现原因需要保持插入顺序LinkedHashMap内部维护……”的连续文本时，必须根据语义恢复为表格，不能只在连续文本中插入几个空格。
12. 代码块必须使用成对的围栏：

```markdown
```java
代码内容
```
```

代码块内的内容不得做中文英文自动加空格、标点替换或代码重排。

13. Java 或其他语言的类名、接口名、包名、方法名、变量名、关键字、注解、命令和代码表达式使用行内代码，例如 `ArrayDeque`、`java.util.concurrent`、`list.remove(i)`。已经位于代码块或反引号中的内容不重复包装。
14. 时间复杂度、数学表达式和幂次使用 LaTeX 行内公式，例如 `O(n)` 改为 `$O(n)$`，`O(log n)` 改为 `$O(\log n)$`，`n^2` 改为 `$n^2$`。较长或独立成行的公式使用成对的 `$$` 包裹，并保持公式内容为合法 LaTeX。代码块中的数学表达式不改写。

### 6. 文件名和 H1 校验

读取每个 Markdown 的首个 H1，计算安全文件名后比较：

```powershell
$title = '首个 H1 的显示文本'
$safe = ($title -replace '`','' -replace '[<>:"/\\|?*]','_').TrimEnd(' ','.')
```

文件名（不含 `.md`）必须等于 `$safe`。发现重名时：

- 完全相同的重复文件只保留一个；
- 标题文件与完整正文文件优先保留完整正文；
- 被移出的重复文件先放入独立备份目录，禁止直接删除。

### 7. 最终审计

对 `D:\Typora\八股文` 递归检查：

- 所有图片引用是否以 `Z:/Public/` 开头；
- 所有图片文件是否真实存在；
- 代码围栏数量是否为偶数；
- 是否恰好一个 H1，且在第一行；
- 是否存在文件末尾空行或 `...`；
- 是否存在整行标题超链接；
- 文件名是否与 H1 一致；
- 是否有空白文件或只有 H1 的文件；
- 是否有残留 `复制代码`、`▼` 等网页转换标记；
- 正文中是否有未包装的裸链接。

审计发现正文只有 H1 的文件时，优先在桌面寻找对应原始 HTML 并重新解析；找不到源文件时必须单独报告，不能自行补写。

## 安全原则

- 先读取、后修改；先生成审计结果，再执行批量变更。
- 不使用 `git reset --hard`、递归删除或覆盖式重写。
- 批量重命名采用临时文件名两阶段操作，避免同目录文件互相覆盖。
- 任何重复文件都先备份再处理。
- 修改后重新审计，只有审计通过才能报告完成。
