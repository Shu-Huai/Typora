# 多模态大语言模型 MLLM

## 什么是 MLLM

MLLM，Multimodal Large Language Model，多模态大语言模型。它可以看成是在 LLM 的基础上，引入了图像、音频、视频、文档页面等非文本输入能力的模型系统。

如果说 LLM 主要处理“文本到文本”的问题，那么 MLLM 处理的是“多模态输入到文本输出”的问题。它不仅能读文字，还能看图、看表格、看截图、看文档版面，甚至理解视频帧和音频片段。

从本质上说，MLLM 仍然是**以语言模型为核心**的系统。它并不是完全抛弃 LLM，而是在 LLM 前面增加了非文本模态的编码与对齐模块，让不同模态的信息最终都能进入语言模型进行统一推理。

## MLLM 和 LLM 的区别

LLM 的输入通常是：

- 文本
- token 序列
- token id 序列
- embedding 向量序列

而 MLLM 的输入通常变成：

- 文本 token 序列
- 图像或其他模态编码后的表示
- 二者组合后的统一输入表示

因此，MLLM 和 LLM 的关键区别不在于“后面的语言模型完全不同”，而在于**输入侧多了一条非文本模态处理链路**。

可以简单理解为：

- **LLM**：只吃文本
- **MLLM**：先把图像、音频等转成模型可接收的表示，再和文本一起交给 LLM

## MLLM 的典型结构

一个典型的 MLLM 通常由三部分组成：

1. 模态编码器
2. 对齐或映射模块
3. LLM 主体

可以写成：

**图像 / 音频 / 视频 → 模态编码器 → projector / adapter → LLM**

### 模态编码器

模态编码器负责把原始非文本数据变成高层特征表示。

例如：

- 图像常用视觉编码器，如 ViT、CLIP Vision Encoder
- 音频常用音频编码器
- 视频常常拆成多帧后再用视觉编码器处理，或者用专门的视频编码器

这一步的作用不是生成文字，而是提取高层语义特征。

### Projector / Adapter

模态编码器输出的特征空间，通常和 LLM 的 embedding 空间不一致，所以中间需要一个映射模块，把视觉或音频特征转换到 LLM 能理解的表示空间中。

这一层可能是

- 线性层
- MLP
- Q-Former
- Cross-Attention 模块

它的核心作用是

**把非文本模态特征转换成语言模型可消费的向量表示。**

### LLM 主体

完成对齐之后，后面的核心推理仍然主要由 LLM 负责。也就是说，MLLM 的“思考”和“输出”能力，很多时候依然主要来自后面的语言模型。

因此，MLLM 的本质不是“重新发明一个全新的智能系统”，而是“给 LLM 接上多模态输入口”。

## 图像不是直接变成文字

一个常见误解是：MLLM 就是“先把图像识别成一句文字，再交给 LLM”。

这不准确。

更真实的过程是：

- 图像先被切成 patch 或区域
- 视觉编码器从这些 patch 中提取视觉特征
- 这些特征经过映射模块，变成 LLM 可接收的表示
- 然后和文本一起进入后续语言模型

所以，MLLM 拿到的不是一段简单 OCR 文本，而是**图像的语义表示**。也正因为如此，MLLM 才不仅能读图中的文字，还能理解：

- 图像内容
- 目标关系
- 图表含义
- 文档布局
- 截图界面
- 多图与文本之间的对应关系

## MLLM 的输入形式

从工程角度看，MLLM 的输入通常可以理解为：

**文本 token 序列 + 视觉 token 或视觉向量序列**

例如用户问：

> 这张图里的人在做什么？

系统内部并不是只送入这句文本，而是同时送入：

- 图像编码后的视觉表示
- 用户问题对应的文本 token

因此，MLLM 的上下文不再只是文本长度，而是：

**文本长度 + 多模态表示长度**

这也是为什么多模态模型在推理时往往更耗显存和上下文预算。因为一张图往往会转换成很多视觉表示，占用一定的上下文容量。

## MLLM 的几类常见路线

### Encoder + Projector + LLM

这是最常见的结构。先用模态编码器提特征，再通过 projector 映射到语言模型空间，最后让 LLM 统一处理。

优点是结构清晰、工程实现相对成熟。

### Q-Former 类桥接结构

这类方法会在视觉编码器和 LLM 之间加入一个专门的“查询模块”，用少量查询向量从大量视觉特征中提取最关键的信息，再送给 LLM。

它的优点是可以压缩视觉信息，减少上下文负担。

### 原生统一建模

有些方法尝试把不同模态都尽量统一成 token，然后用统一 Transformer 处理。这种方式更统一，但训练和工程复杂度也通常更高。

## MLLM 解决了什么问题

现实世界中的信息并不只有纯文本。很多任务都涉及：

- 图片
- 文档页面
- 表格
- UI 界面
- 视频帧
- 医学影像
- 遥感图像
- 图文混合内容

传统 LLM 无法直接处理这些输入，而 MLLM 的价值就在于：

**把语言模型从“纯文本智能”扩展为“跨模态智能”。**

因此，MLLM 特别适合这些任务：

- 图像问答
- 文档理解
- 图文检索
- 多模态 RAG
- 截图与界面理解
- 视觉 Agent
- 多图长文理解
- 医疗或科研图文分析

## MLLM 的难点

### 跨模态对齐

图像和文本天然属于不同表示空间。如何让图中的对象与文本中的概念在语义上对齐，是核心问题之一。

### 上下文和计算成本

图像通常会被表示成较多的视觉 token 或中间特征，因此多模态输入通常比纯文本输入更占显存和上下文。

### 细粒度理解

模型可能能判断“图里有一只猫”，但不一定稳定回答“左下角那只猫旁边杯子的颜色是什么”。全局理解容易，局部精确理解更难。

### 视觉理解与语言推理的衔接

有些模型视觉编码能力不错，语言能力也不错，但两者之间的衔接未必稳定。模型有时会看见部分线索，再由语言模型进行模式补全，而不是真正完成稳定的跨模态推理。

## MLLM 和 LLM 的关系

你可以把 MLLM 理解成是在 LLM 前面加了一条多模态支路。

LLM 的流程大致是：

**文本 → tokenizer → token id → embedding → Transformer → 输出**

MLLM 的流程则可以看成：

**图像 / 音频 / 视频 → 模态编码器 → projector → 多模态表示**

**文本 → tokenizer → token id → embedding → 文本表示**

**多模态表示 + 文本表示 → LLM → 输出**

所以，MLLM 并不是完全不同的一套系统，而是**LLM 主体基本保留，输入侧扩展到多模态。**

## 常见混淆

### MLLM 和 VLM

- **VLM**：Vision-Language Model，通常强调视觉与语言
- **MLLM**：Multimodal Large Language Model，范围更广，不一定只包括视觉，也可能包括音频、视频等

很多场景里这两个词会混用，但严格说，MLLM 的范围更大。

### MLLM 和 OCR

OCR 主要关注“把图中的文字识别出来”。

MLLM 不只是读文字，它还可以理解图像内容、关系、布局、视觉语义，因此不能简单等同于 OCR。

### MLLM 和图像分类模型

图像分类模型通常只输出固定类别标签，而 MLLM 以语言模型为核心，能进行开放式回答、描述、推理和多轮交互，这比传统视觉分类更灵活。
