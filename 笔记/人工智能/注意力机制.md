# 注意力机制

## 注意力机制（Attention Mechanism）

### 核心思想

> 让模型动态决定“当前输入位置应该关注哪些其他位置的信息”。

就像人类读一句话或观察图像时，不是平均处理所有信息，而是**聚焦于重点**部分。

### 数学形式（Scaled Dot-Product Attention）

给定输入序列 $X = [x_1, x_2, ..., x_n]$，对于每个输入 $x_i$，通过线性变换得到：

- $q_i = W^Q x_i$（Query）
- $k_i = W^K x_i$（Key）
- $v_i = W^V x_i$（Value）

其中 $W^Q, W^K, W^V \in \mathbb{R}^{d \times d_k}$ 是可学习参数。

- **Query（$Q$）**：我要找的信息
- **Key（$K$）**：信息的标签，用于被匹配
- **Value（$V$）**：信息的内容

计算步骤：

1. **打分**（相关性）：

    $\text{score}_{ij} = \frac{q_i \cdot k_j}{\sqrt{d_k}}$

2. **softmax归一化**：

    $\alpha_{ij} = \text{softmax}(\text{score}_{ij})$

3. **加权求和**得到输出：

    $\text{output}_{i} = \sum_{j=1}^n \alpha_{ij} v_j$

完整矩阵表达式：
$$
\text{Attention}(Q, K, V) = \text{softmax}\left( \frac{QK^T}{\sqrt{d_k}} \right) V
$$

### $K$/$Q$/$V$ 的直观解释

- **Query（$Q$）**：当前这个位置想了解什么
- **Key（$K$）**：其他位置能提供什么
- **Value（$V$）**：其他位置提供的具体内容

模型通过 **$Q$ 和 $K$ 的相似度** 判断“应该关注谁”，然后通过权重整合对应的 $V$。

#### 换句话说：

对于每个 token，我们都要：

1. 用它自己的向量（Query）
2. 去对比输入序列中所有其他 token 的向量（Key）
3. 得到一组“相关性权重”
4. 用这些权重去加权其他 token 的表示（Value）
5. 得到一个新的向量，代表当前 token 综合了其它 token 的信息

####  举个更具体的例子

句子是：

```
小明 喜欢 吃 苹果
```

现在我们处理 token 「喜欢」：

- 它的 **Query** 是「喜欢」的向量。
- 每个 token（包括「喜欢」自己）都有一个 Key 和一个 Value。
- 我们计算「喜欢」的 Query 和所有 Key 的相似度：
    - 与「小明」的 Key 的相似度 → 权重 $\alpha_1$
    - 与「喜欢」自己的 Key 的相似度 → 权重 $\alpha_2$
    - 与「吃」的 Key 的相似度 → 权重 $\alpha_3$
    - 与「苹果」的 Key 的相似度 → 权重 $\alpha_4$
- 然后将所有 Value 向量按这些权重加权求和，得到一个新的向量，代表「喜欢」的位置输出。

### 什么是“位置”？

- 在文本中，“位置”指的是序列中的每个 token（词）。
- 每个位置有一个向量表示，模型会计算该位置与其它位置的关系。

### 为什么不能直接通过词嵌入的特征向量求相关性？

**因为词嵌入是静态的，而注意力机制需要**在具体上下文中**动态建模 token 之间的关系。**

#### 词嵌入是静态的，不含上下文信息

- 假设 “apple” 这个词，无论出现在“吃了一个 apple”还是“Apple 发布新产品”，它的词嵌入向量是一样的。
- 词嵌入只是描述“apple”这个词本身的语义，但**不了解它在句子中的具体含义或用途**。

所以直接用词嵌入之间做相似度计算，会失去上下文语境。

#### 注意力机制需要“谁来关注谁”

注意力不是只看两个词是否语义相似，而是问：

> “在当前语境下，这个 token **是否对我有用**？”

举例：在句子“我喜欢吃苹果”中，“喜欢”想知道“吃苹果”的信息，但可能不需要关注“我”。

所以我们需要一个方式，让当前 token（“喜欢”）去**主动询问别的词能不能帮到我**。

这就是为什么我们使用：

- **Query（$Q$）** 表示“我想找什么”
- **Key（$K$）** 表示“你能提供什么”
- 不是直接比较词嵌入，而是通过投影成 $Q$ 和 $K$ 再比

#### $K$/$Q$/$V$ 映射是可学习的，具有任务适应性

- 词嵌入只是预训练的静态向量。
- $K$/$Q$/$V$ 是通过训练得到的线性变换，可以学出更适合当前任务的表示方式。
- 在不同任务、不同层里，$K$/$Q$/$V$ 的变换方式是不同的 —— 比如有的层关注语义，有的层关注语法。

## 自注意力

**每个 token 同时作为 Query、Key、Value，互相之间计算注意力**。

### 换句话说

> 每个位置都在问：“我该从句子中哪些位置吸收信息来完善自己？”
>
>  并且这个问答过程发生在句子中的所有位置之间，同时进行。

### 数学结构

假设有输入序列：

$X = [x_1, x_2, ..., x_n],\quad x_i \in \mathbb{R}^d$

我们对整段输入进行三个线性变换：

$Q = X W^Q,\quad K = X W^K,\quad V = X W^V$

接着使用注意力计算公式：

$\text{Attention}(Q, K, V) = \text{softmax}\left( \frac{Q K^\top}{\sqrt{d_k}} \right)V$

![经典自注意力机制计算流程](http://public.file.lvshuhuai.cn/images\2022340-1.jpg)

### 特点

| 特性     | 内容                                        |
| -------- | ------------------------------------------- |
| 共享输入 | 所有位置的输入向量都来自同一个序列          |
| 动态建模 | 每个 token 根据上下文决定关注谁             |
| 可并行   | 所有位置的计算可同时进行，非常适合 GPU 加速 |

### 例子解释

句子：「我 喜欢 吃 苹果」

#### 第 2 个 token 是「喜欢」：

- 「喜欢」生成自己的 **Query 向量**
- 与整句中所有 token（包括自己）的 Key 向量计算相似度
- 得到相关性权重（谁更值得关注）
- 用这些权重加权整句中的 Value 向量
- 得到新的「喜欢」的表示：它不仅包含原始信息，还融合了「吃」、「苹果」等信息

这个过程对句子中所有 token 并行进行，每个 token 都在融合整个句子的信息。

## 交叉注意力

### 什么是交叉注意力？

> **交叉注意力**是一种注意力机制，其中 **Query（$Q$）来自一个序列**，**Key（$K$）和 Value（$V$）来自另一个序列**。

这种结构常用于**两个序列之间的信息交互**，最常见于 Transformer 的 **Decoder 阶段**。

### 应用场景：机器翻译

#### 输入（Encoder）

中文句子：「我 喜欢 吃 苹果」 → 编码为一组向量（$K$ 和 $V$）

#### 输出（Decoder）

正在逐步生成英文句子，比如已经生成了 "I like"，准备生成 "to"

此时：

- 当前 Decoder 的状态向量是 **Query（$Q$）**
- Encoder 的输出是 **Key（$K$）和 Value（$V$）**
- Decoder 使用注意力机制，从 Encoder 输出中找到与当前状态最相关的信息

### 交叉注意力的数学表达

设：

- $Q \in \mathbb{R}^{t \times d}$：Decoder 当前状态向量
- $K, V \in \mathbb{R}^{s \times d}$：Encoder 输出向量（$s$ 是输入序列长度）

则交叉注意力为：

$\text{Attention}(Q, K, V) = \text{softmax}\left( \frac{Q K^\top}{\sqrt{d}} \right) V$

其中：

- $QK^\top$：计算 Decoder 与 Encoder 各位置的相关性
- softmax：归一化成注意力权重
- 与 $V$ 相乘：根据权重聚合 Encoder 的信息，反馈给 Decoder

### 为什么用交叉注意力？

| 目的       | 说明                                                       |
| ---------- | ---------------------------------------------------------- |
| 信息对齐   | Decoder 能动态对齐输入的各部分（如翻译时知道该对齐哪个词） |
| 上下文提取 | 帮助 Decoder 利用输入全局信息指导生成过程                  |
| 动态聚焦   | 每个输出位置都可以关注输入的不同区域                       |

### 与自注意力的对比：

| 类型           | $Q$ 来源 | $K$/$V$ 来源 | 场景                         |
| -------------- | -------- | ------------ | ---------------------------- |
| 自注意力       | 当前序列 | 当前序列     | Encoder/Decoder 内部信息融合 |
| **交叉注意力** | 一个序列 | 另一个序列   | Encoder → Decoder 信息传递   |

## 多头注意力

![在这里插入图片描述](http://public.file.lvshuhuai.cn/images\6ae412e01df6f22976ecfb072aa8523b.png)

### 为什么需要多头注意力？

单个注意力头只能在一个子空间中建模 token 之间的关系，**表达能力有限**。

### 多头注意力的核心思想：

**同时使用多个不同的线性变换子空间计算注意力**，每个子空间可以关注不同的信息结构（如语法、语义、位置等）。

### 结构流程

给定输入向量序列 $X \in \mathbb{R}^{n \times d_{\text{model}}}$：

1. 对每个头 $i$，独立计算：

    $Q_i = X W^Q_i,\quad K_i = X W^K_i,\quad V_i = X W^V_i$

2. 计算第 $i$ 个注意力头的输出：

    $\text{head}_i = \text{Attention}(Q_i, K_i, V_i) = \text{softmax}\left( \frac{Q_i K_i^\top}{\sqrt{d_k}} \right) V_i$

3. 然后拼接所有头的输出

    $\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h) W^O$

其中：

- $W^Q_i, W^K_i, W^V_i \in \mathbb{R}^{d_{\text{model}} \times d_k}$
- $W^O \in \mathbb{R}^{h \cdot d_k \times d_{\text{model}}}$

### 优势总结

| 优点               | 解释                               |
| ------------------ | ---------------------------------- |
| **多角度理解信息** | 每个头关注不同的关系结构或位置模式 |
| **增强表达能力**   | 比单一注意力头更全面地建模上下文   |
| **高效并行计算**   | 所有头同时计算，适合 GPU 加速      |

### 和自注意力的关系

- 多头注意力是对 **自注意力（Self-Attention）** 的扩展
- 每个注意力头都是一个自注意力，只是参数不同
- 多个头并行计算，最后合并结果，提升模型能力
