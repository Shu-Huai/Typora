# 02 请求参数

接口的参数从哪来，FastAPI 的判断规则很简单：看声明。路径占位符是路径参数，函数参数是查询参数，Pydantic 模型是请求体，显式写了 Header 和 Cookie 就从请求头里取。这一篇讲清楚前两类，请求体交给 03。

## 参数来源

同一个接口可以同时接收多类参数，FastAPI 按声明方式区分：

![请求参数的四类来源](http://public.file.lvshuhuai.cn/images\fastapi-params.png)

| 来源 | 声明方式 | 示例 | 常见用途 |
| --- | --- | --- | --- |
| 路径参数 | 路径里写占位符 | `/items/{item_id}` | 资源标识，必填 |
| 查询参数 | 函数参数 | `?q=abc` | 筛选、分页、排序 |
| 请求头 | `Header()` | `X-Token: xxx` | 令牌、追踪号 |
| Cookie | `Cookie()` | `session=xxx` | 会话标识 |

识别规则总结成一句话：

- 路径字符串里出现的 `{名字}`，按路径参数处理
- 不在路径里的简单类型函数参数(str、int、bool)，按查询参数处理
- 类型是 Pydantic 模型的参数，按请求体处理
- 用 `Header()`、`Cookie()` 包过的参数，从对应位置取

这套规则的根基是类型注解。注解不只是给 IDE 看的提示，FastAPI 真的在运行时用它做类型转换和校验，顺便生成文档。

### 类型转换的内幕

FastAPI 对参数的转换发生在运行时：查询参数传来的字符串 "10" 会变成真正的 int 10，转换失败直接 422。bool 走专门的解析规则，日期类型也可以直接声明：

```python
from datetime import date


@app.get("/events")
def list_events(start: date | None = None):
    return {"start": start}
```

传 `?start=2026-08-15` 自动转成 date 对象，格式不对返回 422。转换是逐参数进行的，一个参数失败不影响其他参数，但整次请求都会被拒绝。

URL 里的特殊字符有编码问题：中文和空格会被百分号转义，FastAPI 解码后再处理，函数里拿到的永远是解码后的原文。

## 路径参数

路径参数写在装饰器的路径里，用花括号占位：

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}
```

函数参数名必须和占位符一致。注解成 `int` 之后，FastAPI 自动做两件事：把路径里的字符串转成整数、校验转换结果。

> You can declare path "parameters" or "variables" with the same syntax used by Python format strings.
>
> 路径参数用 Python 格式化字符串的同一套语法声明。
>
> —— FastAPI 官方文档《Path Parameters》

传一个转不了的值试试：

```text
GET /items/abc

{
  "detail": [
    {
      "type": "int_parsing",
      "loc": ["path", "item_id"],
      "msg": "Input should be a valid integer, unable to parse string as an integer",
      "input": "abc"
    }
  ]
}
```

状态码 422，`loc` 明确指出是 path 里的 item_id 出了问题。这就是类型注解换来的：没写一行校验代码，非法输入已经被拦在门外。

需要更细的约束时用 `Path()`：

```python
from fastapi import Path


@app.get("/items/{item_id}")
def read_item(item_id: int = Path(ge=1, le=1000, description="物品编号")):
    return {"item_id": item_id}
```

`ge`、`le` 限定数值范围，`description` 会出现在文档里。传 0 或者 1001 都会收到 422，报错信息里写明约束条件。

路径参数只接受有限几种值时，用枚举：

```python
from enum import Enum
from fastapi import FastAPI

app = FastAPI()


class Color(str, Enum):
    red = "red"
    blue = "blue"


@app.get("/colors/{color}")
def read_color(color: Color):
    return {"color": color}
```

传枚举之外的值同样 422，Swagger 文档里会出现下拉框。

一个经典的顺序坑：固定路由必须定义在参数路由之前。

```python
@app.get("/users/me")
def read_me():
    return {"name": "当前用户"}


@app.get("/users/{user_id}")
def read_user(user_id: str):
    return {"user_id": user_id}
```

如果顺序反了，访问 `/users/me` 时，me 会被当成 user_id 的值吞掉，永远走不到 read_me。FastAPI 按定义顺序匹配路由，谁先定义谁优先。

## 查询参数

函数参数只要不在路径占位符里，就是查询参数：

```python
@app.get("/items")
def list_items(skip: int = 0, limit: int = 10):
    return {"skip": skip, "limit": limit}
```

访问 `/items?skip=20&limit=5`，拿到 skip=20、limit=5；不带参数则用默认值。默认值决定了可选性：

- 有默认值，参数可选
- 没有默认值，参数必填，不传就 422

布尔参数有个方便的特性，自动解析常见写法：

```python
@app.get("/items")
def list_items(stock: bool = False):
    return {"stock": stock}
```

`?stock=true`、`?stock=1`、`?stock=yes` 都会变成 True，只有空串和 false 一类写法是 False。

查询参数的校验用 `Query()`：

```python
from fastapi import Query


@app.get("/items")
def list_items(
    q: str | None = Query(default=None, max_length=50),
    page: int = Query(default=1, ge=1),
):
    return {"q": q, "page": page}
```

`max_length` 限长，`ge` 限最小页数。想用别名时加 alias 参数，比如 `Query(alias="item-query")`，客户端传 `item-query`，函数里用原名接收。

请求头和 Cookie 也属于参数来源，只是必须显式声明：

```python
from fastapi import Cookie, Header


@app.get("/who")
def read_who(user_agent: str | None = Header(default=None), session: str | None = Cookie(default=None)):
    return {"user_agent": user_agent, "session": session}
```

Header 参数名自动做下划线到连字符的转换，函数里的 `user_agent` 对应请求头 `User-Agent`。Cookie 直接按名字取。

所有参数校验失败的响应结构都一样：422 状态码，detail 里是列表，每条包含 loc（出错位置）、msg（原因）、input（原始输入）。读报错先看 loc，定位是路径、查询还是请求体的哪个字段。

### 组合参数示例

把几类参数放进同一个接口，观察它们怎么各归各位：

```python
from fastapi import FastAPI, Header

app = FastAPI()


@app.get("/users/{user_id}/orders")
def list_orders(
    user_id: int,
    status: str = "all",
    page: int = 1,
    x_trace: str | None = Header(default=None),
):
    return {
        "user_id": user_id,
        "status": status,
        "page": page,
        "x_trace": x_trace,
    }
```

请求 `/users/42/orders?status=paid&page=2` 带上 `X-Trace` 请求头，四个参数分别从四个位置取到值。这就是 FastAPI 参数处理的全景：声明位置决定来源，类型注解决定转换和校验，其余全部自动。

## 练手题

1. 写一个除法接口 `/divide/{a}/{b}`，a、b 都是 int，b 限 ge=1，传 b=0 和 a=abc 分别观察 422 的报错结构。
2. 写一个列表接口，带 skip、limit 查询参数，验证不传、传字符串、传负数的三种行为。
3. 定义一个状态枚举(open/closed/pending)，做 `/tasks/{status}` 接口，在 /docs 里观察下拉框。
4. 验证路由顺序坑：把 `/users/me` 和 `/users/{user_id}` 两种顺序各试一遍，确认现象。
5. 写一个接口同时声明 Header 和 Cookie 参数，用浏览器开发者工具或 curl 传值验证。
