# 09 身份认证

前面几篇的接口都是敞开大门随便访问。真实的系统里，大部分接口需要确认请求方是谁。这篇讲 FastAPI 最主流的组合：OAuth2 密码流负责登录换令牌，JWT 负责后续请求的身份携带。

## 认证方式

先理清两个词：**认证**回答“访问者是谁”，**授权**回答“来访者能做什么”。登录验证身份是认证，判断权限是授权，FastAPI 官方的安全方案主要解决前者。

![JWT 的签发与验证](http://public.file.lvshuhuai.cn/images\fastapi-jwt.png)

主流方案各有适用场景：

| 方式 | 工作模式 | 特点 | 适用场景 |
| --- | --- | --- | --- |
| Session | 服务端存状态，客户端带 Cookie | 可随时吊销，服务端要存会话 | 传统 Web 站点 |
| Token | 客户端带随机令牌 | 简单，服务端要查库验证 | 内部系统 |
| JWT | 客户端带签名令牌 | 无状态，验签即可，吊销困难 | 前后端分离 API |
| OAuth2 | 第三方授权协议 | 不暴露密码，流程较重 | 对接第三方登录 |

FastAPI 的官方文档把这套组合做成了开箱即用的模式：登录接口走 OAuth2 密码流，后续请求带 JWT。这篇照这个路线走，示例里的用户校验用假数据简化，真实项目替换成数据库查询和密码哈希。

## OAuth2 密码流

密码流(password flow)是最直接的 OAuth2 模式：客户端拿用户名密码换令牌。FastAPI 内置了表单解析：

```python
from fastapi import Depends, FastAPI, HTTPException
from fastapi.security import OAuth2PasswordRequestForm

app = FastAPI()

fake_users = {
    "alice": {"name": "Alice", "password": "secret123"},
}


@app.post("/token")
def login(form: OAuth2PasswordRequestForm = Depends()):
    user = fake_users.get(form.username)
    if user is None or user["password"] != form.password:
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    return {"access_token": form.username, "token_type": "bearer"}
```

`OAuth2PasswordRequestForm` 是内置的表单模型，字段固定为 username、password，可选带 scope。它走 multipart 表单编码，这是 04 里表单参数的直接应用。

登录接口返回的 JSON 里，`token_type` 字段是规范要求，告诉客户端令牌怎么用，bearer 表示放进请求头 `Authorization: Bearer 令牌`。

一个值得知道的设计：Swagger 文档页认识 OAuth2。在接口上声明安全方案后，/docs 右上角会出现 Authorize 按钮，填用户名密码就能在文档页里直接调试需要登录的接口：

```python
from fastapi.security import OAuth2PasswordBearer

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/token")


@app.get("/me")
def read_me(token: str = Depends(oauth2_scheme)):
    return {"token": token}
```

`OAuth2PasswordBearer` 声明了“这个接口需要 Bearer 令牌”，tokenUrl 告诉文档页去哪里登录。文档页点 Authorize 走一遍，后续请求自动带上令牌，省去手填请求头的麻烦。

## JWT 实战

JWT 全称 JSON Web Token，结构是三段 base64，中间用点号隔开：

```text
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhbGljZSIsImV4cCI6MTc1NTI0NTQ3Mn0.签名部分
```

三段分别是：

- header：签名算法(HS256)
- payload：业务数据，sub 存用户标识、exp 存过期时间
- signature：前两段加密钥算出的签名

验证时重新算一遍签名，对得上说明令牌没被篡改。关键认知：payload 是明文 base64，不是加密，绝不能放密码这类敏感信息。

### 令牌结构拆解

把令牌按点号切开，前两段用 base64 解码，能看到明文内容：

```python
import base64
import json

token = "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhbGljZSJ9.签名"
header, payload, _ = token.split(".")
print(json.loads(base64.urlsafe_b64decode(payload + "==")))
# 输出：{'sub': 'alice'}
```

亲手解一次就明白：JWT 只签名不加密，任何拿到令牌的中间人都能读出 payload。签名保证的是内容没被篡改，不是内容不可见。敏感信息一律不进令牌，服务端校验也要靠签名而不是靠 payload 自报家门。

签发票据用 PyJWT：


```python
import time
import jwt

SECRET_KEY = "换成足够长的随机字符串"
ALGORITHM = "HS256"


def create_token(username: str, expire_minutes: int = 30) -> str:
    payload = {
        "sub": username,
        "exp": int(time.time()) + expire_minutes * 60,
    }
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)


def verify_token(token: str) -> str:
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=401, detail="令牌已过期")
    except jwt.InvalidTokenError:
        raise HTTPException(status_code=401, detail="令牌无效")
    return payload["sub"]
```

`exp` 是过期时间戳，decode 时 PyJWT 自动校验，过期的抛 ExpiredSignatureError，改动的抛 InvalidTokenError，分别转成 401 响应。

把验证逻辑放进依赖，受保护的接口一行声明就够：

```python
from fastapi import Depends, FastAPI, HTTPException
from fastapi.security import OAuth2PasswordBearer

app = FastAPI()
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/token")


def get_current_user(token: str = Depends(oauth2_scheme)) -> str:
    return verify_token(token)


@app.get("/me")
def read_me(username: str = Depends(get_current_user)):
    return {"username": username}
```

`get_current_user` 是普通函数，被 Depends 引用就成了依赖。FastAPI 先解出请求头里的令牌，再跑验证逻辑，失败直接 401 短路，处理函数根本不会执行。这是 06 依赖注入在安全场景的标准用法，任何接口想保护，加一个 Depends 参数即可。

> JWT 官方规范：JSON Web Token (JWT) is a compact, URL-safe means of representing claims to be transferred between two parties.
>
> JWT 是一种紧凑、URL 安全的声明表示方式，用于在双方之间传递。
>
> —— RFC 7519

JWT 的局限值得提前知道：

- 签发了就收不回，令牌被偷走，过期前一直有效。缓解办法是短过期时间加刷新令牌，或者服务端维护黑名单
- payload 会随请求变大，别塞太多字段
- 密钥泄露等于全线失守，生产环境用环境变量管理，定期轮换

安全基线再列几条：密码哈希存储(bcrypt 或 argon2，示例里的明文只是演示）、全站 HTTPS、令牌不落 localStorage(XSS 风险）而放 httpOnly Cookie。

## 练手题

1. 完成登录接口，密码校验换成固定测试用户，用 curl 或 /docs 拿一个令牌。
2. 用 verify_token 依赖保护一个接口，分别传错令牌、过期令牌、不带令牌，记录三种 401 的区别。
3. 把 SECRET_KEY 移到环境变量，用 pydantic-settings 读取，验证不设置时的启动行为。
4. 解一个真实的 JWT：把令牌按点号切成三段，用 base64 解开前两段，观察 payload 里有什么。
5. 给令牌加一个 role 字段，写一个依赖检查管理员角色，普通用户访问时返回 403。
