# 03 请求体

查询参数把数据放在 URL 里，适合 GET 场景的简单筛选。接口一旦要接收复杂结构，例如创建商品时的名称、价格、折扣标志，JSON 请求体是更合适的选择。FastAPI 处理请求体的方式高度依赖 Pydantic：先定义一个模型类，再把模型声明为路径操作函数的参数，框架自动完成解析、校验与文档生成。

本章环境约定：Python 3.10 以上，FastAPI 0.100 以上，Pydantic v2。启动命令以 Windows PowerShell 为例，macOS、Linux 除了激活虚拟环境的写法不同，其余命令完全一致。

## Pydantic 模型

Pydantic 是 Python 界使用最广的数据校验库。v2 版本用 Rust 重写了核心解析引擎，校验速度比 v1 提升了一个数量级，同时保持 API 大体兼容。在 FastAPI 中，Pydantic 模型承担三类职责：请求体解析、响应序列化、OpenAPI Schema 生成。

> 官方文档对两者关系的表述是：“FastAPI is built on top of Pydantic v2 for all the data validation, data serialization and automatic model documentation (based on JSON Schema)。” 大意是：FastAPI 构建在 Pydantic v2 之上，数据的校验、序列化、自动文档（基于 JSON Schema)全部交给它完成。

声明模型的套路固定：继承 **BaseModel**，把字段写成带类型注解的类属性。类型注解就是契约，FastAPI 依据它决定如何解析传入的 JSON。

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    price: float
    is_offer: bool | None = None


@app.post("/items/")
def create_item(item: Item):
    return {"name": item.name, "price": item.price}
```

保存为 main.py，启动服务：

```powershell
uvicorn main:app --reload
```

用 PowerShell 发送请求：

```powershell
$body = '{"name": "锤子", "price": 9.9}'
Invoke-RestMethod -Uri http://127.0.0.1:8000/items/ `
    -Method Post -Body $body -ContentType "application/json"
    # 输出：name=锤子  price=9.9
```

函数参数 item 没有默认值，FastAPI 判断它是一个请求体参数。请求体的声明方式和查询参数一样简单，复杂的事情都藏在模型定义里。

### 解析流程

Pydantic v2 的解析方法分两类：以 validate 开头的方法做解析，以 dump 开头的方法做序列化。不经过 FastAPI，单独运行模型也能验证：

```python
from pydantic import BaseModel


class Item(BaseModel):
    name: str
    price: float
    is_offer: bool | None = None


item = Item.model_validate({"name": "锤子", "price": 9.9})
print(item)  # 输出：Item(name='锤子', price=9.9, is_offer=None)
print(item.model_dump())  # 输出：{'name': '锤子', 'price': 9.9, 'is_offer': None}
print(item.model_dump(exclude_none=True))  # 输出：{'name': '锤子', 'price': 9.9}
```

v1 时代的 parse_obj 与 dict 方法在 v2 里换成了 **model_validate** 与 **model_dump**。旧方法仍然保留，但新项目直接写新名字即可。model_dump 的 exclude_none 参数在拼装数据库更新语句时很常用，值为 None 的字段直接不输出。

自动类型转换是 Pydantic 的默认行为。JSON 里字符串数字很常见，例如前端表单收集的 "36"，int 字段收到字符串数字时会做宽容转换：

```python
from pydantic import BaseModel


class Count(BaseModel):
    n: int


c = Count.model_validate({"n": "36"})
print(c.n)  # 输出：36
print(type(c.n))  # 输出：<class 'int'>
```

反向转换不存在：int 字段收到 "abc" 会直接校验失败。转换只发生在明确的数值字符串上，bool 字段收到 "true" 这类字符串同样会被拒绝。

嵌套模型把多个模型组合成树状结构。用户模型内嵌地址模型，传入的 JSON 对应嵌套结构：

```python
from pydantic import BaseModel


class Address(BaseModel):
    city: str
    street: str


class User(BaseModel):
    name: str
    age: int
    address: Address


raw = {"name": "张三", "age": 30, "address": {"city": "杭州", "street": "文一西路"}}
user = User.model_validate(raw)
print(user.address.city)  # 输出：杭州
print(user.model_dump())
```

深层字段校验失败时，422 响应的 loc 会完整记录路径，例如 ["body", "address", "city"]。嵌套层数没有硬性限制，但超过三层后建议拆分成独立模型，便于维护。

默认值字段构成可选字段，JSON 里不传该字段不会报错。可空的字段写成 None 与类型的联合：

```python
from pydantic import BaseModel


class Item(BaseModel):
    name: str
    price: float = 0.0
    tags: list[str] = []
    note: str | None = None


item = Item.model_validate({"name": "扳手"})
print(item.model_dump())
    # 输出：{'name': '扳手', 'price': 0.0, 'tags': [], 'note': None}
```

旧教程里常见的 Optional[str] 与 str | None 等价，Python 3.10 起可以直接写后者。`list[str] = []` 这种写法 Pydantic 会在每个实例上复制默认值，不会出现共享可变默认值的经典坑。

## 字段校验

类型注解只是第一层防线，业务规则要靠 **Field** 函数补充。Field 的第一个参数是默认值，其余参数是约束。

```python
from pydantic import BaseModel, Field


class Product(BaseModel):
    name: str = Field(min_length=1, max_length=50)
    price: float = Field(gt=0)
    stock: int = Field(ge=0)
    sku: str = Field(pattern=r"^[A-Z]{3}-\d{4}$")
    description: str | None = Field(default=None, max_length=200)


p = Product.model_validate({"name": "键盘", "price": 299, "stock": 10, "sku": "KBD-0001"})
print(p.model_dump())
```

约束不满足时抛 ValidationError。在 FastAPI 场景中这个异常被框架捕获，转成 422 响应，不会把堆栈暴露给客户端。

常用约束汇总如下：

| 约束 | 写法 | 示例 |
|---|---|---|
| 大于 | gt | price: float = Field(gt=0) |
| 大于等于 | ge | stock: int = Field(ge=0) |
| 小于 | lt | score: int = Field(lt=100) |
| 小于等于 | le | level: int = Field(le=5) |
| 最小长度 | min_length | name: str = Field(min_length=1) |
| 最大长度 | max_length | title: str = Field(max_length=50) |
| 正则匹配 | pattern | sku: str = Field(pattern=r"^[A-Z]{3}-\d{4}$") |
| 示例值 | examples | name: str = Field(examples=[“锤子”]) |

EmailStr 等复杂类型由额外的包提供。EmailStr 在 pydantic 主包里，但需要 email-validator 才能用：

```powershell
pip install "pydantic[email]"
```

```python
from pydantic import BaseModel, EmailStr


class Subscriber(BaseModel):
    email: EmailStr


s = Subscriber.model_validate({"email": "abc@example.com"})
print(s.email)  # 输出：abc@example.com
```

更多现成类型如支付卡号、电话号码、颜色值，安装 pydantic-extra-types 后从对应模块导入：

```powershell
pip install pydantic-extra-types
```

```python
from pydantic import BaseModel
from pydantic_extra_types.color import Color
from pydantic_extra_types.phone_numbers import PhoneNumber


class Profile(BaseModel):
    theme: Color
    phone: PhoneNumber


p = Profile.model_validate({"theme": "#3366ff", "phone": "+86 138-0013-8000"})
print(p.theme.as_hex())  # 输出：#3366ff
```

### 自定义校验器

Field 覆盖不了跨字段的规则，例如两次密码一致。这种逻辑交给 **@field_validator**，这是 v2 的写法：

```python
from pydantic import BaseModel, field_validator


class RegisterForm(BaseModel):
    username: str
    password: str
    password_confirm: str

    @field_validator("password")
    @classmethod
    def check_length(cls, v: str) -> str:
        if len(v) < 8:
            raise ValueError("密码至少 8 位")
        return v

    @field_validator("password_confirm")
    @classmethod
    def check_match(cls, v: str, info) -> str:
        if v != info.data["password"]:
            raise ValueError("两次密码不一致")
        return v
```

v1 的 @validator 在 v2 里改名成 **@field_validator**，语义相同，仅装饰器名字和参数略有调整。校验器里抛 ValueError，框架会把它包装进 422 响应。

校验失败时 FastAPI 返回 422，响应体结构如下：

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "password"],
      "msg": "String should have at least 8 characters",
      "input": "abc123",
      "ctx": { "min_length": 8 }
    }
  ]
}
```

三个关键字段的含义：loc 是出错位置，body 表示请求体，后面跟字段名，嵌套结构会给出完整路径；msg 是人类可读的错误描述；type 是稳定的错误码，程序判断错误类型时用 type 而不是 msg。detail 永远是数组，一次请求可以同时报告多个字段的问题。

## 模型复用

请求模型与响应模型拆开后职责清晰。创建商品时客户端不传 id，数据库落库后 id 才存在，同一个模型两头凑合会牺牲两侧的准确性：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class ItemCreate(BaseModel):
    name: str
    price: float


class ItemResponse(BaseModel):
    id: int
    name: str
    price: float


@app.post("/items/", response_model=ItemResponse)
def create_item(item: ItemCreate):
    return {"id": 1, "name": item.name, "price": item.price, "secret": "不应外露"}
```

路径操作同时声明两个模型，FastAPI 依据参数类型自动区分：ItemCreate 是请求体，返回值注解里的 response_model 是响应模型。响应模型决定 OpenAPI 文档里展示的结构，也决定实际返回给客户端的数据范围，示例返回值里多出的 secret 字段会被静默过滤。

### 模型继承

两个模型有大量重复字段时，抽一个基类：

```python
from pydantic import BaseModel


class ItemBase(BaseModel):
    name: str
    price: float


class ItemCreate(ItemBase):
    pass


class ItemResponse(ItemBase):
    id: int
```

继承链 ItemBase → ItemCreate 与 ItemBase → ItemResponse 各自独立。基类改动会同时影响两个子类，适合字段高度重合的场景。

枚举类型适合状态字段，非法值直接在解析层拦截：

```python
from enum import Enum

from pydantic import BaseModel


class Status(str, Enum):
    pending = "pending"
    done = "done"
    failed = "failed"


class Task(BaseModel):
    title: str
    status: Status


t = Task.model_validate({"title": "迁移数据", "status": "done"})
print(t.status.value)  # 输出：done
```

继承 str 的枚举在序列化时会输出字符串值而不是枚举对象，response_model 场景下直接可用。文档里枚举字段会展示成固定的取值列表。字面量类型适合候选值不会变化的情况，写法更短：

```python
from typing import Literal

from pydantic import BaseModel


class Message(BaseModel):
    kind: Literal["text", "image", "voice"]


m = Message.model_validate({"kind": "voice"})
print(m.kind)  # 输出：voice
```

### 联合类型

Union 类型或 | 语法允许一个字段接受多种结构：

```python
from pydantic import BaseModel


class Cat(BaseModel):
    meow: str


class Dog(BaseModel):
    bark: str


class Zoo(BaseModel):
    animal: Cat | Dog


z1 = Zoo.model_validate({"animal": {"meow": "喵"}})
z2 = Zoo.model_validate({"animal": {"bark": "汪"}})
print(z1.animal.meow)  # 输出：喵
print(z2.animal.bark)  # 输出：汪
```

联合类型在响应模型里有坑：OpenAPI 里生成 anyOf，很多客户端代码生成工具没法处理，前端拿到的结构不可预测。响应模型尽量用固定类型，联合类型留给请求体这类内部可控的场景。

容器类型直接写在参数注解里。批量创建时请求体声明列表，元素类型写在泛型参数里：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    price: float


@app.post("/items/bulk/")
def create_many(items: list[Item]):
    return {"count": len(items), "first": items[0].name}
```

list[Item] 也可以写成 typing.List[Item]，两者等价。键值型数据用字典类型，键类型写在前：

```python
@app.post("/scores/")
def set_scores(scores: dict[str, int]):
    return {"average": sum(scores.values()) / len(scores)}
```

## 练手题

1. 定义一个内嵌 Address 模型的 User 模型，挂到 /users/ 接口上，发送嵌套 JSON，确认 user.address.city 能正常取到值；再把 city 改成数字，观察 422 响应里 loc 的完整路径。
2. 给价格字段加 Field(gt=0)，发送负数价格，把响应里的 loc、msg、type 三个字段抄下来，说明各自含义。
3. 用 @field_validator 写一个校验器，拒绝长度不足 8 的密码，用 Invoke-RestMethod 验证两种输入的结果。
4. 设计 ItemBase → ItemCreate → ItemResponse 三层模型，分别调用 model_json_schema 方法，对比三个模型生成的 Schema 差异。
5. 实现接收 List[Item] 的批量接口，一次发送三条记录，检查返回的数量是否等于 3。

v2 的模型常用方法汇总：

- **model_validate**：从字典解析并校验，返回模型实例。
- **model_validate_json**：从 JSON 字符串解析并校验。
- **model_dump**：模型实例转字典。
- **model_dump_json**：模型实例转 JSON 字符串。
- **model_copy**：复制实例，可用 update 参数覆盖字段。
- **model_json_schema**：生成 JSON Schema。
