# 06 依赖注入

FastAPI 的依赖注入体系把“处理函数需要什么”和“怎么构造这些东西”拆开。处理函数只声明依赖，构造逻辑由框架负责执行。这一章讲 Depends 的用法、复用场景，以及 yield、全局依赖、子依赖这些进阶写法。

本章环境约定：Python 3.10 以上，FastAPI 0.100 以上，Pydantic v2。启动命令以 Windows PowerShell 为例，macOS、Linux 除了激活虚拟环境的写法不同，其余命令完全一致。

## 依赖是什么

![](http://public.file.lvshuhuai.cn/images\fastapi-di.png)

上图是一条依赖树：处理函数声明依赖 A 和依赖 B，B 又声明依赖 C。请求进来时 FastAPI 先解析叶子依赖 C，再逐层向上注入，最后才执行处理函数。

依赖就是一个可调用对象，用 **Depends** 传给处理函数参数：

```python
from fastapi import Depends, FastAPI

app = FastAPI()


def get_username() -> str:
    return "alice"


@app.get("/whoami")
def whoami(name: str = Depends(get_username)):
    return {"name": name}
```

保存为 main.py，启动服务：

```powershell
uvicorn main:app --reload
```

浏览器打开 http://127.0.0.1:8000/whoami，响应是 {"name": "alice"}。get_username 的返回值被注入 name 参数。Depends 里传的是函数本身，不带括号，调用由框架完成。

### 执行顺序

FastAPI 先执行依赖函数，把返回值赋给处理函数参数，再进入处理函数本体。依赖和处理函数使用同一套声明方式：类型注解、**Query**、**Path**、**Header** 全部可以出现在依赖的参数里。

```python
from fastapi import Depends, FastAPI, Query

app = FastAPI()


def paginate(
    page: int = Query(1, ge=1),
    size: int = Query(10, ge=1, le=100),
):
    return {"page": page, "size": size}


@app.get("/items/")
def list_items(p: dict = Depends(paginate)):
    return p
```

访问 /items/?page=2&size=20，响应是 {"page": 2, "size": 20}。依赖自己也能带参数，参数从请求的查询串、路径、请求头等位置读取，和处理函数参数完全同构。

### 单次请求缓存

同一个请求里，同一个依赖只执行一次。多个处理函数参数引用同一个依赖时，第二次引用直接拿缓存结果。

```python
from fastapi import Depends, FastAPI

app = FastAPI()

call_log = []


def common() -> dict:
    call_log.append(1)
    return {"from": "common"}


@app.get("/a")
def a(x: dict = Depends(common)):
    return {"x": x, "call_count": len(call_log)}


@app.get("/b")
def b(x: dict = Depends(common), y: dict = Depends(common)):
    return {"x": x, "y": y, "call_count": len(call_log)}
```

先访问 /a，再访问 /b。每次请求里 common 都只执行一次，两个接口的 call_count 都是 1。缓存按请求隔离，跨请求不共享，依赖里放数据库连接这类资源时不会串用。想让依赖每次都重新执行，传 **use_cache=False**。

> 官方文档对依赖注入的定义：“Dependency Injection means, in programming, that there is a way for your code (in this case, your path operation functions) to declare things that it requires to work and use: 'dependencies‘。” 大意是：依赖注入指代码可以声明自身运行所需的东西，随后由框架负责提供这些依赖。

## 依赖复用

多个接口共享同一段逻辑时，把逻辑抽成依赖，这是依赖注入最实际的动机。

### 分页参数

列表接口普遍需要 page、size、keyword 三个参数，逐个接口写一遍容易改漏。抽成依赖后只维护一份：

```python
from fastapi import Depends, FastAPI, Query

app = FastAPI()


def common_parameters(
    page: int = Query(1, ge=1),
    size: int = Query(10, ge=1, le=100),
    keyword: str = Query(""),
):
    return {"page": page, "size": size, "keyword": keyword}


@app.get("/items/")
def list_items(params: dict = Depends(common_parameters)):
    return {"params": params, "data": []}


@app.get("/users/")
def list_users(params: dict = Depends(common_parameters)):
    return {"params": params, "data": []}
```

两个接口的参数规则完全一致。以后要改 size 上限，只动 common_parameters 一处。数据库会话也是同样的思路：

```python
from fastapi import Depends, FastAPI

app = FastAPI()


class FakeDB:
    def query(self, sql: str):
        return [{"id": 1, "sql": sql}]


def get_db():
    return FakeDB()


@app.get("/rows")
def rows(db: FakeDB = Depends(get_db)):
    return {"rows": db.query("SELECT 1")}
```

真实项目里 get_db 会从连接池取连接，完整写法涉及 yield 清理，放在第 08 篇展开。用户认证依赖放在第 09 篇：从请求头解析 Token、校验失败直接抛 HTTPException。依赖里抛异常会短路整个请求，处理函数不会执行：

```python
from fastapi import Depends, FastAPI, HTTPException

app = FastAPI()


def check_api_key(api_key: str = ""):
    if api_key != "secret-key":
        raise HTTPException(status_code=401, detail="无效的 API Key")
    return api_key


@app.get("/secure")
def secure(key: str = Depends(check_api_key)):
    print("这条日志不会出现")
    return {"ok": True}
```

不带正确参数访问 /secure，响应是 {"detail": "无效的 API Key"}，状态码 401，处理函数体没有机会执行。短路行为让依赖成为天然的守卫，权限校验放在依赖里比放在每个处理函数开头干净。

## 依赖进阶

### yield 依赖

yield 之前的代码在处理函数执行前运行，yield 之后的部分变成清理逻辑，在处理函数返回后运行。典型用途是数据库连接的获取与关闭：

```python
from fastapi import Depends, FastAPI


class FakeDB:
    def query(self):
        return ["row1", "row2"]

    def close(self):
        print("数据库连接已关闭")


app = FastAPI()


def get_db():
    db = FakeDB()
    try:
        yield db
    finally:
        db.close()


@app.get("/rows")
def rows(db: FakeDB = Depends(get_db)):
    return {"rows": db.query()}
```

访问 /rows，服务端日志先输出响应信息，再输出“数据库连接已关闭”。try/finally 保证处理函数抛异常时清理逻辑也执行，这是 yield 依赖比普通函数依赖强的地方。

全局依赖挂在 FastAPI 实例上，对所有路由生效：

```python
from fastapi import Depends, FastAPI, Request


def log_request(request: Request):
    print(f"{request.method} {request.url.path}")


app = FastAPI(dependencies=[Depends(log_request)])


@app.get("/items/")
def items():
    return {"msg": "ok"}
```

全局依赖适合鉴权、日志、限流这类横切逻辑。某个路由想追加额外依赖，用路由级的 **dependencies** 参数：

```python
from fastapi import Depends, FastAPI, Header, HTTPException

app = FastAPI()


def verify_token(x_token: str = Header()):
    if x_token != "fake-super-secret-token":
        raise HTTPException(status_code=400, detail="X-Token header invalid")
    return x_token


@app.get("/public")
def public():
    return {"msg": "无需校验"}


@app.get("/private", dependencies=[Depends(verify_token)])
def private():
    return {"msg": "需要 Token"}
```

/private 的请求必须带 X-Token: fake-super-secret-token 头，/public 不受影响。路由级 dependencies 和全局 dependencies 叠加生效，先执行全局的，再执行路由级的。

子依赖指依赖里再声明依赖，可以无限嵌套：

```python
from fastapi import Depends, FastAPI

app = FastAPI()


def c() -> str:
    return "c"


def b(x: str = Depends(c)) -> str:
    return f"b({x})"


def a(x: str = Depends(b)) -> str:
    return f"a({x})"


@app.get("/chain")
def chain(result: str = Depends(a)):
    return {"result": result}
```

访问 /chain，响应是 {"result": "a(b(c))"}。FastAPI 自底向上解析：先执行 c，再执行 b，最后执行 a。同一请求内重复出现的依赖命中缓存，三层链里 c 只执行一次。想让同一个依赖函数执行多次，传 use_cache=False：

```python
@app.get("/twice")
def twice(
    p1: dict = Depends(paginate),
    p2: dict = Depends(paginate, use_cache=False),
):
    return {"p1": p1, "p2": p2}
```

p1 走缓存，p2 重新执行一遍 paginate。依赖的声明方式对比：

| 方式 | 写法 | 特点 |
| 普通函数 | def dep()： ... | 最常见，适合参数解析和数据获取 |
| 异步函数 | async def dep()： ... | 适合异步 IO，例如异步数据库驱动 |
| 类 | class Dep: def __init__(self, ...)： ... | 实例作为结果注入，构造逻辑放 __init__ |
| yield 函数 | def dep()： ... yield value | 支持清理逻辑，例如关闭连接 |
| 闭包工厂 | def make(x)： def dep()： return x; return dep | 外层参数定制依赖行为 |

yield 依赖的注意事项：

- 一个依赖函数里只允许一个 yield，yield 之后的代码全部是清理逻辑。
- 依赖使用 yield 后必须是普通 def，异步清理要写成 async def 加 async yield。
- yield 之前抛异常，清理代码不执行；yield 之后抛异常，清理代码照常执行。
- 处理函数抛异常时清理代码仍然执行，适合放连接关闭和事务回滚。

## 练手题

1. 写一个分页依赖，支持 page、size、order 三个参数，接入两个不同的列表接口，用 Invoke-RestMethod 验证参数校验生效。
2. 写一个 yield 依赖模拟数据库连接，在处理函数返回后打印关闭日志，确认关闭动作发生在响应之后。
3. 写一条三层依赖链，c 被 b 依赖，b 被 a 依赖，观察最终返回值是否为 a(b(c))。
4. 用全局依赖给所有接口加请求日志，再在其中一个接口上用 dependencies 参数追加一个校验依赖。
5. 在依赖里抛 HTTPException，验证处理函数体里的 print 不会执行，记录响应状态码和 detail。
