# 08 数据库访问

FastAPI 不绑定任何 ORM。社区最常见的组合是 SQLAlchemy 2.x 与 Pydantic v2，职责划分清晰：SQLAlchemy 管表结构与 SQL 执行，Pydantic 管接口输入输出校验。本章从 SQLite 起步，跑通完整的增删改查，代码整体可迁移到 PostgreSQL 或 MySQL。

## SQLAlchemy 结构

![](Z:\Public\images\sqlalchemy-logo.png)

SQLAlchemy 分两层：**Core** 提供 Engine、连接池与 SQL 表达式；**ORM** 在 Core 之上提供对象关系映射。FastAPI 项目里常见三个角色：**Engine** 管理连接池，**Session** 代表一次数据库会话，**Base** 是所有 ORM 模型的基类。

![](Z:\Public\images\sqlalchemy-session.png)

三层关系：Engine 负责与数据库的物理连接，Session 从 Engine 借用连接执行事务，ORM 模型通过 Session 完成对象持久化。一次 HTTP 请求对应一个 Session，请求结束关闭 Session，连接归还给 Engine 的连接池。

初始化顺序：

1. 定义连接字符串
2. 创建 Engine
3. 用 sessionmaker 绑定 Session 工厂
4. 声明 Base 并定义模型
5. 执行 create_all 建表

完整初始化代码：

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import DeclarativeBase, sessionmaker

# SQLite 文件型连接。check_same_thread=False 允许跨线程使用同一连接，FastAPI 场景必需
DATABASE_URL = "sqlite:///./app.db"

# echo=True 把每条 SQL 打印到控制台，调试期建议开启，上线前关闭
engine = create_engine(
    DATABASE_URL,
    echo=True,
    connect_args={"check_same_thread": False},
)

# sessionmaker 是 Session 工厂。autoflush、autocommit 保持默认关闭，由代码显式控制
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False)


# 2.x 写法：声明式基类，所有模型都继承它
class Base(DeclarativeBase):
    pass
```

参数逐一说明。`echo=True` 打开 SQL 日志，学习期可以看到每条语句的真实长相。`check_same_thread=False` 是 SQLite 特有参数：SQLite 默认禁止跨线程复用连接，FastAPI 的接口可能在不同线程执行，不关掉会报错，原文是 ProgrammingError: SQLite objects created in a thread can only be used in that same thread。`autoflush=False` 关闭自动刷新，避免查询前意外发送未提交的修改；`autocommit=False` 关闭自动提交，事务边界由代码控制。

### 连接字符串

连接字符串决定 SQLAlchemy 与哪台数据库通信。格式为 dialect+driver://user:pass@host:port/dbname，SQLite 例外，直接写文件路径。

| 数据库 | 连接字符串格式 | 驱动 |
| --- | --- | --- |
| SQLite | sqlite:///./app.db | 内置 |
| PostgreSQL | postgresql+psycopg2://name:secret@localhost:5432/mydb | psycopg2 |
| MySQL | mysql+pymysql://name:secret@localhost:3306/mydb | pymysql |

表中 name 与 secret 是用户名与密码的占位符。切换数据库只改这一处字符串与对应驱动包，其余代码不动。

### 创建表

定义好模型后，用 metadata 一次性建表：

```python
from database import Base, engine
from models import Item  # 必须先导入模型，表才会注册到 metadata

# 创建所有尚未存在的表，已存在的表不做修改
Base.metadata.create_all(bind=engine)
```

create_all 只建不存在的表，不改已有表结构。字段调整要交给迁移工具 Alembic，完整迁移流程留在 SQLAlchemy 专题笔记。

## 数据模型

### 字段类型对应

SQLAlchemy 2.x 的推荐写法是 **Mapped** 加 **mapped_column**：Mapped 里的 Python 类型负责静态检查，mapped_column 里的 SQLAlchemy 类型负责建表 DDL。

```python
from datetime import datetime, timezone

from sqlalchemy import DateTime, Float, String
from sqlalchemy.orm import Mapped, mapped_column

from database import Base


class Item(Base):
    # 显式指定表名，避免默认命名规则带来的歧义
    __tablename__ = "items"

    # 主键：整型自增，index=True 建索引加速主键查询
    id: Mapped[int] = mapped_column(primary_key=True, index=True)
    # 字符串列：指定长度，unique=True 加唯一约束
    name: Mapped[str] = mapped_column(String(50), unique=True)
    # 浮点列：可空，创建时可以不填
    price: Mapped[float | None] = mapped_column(Float, nullable=True)
    # 时间戳：带时区，默认取当前时间
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        default=lambda: datetime.now(timezone.utc),
    )
```

常用字段类型对照：

| Python 类型 | SQLAlchemy 类型 | 建表结果 |
| --- | --- | --- |
| int | Integer | INTEGER |
| str | String(50) | VARCHAR(50) |
| float | Float | FLOAT |
| bool | Boolean | BOOLEAN |
| datetime | DateTime | DATETIME |

**数据表模型与 Pydantic schema 的分层**：ORM 模型管表，Pydantic 模型管接口。创建与响应用两个不同的 Pydantic 类，id 与时间戳由数据库生成，创建模型里不出现：

```python
from datetime import datetime

from pydantic import BaseModel, ConfigDict


class ItemCreate(BaseModel):
    # 创建时提交的字段，id 与 created_at 由数据库生成
    name: str
    price: float | None = None


class ItemOut(BaseModel):
    # 响应字段。from_attributes=True 允许从 ORM 对象属性构建实例
    model_config = ConfigDict(from_attributes=True)

    id: int
    name: str
    price: float | None
    created_at: datetime
```

`from_attributes=True` 是 Pydantic v2 的新写法，等价于 v1 的 orm_mode=True。开启后 `ItemOut.model_validate(orm_obj)` 或直接作为 response_model 使用都能正常工作。

relationship 只提一句：它声明两张表之间的关联，加载策略与级联删除行为较复杂，放到 SQLAlchemy 专题笔记展开。

## 增删改查

### get_db 依赖

每个请求需要独立的 Session。FastAPI 的 yield 依赖正好匹配这个生命周期：进入时创建，结束时关闭。

```python
from typing import Generator

from sqlalchemy.orm import Session

from database import SessionLocal


def get_db() -> Generator[Session, None, None]:
    # 每个请求创建一个独立 Session
    db = SessionLocal()
    try:
        yield db
    finally:
        # 无论接口正常返回还是抛异常，finally 都会执行
        db.close()
```

生成器依赖的执行顺序：请求进入时运行到 yield，把 Session 注入接口；接口完成后回到 finally，关闭 Session。异常场景同样经过 finally，不会泄漏会话。

> SQLAlchemy 官方文档原文：The Session is a regular Python class which can be directly instantiated. However, to standardize how sessions are configured and acquired, the sessionmaker class is normally used to create a top level Session configuration which can then be used throughout an application without the need to repeat the configurational arguments. 中文大意：Session 是可以直接实例化的普通 Python 类。为了统一配置与获取方式，通常用 sessionmaker 建立一份顶层配置，供整个应用反复使用，不必每次重复配置参数。

五个接口的完整实现：

```python
from typing import Generator

from fastapi import Depends, FastAPI, HTTPException
from sqlalchemy import select
from sqlalchemy.orm import Session

from database import Base, SessionLocal, engine
from models import Item
from schemas import ItemCreate, ItemOut

Base.metadata.create_all(bind=engine)

app = FastAPI()


def get_db() -> Generator[Session, None, None]:
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()


@app.post("/items", response_model=ItemOut, status_code=201)
async def create_item(payload: ItemCreate, db: Session = Depends(get_db)):
    # 创建：构造对象，add 后 commit 才真正写入数据库
    item = Item(name=payload.name, price=payload.price)
    db.add(item)
    db.commit()
    # commit 后 ORM 自动刷新主键与默认值
    db.refresh(item)
    return item


@app.get("/items", response_model=list[ItemOut])
async def list_items(db: Session = Depends(get_db)):
    # 列表：select 语句加 order_by 排序
    stmt = select(Item).order_by(Item.id.desc())
    return db.scalars(stmt).all()


@app.get("/items/{item_id}", response_model=ItemOut)
async def read_item(item_id: int, db: Session = Depends(get_db)):
    # 详情：get 按主键查询，找不到返回 None
    item = db.get(Item, item_id)
    if item is None:
        # 404 用 HTTPException 表达
        raise HTTPException(status_code=404, detail="记录不存在")
    return item


@app.put("/items/{item_id}", response_model=ItemOut)
async def update_item(
    item_id: int, payload: ItemCreate, db: Session = Depends(get_db)
):
    item = db.get(Item, item_id)
    if item is None:
        raise HTTPException(status_code=404, detail="记录不存在")
    # 更新：直接修改属性，commit 生成 UPDATE 语句
    item.name = payload.name
    item.price = payload.price
    db.commit()
    db.refresh(item)
    return item


@app.delete("/items/{item_id}", status_code=204)
async def delete_item(item_id: int, db: Session = Depends(get_db)):
    item = db.get(Item, item_id)
    if item is None:
        raise HTTPException(status_code=404, detail="记录不存在")
    # 删除：delete 后 commit，返回 204 无响应体
    db.delete(item)
    db.commit()
    return None
```

查询语法对照。`select` 构造查询语句，`filter` 相当于 SQL 的 WHERE 子句，`order_by` 负责排序，`scalars` 取出结果行：

```python
# 条件查询：filter 相当于 SQL 的 WHERE 子句
stmt = select(Item).filter(Item.price > 10).order_by(Item.price)
expensive_items = db.scalars(stmt).all()
```

提交与回滚的时机。add、delete、属性修改都只改 Session 内存里的状态，commit 才生成 SQL 真正落库。commit 过程中数据库报错（如唯一约束冲突）会抛异常，此时要 rollback 才能继续使用这个 Session：

```python
from sqlalchemy.exc import IntegrityError

try:
    db.add(item)
    db.commit()
except IntegrityError:
    # 回滚后 Session 回到可用状态
    db.rollback()
    raise HTTPException(status_code=409, detail="记录已存在")
```

404 的处理：主键查询用 `db.get`，找不到返回 None，转成 HTTPException 即可，见详情接口。

CRUD 操作对照：

| 操作 | SQLAlchemy 写法 | 接口方法 |
| --- | --- | --- |
| 创建 | db.add(obj) + db.commit() | POST /items |
| 列表 | db.scalars(select(Item).order_by(Item.id)) | GET /items |
| 详情 | db.get(Item, item_id) | GET /items/{item_id} |
| 更新 | 修改属性 + db.commit() | PUT /items/{item_id} |
| 删除 | db.delete(obj) + db.commit() | DELETE /items/{item_id} |

常见坑：

- 会话泄漏：Session 不在 finally 里关闭，连接池被耗尽，接口开始报 timeout
- 分离对象：Session 关闭后访问 relationship 属性，抛出 DetachedInstanceError
- 共享 Session：一个 Session 被多个请求同时使用，事务相互干扰
- SQLite 跨线程：不加 check_same_thread=False 直接报错
- 忘记 commit：修改停在内存，进程退出即丢失
- 响应序列化失败：response_model 没有配 from_attributes=True

## 练手题

1. 按本章结构搭出 SQLite 版项目，用 Invoke-RestMethod 跑通五个接口，观察控制台打印的 SQL。
2. 给 Item 增加 quantity 字段，新增 PATCH 接口支持部分更新，体会 PATCH 与 PUT 的语义差别。
3. 把 price 改成必填，请求不带 price，观察 422 默认错误结构。
4. 故意插入两条同名记录触发 IntegrityError，验证 rollback 之后 Session 是否还能继续使用。
5. 只改连接字符串与驱动依赖，把项目切换到 PostgreSQL，其余代码不动，确认接口全部可用。
