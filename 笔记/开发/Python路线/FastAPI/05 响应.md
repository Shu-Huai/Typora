# 05 响应

处理函数把返回值交给 FastAPI 之后，框架还要做三件事：按 response_model 过滤字段、序列化成 JSON、附上状态码。返回值可以是 dict、Pydantic 模型，也可以是 Response 的子类。这一章按加工流程拆开讲。

本章环境约定：Python 3.10 以上，FastAPI 0.100 以上，Pydantic v2。启动命令以 Windows PowerShell 为例，macOS、Linux 除了激活虚拟环境的写法不同，其余命令完全一致。

## 返回值的加工

![](Z:\Public\images\fastapi-response.png)

上图是响应加工的完整链路：处理函数返回 Python 对象，response_model 负责过滤多余字段，最后一步做 JSON 序列化并附加状态码。三步缺一不可。

### 自动序列化

处理函数返回 dict、list、Pydantic 模型实例，FastAPI 都会自动序列化成 JSON，不需要手动调用 json.dumps。序列化规则由 Pydantic 决定。

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    price: float


@app.get("/items/")
def list_items():
    return [Item(name="键盘", price=199.0), Item(name="鼠标", price=89.5)]
```

保存为 main.py，启动服务：

```powershell
uvicorn main:app --reload
```

浏览器打开 http://127.0.0.1:8000/items/，响应体如下：

```json
[{"name": "键盘", "price": 199.0}, {"name": "鼠标", "price": 89.5}]
```

返回 dict 的效果完全相同：

```python
@app.get("/items/1")
def get_item():
    return {"name": "键盘", "price": 199.0}
```

模型实例和 dict 混用也允许，序列化阶段两者的处理方式一致。字符串返回值会被 JSON 编码，响应体带引号。

### response_model 过滤字段

直接返回数据库对象会把敏感字段一起发出去。典型场景是用户模型带密码字段，响应里必须剔除。做法是单独定义一个输出模型，通过 **response_model** 参数声明：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str


class UserOut(BaseModel):
    username: str


users_db = {
    1: UserIn(username="alice", password="secret-123"),
}


@app.get("/users/{user_id}", response_model=UserOut)
def get_user(user_id: int):
    return users_db[user_id]
```

用 TestClient 验证(TestClient 依赖 httpx，先安装）：

```powershell
pip install httpx
```

```python
from fastapi.testclient import TestClient

client = TestClient(app)
resp = client.get("/users/1")
print(resp.json())
# 输出：{'username': 'alice'}
```

password 字段在最终响应里消失。过滤发生在序列化阶段，处理函数内部拿到的仍是完整对象，只有响应体被裁剪。输出模型单独定义的另一个好处：OpenAPI 文档里不会出现 password 字段，交互文档和客户端代码生成工具都拿不到这个字段。

### 响应模型校验

response_model 不止过滤，还会对返回值做校验。返回值类型对不上时，服务端抛 **ResponseValidationError**，客户端拿到 500。把 get_user 的返回值改成错误类型：

```python
@app.get("/users/{user_id}", response_model=UserOut)
def get_user(user_id: int):
    return {"username": 123}
```

启动后访问 /users/1，服务端日志（节选）：

```
ERROR:    Exception in ASGI application
Traceback (most recent call last):
  ...
fastapi.exceptions.ResponseValidationError
```

客户端收到的响应：

```json
{"detail": "Internal Server Error"}
```

这类错误说明返回值类型写错了，响应校验在开发期把问题暴露在服务端日志里。生产环境要配日志告警，否则 500 会被埋进日常错误里。

### 两个排除参数

**response_model_exclude_none** 剔除值为 None 的字段，**response_model_exclude_unset** 剔除返回值里没有显式设置的字段。

```python
from typing import Optional

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class UserOut(BaseModel):
    username: str
    email: Optional[str] = None
    is_active: bool = True


@app.get(
    "/users/me",
    response_model=UserOut,
    response_model_exclude_none=True,
)
def get_me():
    return {"username": "alice", "is_active": True}
```

访问 /users/me，email 字段被剔除：

```json
{"username": "alice", "is_active": true}
```

exclude_unset 以“返回值里实际设置过哪些字段”为准。模型字段的默认值无法区分是否显式设置，这个参数对 dict 返回值最有效。响应模型的整体策略：

1. 入参和出参字段一致时，直接复用同一个模型。
2. 输出需要隐藏密码这类字段时，单独定义 Out 模型。
3. 输出需要聚合多个来源时，再建一个汇总响应模型。
4. 结构简单到不值得建模型时，用 response_model=dict[str, str] 这类泛型声明。

## 状态码

不声明时 FastAPI 默认返回 200。创建资源的场景通常用 201，通过 **status_code** 参数修改：

```python
from fastapi import FastAPI

app = FastAPI()


@app.post("/items/", status_code=201)
def create_item():
    return {"id": 1}
```

status_code 也接受 http.HTTPStatus 枚举，语义比裸数字清楚：

```python
import http

from fastapi import FastAPI

app = FastAPI()


@app.post("/items/", status_code=http.HTTPStatus.CREATED)
def create_item():
    return {"id": 1}
```

删除接口常见 204，响应体为空，处理函数直接返回 None：

```python
@app.delete("/items/{item_id}", status_code=204)
def delete_item(item_id: int):
    return None
```

抛出 HTTPException 时，异常自带的 status_code 优先于装饰器声明。**HTTPException** 两个关键参数：status_code 和 detail。

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()

items = {1: "键盘"}


@app.get("/items/{item_id}")
def get_item(item_id: int):
    item = items.get(item_id)
    if item is None:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"item": item}
```

访问 http://127.0.0.1:8000/items/99，响应体是固定结构：

```json
{
  "detail": "Item not found"
}
```

detail 的值可以是任意 JSON 兼容数据，列表、dict 都允许。响应头的 Content-Type 是 application/json，状态码 404。用 PowerShell 发送同样的请求，报错原文：

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8000/items/99 -Method Get
# 报错原文：The remote server returned an error: (404) Not Found.
```

常见状态码速查：

| 状态码 | 含义 | 使用场景 |
| 200 | OK | 查询、更新成功 |
| 201 | Created | 创建资源成功 |
| 204 | No Content | 删除成功，响应体为空 |
| 400 | Bad Request | 请求格式错误，参数语义不符 |
| 401 | Unauthorized | 未登录或凭证无效 |
| 403 | Forbidden | 已登录但权限不足 |
| 404 | Not Found | 资源不存在 |
| 409 | Conflict | 资源冲突，例如用户名重复 |
| 422 | Unprocessable Entity | 参数校验失败，FastAPI 自动返回 |
| 500 | Internal Server Error | 服务端未处理异常 |

其中 422 由 FastAPI 在请求校验失败时自动返回，不需要手动抛出。401 和 403 的区别容易混：401 表示身份不明，403 表示身份明确但权限不够。

## 响应类型

默认响应类是 **JSONResponse**。处理函数返回 dict 时序列化成 JSON，返回字符串时同样走 JSON 编码。要精确控制响应体，直接返回 **Response** 或子类。

```python
from fastapi import FastAPI, Response

app = FastAPI()


@app.get("/plain")
def plain():
    return Response(content="纯文本内容", media_type="text/plain")
```

Response 跳过序列化，content 原样进入响应体，适合返回 XML、纯文本这类非 JSON 内容。需要自定义响应头时同样直接返回：

```python
from fastapi import FastAPI
from fastapi.responses import JSONResponse

app = FastAPI()


@app.get("/custom")
def custom():
    return JSONResponse(
        content={"code": 0, "data": []},
        headers={"X-Version": "1.0"},
    )
```

文件下载用 **FileResponse**：

```python
from fastapi import FastAPI
from fastapi.responses import FileResponse

app = FastAPI()


@app.get("/download")
def download():
    return FileResponse(path="report.pdf", filename="年报.pdf")
```

path 是服务器磁盘上的文件路径，filename 决定浏览器保存时的文件名，写进 Content-Disposition 头。path 指向的文件必须真实存在，服务启动前先准备一个 report.pdf。大文件或实时数据用 **StreamingResponse**：

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()


@app.get("/logs")
def logs():
    def generate():
        with open("app.log", encoding="utf-8") as f:
            for line in f:
                yield line

    return StreamingResponse(generate(), media_type="text/plain")
```

生成器逐块产出内容，整个文件不会一次性读进内存。服务端推送事件(SSE)也基于 StreamingResponse，把 media_type 换成 text/event-stream 即可。返回 HTML 页面用 **HTMLResponse**：

```python
from fastapi import FastAPI
from fastapi.responses import HTMLResponse

app = FastAPI()


@app.get("/", response_class=HTMLResponse)
def index():
    return "<h1>首页</h1>"
```

路由上单独声明 response_class，其他路由不受影响。JSON 序列化想提速可以换 **ORJSONResponse**：

```powershell
pip install orjson
```

```python
from fastapi import FastAPI
from fastapi.responses import ORJSONResponse

app = FastAPI(default_response_class=ORJSONResponse)


@app.get("/items/")
def items():
    return [{"name": "键盘"}]
```

**default_response_class** 在创建 FastAPI 实例时统一声明，全部路由生效；单个路由用 response_class 参数覆盖。官方文档对 orjson 有一句提醒：

> 官方文档在 Custom Response 一节的性能说明：“In short, if you want the maximum performance, use a Response Model and don't declare a response_class in the path operation decorator.” 大意是：追求最高性能时，用响应模型，不要在路由装饰器里声明 response_class。

原因是 Pydantic v2 底层用 Rust 做 JSON 序列化，和 orjson 是同一套机制。ORJSONResponse 只在没有声明响应模型的场景里才有优势。

选择响应类型的判断路径：

- 返回 JSON 数据：默认 JSONResponse，数据量大时换 ORJSONResponse。
- 返回文件下载：FileResponse，用 filename 指定保存名。
- 返回流式内容：StreamingResponse，配合生成器逐块输出。
- 返回 HTML：HTMLResponse，也可用 response_class 声明。
- 精确控制状态码和响应头：直接返回 Response，或继承 Response 写自定义类。

## 练手题

1. 写一个注册接口，注册时接收 username 和 password，响应只返回 username 和注册时间，密码不得出现在响应体里；用 Invoke-RestMethod 观察完整响应。
2. 写一个删除接口，删除成功后返回 204，响应体必须为空，验证 PowerShell 拿到的是否是空字符串。
3. 用 FileResponse 写下载接口，把服务器上的 backup.zip 以“数据-备份.zip”的文件名下发，用 Invoke-WebRequest 确认保存下来的文件名。
4. 把默认响应类换成 ORJSONResponse，对比一万条数据接口在更换前后的响应时间，再改回 response_model 声明，比较三者的耗时。
5. 写一个查询接口，id 不存在时抛 HTTPException(404)，用 curl -i 观察完整响应，包括状态行、Content-Type 头和响应体。
