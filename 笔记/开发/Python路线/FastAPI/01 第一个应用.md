# 01 第一个应用

这篇解决三件事：搞清楚 FastAPI 在 Python Web 生态里的位置、把第一个服务跑起来、认识自动生成的接口文档。之后九篇的代码都假设环境里有 Python 3.10 以上版本和 FastAPI 0.100 以上版本。

## FastAPI 的定位

FastAPI 是一个用 Python 写 API 服务的 Web 框架，2018 年底发布，背后是 Sebastián Ramírez。官方文档开篇的自述直白：

> FastAPI is a modern, fast (high-performance)， web framework for building APIs with Python based on standard Python type hints.
>
> FastAPI 是一个现代、高性能的 Web 框架，基于标准的 Python 类型注解来构建 API。
>
> —— FastAPI 官方文档

![FastAPI 官方标志](http://public.file.lvshuhuai.cn/images\fastapi-logo.png)

技术底座值得先看清。FastAPI 本身只做三件事：定义路由、解析参数、生成文档，底层的活全交给两个库：

![FastAPI 的三层底座](http://public.file.lvshuhuai.cn/images\fastapi-overview.png)

| 层 | 角色 | 关键词 |
| --- | --- | --- |
| FastAPI | 顶层框架 | 路由、依赖注入、自动文档 |
| Starlette | ASGI 应用 | HTTP 收发、中间件、WebSocket |
| Pydantic | 数据闸门 | 请求体校验、响应序列化 |

几个决定性的设计选择：

- **类型注解驱动一切**。参数类型、校验规则、文档全部从函数签名推导，一份声明多处使用
- **ASGI 原生**。异步接口与同步接口共存，同一个应用里 await 和普通函数都能写
- **文档即代码**。Swagger UI 和 OpenAPI 规范自动生成，永远和代码同步，不会出现文档落后于实现的问题
- **性能在第一梯队**。官方基准接近 Node.js 和 Go 框架，日常业务里性能瓶颈几乎不会落在框架上

定位上要说清楚：FastAPI 适合写 API 服务，数据看板、后端接口、AI 网关都合适；它不适合以服务端渲染 HTML 页面为主的项目，那种场景用 Django（本仓库里有单独的 Django 笔记）或者模板引擎更顺手。

短板也摆出来：生态比 Django 年轻，全家桶式的成熟组件少；异步编程对新手有门槛，写错了容易在并发上翻车；自动文档依赖类型注解的规范程度，注解写得乱，文档也跟着乱。

## 安装启动

两个包就够：fastapi 是框架本体，uvicorn 是 ASGI 服务器：

```powershell
pip install "fastapi[standard]"
```

标准安装会带上 uvicorn 和它常用的依赖，省去手动拼装。用 uv 管理的可以参考仓库里的 [《Python 包管理工具 uv》](../Python%20包管理工具%20uv.md)，等效命令是：

```powershell
uv add "fastapi[standard]"
```

新建 main.py：

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI"}
```

启动：

```powershell
uvicorn main:app --reload
```

```text
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process
INFO:     Started server process
INFO:     Waiting for application startup.
INFO:     Application startup complete.
```

`main:app` 的意思是：main 模块里的 app 对象。`--reload` 打开热重载，改完代码保存，服务自动重启，开发期必备。

![一个请求的完整旅程](http://public.file.lvshuhuai.cn/images\fastapi-first-app.png)

请求的旅程就是上图：浏览器发 GET 请求，uvicorn 作为 ASGI 服务器接住，交给 FastAPI 应用匹配路由，命中处理函数，返回的字典被序列化成 JSON，原路返回。处理函数返回字典自动变 JSON，这是 FastAPI 上手最舒服的一点。

常用启动参数：

| 参数 | 作用 |
| --- | --- |
| `--reload` | 代码变更自动重启，仅开发环境使用 |
| `--port 9000` | 换端口，默认 8000 |
| `--host 0.0.0.0` | 允许外部访问，默认只监听本机 |
| `--workers 4` | 多进程工作数，生产环境才需要 |

常见的启动问题：

- 端口被占：报错 `[Errno 10048]`，换 `--port` 或者杀掉占用进程
- 改了代码没生效：热重载只监听已加载的模块，新文件第一次引用时保存生效
- 中文路径：项目目录含中文一般没事，但尽量用英文目录，个别工具链会踩编码坑

### 同步还是异步

FastAPI 同时支持普通函数和异步函数：

```python
@app.get("/sync")
def sync_route():
    return {"mode": "sync"}


@app.get("/async")
async def async_route():
    return {"mode": "async"}
```

写法差别只是一个 async 关键字，两个接口的行为完全一致。真正影响性能的是函数内部的调用：async 函数里写同步的阻塞调用（同步数据库查询、requests 请求）照样卡住整个事件循环，而普通 def 函数 FastAPI 会放进线程池执行。选择规则一句话：IO 密集就用 async 配异步库(httpx、异步 SQLAlchemy)，计算密集或者拿不准就用普通 def。

## 自动文档

启动后打开两个地址，文档已经在了：

| 地址 | 内容 |
| --- | --- |
| http://127.0.0.1:8000/docs | Swagger UI，可交互的接口文档 |
| http://127.0.0.1:8000/redoc | ReDoc，偏阅读的排版 |
| http://127.0.0.1:8000/openapi.json | OpenAPI 规范原文，机器可读 |

文档不是静态生成的，FastAPI 在启动时从路由和类型注解里实时推导。往处理函数上加点东西，文档立即跟着变：

```python
@app.get("/items/{item_id}", tags=["物品"], summary="查询物品详情")
def read_item(item_id: int, q: str | None = None):
    return {"item_id": item_id, "q": q}
```

`tags` 控制分组，`summary` 写一句话说明，文档页里立刻出现对应的分区和描述。

Swagger UI 页面的价值不止是看，还是测试入口：

1. 点开某个接口，参数框已经按注解生成
2. 填好参数点 Try it out，右侧直接出响应和状态码
3. 不用 Postman，接口自测在浏览器里就能完成

openapi.json 是整份规范的机器描述，前端可以用它自动生成类型定义和请求代码，这就是 OpenAPI 生态的价值。文档、测试、类型三者同源，这份一致性是 FastAPI 相比手写接口文档的最大优势。

### OpenAPI 的用途

openapi.json 节选长这样：

```json
{
  "openapi": "3.1.0",
  "info": {"title": "FastAPI", "version": "0.1.0"},
  "paths": {
    "/": {
      "get": {
        "summary": "Read Root",
        "responses": {"200": {"description": "Successful Response"}}
      }
    }
  }
}
```

每个接口的路径、方法、参数、响应都在里面。几个常见的消费方式：

- 前端工程用 openapi-generator 之类的工具生成类型安全的请求客户端
- Postman、Apifox 直接导入这份 JSON，接口清单不用手工维护
- CI 里做接口契约测试，响应结构变化提前暴露

写接口时保证注解完整，等于免费维护了一份机器可读的契约。注解省掉的地方，文档和客户端生成也会跟着缺。

## 练手题

1. 写一个 hello 接口，返回包含时间戳的字典，用 uvicorn 启动后在浏览器里访问。
2. 给接口加上 tags 和 summary，刷新 /docs 观察变化。
3. 打开 /openapi.json，找出刚才写的接口在 JSON 里的位置，理解文档和代码的对应关系。
4. 故意把端口设置成 80，观察 Windows 下的报错，再用 --port 换回可用端口。
5. 用 uv 创建一个新项目并装 fastapi[standard]，对比 pip 安装方式的步骤差异。
