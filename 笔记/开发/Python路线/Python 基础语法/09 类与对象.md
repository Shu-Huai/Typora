# 09 类与对象

## 类与实例

先看一段不用类的代码。比如一个学生成绩的小脚本，长这样：

```python
students = [
    {"name": "小明", "score": 85},
    {"name": "小红", "score": 92},
]


def add_student(name, score):
    students.append({"name": name, "score": score})


def average(students):
    total = 0
    for s in students:
        total += s["score"]
    return total / len(students)


add_student("小刚", 78)
print(average(students))  # 输出： 85.0
```

代码能跑，也不算难看。学生是字典，操作是函数，`add_student("小刚", 78)` 谁都能看懂。问题出在项目变大以后：学生数据可能散在三个列表里，改一处结构，所有函数跟着改；过两周回来看，已经想不起字典里有哪些 key，也想不起 "score" 有没有拼错过。

**面向对象**的思路是把数据和操作它的函数捆在一起，改成类：

```python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def is_pass(self):
        return self.score >= 60


class Classroom:
    def __init__(self):
        self.students = []

    def add(self, student):
        self.students.append(student)

    def average(self):
        total = 0
        for s in self.students:
            total += s.score
        return total / len(self.students)


room = Classroom()
room.add(Student("小明", 85))
room.add(Student("小红", 92))
print(room.average())  # 输出： 88.5
```

好处很直接。一个学生有哪些字段，翻 `Student` 的定义就知道；和成绩有关的逻辑都在 `Classroom` 里，不用满文件找。坏处是代码变长。脚本总共三十行的话，字典加函数完全够用，硬套两个类反而绕。也有人为打印一条日志写过 Logger 类，里面就一个方法，这不如一个函数。

什么时候其实不需要类：

- 一次性脚本，写完就跑的，函数和字典更快
- 纯数据转换，管道式函数调用比维护对象状态顺
- 字段和结构短期不会变，现成的字典够用

等逻辑开始纠缠、字段开始变多、同一份数据被四处传递的时候，再考虑类。为 OOP 而 OOP 的代码，改起来比纯函数还头疼。

> 类和对象只是工具箱里的一种工具，不是纪律。几十行脚本用函数和字典就够，模型和逻辑都变多的时候再上 class 不迟。

定义一个最简单的类：

```python
class Dog:
    pass


d = Dog()
print(type(d))  # 输出： <class '__main__.Dog'>
```

`class Dog:` 定义一个类，`Dog()` 调用它生成一个**实例**。空类什么也干不了，给它加上初始化方法和行为：

```python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def bark(self):
        print(f"{self.name} 在叫")


d1 = Dog("旺财", 3)
d2 = Dog("来福", 5)
d1.bark()  # 输出： 旺财 在叫
print(d1.name, d1.age)  # 输出： 旺财 3
```

`__init__` 在实例创建时自动执行，负责把数据挂到实例上。`self` 指当前这个实例，`d1.bark()` 内部等价于 `Dog.bark(d1)`，d1 被当成第一个参数传进去。self 不是关键字，只是约定，改名也能跑：

```python
class Cat:
    def __init__(this, name):
        this.name = name

    def meow(this):
        print(this.name)


c = Cat("咪咪")
c.meow()  # 输出： 咪咪
```

能跑，但没人这么写。IDE、lint 工具、代码评审都默认第一个参数叫 self，改名只会招来一句“图什么”。

类里放两种东西：属性（数据）和方法（函数）。找属性的过程看这张图：

![](http://public.file.lvshuhuai.cn/images\class-instance.png)

d1 和 d2 各自存了一份 name 和 age，bark 方法只存了一份，挂在类 Dog 上。调用 d1.bark() 时，解释器先在 d1 自己身上找 bark，找不到，就沿着虚线箭头去类里找。属性查找的顺序是：实例、类、父类，一路往上。因为方法只有一份，两个实例共享，比每个实例复制一份方法省内存。

### 类属性与实例属性

```python
class Dog:
    species = "犬科"      # 类属性：所有实例共享

    def __init__(self, name):
        self.name = name  # 实例属性：各自独立


d1 = Dog("旺财")
d2 = Dog("来福")
print(d1.species, d2.species)  # 输出： 犬科 犬科
Dog.species = "犬"
print(d1.species)  # 输出： 犬
```

**类属性**属于类，所有实例共享一份。改类属性，所有实例都跟着变，这是类级别的状态。实例属性在 `__init__` 里用 self 挂上，每个实例各存各的。

坑在**可变类属性**：

```python
class Team:
    members = []


t1 = Team()
t2 = Team()
t1.members.append("小明")
print(t2.members)  # 输出： ['小明']
```

在 t1 上 append，t2 也看见了。members 列表只有一份，挂在 Team 上，所有实例共享同一个列表对象。想要每个实例一份空列表，放进 `__init__`：`self.members = []`。

Python 还允许给实例动态加属性：

```python
d = Dog("旺财")
d.weight = 12.5     # 运行期随手加，不报错
print(d.weight)     # 输出： 12.5
```

灵活是灵活，代价是拼错属性名不会报错，只会悄悄创建新属性。想在类里禁止动态添加，用 `__slots__` 声明允许的属性名，顺带省内存。日常脚本用不上，知道有这回事就行。

## 方法与继承

### 方法类型对照

类里能定义四种方法，差别在一个装饰器，用途完全不同：

| 类型 | 定义方式 | 第一个参数 | 常见用途 |
| ---- | -------- | ---------- | -------- |
| 实例方法 | `def f(self)` | self，实例本身 | 读写实例数据 |
| 类方法 | `@classmethod` + `def f(cls)` | cls，类本身 | 替代构造器、改类属性 |
| 静态方法 | `@staticmethod` + `def f()` | 无 | 和类沾边的工具函数 |
| property | `@property` + `def f(self)` | self | 把方法伪装成属性 |

**@classmethod** 最常见的用法是替代构造器，比如用字符串直接构造日期对象：

```python
class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    @classmethod
    def from_string(cls, text):
        y, m, d = text.split("-")
        return cls(int(y), int(m), int(d))


d = Date.from_string("2026-08-13")
print(d.year, d.month, d.day)  # 输出： 2026 8 13
```

`from_string` 不需要实例，直接类名调用，返回一个构造好的实例。写 cls 而不是 Date，是为了继承后也能正确工作：子类调用继承来的 from_string 时，cls 是子类，造出来的就是子类对象。

**@staticmethod** 和普通函数差不多，不接收 self 也不接收 cls：

```python
class Date:
    @staticmethod
    def is_leap(year):
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)


print(Date.is_leap(2024))  # 输出： True
```

它和类之间唯一的联系是写在类的命名空间里。多数场景直接放模块级函数就行，不用硬塞进类。staticmethod 的适用场景很少，多数时候只是想告诉读代码的人“这函数和 Date 相关”。

**property** 把方法伪装成属性，访问时不用写括号：

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def area(self):
        return 3.14159 * self.radius ** 2


c = Circle(5)
print(c.area)  # 输出： 78.53975
```

适合“从其他属性算出来的值”，半径改了面积自动跟着算。调用方不用关心它是存好的属性还是现算的方法。

### 继承、super 与 MRO

子类继承父类的属性和方法：

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        print(f"{self.name} 发出声音")


class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)  # 调用父类的 __init__
        self.breed = breed

    def speak(self):            # 覆盖父类方法
        print(f"{self.name} 汪汪叫")


d = Dog("旺财", "柯基")
d.speak()          # 输出： 旺财 汪汪叫
print(d.breed)     # 输出： 柯基
```

`class Dog(Animal)` 表示 Dog 继承 Animal。`super().__init__(name)` 调用父类的初始化方法，把 name 交给父类处理。不写这行的话，父类的 `__init__` 不会自动执行，self.name 就丢了。Dog.speak 覆盖了 Animal.speak，调用时走子类版本，这就是**多态**。

多继承时 Python 按 MRO 顺序找方法，MRO 全称 method resolution order：

```python
class A:
    def f(self):
        print("A")


class B(A):
    pass


class C(A):
    def f(self):
        print("C")


class D(B, C):
    pass


print(D.__mro__)
# 输出： (<class '__main__.D'>， <class '__main__.B'>， <class '__main__.C'>， <class '__main__.A'>， <class 'object'>）
D().f()  # 输出： C
```

D 继承 B 和 C，B、C 又都继承 A，这就是经典的钻石结构。Python 用 C3 线性化算法算出唯一的查找顺序，不会把 A 重复查两遍。顺序本身可靠，但阅读代码的人不一定算得清，所以社区对多继承普遍谨慎，能用组合代替就别上多继承。

顺带说**鸭子类型**：判断一个对象能不能用，Python 看它有没有对应的方法，不看它继承自谁。

```python
class Duck:
    def speak(self):
        print("嘎嘎")


def make_sound(animal):
    animal.speak()


make_sound(Duck())               # 输出： 嘎嘎
make_sound(Dog("旺财", "柯基"))  # 输出： 旺财 汪汪叫
```

Duck 和 Dog 没有任何继承关系，只要都有 speak()，就都能传给 make_sound。走路像鸭子、叫起来像鸭子，就把它当鸭子用。所以 Python 代码里很少见层层 isinstance 检查，官方文档也提醒 isinstance 检查会牺牲鸭子类型的灵活性，能用协议约束就别用类型卡死。

## 魔术方法与 dataclass

**魔术方法**是双下划线开头结尾的方法，Python 在特定时机自动调用。最常写的是 `__repr__`，先看没有它时的样子：

```python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score


s = Student("小明", 85)
print(s)
```

```text
<__main__.Student object at 0x000001F2A4C5B710>
```

打印出来是一串内存地址，信息量为零。调试的时候每 print 一次都要手拼字符串，很烦。加上 `__repr__`：

```python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def __repr__(self):
        return f"Student(name={self.name!r}, score={self.score!r})"


s = Student("小明", 85)
print(s)          # 输出： Student(name='小明', score=85)
print([s])        # 输出： [Student(name='小明', score=85)]
```

`__repr__` 面向开发者，交互式环境、列表嵌套打印都用它；`__str__` 面向用户，print 时优先用。只写 `__repr__` 时 `__str__` 自动回退到它，所以偷懒就只写 `__repr__`。返回的字符串最好长得像能重新构造出对象的代码，调试时一眼能看出字段值。

`__len__` 和 `__getitem__` 让自己的类支持 len() 和 []：

```python
class Playlist:
    def __init__(self, songs):
        self.songs = songs

    def __len__(self):
        return len(self.songs)

    def __getitem__(self, index):
        return self.songs[index]


p = Playlist(["晴天", "七里香", "稻香"])
print(len(p))  # 输出： 3
print(p[1])    # 输出： 七里香
for song in p:
    print(song)
```

```text
晴天
七里香
稻香
```

实现这两个方法之后，len()、[] 索引、for 循环、切片全都免费获得。Python 内置类型好用的原因就在这里：语法糖最后都落到魔术方法上，谁实现了谁就获得同样的能力。

`__eq__` 控制 == 的比较逻辑：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y


p1 = Point(1, 2)
p2 = Point(1, 2)
print(p1 == p2)  # 输出： True
```

默认的 == 比的是身份，两个内容完全相同的实例被认为不相等。定义 `__eq__` 之后比的是值。注意 Python 3 里不定义 `__eq__` 时，== 的行为等价于 is。

上下文管理器靠 `__enter__` 和 `__exit__`。最实用的例子是 Timer，测一段代码耗时：

```python
import time


class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        cost = time.perf_counter() - self.start
        print(f"耗时 {cost:.4f} 秒")


with Timer():
    total = 0
    for i in range(1_000_000):
        total += i
print(total)  # 输出： 499999500000
```

```text
耗时 0.0417 秒
```

with 进入时调 `__enter__`，离开时调 `__exit__`，块内即使报错也会执行 `__exit__`，所以适合做清理：关文件、释放锁、恢复工作目录。

### dataclass(3.7+）

手写 `__init__`、`__repr__`、`__eq__` 是每个数据类的标准动作，Python 3.7 引入的 **dataclass** 自动生成它们：

```python
from dataclasses import dataclass


@dataclass
class Student:
    name: str
    score: int


s1 = Student("小明", 85)
s2 = Student("小明", 85)
print(s1)        # 输出： Student(name='小明', score=85)
print(s1 == s2)  # 输出： True
```

字段上的类型标注在这里只是文档，dataclass 不会在运行时校验类型。默认值直接写在字段上：

```python
@dataclass
class Student:
    name: str
    score: int = 60


print(Student("小红"))  # 输出： Student(name='小红', score=60)
```

可变默认值是坑，和 08 讲函数默认参数时是同一个道理。这样写会直接报错：

```python
from dataclasses import dataclass


@dataclass
class Classroom:
    students: list = []
```

```text
ValueError: mutable default <class 'list'> for field students is not allowed: use default_factory
```

报错原文说得很清楚：列表不允许当默认值，用 default_factory。正确写法：

```python
from dataclasses import dataclass, field


@dataclass
class Classroom:
    students: list = field(default_factory=list)


c1 = Classroom()
c2 = Classroom()
c1.students.append("小明")
print(c2.students)  # 输出： []
```

`field(default_factory=list)` 保证每个实例拿到一份全新的空列表，否则所有实例共享同一个列表对象，又回到 Team.members 那个坑。3.10+ 还加了 slots=True 等参数，版本老的项目留意一下。
