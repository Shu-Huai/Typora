# 10 模块与包

一个 `.py` 文件就是一个**模块**，里面可以装函数、类、变量。项目代码多了以后，把功能拆进多个文件再用 import 互相引用，是 Python 项目的基本组织方式。这一篇从 import 的写法讲起，接着讲包的结构、标准库、第三方库和虚拟环境。

## import 机制

导入模块有四种写法，覆盖日常绝大多数场景：

```python
import math                 # 导入整个模块
from math import sqrt       # 从模块里导入单个名字
import math as m            # 导入并起别名
from math import *          # 导入模块里的全部公开名字
```

前三种的实际效果：

```python
import math
print(math.sqrt(16))  # 输出： 4.0

from math import sqrt
print(sqrt(16))  # 输出： 4.0

import math as m
print(m.pi)  # 输出： 3.141592653589793
```

写法怎么选。模块名短、用到的函数多，`import math` 之后逐个 `math.xxx` 调用最清楚。只用一个函数，`from math import sqrt` 省掉前缀。模块名长或者两个库撞名，`import numpy as np` 起别名。第四种星号导入基本不该出现：

```python
from math import *
print(sin(1), cos(1), pi)
```

代码能跑，坏处不少：

- `*` 把模块里全部公开名字倒进当前文件，几十个名字来历不明
- 两个库都做星号导入时，后导入的会静默覆盖先导入的同名函数
- IDE 的跳转、自动补全、静态检查全部失灵

大型项目普遍禁用星号导入。`from math import sqrt` 这种显式写法还有一个副作用要留意：导入的名字会盖住当前文件里的同名变量。写代码时如果定义过自己的 `sqrt`，from 导入之后这个名字就指向 math 里的那个了。

import 会执行模块的顶层代码。新建 `greet.py`：

```python
# greet.py
def hello():
    print("hello")


print("greet 模块被加载了")
```

另一个文件里导入它：

```python
import greet
greet.hello()
```

```text
greet 模块被加载了
hello
```

import 的瞬间，`greet.py` 顶层的 `print("greet 模块被加载了")` 被执行了。函数体不会执行，但顶层的赋值、print、联网、读大文件都会跑一遍。模块顶层放重活，每次 import 都要白等。解决办法是 `__main__` 判断，第三小节展开。

import 找模块靠 `sys.path`，一串目录按顺序查找：

```python
import sys
for p in sys.path:
    print(p)
```

Windows 上的典型输出（路径因安装而异）：

```text
C:\Users\xxx\Desktop\test
C:\Users\xxx\AppData\Local\Programs\Python\Python312\Lib
C:\Users\xxx\AppData\Local\Programs\Python\Python312\Lib\site-packages
```

第一项通常是脚本所在目录，这就是「当前目录优先」。后果：本地文件和标准库同名时会**遮蔽**标准库。在项目目录建一个 `random.py`：

```python
# random.py
print("这是本地 random.py")
```

然后运行 `import random; print(random.randint(1, 10))`：

```text
这是本地 random.py
AttributeError: module 'random' has no attribute 'randint'
```

import 找到的是本地 `random.py`，标准库的 random 被挡住了。报错说 random 没有 randint，初看很迷惑，标准库明明有。排查方法：`print(random.__file__)` 打印实际加载的文件路径，一看是本地文件就明白了。直接改名最省事。`random.py`、`math.py`、`string.py`、`json.py` 这类与标准库同名的文件名都要避开。

模块不存在时，报错是：

```text
ModuleNotFoundError: No module named 'requests'
```

名字拼错、库没装，都会看到这一行。安装第三方库见后文的「第三方库与虚拟环境」小节。

## 包的目录结构

包就是装着模块的目录。目录里放一个 `__init__.py`，这个目录就成了包：

![包的结构示意](http://public.file.lvshuhuai.cn/images\package-tree.png)

```text
myproject/
├── main.py
├── pkg/
│   ├── __init__.py
│   ├── utils.py
│   └── calc.py
└── data/
    └── config.json
```

`__init__.py` 有两个作用。一是标记目录为包。Python 3.3 之后没有它也能当命名空间包导入，但保留这个文件更明确，很多打包工具也依赖它。二是充当包的初始化脚本，import 包时会先执行它：

```python
# pkg/__init__.py
print("pkg 被导入了")
```

```python
import pkg
```

```text
pkg 被导入了
```

`__init__.py` 里定义 `__all__`，可以控制 `from pkg import *` 导入哪些名字：

```python
# pkg/__init__.py
__all__ = ["utils", "calc"]
```

`__all__` 只约束星号导入，`import pkg.utils` 这种显式导入不受影响。

`__init__.py` 还可以提前导入子模块，给使用方一个干净的入口：

```python
# pkg/__init__.py
from .utils import clean_text
from .calc import add
```

使用方直接 `from pkg import add`，不用关心 add 定义在哪个文件。好处是入口简洁；代价是 import pkg 会把子模块全部加载一遍，包很大时拖慢启动。常见的折中：`__init__.py` 只放 `__all__` 和版本号，显式导入留给使用方。

包内部互相导入用**相对导入**，点号表示层级：

```python
# pkg/calc.py
from . import utils        # 当前包里的 utils 模块
from .utils import fmt     # 当前包 utils 里的 fmt 函数
from .. import config      # 上一级包里的 config 模块
```

一个 `.` 是当前包，两个 `..` 是上一级。相对导入只认包的身份，把 `calc.py` 当普通脚本直接运行会报：

```text
ImportError: attempted relative import with no known parent package
```

脚本直接运行时，Python 认为它不属于任何包，`.` 没有参照物。包内部模块要么用 `python -m pkg.calc` 的方式运行，要么把入口文件放在包外面，由入口去导入包。

导入写法与调用方式的对照：

| 导入写法 | 调用方式 | 适用场景 |
| --- | --- | --- |
| `import math` | `math.sqrt(16)` | 模块名短，用到的函数多 |
| `import pkg.sub.mod` | `pkg.sub.mod.f()` | 深层模块，调用次数少 |
| `from pkg.sub.mod import f` | `f()` | 深层模块，调用次数多 |
| `import math as m` | `m.sqrt(16)` | 模块名长或名字冲突 |

一句话总结：import 导进来的是一个整体，调用要写全名；from...import 导进来的是单个名字，直接调用。深层模块调用频繁就 from，只调一两次就写全名，全名读起来更清楚。

把上面这些拼成一个能跑的最小包。`pkg/utils.py`：

```python
def clean_text(text):
    return text.strip()
```

`pkg/calc.py`：

```python
def add(a, b):
    return a + b
```

`pkg/__init__.py`：

```python
__all__ = ["utils", "calc"]
```

`main.py`：

```python
from pkg.calc import add
from pkg.utils import clean_text

print(add(1, 2))  # 输出： 3
print(clean_text("  空格  "))  # 输出： 空格
```

`main.py` 和 `pkg` 平级放在同一目录，PowerShell 里运行 `python main.py` 即可。

## 入口判断与常用库

`__name__` 是 Python 自动设置在每个模块上的变量：模块被直接运行时是 `"__main__"`，被 import 时是模块名。第一小节说的顶层 print 问题，标准解法是：

```python
# greet.py
def hello():
    print("hello")


if __name__ == "__main__":
    print("直接运行 greet.py")
    hello()
```

直接运行 `python greet.py` 打印两行；被 `import greet` 时静悄悄。`if __name__ == "__main__":` 里的代码只有作为主程序运行时才执行。它的典型用途：把自测代码放进去，模块既能当脚本跑又能干净地被导入；配合 `python -m pkg.calc` 这种包内模块的运行方式。

### 标准库精选

Python 自带的标准库覆盖面很广，日常的数学、时间、文件系统、正则都有。常用的列成表格：

| 库 | 一句话用途 | 示例 |
| --- | --- | --- |
| math | 数学函数与常量 | `math.sqrt(16)` 得 4.0 |
| random | 随机数 | `random.randint(1, 6)` 模拟骰子 |
| datetime | 日期与时间 | `datetime.date.today()` 得今天日期 |
| os | 操作系统接口 | `os.path.join("a", "b")` 拼路径 |
| pathlib | 面向对象的路径 | `Path("data.txt").read_text(encoding="utf-8")` |
| json | JSON 编解码 | `json.dumps({"a": 1})` 得字符串 |
| re | 正则表达式 | `re.findall(r"\d+", "订单123")` 得 ['123'] |
| collections | 增强容器类型 | `Counter("aabbc")` 统计字符频次 |
| functools | 高阶函数工具 | `reduce(lambda x, y: x + y, [1, 2, 3])` 求和 |
| itertools | 迭代器工具 | `permutations("AB")` 生成全排列 |

挑几个跑一遍：

```python
import math
import random
import datetime

print(math.gcd(24, 36))  # 输出： 12
print(random.choice(["石头", "剪刀", "布"]))  # 输出： 石头（每次随机）
print(datetime.date.today())  # 输出： 2026-08-13（当天日期）
```

```python
from pathlib import Path
import json
from collections import Counter

print(Path(".").resolve())  # 输出： 当前目录的绝对路径
print(json.dumps({"name": "小明"}, ensure_ascii=False))  # 输出： {"name": "小明"}
print(Counter("aabbc"))  # 输出： Counter({'a': 2, 'b': 2, 'c': 1})
```

```python
import re
import itertools
from functools import reduce

print(re.findall(r"\d+", "第3页共25条"))  # 输出： ['3', '25']
print(list(itertools.permutations("AB")))  # 输出： [('A', 'B'）， ('B', 'A'）]
print(reduce(lambda x, y: x + y, [1, 2, 3, 4]))  # 输出： 10
```

路径处理上 pathlib 比 os 更现代。`Path("a") / "b"` 用 `/` 拼接路径，可读性比 `os.path.join` 好：

```python
from pathlib import Path

data_dir = Path(".") / "data" / "config.json"
print(data_dir)  # 输出： data\config.json(Windows 上是反斜杠）
```

需要什么功能，先到 docs.python.org 查标准库，没有再考虑第三方库。

### 第三方库与虚拟环境

标准库没有的，用 pip 装第三方库。pip 随 Python 一起安装，PowerShell 里：

```powershell
pip install requests
```

默认从国外 PyPI 下载，国内网络容易卡，换清华镜像源：

```powershell
pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple
```

阿里云、中科大也有镜像，把地址换成对应域名即可。

依赖多了，用 requirements.txt 记录版本清单。生成：

```powershell
pip freeze > requirements.txt
```

文件内容类似：

```text
certifi==2024.8.30
requests==2.32.3
```

换机器部署时一条命令装回全部依赖：

```powershell
pip install -r requirements.txt
```

requirements.txt 要提交进 git，拿到项目的人才能复现同样的环境。

pip 默认装进全局环境，多个项目挤在一起，版本迟早冲突。项目 A 要 Django 3，项目 B 要 Django 5，全局只能留一份。**虚拟环境**给每个项目一个独立的 Python 环境。创建：

```powershell
python -m venv venv
```

第二个 venv 是目录名，环境就建在这个目录里。激活(PowerShell)：

```powershell
.\venv\Scripts\Activate.ps1
```

激活后提示符前出现 `(venv)`，之后的 pip install 装进这个项目的环境。激活的实质是把 PATH 指向 venv 目录里的 Python 和 pip，离开环境一切还原。macOS/Linux 的激活命令是 `source venv/bin/activate`，退出都执行 `deactivate`。

PowerShell 如果报「无法加载文件……因为在此系统上禁止运行脚本」，是执行策略拦截了 Activate.ps1，改用 `.\venv\Scripts\Activate` 或调整执行策略。venv 目录不要提交进 git，写进 .gitignore。

pip 和 venv 能用，但装包慢、环境散。Python 3.12 之后官方推荐的 uv 把这些步骤简化成了两条命令。仓库里有一篇专门笔记：

> 虚拟环境、uv 的安装与常用命令，见 [《Python 包管理工具 uv》](../Python%20包管理工具%20uv.md)。

## 踩坑清单

1. 本地 `random.py`、`math.py` 遮蔽标准库，import 拿到的是自己的文件。用 `print(模块.__file__)` 看加载路径，改名解决。
2. 包内模块用相对导入，直接 `python pkg/calc.py` 报 `ImportError: attempted relative import with no known parent package`。改用 `python -m pkg.calc`。
3. 测试代码和初始化 print 写在模块顶层，import 一次执行一次。测试放进 `if __name__ == "__main__":`。
4. 不激活虚拟环境就 pip install，包装进全局环境，多个项目互相污染。先 `python -m venv venv`，再激活，确认提示符有 `(venv)`。
5. `from xxx import *` 污染命名空间、难以溯源。显式列出需要的名字，放弃星号导入。
