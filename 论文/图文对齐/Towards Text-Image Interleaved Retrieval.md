# Towards Text-Image Interleaved Retrieval

## 基本信息

- 面向图文交错检索
- ACL 2025
- GitHub：[vec-ai/wikiHow-TIIR: [ACL 2025] Towards Text-Image Interleaved Retrieval](https://github.com/vec-ai/wikiHow-TIIR)

## 摘要

当前多模态信息检索研究主要集中于单图像输入，这限制了涉及多图像和图文交错内容的实际应用。本工作提出图文交错检索（TIIR）任务，其查询与文档均为图文交错序列，要求模型通过理解交错上下文语义实现高效检索。我们基于自然交错的 wikiHow 教程构建了 TIIR 基准数据集，并设计特定流程生成交错查询。为探索该任务，我们适配多种现成检索器，并通过交错式多模态大语言模型（MLLM）建立稠密基线。继而提出新型套娃多模态嵌入器（MME），通过多粒度压缩视觉标记数量，以解决基于 MLLM 的 TIIR 模型中视觉标记冗余的挑战。实验表明，简单适配现有模型无法持续产生有效结果。我们的 MME 以显著减少的视觉标记实现了对基线的重大改进。我们提供全面分析，并将公开数据集与代码以促进后续研究。

## 关键方法

### 数据集构建

#### 问题定义

- **任务形式（TIIR）**：将交错多模态实例 $X=[x_1,\dots,x_n]$ 定义为**文本块与图像按语义顺序交错**的序列；给定交错查询 $X_Q$ 与由交错文档 ${X^{D}_1,\dots,X^{D}_m}$ 组成的语料库，从中检索与 $X_Q$ **序列级语义**最相似的文档 $X^D$。相似度由函数 $f(X_Q, X^D)$ 衡量，模型需理解文本与图像在**上下文中的交错语义**。

#### 数据构建

<img src="http://public.file.lvshuhuai.cn/images\image-20251011155551246.png" alt="image-20251011155551246" style="zoom:50%;" />

- **语料来源**：基于 wikiHow 教程，转换为 **15 万**条交错文档检索语料。
- **查询生成流水线**
    1. **图像描述与文本查询生成**：先用多模态模型为每张图片生成 caption，再据教程文本与 captions 指示强 LLM 生成指向文档某一步骤的**文本查询**（含防幻觉提示）。
    2. **文本-图像信息重组**：将查询文本分句，利用 **BM25** 在正样文档上选出信息含量高的句子，作为**文本转图像**的候选；随后用**文生图**生成对应图片。
    3. **人工标注与过滤**：对生成的查询与图像进行人工检查，保证**合法、安全、相关、一致且无生成错误**。
- **规模与划分**：最终得到**7,654** 组高质量**查询-文档**对用于测试，其余生成查询进入训练集；训练集规模 **73,084** 对；语料库共 **155,262** 篇文档。

#### 数据分析

- **交错结构重要性（RQ1）**：仅在**原生交错模型**上做控制变量实验：打乱**图像顺序**、打乱**图像位置**、或两者同时，会导致**显著性能下降**，表明图像间顺序与图像-文本对齐共同影响上下文语义。
- **适配策略有效性（RQ2）**：对“非交错”现成模型的改造进行评估：
    - **多图合并为一图**：并不总是奏效，因丢失交错上下文且引入噪声；
    - **图像描述替代图片**：通常降低性能；
    - **向量级融合（vector-fusion）**：有时提升；
    - **可视化文档（visual doc）截图式输入**：在保留交错结构时也能有效。结论：**保留交错结构**是关键。

### 方法

#### 基线模型

- **改造型非交错基线**：

    - Text w/ Merged Image（将多图拼为单图输入单图检索器）；
    - Text w/ Caption（以生成的图像描述替代图片，退化为文本检索）；
    - Vector-Fusion（文本与图像特征级融合）；
    - Visual Doc（将交错序列渲染成可视化文档截图）。

    在 Table 3 的对比中，若“改造后得分”**低于**“忽略图像的纯文本得分”，则认为无效；多图合并和 caption 替代普遍不稳甚至降分，而 **vector-fusion** 与 **visual-doc** 在某些设定下可有效，因为后者**保留了交错结构**。

- **原生交错基线**：论文采用支持交错输入的**原生交错检索器**作为对照，并据此证明“非交错改造”整体落后于“原生交错”。

#### 套娃多模态嵌入器（MME）

<img src="http://public.file.lvshuhuai.cn/images\image-20251011160651954.png" alt="image-20251011160651954" style="zoom:50%;" />

- **动机**：多模态 LLM 作为密集检索器虽可处理交错输入，但**每张图需要数百视觉 token**，导致**序列过长**与**视觉主导**（embedding 受图像过度影响）。
- **核心做法**：提出 **Matryoshka Multimodal Embedder (MME)**，通过在视觉侧以不同**粒度 $N$**（如 $N\in{1,2,3,4,6,8,12,24}$）**压缩视觉 token**，在保持交错顺序的同时获得更有效的序列级嵌入。
- **训练策略**：**Random / MRL / Mean** 三种训练策略均可配合不同 $N$；实验证明三者在 $N$ 上形成**倒 U 型**性能曲线，文中最终选用 **Mean** 为主。
- **现象与选择**：不同 $N$ 下性能呈**先升后降**；过少 token 捕获不了图像语义，过多 token 又造成视觉主导与语义偏置。多项实验显示在本数据域上**最佳 $N=3$**，文本—图像影响达到更平衡。
- **效率收益：降低 $N$ 明显缩短**平均序列长度**、加速**编码时间**并增大**批量**；例如当 $N$ 从 24（相当于未压缩/类 DPR）降至 3，**平均序列长度**与**编码时间**显著下降、**最大 batch**保持高位；论文给出各 $N$ 的长度/时间/批量明细以支持**按预算部署**。
- **总体结论**：MME 相较原生交错基线**大幅提升**，并通过**可调粒度**在“效果—效率”间灵活权衡，适合大规模召回与精排级联。
